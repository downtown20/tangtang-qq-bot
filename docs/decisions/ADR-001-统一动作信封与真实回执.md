# ADR-001：统一动作信封与真实回执

## 状态

Accepted（分阶段迁移）

回执持久化、受理/终局状态、跨回合消费和媒体独立动作的精确语义由 [ADR-002：持久动作回执邮箱与媒体事实语义](ADR-002-持久动作回执邮箱与媒体事实语义.md) 细化；冲突处以 ADR-002 为准。

## 日期

2026-08-28

## 背景

小糖糖坚持单脑架构：LLM 决定是否说话、发语音、贴图、唱歌或创建提醒；系统只执行、持久化和报告事实。当前实现已具备部分正确基础：

- `send_message`/传话会立即执行并向工具循环返回真实 JSON receipt。
- NapCat 的群/私发送统一产生 `SendResult`，可区分 `confirmed/uncertain/failed`，可重试的确定失败由发送方法统一进入 outbox。
- 定时任务有持久 typed payload 和 `sending/uncertain` 崩溃边界。
- 语音、贴图、CG、唱歌仍先写入 `turn_actions`，工具只返回“准备发送”，真实结果发生在回合后处理；LLM 看不到真实送达结果。
- 同一贴图意图在即时回合保存 CQ 列表，在定时任务保存情绪词，匹配与回执口径分裂。

因此问题不是缺少更多行为规则，而是缺少一种跨入口稳定的“LLM 意图 → 系统执行 → 真实结果”契约。

## 决策

建立一个共享的执行契约，按小切片迁移现有路径：

### ActionEnvelope

- `action_id: str`：一次动作的稳定标识；需要持久幂等时由来源事件和规范化参数生成。
- `kind: text | voice | sticker | image | sing`。
- `channel: group | private`。
- `target: str`。
- `payload: dict`：由 `kind` 决定的最小 typed payload，不接受任意行为规则。
- `review: bool`：只生成草稿，不执行副作用。

### ActionReceipt

- `action_id/kind/channel/target`：与信封对应。
- `status: confirmed | uncertain | failed | draft`。
- `message_ids: list[int]`：QQ 明确确认的消息 ID；批量动作可有多个。
- `actual: dict`：实际执行内容，例如最终文字、语音参数或已选择贴图；不能写成未发生的结果。
- `error_code: str`：有界机器码，供 LLM 判断是否改用别的能力；详细异常只进结构化日志。

执行器不得决定“该不该做动作”，只验证参数、调用既有能力并生成 receipt。即时第三方发送可在工具循环内执行；当前会话的媒体回复可在回合后执行，但真实 receipt 必须按 scope 保存并在下一轮上下文中仅消费一次。不得为了讲述 receipt 再启动一轮 LLM，也不得在 `uncertain` 时自动重放。

NapCat 继续负责 QQ 发送三态与 outbox；TaskManager 继续负责到期、claim 和崩溃恢复。统一动作契约不会复制 `attempts/retry_delay/scheduled_at/correlation_id` 等已有状态。

## 迁移顺序

1. 新增纯数据契约与旧文本 receipt 兼容适配；不改变发送行为。
2. 让语音/贴图后处理产生真实 `ActionReceipt`，按 scope 一次性提供给下一轮 LLM；“准备发送”只是 accepted 受理确认，不是 receipt 或 confirmed 送达事实。
3. 即时与定时贴图共用同一 typed payload 和匹配函数；随后逐个迁移 CG、图片、唱歌。
4. 当所有消费者完成迁移后，删除重复的 bool/stats 结果口径。

每一步必须包含 confirmed/uncertain/failed、批量部分成功、重启和不重复发送测试，并可独立回滚。

## 不采用的方案

### 继续给每种媒体增加专用字段

会让 `turn_actions`、任务 JSON 和工具 schema 继续漂移，无法统一回执和故障恢复。

### 系统根据文本关键词决定动作或失败降级

违反单脑原则；系统只能执行 LLM 已选择的动作。唯一允许的自动降级是已明确写入能力契约且不会造成重复副作用的技术降级。

### 所有动作一开始就强制进入同一数据库队列

当前 NapCat outbox 与 tasks 已分别正确拥有重试和定时状态。立即合并会复制状态机并扩大误重放风险；先统一接口与事实语义，再由测量证据决定是否合并存储。

## 后果

- LLM 能在后续追问中依据真实回执回答，不再把“准备发送”当成“已经送达”。
- 媒体、定时与即时路径逐步共享 payload 和测试，但迁移期允许旧适配层存在。
- receipt 增加少量上下文 token；只注入未消费的最近结果并设置数量上限。
- `uncertain` 仍需要人工核验，不能以提高成功率为名自动重放。
