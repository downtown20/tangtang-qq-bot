# ADR-004：统一媒体动作计划与执行器

## 状态

In progress（P1-3c；即时贴图与 CG 已接入，定时贴图/语音已完成离线统一计划接线，生产 canary 待安全重启；图片/唱歌仍待迁移）

## 背景

当前文本、语音、贴图、CG、图片、唱歌和定时任务存在多套发送路径。部分路径依赖“文本发送成功”才发送媒体，部分路径直接调用 NapCat，部分只保存 plain payload；因此会出现媒体静默丢失、目标间状态互相阻断、角色切换后动作漂移、已确认动作无法修复，以及“成功”日志没有平台回执。

## 决策

### 1. 先建立逻辑计划，再执行子动作

每个 LLM 回合或主动事件生成一个 `ActionPlan`：

- `plan_id`：稳定逻辑动作身份；
- `scope_id`、`channel`、`target`：不可跨会话；
- `source_id`、`created_at`、`role_id`/`library_id`：冻结来源和媒体版本；
- `children[]`：有序的 `ActionEnvelope`，每个 child 有 `ordinal`、typed payload 和自己的 domain ID。

父计划只聚合子动作状态，不替子动作伪造送达；一个 child confirmed 不会阻断或确认其他 child。

### 2. 媒体 payload 必须冻结可重放事实

- sticker/CG：冻结具体 `asset_ref`（或哈希+图库版本），不能在重试时重新随机选图；
- image：resolver 只允许白名单目录/安全 URL，冻结 `asset_ref`、哈希和大小；
- voice：冻结完整文本、情绪、语速、停顿、音色/模型版本；
- sing：冻结 song/section 标识和音频引用；
- reminder/scheduled：保存 source/scope/role/library/plan schema，不能到点依赖当前角色或随机状态。

### 3. 统一执行器与终态

`ActionExecutor` 是唯一媒体发送入口。每个 child 都执行：

```text
draft → persisted → sending → confirmed | uncertain | failed/dead
```

confirmed 经过 ADR-003 的永久事实归账；uncertain 永不自动重发，保留 DB-only 核验入口；failed/dead 不写成功历史。网络调用和本地结算分离，任何“已确认后的本地异常”只能进入 `confirmed_unaccounted`。

### 4. 兼容与迁移顺序

先保留旧入口作为适配层，但禁止新增直发逻辑。迁移顺序：

1. ActionPlan/child envelope/receipt 聚合与 schema；
2. 即时贴图、CG 与语音+贴图组合；
3. TaskManager/Cron/DailyReport 的定时和复合动作；
4. image share/gen；
5. sing 工具、命令路径和旧 `[SING]` marker；
6. 删除 CQ 文本协议和随机重选路径，完成重启/故障注入/回滚演练。

`skip_response` 只表示文本回复决定：媒体 child 要么已执行完毕，要么显式返回结构化失败，不能因外层 `respond=False` 静默丢弃。

## 验收门槛

- 同回合多个媒体动作按 ordinal 全部可见、可分别确认；
- 文本为空时 sticker/voice/image/sing 仍可独立执行；
- 任一 child uncertain/failed 不阻断其他目标，且无重复发送；
- 创建定时动作后切换角色/图库，执行仍使用创建时冻结版本；
- 图片路径穿越、非法 schema、坏 JSON、未知 payload 均 fail-closed；
- 部分送达、进程强杀、重启和 DB-only repair 有回归测试；
- 每个 child 的送达状态进入观察器，父计划不掩盖失败。

### TaskManager 迁移闸门（2026-08-28）

定时任务暂只完成 payload 边界收口，尚未宣称统一媒体完成。下一切片必须按以下顺序推进：

1. 先把 legacy text/typed text 冻结为单 child `ActionPlan`，落盘 plan/child identity 后再发送；旧空 payload 仍走兼容文本改写，但改写结果必须先冻结，不能在每次重试时重新调用 LLM。
2. 以 outbox 或 TaskManager 二选一作为 retry owner；不能让 `SendResult(retryable=True)` 同时触发 NapCat outbox 与任务 release。confirmed/uncertain/partial 均不可盲重放，全部 child confirmed 才允许 `done` 和开窗钩子。
3. 再迁 voice（冻结 emotion/speed/pause/model）与 sticker（冻结 asset/hash/role/library），最后迁 image/sing/Cron；每个 child 都要有真实 receipt、重启恢复和部分送达回归。

该顺序是强制安全门槛，避免仅增加 ActionExecutor 调用却没有持久计划、永久事实或唯一重试所有权。

按 child 停止新执行器，旧入口仅处理已存在的 v1 文本/运输动作；保留 ActionPlan、receipt、confirmed fact 和冲突审计，不删除或重放任何 confirmed/uncertain 动作。
