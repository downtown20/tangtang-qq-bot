# ADR-006：出站平台回执契约与安全边界

状态：**已实现契约、生产接入 feature-off**（2026-08-29）

## 背景

Phase 2b 需要处理“请求已发出但本地响应丢失”的迟到送达证据。取证显示：

* OneBot HTTP `send_*` 响应只保证 `status/data.message_id`，当前 `_call_api` 没有
  `echo`，无法从后续事件反查 outbox；
* NapCat 的 `message_sent` 是扩展事件，没有 echo；当前反向 WS 路由不接收它，且
  SnowLuma/NapCat 的群、私聊 self event 行为并不一致；
* 反向 WS 只校验 localhost，没有连接级鉴权；任何本机进程注入 raw 帧都不能成为
  永久“已发送”事实。

因此不能直接用 `message_id`、入站 `v2:` event_key 或 self event 猜测动作身份。

## 决策

新增 `agent/platform_receipts.py` 作为独立的纯验证层，不调用 Store、不改变 outbox
状态。未来适配器只有在验证通过后，才允许使用 Store 的 capability 入口：

1. 发送前持久化不泄漏内容的 `transport_request_id`；出站事件键固定为独立的
   `out:v1:<hash>` 命名空间，禁止复用入站 event_key。
2. 回执必须同时带 `outbox_id`、`self_id`、channel、target、正文 SHA-256、唯一合法
   signed-int32 `message_ids`、来源和观测时间；字段未知或身份不匹配一律拒绝。
3. 默认只把真实 WS API response 视为可自动确认候选；`message_sent`/synthetic
   回执除非显式 canary 选项，否则 fail-closed。
4. 时间窗、self_id 和 payload hash 校验失败时保持 `uncertain`，不得重发、不得改写
   current attempt；所有拒绝应由未来 adapter 记录 `unmatched/mismatch/missing_id`
   指标。

本 ADR 只定义身份和验证契约，不在没有真实适配器 echo、WS 鉴权和群/私 canary 之前
修改 `_event_route` 或 `_call_api`，避免 HIGH 影响面下的误确认。

## 验收与回滚

`tests/test_platform_receipts.py` 覆盖独立 event_key、transport request 绑定、
message_id 边界、self/时间窗/正文哈希/未知字段和 synthetic 默认拒绝。生产接入仍由
feature flag 控制；验证器出现问题时可保持现有 `uncertain` 流程，不需要修改历史事实。

## 2026-10-15 决定：暂不接入生产（先补前置条件）

**背景**：本 ADR §「实施状态」承诺的两个 feature flag 在 `config.yaml` 里**根本不存在**，
`agent/platform_receipts.py` 在 `agent/`、`onebot/` **零消费者**（生产接入 0%）。
也就是说：决策写了，实现写了，**接线没做**，而文档看起来像是做了。

**影响评估结论（2026-10-15，证据见 docs/审查/文档核查_20261015/改动影响评估.md）**：

1. **确认率不升反降**：回执校验失败一律 fail-closed 到 `uncertain`，而 `uncertain` 在行为
   canary 之前**禁止重发**（ADR-005）⇒ 把今天「HTTP 响应即确认」的路径**变窄**。
2. **反向 WS 的鉴权缺口会从「理论」变成「入口」**：`_event_route` 一旦开始收
   `message_sent`，一条**没有连接级鉴权**的通道就可以伪造回执——而回执的唯一去向是写
   **不可变**的 `confirmed_action_facts`。本 ADR 自己（§前置条件）要求
   「先鉴权、先 canary、后接线」，今天这三条**一条都不满足**。
3. **outbox 会变成热表**（每回合插删 + 触发器 + `BEGIN IMMEDIATE`），影响**未测量**。

**决定：暂不接入。** 顺序按本 ADR 自己写的来：**先做完鉴权（连接级）+ canary，再谈接线**。
在此之前，`platform_receipts.py` 保持「已实现、未接线」的状态——
**但本文档必须如实这么写**，不能让人以为它已经在生产里跑。

**重新打开的条件**：① 反向 WS 加上连接级鉴权（或确认 NapCat 侧不可伪造）；
② 有一个可回滚的 canary 窗口与对照指标；③ 想清楚接入后 `uncertain` 变多、
重发被禁的代价由谁承担。
