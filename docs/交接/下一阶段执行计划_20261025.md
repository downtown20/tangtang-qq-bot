### 1.3 已取证（2026-10-25 11:05 压缩前做完，**不必重查**）

#### A. `memory.reinforce(qq_id, entries)` — `memory.py:624-656`

```
遍历 entries（MemoryEntry，取 .id）：
  · origin == "summarized" → 跳过
    （2026-08-16 事故：检索→强化→再合成循环把错误画像从 importance 4 滚到 10）
  · 30 分钟冷却：kv_get(f"last_reinforce:{id}")，未过冷却就跳过
  · store.reinforce_memory_by_id(id, now) + kv_set(冷却键, now)
```

⚠ **它会 `importance +1`（上限 10）**——不只是记录，**会真的改变排序**。
⚠ 冷却键永久累积（一条记忆一个 kv 键；1561 条 → 1561 个键），可接受但要知道。
⚠ **性能**：每条 3 次 DB 操作（kv_get + UPDATE + kv_set）× 5 条 = **15 次**。

#### B. `store.reinforce_memory_by_id(id, now)` — `store.py:11793-11811`

```sql
UPDATE memories SET importance = MIN(10, importance + 1),
                    last_recalled = ?, recall_count = recall_count + 1
WHERE id = ?
```

单条 UPDATE、独立事务。docstring 明确「刻意不写 `memory_revisions`」——否则流水会按
「召回次数 × 记忆数」爆炸，而信息量已由 `recall_count` / `last_recalled` 两列承载。

#### C. 连带影响：`cleanup_stale_memories(days=90)` **一直在跑**

调用点：`main.py:399`（启动）、`handler_autonomy.py:422` / `:2410`（定时）。
删除条件（`store.py:11190` 起）：`importance <= 2` 且 `recall_count=0`（从未回忆）且 `>90 天`。

→ **因为 `recall_count` 全 0，系统一直把所有记忆当「从未回忆」**。目前没出事只是
因为自忆 `importance >= 4` 挡着（最小 4）。接上 `reinforce` 后这个判据才**第一次变正确**：
被想起过的不该被当作「从未用过」清掉。**这是接线的正向副作用，不是风险。**

#### D. `recall()` 是同步函数，已跑在线程池里

调用点（如 `handler.py:10531`）都套了 `run_bounded_blocking` → **在 `recall()` 内部同步写库
不会阻塞 event loop**，但会增加该次召回耗时（15 次 DB 操作）。所以：**要么批量，要么异步。**

### 1.4 修法（取证后定稿方向）

**接线位置：`memory.py` 的 `recall()` 返回前**——不是 `_get_self_memory_context` 里。
理由：`recall()` 是唯一公共入口（自忆 / 记忆块 / 工具 / 反思 / 关系都走它），
接在底层一次覆盖全部；接在上层只能覆盖自忆一条路（第 9 轮「假取回路径」就是只看了上层）。

**必须做的三件事（按顺序）：**

1. **先改 `reinforce` 成批量**——现在逐条 `kv_get`/`kv_set`，5 条 15 次 DB 操作太慢。
   做法：一次拿到命中 id 的冷却状态（`kv_get` 批量或进程内当天缓存），把 DB 操作压到 ~2 次。
   **不要直接调现状实现**。
2. **fail-open**：回写任何异常都不能影响召回结果（`try/except` + `logger.debug`）。
3. **给一个参数**：`recall(..., reinforce=True)` 默认开，便于将来按调用点关掉。

**docstring 必须写清两件事**：
- 回写一开，`memory.py:545-556` 的「休眠降权」**从此真正生效**（此前是纸面的，因为字段全空）；
- `importance +1` 会带来排序漂移，这是**设计意图**（用起来的记忆更重要），不是 bug。

**离线影响评估要做**：接上后跑一遍「523 条 promise 的 importance 分布变化」+「自忆 top5 是否改变」。
