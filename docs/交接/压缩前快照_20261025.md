## 2. 这个项目是什么（一句话）

小糖糖 = 一个跑在本机的 QQ bot。**我是她的「主治医师」**：不等主人报 bug，
自己去会客厅跟她对话，从她的话里发现缺陷，倒查注入链路，最小改动修复，
三条验证通过后回去复验。详见 [CLAUDE.md](../../CLAUDE.md) 一-2 节 +
[docs/工作方式/自主发现修复闭环_毛选视角_20261025.md](../工作方式/自主发现修复闭环_毛选视角_20261025.md)。

**四条不能丢的纪律**：
1. 她的话是证据，不是产品——先取证再归因。
2. 归因只有一个二分：**「不知道」还是「知道但用错」**？不知道→修注入源；知道但用错→修协议文本。
3. 每轮只打一类缺陷，一次只改一处注入源。
4. **禁止用「让她更小心」来修**——要给她信息，不要加规则。

## 4. ✅ 第 10 轮：已完成（2026-10-25 10:17，已修 + 已重启生效）

> 完整取证见 [第10轮_自忆元数据吃掉68%预算](第10轮_自忆元数据吃掉68%预算_20261025.md)。

### 4.1 缺陷是什么：元数据吃掉自忆块 **68%** 的预算

`_format_self_memories` 每条的行前缀是
`[承诺过 | 2026-08-27 22:22 | 置信度0.70 | 来源 chat_log#236563 私聊] `（50 字符 ≈**33t**），
而 promise 类正文只有 9~20 字。实测（她真答出来的 5 条真数据）：

- 单条 **40~51t**，5 条 **242t**，其中 **165t（68%）是元数据**
- 150t 预算下只装 **2 条**——而代码检索的正是 5 条（`candidates[:5]`），**每次白跑 3 条**

两个字段是纯噪音：`置信度0.70`（1673 条 active 自忆**全是同一个值**，写入侧硬编码）、
`来源 chat_log#N`（她**没有**能按 chat_log id 取回的工具，`search_chat_history` 是关键词检索
——第 9 轮同型假路径）。

**同族证据**：同一个「记住说过的话」能力，记忆块 `format_compact_memories` 早在第 8 轮
就是 `💭 内容`，**自忆块没跟着压**——两套实现只压过一套（教训 #38 同族）。

### 4.2 修法与结果

只改渲染（`💭 {类型} {MM-DD}{群号} {内容}`），预算/优先级/检索条数**全不动**。

| | 改前 | 改后 |
|---|---|---|
| 单条 | 40~51t | **14~25t** |
| 5 条合计 | 242t | **116t** |
| 150t 下保留 | **2 条** | **5 条** |

**线上复验（重启后 pid 40924→57316，同一语义再问一次）**：

```
改前 09:23  裁=3（窗口 369→158t、自忆 249→150t、记忆 307→181t）| 预算 1069/1100
改后 10:17  裁=2（窗口 369→211t、记忆 311→186t）            | 预算  970/1100
            ↑「自忆」从裁剪列表里消失——一条不丢，且省 99t，窗口块也少砍 53t
```

三件套：**3443 passed** / 静态检查 undefined=**0** / 变异 **5 真红 0 不合格**。
新增闸门 `tests/test_self_memory_budget.py`（5 用例，把**条数**而不是 token 变成断言）。

### 4.3 ⚠ 两个别再重做的假设（本轮最贵的取证）

1. **「`_get_self_memory_context` 取最近 5 条不加过滤」——伪。**
   它**已经做了 BGE 语义匹配**（`handler.py:10519`：`query_text=message[:150]` + `target_qq`
   + `grounded_only=True`）；「取最近 5 条」只发生在 **BGE 未就绪的降级路径**。
   第 10 轮的真凶在同一条链路的**下一段**：召回到了 5 条，**格式化后被裁成 2 条**。

```python
# PowerShell 传中文参数会乱码 → 用 python 直接调 HTTP
import json, urllib.request
def call(method, path, body=None, timeout=300):
    url = f"http://127.0.0.1:8765{path}"
    data = json.dumps(body, ensure_ascii=False).encode("utf-8") if body is not None else None
    req = urllib.request.Request(url, data=data, method=method)
    req.add_header("Content-Type", "application/json; charset=utf-8")
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read().decode("utf-8") or "{}")
```

## 9. 上下文管理现状（**主人这次特别问的**）

### 9.1 `billion-context-dsh` 装上了但**用不了**

- 位置：`C:\Users\Administrator\.dsh\profiles\web\node_modules\billion-context-dsh`
- 版本：**v0.2.27**，即 **Active Context Pruning (ACP)**——模型驱动的上下文管理，
  作为 `CompactionEngine` 后端；提供四个模型工具 + `/acp-prune` 命令 + nudge + 提示词段
- **阻塞点**（`cordis.patch.yml` 里 2026-10-24 的注释原文）：
  > 「billion 在本机 dsh 0.2.1-rc.2 上**超出 peer 区间**（`<0.2.1-0`），
  > 所以这一层现在只能靠 context-mode。」
- 旁证：`profiles/web/node_modules` 里**没有** `@deepseek-ai/dsh-compaction`，
  peer 依赖不可能满足。
- **结论**：不是配置没开，是**版本不兼容装不上**。要用它必须动 dsh 版本，这在
  会话内做不到（不能重启 harness）。

### 9.2 现在实际在用：`context-mode` MCP

已装在 `cordis.patch.yml` 的 `mcp-context-mode`。它管的是**另一层**：

| | billion-context-dsh | context-mode |
|---|---|---|
| 管什么 | 会话**什么时候**压缩（ACP） | 单次工具输出**先别进**上下文 |
| 状态 | 装不上 | **可用** |

**局限（配置文件里写明）**：
> 「context-mode 靠 hooks 做的『自动路由』在 DSH 上不生效——工具能用，但没人 nudge
> 你去用。**必须主动用**，否则等于没装。」

**所以本会话的规矩**：大输出（测试日志、网页、大 JSON、大文件分析）一律先走
`ctx_execute` / `ctx_execute_file` / `ctx_fetch_and_index`，只把结论读进上下文。
这次第 8/9 轮已经这么用了（日志统计、库查询全部走 ctx_execute）。
