## 2. 精华经验（按代价排序）

### 2.1 `pinned` 的词义陷阱（最贵的）

`assemble_user_message(pinned=...)` 里 `pinned` 的含义是**不参与背景预算淘汰**，
**不是**无条件注入。我从「它走 pinned」推出「它每轮都在」，写成「常驻直投」——
真实条件是「私聊 + 已挂该场景 + 已激活」，平时一个字都不进。

**词义接近、行为相反。** 一个词的含义要看它**守卫的代码路径**，不是字面。

### 2.2 「脚本跑过了」≠「改对了」（已记教训 #53）

patch 脚本把 `write()` 放最后一行，中间某步 `raise SystemExit` → 前面**全没落盘**，
而汇报里写着「已修好」。起浏览器读 `getComputedStyle` 才发现 CSS 根本没写进去。

**纪律**：每步打 applied/SKIP；报「已修」只能依据**读回来的文件**。

### 2.3 本仓 CRLF 文件（同一类失败踩了三次）

`config.yaml`、`agent/handler.py`、`agent/console_api.py`、
`tests/test_private_interjection.py` 都是 **CRLF**。

```python
raw = io.open(p, encoding="utf-8", newline="").read()
NL = "\r\n" if "\r\n" in raw else "\n"
old.replace("\n", NL)
```

⚠ **`open(p, encoding="utf-8")` 不带 `newline=""` 会把 CRLF 静默转成 LF**（universal newlines），
再用 `newline=""` 写回 → 整份文件的换行被抹平、git diff 显示全文件改动。
2026-10-26 在 `tools/desktop_bridge.py` 上踩了一次（2003 行 CRLF → 0）。
读写**同一份** Windows 源码时，两端都要 `newline=""`。

### 2.4 变量遮蔽（安静的数字错误）

```python
budget = int(pack["budget"])                     # 总量 13500
for slot_name, budget in SLOT_BUDGETS.items():    # ← 循环覆盖了总量
```
结果「总量超预算」报出最后一个槽位的数（11,529 被报成「超出总预算 6800」）。
**校验/告警里别让循环变量和外部同义变量重名。**

### 2.5 手拼结构化文本

`desc: `~` 标记的含义…` —— 反引号是 YAML 保留字符，手拼直接 `ScannerError`，
5 条协议文件头解析失败、正文连头进了 prompt。
**生成 YAML 一律 `yaml.safe_dump`**。

### 2.6 用「名字出现几次」当判据（弱测试，教训 #36 同族）

断言「`INTIMATE_REFERENCE_LABEL` 出现 1 次」。多包化后它合法地出现第 2 次，
测试红了但挂载点一处没多。**守性质**（挂载点唯一 / 有守卫 / 私聊不受影响），不数名字。

### 2.7 整份重写配置 = 注释全丢

`api_config_save` 用 `yaml.safe_dump` 重写整个 `config.yaml`——注释是它一半的价值。
**改某一节用文本级替换**（找块范围、只重写这块、保留上方说明）。
边界：块**内**行尾注释仍会被 `safe_dump` 重新格式化，这是能力边界。

### 2.8 把使用者的具体设定写进通用文案（主人第三次纠正）

「群成员可能含未成年人」是他这套部署的情境。通用文案只能写对任何部署都成立的性质
（「群级设置，开了对全群生效」），判断权交回使用者。同族：`色色参考`、`恋爱军师`
这类内容名也不该进架构文案（教训 #52）。

### 2.9 组级属性被复制成条目级副本（已记教训 #54）

「组叫什么、排第几」是**组**的属性，却被写进**每条**协议的文件头。memory 组 6 条
就有 6 份 `group_title` 副本，改哪份生效取决于遍历顺序（`setdefault`：第一条赢）；
两条不同 key 撞了同名标题则被前端合并成一组。三个症状（条目跑位 / 改标题不生效 /
组合并）同一个根因。

**判据**：问「这个字段的拥有者是组还是这一条」。组级 → 只留**一份定义**
（`prompts/_groups.yaml`），条目只写引用 `group: <key>`；前端按 key 切组，不按文字。

**顺带修的**：`origin` 从来没被读过（只读代码表）→ 文件里改它是死数据。
区分「没写」和「写了空」必须 `"origin" in meta`，不能用真值判断。

### 2.10 「讲解」开关只控一部分（已记教训 #55 同族的静默失效）

CSS 写的是 `html[data-explain='off'] .explain-only`（**单类**选择器），
而 `PromptLedger.tsx` 里写的是 `className="pl-note pl-explain-only"` ——
前缀命名**永远匹配不到**。开关点了它不动，而且没有任何报错。
主人看到的现象是「这按钮只管『她怎么想』」。

修：选择器改成 `[class*='explain-only']`（含这个词就受控）+ 把资产页/调参页/
设置页/特殊模式/概览/两处图例全部补上类。
**判类标准**（藏了会不会做错操作）：机制说明/参数含义/图例 → 藏；
操作步骤/改完怎么生效/数据/错误预警 → **永不藏**（闸门 `tests/test_desktop_explain_mode.py` 反向断言）。

## 3. 关键决策（有理由，别轻易推翻）

| 决策 | 理由 |
|---|---|
| **特殊模式多包** | 主人要「不是指定的一个场景」；`require_marker` 把「要不要激活动作」变成配置 |
| **TTL 默认 0 = 永久** | 主人：「TTL 也在前端改，默认永久」。原硬编码 6 小时从没在前端露过面 |
| **`allow_groups` 默认 false** | 群场景是群级设置，升级不该默认把范本推进群聊 |
| **群聊不看激活状态** | `_sed_active` 按 QQ 存，群聊没有「谁激活了」的对应物。如实写，不装作支持 |
| **场景完全中立（无白名单）** | 主人纠正：「换成陪伴场景只是对于我的设置不适合，不代表别的用户不适合」。变异 spec 有一条专守 |
| **`assets.yaml` 独立注册表** | 不放 `config.yaml`：那份文件的注释经不起程序化写入 |
| **协议元数据放 front-matter** | 「和场景卡一样在文档内可改」；代码表降级为默认值 |
| **正文字段不含 front-matter** | 文件头是文案，进 prompt 就是事故。`read_override()` 负责剥离 |
| **组标题只住 `prompts/_groups.yaml`** | 组是组级的东西，条目级副本 = 改哪份生效不可知（#54）。组表缺失才回落代码表 |
| **组头双击改名、不给「新建组」按钮** | 组的 key 是分类学（代码默认值与排序都依赖它），用户新建只会造出孤组。标题可改、key 不可随意改 |

## 8. 主人偏好（这轮被纠正过的，别再犯）

1. **文案中立**：不写他的具体设定（未成年人、色色、恋爱军师…）进通用文案。
2. **交互少一步**：改名走「双击原作改」，不要额外按钮/弹窗。
3. **不过度注释**：注释写「为什么」，不写「做了什么」。
4. **按实际设计，不要一味迎合**：「不要一味迎合我的需求，按照实际以用户、开发者角度合理设计」——他能提现象，但方案该由我按「别人也会遇到吗」判断。
4. **前端要自解释**：不能让人看配置文件才知道机制（教训 #48）。
5. **先调研再解释**：「你没说清楚」「该解释很无力」——他要查证后的说明，不是重述代码。
6. **文案禁 Markdown 记号**，也别含糊其词。
