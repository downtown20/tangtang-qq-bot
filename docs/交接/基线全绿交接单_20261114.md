## 5. 踩过的坑（别重犯）

1. **不要用切片拼接改 conftest**：`t3[:start] + fixture` 会把中间所有 fixture 删掉。
   我这么干过一次，导致 703 个 `fixture 'store' not found`。**追加到末尾**。
2. **批量删用例前先区分 helper**：AST 只按「函数体里出现已删文件名」判定，
   `_local_packages` / `_expected_file_count` 这种 helper 会被误删 → NameError。
   误删后恢复手法：`git show HEAD:<path>` 取出原函数体，追加回去（**不要用 `>` 重定向，
   PowerShell 会写成 UTF-16 把文件弄坏**，用 `git checkout HEAD~1 -- <path>` 或 python 读 `git show` 输出）。
3. **改 `tools/打包发布版本.py` 的 TAG 不要用 pwsh 内联 python -c**：引号会被 PowerShell 吞，
   表现为 `SyntaxError: unterminated string`。写一个 `.py` 临时脚本改，或直接用 Edit 工具。
4. **注释里不要写真实盘符路径**（如 `D:\桌面\...`）：`tools/准备发布.py` 的敏感扫描会命中，
   写 `.release-blocked` → 打包被拒。这个闸门已经拦过我三次。
5. **打包脚本会自动把 zip 复制到桌面**（`_copy_to_desktop`），桌面路径走注册表
   `User Shell Folders\Desktop`（本机 = `D:\桌面`），不写死 `~/Desktop`。
6. **`importlib.util.find_spec()` 是探测语义，不是导入语义**：在 `sys.meta_path` 的
   `find_spec` 里 `raise ImportError` 并不会让调用方看到「未安装」，而是把探测本身炸掉。
   我曾用这个手法制「坏 jieba_fast 视为未安装」的钩子，直接让
   `gpt-sovits/start_api_patched.py:23` 在被 import 时崩 → 两个测试文件**收集期 ERROR**。
   要表达「未安装」，正确做法是让它**真的**找不到（`find_spec` 返回 None）；
   装一个坏包却想当没装，那是运行时该修的事，不是测试该伪造的。
7. **测试里凡是「距今多久」判定的数据，时间戳一律现算**：写死 `2026-10-25 06:00:00`
   配 `active_hours=240` 的窗口，过 10 天这条测试就自己变红，而且**症状极具误导性**
   （`short_term == {}` 看起来像「短时记忆结构没被填充」，实际是数据被窗口过滤光了）。
   用 `datetime.now() - timedelta(minutes=N)`。
8. **mock / 假 subprocess 的判据不要用宽子串**：`any("torchaudio" in c for c in cmd)`
   会命中 pytest 的 `tmp_path`（里面带测试函数名 slug `…test_cuda_torchaudio_is_soft_s0`），
   于是 `--cache-dir <tmp>` 这条也被判成失败，**每条** pip 命令都失败。
   用 `c.startswith("torchaudio==")` 只认「要装的包名」那一格。
9. **闸门随功能下线时要「条件化」而不是删掉断言**：Qt 控制台删了，`agent/` 里再没有 Qt 回调，
   但直接把「必须有 Qt 回调条目」这条断言删掉，等于让闸门永久哑巴（教训 #30 变体）。
   改成「agent/ 里还存在 GUI 框架导入时才要求」——哪天重新引入，要求自己回来。
10. **改测试前先问「这条测试测的是哪条分支」**：`test_ollama_models` 4 条一起红，
    看着像三处文案不一致，实际是新增的 TCP 预检把所有用例短路到了另一条分支。
    一个 autouse fixture 修好全部，而按文案逐条改会「改绿了但测的仍是错的分支」。
