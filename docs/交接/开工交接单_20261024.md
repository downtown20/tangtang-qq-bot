## 0.2.1 ✅ 第 9 轮：一条**假的**取回路径（2026-10-25 09:23，已修 + 已重启生效）

> 完整取证见 [第9轮_假的取回路径](../诊断/第9轮_假的取回路径_20261025.md)。

**现象**：自忆块在 15 天 390 条淘汰记录里**被整块淘汰 365 次（第一名）**——

| 2 | `BACKGROUND_PRIORITY["自忆"]` P10 → **P6** | 假路径还在，偶尔淘汰仍把她引向死路 |
| 3 | `BACKGROUND_BUDGET_TOKENS` 900 → **1100** | 自忆排最后，加多少钱都被别人先吃（实测 1200 仍淘汰） |

## 3.1 语义回挂的两个真问题（2026-10-24 夜，抽样取证，已修）

**发现 1：「引文逐字存在」≠「语义成立」。** 抽 21 条已落地记录核对，evidence_ids
全部能在 chat_log 里找到（引文闸门有效），但至少 2 条语义完全不成立：

- `mem#6069` 记忆是「刚满20岁的调酒师，17岁辍学…」，证据原话是「我讨厌迷你世界」；
- `mem#10211` 记忆是「是男性（爷们）」，证据是系统注入文本

**根因**：第二次语义闸门的判据太宽（原文只问「是否足以支持」），LLM 对
「归纳性记忆 + 一个相关碎片」会回 yes。

**发现 2：chat_log 里存的不是纯用户原话。** 有的行带系统注入前缀（`【…】`）、
图片/表情占位符、引用占位符。这些被当成证据时既污染语义判断，也会让占位符
变成「事实」（`mem#1497`「发图片、动画表情」的证据就是 `[图片:[动画表情]]`）。

**已修**（`tools/回挂记忆证据.py` + `tools/语义回挂证据.py`）：
1. `clean_user_utterance()`：证据原话先删掉 `【…】` 系统块与三类占位符，
   清洗后短于 4 字的整条丢弃（只删不改写——引文闸门比对的必须是原文逐字片段）；
2. `VERIFY_SYSTEM` 收紧：要求「原话**直接陈述**了记忆里那个具体信息」，
   归纳性记忆只有一个碎片时必须 no，并写明「宽松一次就等于给无据记忆发可信等级」。

## 3.2 「她以为我说了两遍」的真缺陷（2026-10-25 凌晨，已修）

**主人报的现象**：在桌面端会客厅发言，她会「识别成我发了两次，相当于桌面端和手机各发一次」。

**先排除的**：主库 `chat_log` 里没有重复入库（每次输入一行，event_key 唯一）；
平台重投的持久去重层近 4 天只命中过 1 次；群聊日志里同一条 `📥` 打两行是
`message_batcher` 的设计（第一次入队后 return，批处理窗口到期带 `_batched=True` 重入才真跑 LLM）。

**真缺陷**（代码链路可证，不是猜测）：

```
handle_group_message / handle_private_message
  add_to_buffer(...)                  # 当前消息立刻进短期缓冲
  get_recent_context_messages(...)    # 取最近 N 条 → 把当前消息也取出来了
  _call_deepseek(system, user_message, history_messages, ...)
      api_messages = [system] + history_messages + [user_message]
                                                ↑ 同一条用户消息，第二次
```

`_call_deepseek`（handler.py:6691）把 `history_messages` 整段 `extend` 进 `api_messages`，
而 `user_message` 就是**同一条**用户话（只多了背景块前缀）。于是这条消息在请求体里出现两遍。
**这是真能让她说「你说了两遍」的机制**，而且从上线起就有——只是没人查过请求体。

**修复（单一判定点）**：不在 `_call_deepseek` 里按内容猜重删（`user_message` 带背景块、
图片占位符会被中性化，两者不总相等，内容比对是脆的），而是：

1. `MemorySystem.add_to_buffer()` 返回该条消息的 `seq` 锚点（`memory.py`）；
2. `get_recent_context_messages(..., exclude_seq=)` 按 seq **精确排掉那一条**（默认 0 = 不排除，向后兼容）；
3. handler 的群聊/私聊两个入口把 seq 传下去。

**验证**：`tests/test_history_excludes_current_message.py` 9 条闸门（含 AST 检查「两个调用点
必须传 `exclude_seq`，删了就红」+ 反向闸门「不许在 `_call_deepseek` 里做内容级删除」）；
5 个变异全 RED（`变异_历史重复.json` 3 个 + `变异_历史重复_handler.json` 2 个）；
全量 **3337 passed / 0 failed**；静态检查 undefined=0。已重启生效（boot=`f9834756`）。

**副作用提醒**：这条修复让**她的历史里少了一条重复的当前消息**。凡是「她对自己上一句/对方
本句的判断出错」的现象，先怀疑这里——不要再按内容字符串去加第二道删除。

## 3.4 预算尺子坏了——她有一半说明书从来没送到（2026-10-25 06:00，已修 + 已重启生效）

> 记录：[docs/诊断/第2轮_投递链路_20261025.md](../诊断/第2轮_投递链路_20261025.md)

**不是估算，是问出来的**：把她的真实 system prompt（3000 字符 / 中文 2340）
原样发给同一个模型，读 `usage.prompt_tokens` = **1926**。旧公式
`中文×1.8 + 其他×0.5` 估 **4542** —— **高估 2.36 倍**。
于是预算 3000 只装得下约 1271 真实 tokens，`_truncate_text` 从头保留砍尾部，

不知道关系档位）。

| 改哪里 | 改成什么 |
|---|---|
| `context_builder.estimate_tokens` | 中文系数 **1.8 → 0.72**（实测 0.64，取略保守）；其他字符保留 0.5（对英文仍高估，安全方向） |

| `protocols.MAX_BACKGROUND_BLOCK_TOKENS` | 600 → **240**（同比例） |
| `protocols.EVIDENCE_RESERVE_TOKENS` | 400 → **160**（原为背景预算的 33%；不折算会变成 480 的 83%，证据块吃掉全部预算） |

## 3.6 重启就忘——对话窗口从 chat_log 重建（2026-10-25 06:45，已修 + 已重启生效）

## 3.9 帮别人修正记忆，结果记到了自己头上（2026-10-25 08:10，已修 + 已重启生效）

> 记录：[docs/诊断/第7轮_第三人称转述_20261025.md](../诊断/第7轮_第三人称转述_20261025.md)
> 起于第 6 轮末尾发现的互斥记忆（`mem#17589` corrected vs `mem#18121` verified）。

**顺证据链挖出的真相**：`mem#18121` 的证据是 `chat#199048`，原文是——

> 「帮我修正一下「穷到吃外卖」的记忆：他说的「33岁上班族」是开玩笑的，不是事实。
> **他**实际是今年7月刚靠指标生名额考上一中的高一新生，8月19号要去军训。」

**主人在让糖糖修正另一个人的记忆**（2377255095），句中的「他」指那个人。
纠正工具干对了（`mem#17485` 正确写进 2377255095 名下），
**但第二天的提取器把这句话提取成了主人自己的身份记忆**，而且因为有逐字证据，
信任校验完全通过 → 直接 verified。

根因：提取 prompt 的 🚫 清单有「引用转述（『他说』）」，覆盖**引用别人的话**，
不覆盖**「主语是第三方的描述」**（「他实际是高一新生」不是引用，是陈述）。

修法：`agent/memory.py` 提取 prompt 加一条边界 + **反例**：

```
- 关于别人的陈述——主语是第三方的句子（「他今年高一」「她不喜欢抽烟」）说的是
  **那个人**。尤其当用户让你「修正 XX 的事」时，那句事实属于 XX，记到当前用户
  名下就是张冠李戴。
  判据**看主语，不看句子里有没有「他/她」**：
  ✅「我老婆叫米雪儿」「我妈是医生」——主语是「我」，是自述
  🚫「她叫米雪儿」「他今年高一」——主语是第三方，说的是别人
```

**反例是设计要点**：抽 2000 条有证据记忆，192 条（9.6%）正文含「他/她」，
但绝大多数主语仍是本人。只写「有第三方就跳过」会误杀正常自述——
所以规则必须是**判主语**，不是**判词**。

**行为验证（本轮第一次做到改前改后都跑真模型）**：

| | 结果 |
|---|---|
| 事故消息 改前 | `[identity] 今年7月刚靠指标生名额考上一中，是高一新生` + `[open_loop] 8月19号要去军训` |
| 事故消息 **改后** | **`[]`** |
| 反例「我老婆叫米雪儿…」改后 | 仍提取 `[relationship] 老婆叫米雪儿` + `[note] 认为老婆最重要`（**没误伤**） |

验证：4 条闸门 + **2 个变异全红**（删边界 / 只留「有第三方就算」删掉「看主语+反例」）；
静态检查 0；全量 **3413 passed / 0 failed（826s）**。**已重启生效（bot pid 33204）**。

**存量没动**：`mem#18121` 仍在库里、仍 verified，与 `mem#17589`（corrected）同时
active。这轮只防未来——两者共存要靠「矛盾仲裁」，下一轮。
