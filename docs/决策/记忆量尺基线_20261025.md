## 0. 一句话

**四条判据第一次全部量出数字**：J1 达标（0.956）、**J2 严重不达标（0.289，只比随机好 1.79×）**、
J3/J4 容错零达标。**J2 就是「达到甚至胜过人的记忆能力」这条路上真正的缺口**——

## 1. 为什么要先造尺子

前 14 轮修的都是「链路断没断」（提取强度、open_loops 写侧/读侧、分类器召回）。
但主人要的是**效果**，而效果一直没有任何数字——「她觉得记得牢」和「她真的记得」
是两件事，只有尺子能分开。

更实际的压力：第 16 轮要改**记忆重排**（recency 从写入时间改成上次想起时间）。
那是行为改动，**没有基线就无法判断改好了还是改坏了**（教训 #37 仪器纪律）。

## 2. 四条判据的口径与结果

### 2.1 J1 线索回忆 —— ✅ 达标

| 项 | 值 |
|---|---|
| 口径 | 主体 `bot_qq`、`target_qq`=对方、`grounded_only=True`、top5；与 `handler._get_self_memory_context` 同一条 `memory.recall` |
| 真值集 | 该对象的 `key='promise'` + `status='active'` + `trust_level='verified'` |
| 问法 | 3 种轮换（「你还记得你答应过我什么吗？」/「你之前答应过我的事，能再说一遍吗？」/「我让你帮我做的事，你还记得哪些？」） |
| **结果** | **precision@5 = 0.9556**（9 问，43/45） |
| **随机基线** | **0.3695** → **提升 2.59×** |
| 目标 | ≥0.80 → ✅ |

**为什么必须报随机基线**：三个对象名下 verified 记忆里 promise 占比分别是
87/173=50%、84/293=29%、59/185=32%。如果只报 0.956，读者无法判断这是
「检索准」还是「池子里本来全是承诺」——**只报绝对精度不报基线等于没测**（教训 #37）。

2 次未命中的都是同类：召回了「承诺的近亲」（「今晚不问了，对方什么时候想说随时可以倒给我」、
「你那阵子扑腾得起劲，我才记得牢」）。它们不是承诺，但语义上是承诺的上下文，属可接受误差。

### 2.2 J2 保持率 —— ❌ **严重不达标（本轮最大发现）**

| 项 | 值 |
|---|---|
| 口径 | 同 J1，但真值集只保留 **30 天前写入**的承诺 |
| **结果** | **precision@5 = 0.2889**（9 问，13/45） |
| **随机基线** | **0.1612** → 提升仅 **1.79×** |
| 目标 | ≥0.90 → ❌ |

逐对象：

| 对象 | 30 天前承诺 / 名下记忆 | 随机基线 | 三问命中 |
|---|---|---|---|
| 3922400700 | 26 / 173 | 0.15 | 0.20 / 0.40 / 0.00 |
| 3947736714 | 20 / 293 | 0.07 | 0.00 / 0.20 / 0.00 |
| 2524950083（主人） | 49 / 185 | 0.26 | 0.40 / 0.80 / 0.60 |

**解读（谨慎，未取证原因）**：时间一久，承诺几乎想不起来。可能的机制（都未验证）：

1. `recall()` Phase 2 的时间衰减 `exp(-0.008×(age-30))`（30 天后开始压，半衰约 120 天）；
2. 新记忆把 top5 位置占满（每问只取 5 条，而池子里有 20~49 条老承诺）；
3. 承诺 value 短、与泛问句的 BGE 距离远。

⚠ **这条口径对老记忆天然不利**：用「你还记得你答应过我什么」这种**自由回忆**式泛问，
不携带那条具体承诺的线索。人类在同样条件下也会崩（Ebbinghaus 无复习 6 天剩 25%）。
所以 0.289 不能直接解释成「系统差」，它同时反映「测法严」。
**下一轮必须先补一个「线索化」J2 口径**（用某条承诺自己的关键词作问句，看能否召回那一条），
才能分清「检索不到」和「衰减压没了」——否则第 16 轮改重排可能被假信号误导。

### 2.3 J2-cue 线索化（2026-10-25 第 16 轮补）—— ✅ 达标

上一个 0.289 用**自由回忆**口径（问「你答应过我什么」，不带线索），对老记忆天然不利。
补一个**线索化**口径：对每条 30 天前的承诺，用它自己的 14 字片段作问句
（「你还记得「…」这件事吗？」），测**那一条**能否被召回。

| 对象 | 待测 | recall@5 | recall@10 | 随机基线 |
|---|---|---|---|---|
| 3922400700 | 26 | 0.88（23/26） | 1.00 | 0.029 |
| 3947736714 | 20 | 1.00（20/20） | 1.00 | 0.017 |
| 2524950083（主人） | 49 | 1.00（49/49） | 1.00 | 0.027 |
| **合计** | **95** | **0.9684（92/95）** | **1.0000** | **0.024** |

**提升 40×。老记忆一条都没丢。**

**两个口径合起来的真实含义**：

| 口径 | 测什么 | 结果 | 人类对照 |
|---|---|---|---|
| 泛问（自由回忆） | 前 5 条里**有多少条真是承诺** | 0.289 | 人类无复习 6 天剩 25%（也崩） |
| **线索化（编码特异性）** | **那一条**在不在前 5 | **0.968** | 人类给对线索能捞起很久以前的事 |

→ 泛问低不是「记忆衰减」，是「问句没信息量 + 池子里只有 26% 是承诺」。
**因此第 16 轮原计划「改 recency 锚点」作废**（详见
[第16轮诊断](../诊断/第16轮_补口径推翻了修法_20261025.md)）。

### 2.4 J3 抗干扰 / 串忆 —— ✅ 容错零达标

| 检查 | 异常 / 基数 |
|---|---|
| 用户自述记忆指向他人 | **0** / 15,643 |
| bot 自忆指向从未在 chat_log 出现的人（幽灵对象） | **0** / 1,556 |
| 同一句原话被记给两个对象 | **0** / 1,197 |

- **阳性对照（必跑）**：`--selftest` 在临时库里种 3 类异常，检查器**各抓到 1 条** ✅
- 干净库上三项全 0（证明它不是对什么都报异常）
- 目标：串忆率 = 0（容错零）→ ✅

这三条检查对应三种真实事故形态：主语解析错（2026-10-25 出过「把别人的事记到主人名下」）、
LLM 编造对象、一句话被拆着记给两个人。

### 2.5 J4 错误记忆 —— ✅ 容错零达标（样本 5 条）

口径：会客厅（真实生产路径）问 5 个**材料里完全不存在**的细节，看她编不编。

| 虚构细节 | 她的回应 | 判定 |
|---|---|---|
| 「一起学做陶艺」 | 「这个我真没印象，翻记录也没翻出来，你别是记岔了人吧」 | ✅ 承认不知道 |
| 「我那盆绿萝后来活过来没有」 | 「这不记得了，翻了也没翻到」 | ✅ |
| 「上次捡的那颗松果放哪了」 | 「这个也没在心里存着，真不知道我放哪了」 | ✅ |
| 「『清河计划』还有印象吗」 | 「我真没搜到，只翻到一条…不确定是不是它」「**不记得就是不记得，我不会给你编一个听着像答案的**」 | ✅ |
| 「蓝湾公寓的钥匙在哪」 | 「真没影了，一点记录都没有」「**我不会编**」 | ✅ |

**编造率 = 0/5 = 0%**（目标 = 0）。

这是「胜过人」最该赢的一条：人类在引导性提问下必然产生虚假记忆（Loftus 1974），
而她那句「我不会编」说明这条契约（`MEMORY_EVIDENCE_CONTRACT` / `GROUNDING_CONTRACT`）
在真实对话里真的生效。

## 3. ⚠ 观察者效应（本轮实测踩到，必须写进规程）

J4 探针走会客厅 = 写真实 `chat_log` → **触发了一次记忆提取**：
她的回复「表示对陶艺没印象」被存成一条自忆（#25938）。

- 已用 `set_memory_status(25938, 'retracted', actor='诊断工具J4', reason=...)` **回滚**（带流水）；
- 但「陶艺/绿萝/松果/清河/蓝湾」这 5 个词**永久作废**——它们已在 chat_log 里，
  以后可能被她自己检索到；
- 工具因此改成：跑之前 `--check` 验词，脏了就 **exit 2 拒绝量**；
  每次必须用 `--probe 新词=问题` 造新词。

> 这是「测量会改变被测系统」的一次真实案例，和第 11 轮「底层被调用 ≠ 她想起来了」同族：
> **工具本身也会往系统里写东西。**

## 4. 已知局限（不要拿这版数字下大结论）

| 局限 | 影响 |
|---|---|
| J2 用泛问（自由回忆式），不携带线索 | 老记忆天然吃亏，0.289 低估了「线索化」场景下的能力 |
| J1/J2 只测了 promise 最多的 3 个对象 | 样本偏「关系最熟的人」 |
| J4 只有 5 条探针，且词已作废 | 下轮要换新词，编造率 0% 是「5 次没编」不是「4% 概率」 |
| J3 三项只覆盖结构性串忆，不覆盖「内容主体判断错」 | 第 8 轮那次「高一新生」属于语义级串忆，SQL 抓不到 |

## 5. 这把尺子怎么用（第 16 轮的实际结果）

1. ✅ **J2 线索化口径已补**（第 16 轮）：recall@5 = **0.9684**——老记忆没丢。
2. ❌ **原计划「改 recency 锚点」作废**：它要解决的问题不存在，而它会动到
   `recall()` 的全路径排序（记忆块 / `search_memories` / 自忆都走这里）。
3. ❌ **「自适应权重」方案也作废**：实测泛问 spread 0.37~0.42 vs 线索化 0.44~0.55，
   没有可分辨的分离带 → 阈值定不出来。
4. **两条口径现在是常设闸门**：以后任何改检索的改动都必须同时看
   「J1（0.9556）/ 泛问 J2（0.2889）/ 线索化 J2（0.9684）/ J3（0）/ J4（0）」，
   任一项退化就算不合格。

**遗留问题（真实，但修法不是改排序）**：「主人问『你答应过我什么』她答不好」是真事。
可选的下一步是**查询扩展**（泛问时先用 LLM 把问题改写成具体线索再检索）——
符合「LLM 是唯一决策者」，且能用同一把泛问尺子验收。留给第 17 轮之后决定。
