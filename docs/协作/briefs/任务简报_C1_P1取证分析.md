## 目标

对 P1 四项分别取真实运行证据，量化「问题是否真实、优化收益多大、成本多高」，最后给出**排序推荐**：哪一项证据最明确、最值得先优化。选哪项由主负责人裁决，本简报不预判结论。

## 四项取证任务

### 1. 低频记忆时效（21 天准入策略）

- 数据源：`extraction_jobs`、`extraction_cursors`（deferred backlog 不是 worker 卡死，是最长 21 天准入）
- 要回答：deferred backlog 规模与年龄分布（最老排队多久、中位数）；21 天准入的历史实际收益（越老的队列最终提取出多少有效记忆）；若缩短阈值（如 7 天/3 天）会覆盖多少当前 backlog；单次提取的 LLM 成本证据（日志里的 token/耗时行）
- 推荐条件：只有数据证明「老消息提取率显著低于新鲜消息」或「backlog 无限增长」时，才建议改阈值

### 2. 窗口自然度（reply/skip/fade 分布）

- 数据源：`conversation_window_events`、`reply_metrics`、tangtang.log 窗口判定行
- 要回答：历史窗口样本的 reply/skip/fade 实际分布；现有样本中「明确请求 / 群友互聊 / 收尾语 / 无关消息」各占多少；是否已积累足够自然样本来判断协议效果，还是样本仍然全是明确请求（阶段总结说 15 个样本多数是明确请求）
- 注意：新 boot（今天 19:58 后）的样本可能有 C3 收尾语，一并纳入

### 3. 自治与驱动力（promise→completion 结算 vs 饱和）

- 数据源：`decision_runs`、`proactive_events`、`proactive_event_state`、`episodes`、`kv_store`（驱动力持久化落点先定位）、`tangtang_journal`
- 要回答：驱动力当前各维度的实际值分布，是否长期接近 1.0 饱和；promise→completion 结算链路的历史执行记录（承诺数、完成数、结算数、超时数）；结算成功时驱动力是否真实回落；自治决策（decision_runs）的样本量与质量
- 推荐条件：若证据显示「饱和真实存在且结算未有效释放」→ 值得修；若「结算有效但样本不足」→ 结论是继续观察而非改代码

### 4. 知识评估集（多来源/长文/冲突版本/空召回）

- 数据源：knowledge/ 目录现状、tests/ 中知识检索相关测试、docs/审查/知识库效率复查+混合检索升级_20260815.md
- 要回答：现有评估集覆盖哪些场景（多来源、长文、冲突版本、空召回各有多少样本）；哪些缺口最大；补齐评估集的工作量估计
- 注意：阶段总结已说「索引内核完成，不再重复建设」——本项只评估「评估集缺口」，不改检索内核

## 产出格式

执行报告 C1 必须含：

1. 四项各自的证据快照（真实查询输出）
2. 每项结论：问题是否真实 / 优化收益量化 / 成本估计 / 建议（优化 or 继续观察）
3. **最终排序推荐表**：四项按「证据明确度 × 收益 × 成本」排序，指明第一优先项及理由
4. 异议栏（按协议）
