## 任务

### P2-1：记忆黄金集 + 评测器

1. **黄金集设计**（先写方案在报告里）：覆盖计划书要求的维度——来源归属（谁说的）、时间（event_time 正确性）、否定（「我不喜欢X」vs「我喜欢X」）、纠正（correct_memory 后旧事实退出）、跨用户/跨群隔离、无证据拒答、重启/重放幂等。每个维度 ≥10 条 case，JSON 结构（参考 knowledge-eval 形态，但字段按 memories 真值契约）
2. **评测器**：`tools/记忆黄金集评测.py`（或 tests/ 下 evaluator）——对生产只读副本或临时库跑评测，输出按维度通过率；失败 case 打印期望/实际差异。**不写生产库**
3. **跑一遍**：用临时库装载黄金集 fixtures（不走真实 LLM 提取；记忆写入用 store API 直接构造），记录基线结果
4. 黄金集数据文件与评测器进 tests/ 由 pytest 复用（维度级断言）

### P2-2：存量清点收口

1. 用 `tools/memory_truth_audit.py --db memory.db` 的当前输出为事实基础
2. 补一份清点报告：legacy 存量规模、origin 分布、有证据/无证据分层、隔离状态（trusted 召回是否零 legacy）
3. 可回滚迁移验收：现有 `rollback_memory_reverification` + 备份机制是否满足「可回滚」要求——写一个验证脚本/测试证明（离线副本上执行提升→回退→断言回到 legacy）
4. 合成记忆（synthetic origin）存量清点与隔离现状
