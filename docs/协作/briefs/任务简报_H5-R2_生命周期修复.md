## 背景（H5 已取证的根因，可信但请复核）

1. **驱动力自动保存无上界**：`agent/self_state.py:443-450,490-495`——`tick()` 只更新 drives；`_auto_save()` 只由 `update_relationship()` 触发且每 10 次关系更新一次。群/私消息与 10 分钟自治循环都可 tick，自治 release 也不保存。无关系更新的自治运行中，未落盘的 tick/release 数**无上界**——重启丢全部未保存增量（违反持久化铁律）
2. **feedback 重复消费**：`feedback:last_consumed` 存时间戳非 id cursor；`_get_feedback_reflection_context()` 每次读取返回同一条反馈，不清除不过滤——同一可信反馈重复注入当前用户上下文直到出现更晚的反馈

## 任务

### 修复 1：drives 有界持久化

- 目标：「重启丢失的 drives 增量有上界」成为全局保证
- 方案建议（你可论证更优）：tick/release 后累计脏计数，每 N 次（如 10）或距上次保存超时（如 5 分钟）落盘一次；`save()` 保持幂等
- 约束：不动 alpha/阈值/任何动力学参数；不改变现有 `update_relationship` 的 10 次节律（只补 drives 独立路径）
- 回归：无关系更新的纯自治 tick/release 序列 → 重建后丢失 ≤ N 次增量；显式 save 后精确恢复（H5 已有测试模式）

### 修复 2：feedback 消费 cursor

- 目标：消费后不再重复注入
- 方案建议：`feedback:last_consumed` 改为可推进 id cursor（保存最后消费的 feedback 行 id），读取只取 id > cursor；兼容旧时间戳值（视为 0/全量）
- 约束：2026-08-16 消费链既有回归（feedback 写入 93/93 可信、消费点唯一）不得破坏；跨用户 cursor 语义与现状一致（全局 cursor vs 每用户——按现状实现，写清理由）
- 回归：同一条反馈两次读取只注入一次；新反馈到达后正常注入；旧时间戳 cursor 迁移兼容
