## 二、每个决策的理由（为什么用户更省力）

1. **删掉「用途（kinds）」**：它与「输入类型」是同一件事的两种说法——能看图的档位
   才能识图/打标。两个复选框组并排，用户要先判断「这两个勾是不是必须一致」，这是
   纯认知负担；实际门禁由 `input` 决定，`kinds` 只是旧字段。识图页/打标页按图片能力
   过滤后，用户第二次也不用再标注一遍。已有 `kinds` 值仍然原样保留在 config 里。

2. **「思考」+「思考强度」合成一个「推理强度」**：用户要表达的是「这个模型想多深」，
   而不是「开关 + 档位」两个正交概念。两个控件意味着用户要先想明白 on+medium 才等于
   「中等」，再分别操作两次；一个下拉四次选项（关闭 / 低 / 中 / 高）一次点完。
   落盘仍拆回两个后端字段，映射只有一处。

3. **温度收进「高级参数」**：温度对绝大多数人不是每次都要调的参数（默认 0.8 几乎总是
   对的），但它必须保留——有些中转站要求显式传。折叠不是藏起来：折叠头右侧常驻
   「温度 0.8」，不用展开也能确认值。

4. **主区只留窗口 / 最大输出 / 输入类型**：这三个是「配完就不动、但选模型时要看」的
   事实；温度、推理强度是「偶尔调」的策略。按「事实 / 策略」分组，用户找参数的路径
   从 9 个里找变成「先看事实，需要再展开」。

5. **请求行为块放宽左右**：改前字段的左右内边距是 0（`.settings-fields` 只有
   padding-bottom、`.dsl-row` 只有 `padding: 16px 0`），标签直接贴在卡片边框上，
   而且标题有 16px 内边距、字段是 0——**标题与字段左边缘不对齐**。现在卡片统一
   20px 内边距（标题与字段对齐），标签↔控件从 24px 放到 32px，并改成两列网格让
   控件左边缘对齐（改前 `space-between` 下每个控件宽度不同，左边缘参差）。

6. **行头收起态不再放输入框**：改前收起态是两个输入框，但保存按钮只在展开区里——
   改了名字不展开就没有任何保存入口，切页即丢（静默）。现在收起态是纯展示行
   （名字 / ID / 能力标签），编辑统一在展开区的第一组，和「保存参数」在一起。
   代价是改名要展开一次；这是刻意的取舍。

7. **能力标签组合并**：`64K` 与 `可看图` 原来各自浮动（一个描边徽标 + 一个色块），
   在一行里造成两个视觉断点；现在是一个 4px 间距的标签组，先看窗口、再看能力。

## 五、三问的书面回答（要转给用户）

**1. 设计是否合理？**

层级是「身份 → 尺寸 → 能力 → 高级 → 操作」，一屏能答三个问题：这个模型叫什么、窗口多大、
能不能看图。收起态是列表行（名字 / ID / 能力标签），不是表单——一个 provider 下的 5 个模型
可以一眼扫完。用间距分组（组内 10px、组间 10px、卡片内 20px），只用一条 0.5px 线分开
「行头 / 编辑区」；三种颜色承担三种角色（名字 = primary，ID 与标签 = tertiary，
能力与状态 = accent），不再靠加边框表达关系。

**2. 是否方便填写数据？**

新模型的最短路径是三步：显示名 → 模型 ID → 保存（窗口可留空，两个体积参数已有默认值）。
placeholder 给的是可照抄的例子（`例如 deepseek-v4.1-flash`）。模型 ID 为空时保存按钮是
禁用的，旁边写明「模型 ID 必填」——改前这种情况会静默丢掉整行、还提示「已保存」。
只有和模型行为相关时才需要展开「高级参数」，而折叠头一直显示当前温度和推理强度，
不下拉也能确认。

**3. 各数据项是否还有必要保留？**

- 显示名：保留。所有下拉、状态栏、会话标题都显示它；不填时退回模型 ID。
- 模型 ID：保留，必填。请求体里的 `model` 字段就是它，没有替代。
- 上下文窗口：保留。窗口徽标（64K / 1M）和选模型时的容量提示都靠它；允许「不知道」。
- 最大输出 tokens：保留。部分中转站要求显式值，默认 64000。
- 温度：保留但折叠。默认 0.8 对多数人是正确值，但有些中转站要求显式传，删不得。
- 推理强度：保留（由 thinking + thinking_effort 合并），影响质量与费用。
- 输入类型：保留，但「文本」不可取消（后端恒为 text），所以它显示为静态标签，
  只有一个可操作项「图片」——它唯一决定这个模型能不能用来识图 / 打标。
- 用途（聊天 / 识图 / 打标）：**从界面移除**。它是「输入类型」的推论，不是独立事实；
  识图页与打标页改成按「能看图」过滤后，用户不需要再标一遍。config 里已有的值不丢。
- provider 组（名称 / 地址 / 协议 / Key）：保留，一组一份（地址与 Key 不再在每个模型里复制）。

## 十、风险与需 Lead 确认的点

1. **`kinds` 透传**：决策 1 要求 `toEntry()` 不写 `kinds`。但后端 `/api/models/save` 是
   `llm["models"] = clean` 全量覆盖，不写 = 老档位的用途标注在下次保存时被静默清空。
   所以 `ModelDraft` 保留了一个**不参与 UI** 的 `kinds` 字段，保存时原样写回。
   界面上已完全没有「用途」。如果你更想要「后端合并」，那前端这行可以删。
2. **`thinking=off` 时 `thinking_effort` 归一为空串**：避免落盘 `thinking=off` +
   `thinking_effort=high` 这种自相矛盾的组合。这会改变用户没主动改过的旧值。
3. **`thinking` 为空 / `auto` 时下拉显示「中（默认）」**：显示是映射，不是写回——用户不动
