## 二、四个必须问题

### ① 「请求行为」左右间距太紧 —— 已修，有实测数字

根因是三条 CSS 叠加：`.settings-fields` 无左右 padding、`.settings-card` 只有
`overflow: hidden`、`.dsl-row` 是 `padding: 16px 0`（左右 0）→ 标签和控件**贴着卡片边**。

实测（Chrome `getBoundingClientRect`，面板宽 558）：

| 项 | 改前 | 改后 |
|---|---|---|
| 卡片内边距 | 0 | `0 20px` |
| 标题 `form-head` 左右 | 0 | 20px（与字段左边缘对齐） |
| 4 行控件左边缘 | 参差（`space-between`） | **全部 522** |
| 标签↔控件 | 24px | 32px |

### ② 模型目录信息密度过大 —— 已重做

- 收起态从「表单行」变成「信息行」：`● 名字 ｜ 等宽 ID ｜ 64K ｜ 可看图 ｜ 当前 ｜ ⌄ ｜ 🗑`
  （改前收起态里有两个输入框，改了名字没有保存入口，切页即丢）
- 展开态 9 个平铺控件 → **5 个字段**（显示名 / 模型 ID / 上下文窗口 / 最大输出 tokens /
  输入类型）+ **1 个默认收起的「高级参数」**（温度 / 推理强度），折叠头常驻摘要
  「温度 0.8 · 推理强度 中」——收起也不丢信息。
- 层级靠间距（组内 10 / 组间 10 / 卡片 20）和一条 0.5px 线，不靠加边框。

### ③ 上下文窗口保存后被清空 —— 已修，根因不在保存，在**另一个写入口**

用临时 config 端到端复现，先排除了嫌疑：`api_models_save()` 本身是对的（保存 0 →
65536，落盘也是 65536）。真凶是 `POST /api/config`：

```
tools/desktop_bridge.py:858  yaml.dump(incoming, ...)   ← 整份重写
                             ↑ incoming = 设置页打开时拉的旧快照
                             ↑ merge_missing 只补缺失键，不纠正已有键
```

于是「保存参数」（写 65536）之后，点底部「保存」会把旧快照里的 `context_window: 0` 写回去。

**修法**（`MODEL_CATALOG_KEYS = ("models", "active_model", "providers")` +
`_preserve_model_catalog()`）：这三个键**用磁盘值替换请求体里的值**，而不是删键。
删键就等于把 `llm.models` 从文件里删掉、用户所有档位凭空消失。顺序也硬性：
必须放在 `merge_missing` **之后**，否则补缺又把旧快照补回来。

顺手：`_coerce_llm_numbers()` 加了 `context_window`（前端发 `"65536"` 时落盘成字符串
会让徽标算错）。

**浏览器实测**（最终代码 + 重启 bridge）：改成 131072 → 保存参数 → **再点底部保存** →
重载页面 → 输入框仍是 `131072`，行头徽标 `128K`。

## 三、我在验证时又发现并修掉的一个 bug（第 5 个）

切「关闭思考」后：档位里 `thinking=off` + `effort=''` 都对，但**扁平** `llm.thinking_effort`
还是 `'medium'` —— 因为同步写的是 `for key in (...): if sel.get(key): llm[key] = sel[key]`，
空串是假值被跳过。状态灯和 `/api/status` 读的正是扁平字段 → 界面显示「中等推理」而实际已关。
改成成对写入，补 2 个用例 + 1 个变异（M6 真红）。

## 五、三个问题的回答

### 1. 设计是否合理

改造前的三层问题：**层级平铺**（9 个控件等权重，把「填一次就不再动」的和「必须填」
的混在一起）、**概念重叠**（「输入类型」与「用途」是同一件事的两种说法）、
**一决定两控件**（思考开关 + 思考强度，且能拼出 `off + high` 这种自相矛盾的组合）。

改造后层级是 **身份 → 尺寸 → 能力 → 高级 → 操作**，一屏答三个问题：这个模型叫什么、
窗口多大、能不能看图。

### 2. 是否方便填写

- 新模型最短路径 3 步：显示名 → 模型 ID → 保存（窗口可留空，体积参数有默认值）。
- placeholder 给可照抄的例子；模型 ID 为空时保存禁用并写明原因（改前会静默丢整行还提示「已保存」）。
- 「获取可用模型」一点列出端点支持的全部模型（实测拉回 12 个）。
- **还不够好的**：上下文窗口该填多少，用户仍得自己去查模型文档。下一步可以让
  「获取可用模型」把能拿到的窗口自动填上（Ollama 的 `/api/show` 已经返了）。

### 3. 温度与思考要不要保留（用户的顾虑）

**温度：保留，但收进高级折叠。** 不能删——它是 OpenAI 兼容协议的标准参数，有些第三方
中转站对缺省值有自己的默认，显式传 0.8 才能保证糖糖人格稳定；但用户几乎不会改它
（调大发飘、调小变机械），放主区只会诱导乱调。折叠头常驻显示「温度 0.8」，所以
「藏起来找不到」的担心不成立。

**思考：保留，但必须合并成一个「推理强度」。** 它直接影响钱和延迟（开思考 → 输出
token 翻倍、首字延迟 +2~5s），不能删；但两个控件让用户算不过来，还允许
`off + high` 这种矛盾组合。合并后：关闭思考 / 低 / 中（默认）/ 高。

**默认值不动**：`thinking=on` + `effort=medium` 保持原样——改默认值会改变糖糖的行为
一致性，那是另一个决策，不该混在这次界面改造里。

**「用途」组：删。** 它是「输入类型」的推论，不是独立事实。config 里已有的值不丢
（后端全量覆盖 models，前端做了透传）。

## 六、遗留（下一轮）

1. 其它页面 **25+ 处不存在的 CSS 变量**（`--bg-layer-4` / `--warning` / `--fs-10` /
   `--surface-2` / `--bg-layer-1`，无 fallback = 整条声明失效）；`--line` / `--bg-elevated`
   有 fallback 但主题不跟随。用户这次明确立了规矩「不得引用不存在的变量名」，该清。
2. `api_models_save` 是全量覆盖 `llm.models`：更彻底的修法是**按 id 合并保留未知键**
   （前端现在是透传规避）。
3. 「API 协议」当前只有一个选项（OpenAI 兼容），读起来像多余的下拉；删了又失去以后加协议的入口。
4. `.dsl-note` 不受「讲解」开关控制（多数是解释可关，但 `voice.provider` 与
   「AI 画图已关闭」是数据/状态，需要 schema 加显式标志）。
