## P2-4 临时库演练：完成

新增 `tools/extraction_resilience_h4.py`，它只在 `TemporaryDirectory` 创建 SQLite：

- 沿用 `tools.memory_llm_soak.run_simulated_soak()` 的已修正 harness，固定 `worker_count=1`，24 jobs、12 用户、4 producers；断言公平覆盖、无跨作用域泄漏、无重复记忆、游标全一致。
- 真实 `MessageHandler._process_extraction_batch()` 注入 429、5xx、超时、非法 JSON、空字符串和断线。每种故障均断言首次不推进游标而回到 `pending`，随后成功重放为 `done`；空字符串按实际实现归类为无效 JSON 后重试，而不将其误报为“成功空产出”。
- 连续 5 次 5xx 断言进入 `dead`；以 `retry_after_seconds=3600` 验证立即重排被冷却挡住，再以临时库 `0` 秒演练人工/到期重排后的成功恢复。生产 1800 秒默认值和参数均未改动。
- `result_json` 截断为半写 JSON 后，重启提交断言 `dead`、游标 0、无记忆；重排后恢复为单条可信记忆。
- 另启动子进程，在 `complete_extraction_job()` 的 SQLite 事务内真正 `terminate`（exitcode=-15）；新 `Store` 重启后仍为 `ready`，重放为 `done`，重复完成不再插入第二条记忆。过期 `leased` job 也经真实 `_resume_extraction_jobs()` 回收并完成。
