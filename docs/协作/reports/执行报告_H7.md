### P5-2 故障注入矩阵

新增 [`tools/p5_fault_matrix_h7.py`](../../../tools/p5_fault_matrix_h7.py)，在系统临时目录内复用 H4 提取状态机演练，并补齐 outbox 网络/数据/进程窗口。它不读取或写入生产 `memory.db`；缺失的 `httpx` / `websockets` 仅以不可调用空壳满足离线导入，真实网络 client 不会创建。

| 域 | 注入 | 恢复 / 死信边界 | 本次结果 |
|---|---|---|---|
| LLM | 429、5xx、超时、空产出、非法 JSON、断线 | 首次 `pending`，成功重跑 `done`，2 attempts；连续 5xx 在第 5 次 `dead`，冷却阻止立即 requeue。 | 全部通过 |
| 数据 | ready payload 半写、损坏 JSON | 半写提取 quarantine 为 `dead` 后可重做；损坏 outbox receipt template 转 `uncertain`，绝不重放。 | 全部通过 |
| 数据 | 外键违规 | `task_action_items.task_id=999999` 被 SQLite `FOREIGN KEY constraint failed` 拒绝并 rollback。 | 通过 |
| 网络 | 断线→重连 | 离线保持 `pending`；恢复 online 后只发送一次并 confirmed。 | 通过 |
| 网络 | 发送超时/响应不确定 | `uncertain` 且 `list_due_send_outbox()==[]`，防止可能已投递的消息盲重发。 | 通过 |
| 网络 | 确定失败 | 3 次后 `dead`，不形成无限热循环。 | 通过 |
| 进程 | 提取中 kill | 真子进程 `terminate` exit=-15；ready 状态重启后 `done`，1 条 trusted memory，无重复。 | 通过 |
| 进程 | 发送中 kill | claim 后真子进程 `terminate` exit=-15；重启转 `uncertain`，不进入 due list。 | 通过 |
| 进程 | 结算事务 pre-commit kill | 回执写入前真子进程 `terminate` exit=-15；重启转 `uncertain` 并写同状态回执，不伪造 confirmed。 | 通过 |

> 结算没有独立的持久状态名；其事务提交前的 crash 在持久化层表现为 `sending`，因此恢复为 `uncertain` 是该状态机的明确死信边界。
