## 生产取证（真实数据定案）

- 本机(台式机)库 id 止于 249824；LAPTOP 快照 id 也止于 249824。分叉起点 249822 两库完全一致，分歧是各自最后 2 条：
  - 台式机：群聊「打个胶先」00:09 + 图片占位符 00:12
  - 笔记本：**私聊**「凌晨好！」01:52 + 糖糖回复 01:52（与台式机内容互斥、场景互斥）
- **根因**：chat_log 自增 id 是行号不是业务键。笔记本从台式机 23:58 快照解包后两边各新增 2 条 → id 恰好都到 249824 → 旧判定 `JOIN ON l.id=s.id` 把两库各自的 249823/249824 配对 → 内容不同 → 误报「双机各自写入 2 条」。**换机接力同源同增量时 id 撞车是必然**，旧判定结构性必误报。
- **副缺陷**：台式机 DB 最后修改 00:13，但其快照停在 00:07——最后 6 分钟（群聊 2 条）从未进任何快照；自动解包只比 mtime（台式机库旧 → 放行）→ 这些记录会被静默覆盖丢失，且无人知晓。
