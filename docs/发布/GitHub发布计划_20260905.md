## 一、被推翻的决策（原计划 vs 实际）

留着这一节，是因为每一条推翻都有代价，下次别再走一遍。

| 原计划（09-05） | 实际（09-19） | 为什么改 |
|---|---|---|
| **三个版本包**：完整版 / 只有文字 / 只有识图 | **一个包 + 安装器勾选功能** | 打完包实测：三个包 1723 个条目里**只差 `版本.txt` 一个文件**，文件集差异为零。用近 3 倍体积换了一句"这是哪个版本"。市场调研印证：AstrBot / Nekro Agent / Koishi / ComfyUI **全是**「一个入口 + 安装时选」——没有任何项目按功能组合发多个包 |
| 主仓 = 纯代码 clone 即跑，语音/唱歌全走附件 | 主包直接含歌曲与角色贴图（974 MB），**解压即用**；只有 6 GB 语音模型走附件 | 「clone 即跑」对开发者成立、对想直接用的人不成立。目标用户是后者 |
| CosyVoice3 也作为语音方案发布 | **只留 GPT-SoVITS**（主人拍板） | 6.3 GB 里 5.1 GB 是上游基础模型，自定义微调声线只有 229 MB；两套并存是维护负担 |
| CC × Codex「简报→报告→裁决」闭环分工 | CC 直接执行 | 发布是一次性动作，派单/收回/裁决的协调成本高于收益 |
| **全新目录 git init**（绝不在 40 G 混合体里 init） | ✅ **保留** | 原目录 40 G 混合体内含隐私数据与第三方引擎，在它里面 init 必然误 add |

## 二、实际发布了什么

| 附件 | 大小 | 在哪条 Release |
|---|---|---|
| `tangtang-v1.1.zip` | 974 MB | v1.1 |
| `tangtang-v1.0.zip` | 973.6 MB | v1.0 |
| `tangtang-voice-1of4.zip` | 1320.4 MB | v1.0 |
| `tangtang-voice-2of4.zip` | 1571.9 MB | v1.0 |
| `tangtang-voice-3of4.zip` | 1751.5 MB | v1.0 |
| `tangtang-voice-4of4.zip` | 1430.3 MB | v1.0 |

**主包**解压即用：代码 + 文档 + 安装器 + 41 首预录歌曲 + 两套角色贴图。

**语音分卷不需要用户手动下载**——只有勾了「发语音」时，安装器才会自己去 Release 拉取并解压到
`gpt-sovits/`。挂在 Release 上是为了让它有源可拉。

**语音分卷可以跨版本复用**：`_voice_files()` 只从 `gpt-sovits/` 取内容（第三方引擎 + 模型），
改代码 / 文档 / 安装器都不影响它。所以 v1.1 只传主包，安装器按 `tangtang-voice-*of*.zip`
这个**版本无关**的命名去 v1.0 那条 Release 抓，用户无感。
（若哪天动了 `gpt-sovits/`，这条复用就不成立了——必须重传分卷。）

安装形态：**一个包 + 安装器勾选 8 个功能**，默认预勾「聊天+记忆 / 唱歌 / 图形控制台」。

## 三、怎么再发一次（复现手册）

```bash
# 1. 快照：白名单复制 + 脱敏扫描 + 排除内部协作文档
python tools/准备发布.py

# 2. 打包：单包 + 语音分卷（分卷阈值 1.8 GB）
python tools/打包发布版本.py
python tools/打包发布版本.py --no-voice   # 补发小版本：沿用现有分卷，省掉重压 6 GB

# 3. 发布前检查：功能 / 安全 / 浏览器 三道闸门，24 项
python tools/发布前检查.py
python tools/发布前检查.py --skip-browser    # 跳过浏览器闸门（快）

# 4. 单元闸门
python -m pytest tests/ -q
```

**产物的单一来源：**

| 产物 | 单一来源 | 不许另存副本 |
|---|---|---|
| Release 正文 | `docs/发布/发版说明_v1.md` | 两份必然漂移 |
| 仓库 README | `docs/发布/README.md` → 发布时拷到仓库根 | 同上 |
| 模块地图 | `docs/发布/模块地图.md` | 同上 |

**上传**：5 个附件共 6.88 GB，`gh release upload v1.0 <文件>` 逐个大文件推。语音分卷建议一次一个，
并发推会互相抢带宽。

## 五、踩过的坑（都加了闸门）

- **GitHub Releases 吞中文附件名**：`小糖糖-v1.0.zip` 上传后变成 `-v1.0.zip`。
  包名必须纯 ASCII → `tangtang-v1.0.zip`。闸门：`test_package_name_is_ascii_and_matches_readme`
- **安装器只会关不会开**：`voice.enabled` / `llm.vision.enabled` 从来没被打开过。
  用户勾了语音、6 GB 下完、启动后一声不吭。已改双向接线（`_config_switches` / `wire_config`）
- **唱歌被 TTS 开关连坐**：`voice.enabled=false` 时只发歌词不放歌。已解耦 6 个调用点
- **听/说共用一个开关**：新增 `voice.asr_enabled`，让"不发声但听得懂语音消息"成为可能
- **README 相对链接的基准是发布后的仓库根**，不是 `docs/发布/`。`../../releases` 在两种形态下解析结果完全不同
- **数字校验测试的反馈环**：校验测试数的测试自己也是测试，写死精确值永远追不上。改用「下限 + 防腐烂」
- **Win10 控制台画不出 emoji 状态标记**（2026-09-19 主人报障）：不是编码问题——Python 把码位
  正确送到了控制台，是 conhost 的字体链（Consolas/新宋体/微软雅黑 → Segoe UI Symbol）
  **不含 Segoe UI Emoji**，而 ✅⬜❌ 只存在于 Segoe UI Emoji，实测渲染成空心方框。
  Win11 默认终端是 Windows Terminal（DirectWrite 完整回退）所以看得到——但 Win10 用户量还很大。
  已全部换成 bracket 家族 `[√] [ ] [×] [!]`。闸门：`tests/test_console_glyphs.py`

## 六、SnowLuma：法律边界，别再尝试自动化

SnowLuma 是 QQ 协议端，属第三方项目。其 EULA 第 5.4 条明文禁止
「将其并入第三方安装包」与「通过自动化脚本部署」——**既不能随包发、也不能让安装器代下**。

做法：安装器开头给官方发布页链接 + 落位说明；控制台点「启动 SnowLuma」而没装时弹同样指引。
用户可以改用任意其他 OneBot 11 反向 WebSocket 实现。
