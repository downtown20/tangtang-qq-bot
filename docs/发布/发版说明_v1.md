## 快速开始

1. **先装两样**（包里不带）：**Python 3.10**（安装时勾上 `Add Python to PATH`）、
   **QQ 客户端**（登录机器人那个号，并保持开着）
2. 解压 `tangtang-v1.08.00.zip`，双击 **`安装糖糖.bat`**，勾选需要功能
3. 双击 **`启动控制台.bat`**，填机器人 QQ 号、你自己的 QQ 号、模型 API Key
4. 点「启动 SnowLuma」——**首次启动会在新开的窗口里打印一行网页面板的初始密码，记下来**
5. 浏览器打开 `http://127.0.0.1:5099`（用户名 `admin`），把两条线接上
6. 点「连接自检」，全绿之后点「启动小糖糖」

> **还差一步**：SnowLuma 是第三方 QQ 协议端，许可协议不允许随本项目分发。
> 需从 [官方发布页](https://github.com/SnowLuma/SnowLuma/releases) 下载 Windows x64 版
> （**认准不带 `-lite` 的那个**，精简包不带 Node.js），解压到 `SnowLuma/` 目录下。
> 也可用任意其他 OneBot 11 实现替代。

断网直接重跑 `安装糖糖.bat`，已下载的部分不会重来；事后补装同样重跑、勾上对应项。

## 本次更新

- **fix(密钥)** 出厂配置模板把密钥字段写成了「你的DeepSeek或Claude的API密钥」这类
  **中文提示文字**，而不是 `${DEEPSEEK_KEY}` 这样的环境变量引用。程序只识别后一种形式，
  所以填在控制台里的 Key 落进了一个没有人读的文件——而界面上一切正常：保存成功、
  字段回显正确。默认供应商恰好有一条兜底路径，症状因此表现为「换一家 API 供应商就 401」
- **fix(密钥)** 同一问题也命中 SnowLuma 令牌，而它没有任何兜底——
  控制台里填的 Token 从来没到过运行期
- **fix(密钥)** `tools/体检.py` 的密钥检查只看得见「形式正确」的引用，
  形式错误的那种它一个字都不报
- **feat(控制台)** 仪表盘新增「记忆自动同步」卡片（控制卡片右侧）：关掉后不再打包、
  不再解包，也不再弹任何同步提示。单机使用（不换机、不配 Syncthing）可以关
- **fix(控制台)** 开机后的 SnowLuma 更新检查**永久静默且不报错**：本地版本号绑死了一个
  具体目录名，同时线上响应在中文 Windows 下解码失败并被吞掉。本机因此落后 8 个版本而无提示
- **fix(控制台)** 网络不通时，控制台启动约 8 秒后界面会**冻结二十秒**，且冻完什么都不显示
- **fix(日志)** 「某某模型没就位」的提示会把 `python -c "from modelscope import …"`
  这类命令原样打印出来，也没有说明它属于哪个功能。装着功能 1/4/6 的用户看到它，
  分不清缺的是识图、语音，还是自己勾的那几项
- **feat(安装)** 安装器现在会记下这次勾了哪几项。运行期据此区分
  「你没装这个功能」和「你装了但它没就位」——在那之前，这两种情况看起来完全一样
- **fix(日志)** 情绪模型 StructBERT 每台新机器都会报一次「未找到」，而它**不在任何安装项里**
  ——想补也没有地方补。已加入模型清单（可选，下载前会先问）
- **fix(安装)** 只勾「发语音」不勾「聊天+高质量记忆」时不会装 `torch`，
  而本地语音引擎的入口第一行就导入它——6.4 G 模型下完之后，服务启动即退出
- **fix(诊断)** 体检与安装器把「向量模型」和「重排序模型」当成同一条来判，
  跳过 2.2 G 重排模型也会显示"已就位"，与启动日志互相矛盾
- **fix(诊断)** 健康自检里没有一项涉及模型：语义向量模型没加载时，
  记忆去重、语义检索、知识库混合检索已全部退化成关键词匹配，而 `/状态` 仍报「全部正常」
- **fix(安全)** `/状态` 的输出里带着主人 QQ 号，而这条命令群主也能用——
  糖糖被拉进陌生群后，群主发一条 `/状态` 就能读到
