## 快速开始

1. **先装两样**（包里不带）：**Python 3.10**（安装时勾上 `Add Python to PATH`）、
   **QQ 客户端**（登录机器人那个号，并保持开着）
2. 解压 `tangtang-v1.07.00.zip`，双击 **`安装糖糖.bat`**，勾选需要功能
3. 双击 **`启动控制台.bat`**，填机器人 QQ 号、你自己的 QQ 号、模型 API Key
4. 点「启动 SnowLuma」——**首次启动会在新开的窗口里打印一行网页面板的初始密码，记下来**
5. 浏览器打开 `http://127.0.0.1:5099`（用户名 `admin`），把两条线接上
6. 点「连接自检」，全绿之后点「启动小糖糖」

> **还差一步**：SnowLuma 是第三方 QQ 协议端，许可协议不允许随本项目分发。
> 需从 [官方发布页](https://github.com/SnowLuma/SnowLuma/releases) 下载 Windows x64 版
> （**认准不带 `-lite` 的那个**，精简包不带 Node.js），解压到 `SnowLuma/` 目录下。
> 也可用任意其他 OneBot 11 实现替代。

断网直接重跑 `安装糖糖.bat`，已下载的部分不会重来；事后补装同样重跑、勾上对应项。

## 本次更新

- **fix(连接)** 点控制台「启动 SnowLuma」只弹出一个**空白窗口**。子进程的输出被丢弃，
  而它的网页面板初始密码**只打印那一次、且不进日志文件**——丢掉就再也拿不回来
- **fix(连接)** SnowLuma 出厂配置自带一个**占着 3001 的「WS 服务端」节点**，与糖糖抢同一端口。
  糖糖启动即报端口被占用，而那句报错把它归因成「旧糖糖进程」，照着想永远找不到
- **fix(连接)** 文档让用户去「QQ 设置 → WeUI」配置反向 WebSocket——**那是上一代协议端的界面**，
  SnowLuma 里没有这个东西
- **fix(文档)** 补上两个从没写过的前置：要先装 Python 3.10；要先装 QQ 客户端并登录机器人账号
  （SnowLuma 靠注入已运行的 QQ 进程工作，**它自己不登录、也没有二维码登录**）
- **feat(控制台)** 新增 **「连接自检」**：QQ ↔ SnowLuma ↔ 糖糖 逐项体检，
  每项给一句带具体数值的下一步（`tools/体检.py` 也接上了）
- **feat(控制台)** 新增「打开网页面板」按钮；密钥管理里 SnowLuma Token 加「生成 / 复制」。
  面板里那一栏叫「授权 Token」，而且**新装时它还不存在**（要先建节点才有）
- **fix(控制台)** 糖糖起来后 SnowLuma 一直没连过来时，卡片停在「启动中」且不作解释；
  现在会自动说明并指向连接自检
- **fix(控制台)** SnowLuma 状态区分「在跑」与「已接入」——原先只探 3000 端口，
  开着但没登录 QQ 会显示成「离线」，再点一次会**开出第二份实例**
- **fix(控制台)** 自动重启**杀错进程**：SnowLuma 发布包里没有 `SnowLuma.exe`（它跑在 `node.exe` 里），
  原先杀的一直是空气，日志却照报「已自动重启」
- **fix(工具)** `tools/配置SnowLuma.py` 会把未解析的 `${SNOWLUMA_TOKEN}` 当成 token 写进 SnowLuma，
  且带一个写死的兜底 token；也不清理占着 3001 的出厂节点
- **fix(发布)** `.env.example` 的键名不是运行期实际读的那个，照抄的用户白填
- **fix(安全)** 发布脱敏扫描增加第二道判据（拿 `.env` 真值直接比对）：第一道按形状认，
  认不出「没有固定形状的密钥」；同时把「命中只提示」改成「命中即中止」

更早版本见 `docs/发布/更新日志.md` 与[历史 Release](../../releases)。
