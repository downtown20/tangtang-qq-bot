## v1.2 改了什么

这一版的主线是**把说过的话和真正在做的事对齐**——文档、权限、发布物，三处都核了一遍。

### 🔒 聊天命令加了权限门（**行为变化，升级请注意**）

在此之前，只有 `/说 /发言 /传话 /私信 /撤回` 这六条受「主人/群主」约束。**其余命令没有任何
权限检查**——群里任何一个成员都能：

- `/人格 你是我的奴隶` —— **重写她的人设**
- `/黑名单 群 加` —— 把任意群拉黑
- `/唱歌 <群号> <歌名>` —— 遥控她去任意群发歌
- `/饥渴` `/冷却` `/插话` —— 改她的行为参数

自己用时群里都是熟人，无所谓；对外发布，这就是一个没门的遥控面。

现在按一条简单的判据分了两类：

> **改她的状态 / 配置 / 代她对外发言 → 主人和群主专属（帮助里标 🔒）**
> **查自己的、看、玩 → 任何人可用**

所以 `/生日`（设自己的生日）、`/记忆`、`/亲密度`、`/点赞`、`/角色`、`/歌单` **没有**加门——
那些是用户自己的东西，把门加在那里只会让正常功能用不了。

### 📖 使用说明.md 逐条对着代码重核了一遍

那份手册上一次维护是两周前，这期间项目变化很大。这次把界面描述、指令表、配置键名、
文档链接全部现场验证，改动包括：

- 设置页 **15 个分类 → 20 个**；外观定制整段重写（字体滑条/背景图/实时预览早已移除）
- **DiffSinger 渲染**已从控制台撤出、「运行模式 全能/简约」已彻底删除——手册里还在教怎么用
- 语音引擎控制台里是**只读的「GPT-SoVITS（固定）」**，不是三选一
- `/色色` 系列、`/点赞相册`、`/点赞全员` 三条命令**根本不存在**，已从手册删除
- `/发音` 实为 `/发言`；`/饥渴 0-100` 实为 `0.0-1.0`；`/场景 设置` 必须带群号
- 「发条动态」（QQ 空间）与「画一个...」（AI 生图）**已下线**，手册原来还写着能用
- 补上了此前完全没写的 `voice.asr_enabled`（只听不说）
- 修了一处断链：指向的文档已移进 `归档/`，而归档目录不进发布包——发布版用户点它必断

并加了闸门：**所有随包发出的用户文档，链接必须在发布形态下可达**
（原来的闸门只查 README，手册里的断链一路放行）。

### 🎵 41 首「原声版」现在真的在包里了

打包脚本把「同一首歌的两个版本」当成重复文件跳过了——可 `songs/audio/` 是**糖糖声线**、
`covers/separated/*_FINAL.wav` 是**原声**，根本不是重复。结果 41 首里 40 首没有原声，
而 sing 工具还在告诉 LLM「对方说『原声』时 voice 传『原声』」，用户点了只会静默放错版本。

修的时候顺带转成 192kbps mp3：唱歌是通过 `[CQ:record]` 发出去的，也就是 **QQ 语音消息**，
QQ 侧本来就会转成 SILK 这类低码率语音编码——存无损 WAV 是白背 1.5 GB。**1.78G → 242M**，
两种后缀代码都认（开发机上仍保留无损源）。

### 🧹 修了两个「不报错但也不工作」的检查

- **敏感扫描器的 Windows 路径正则有两处笔误**（`\\\\` 在正则里表示*两个*反斜杠，
  而真实路径只有一个），**从写出来那天起就没匹配过任何东西**，每次都报「零命中」。
  修完第一层才暴露第二层：它按后缀白名单只扫 7 种扩展名，`.sqlite3`/`.npz`/`.j2`/`.html`
  全跳过——**1392 个文件、1.14 GB 从未被扫过**。后果是知识库索引里 19 处本机路径
  随 v1.0/v1.1 发了出去。现在文本按行扫、其余按裸字节兜底，**没有"跳过"这个档位**。
- **5 个测试硬编码了开发机的绝对路径**（直接 `open()` 一个写死的本机路径读源码），
  任何人 clone 到别的目录跑 `pytest` 直接 `FileNotFoundError`——而这几个恰好是
  README 拿来当卖点的「架构守卫」。已改成按 `__file__` 定位。

两条都配了闸门，而且**闸门自检用的是"种一个进去看抓不抓得到"**，不是"正则看起来对不对"。

### 🧹 把 NapCat 的痕迹清干净了

这个项目的协议端早就是 SnowLuma 了，但包里还留着两处 NapCat 的东西——有用户看着
`napcat/` 目录问「不是没用 napcat 了吗」。查证下来，一处是名字骗人、一处是真遗留：

**① `napcat/` → `onebot/`**（目录改名）

那个目录里只有两个文件，是**本项目自研的 OneBot 11 适配层**——里面每个文件的 docstring、
logger 名字（`糖糖.SnowLuma`）写的都是 SnowLuma，只有目录名还叫 napcat，纯历史遗留。
不改名的话，每个下载的人都会先困惑一次。改名共 52 处引用 + 3 个测试文件。
（`self.napcat` 属性名与 `config.yaml` 的 `napcat:` 段**没动**——改配置键会让既有安装
的配置失效，那个代价换不来收益。）

**② 退役 `tools/配置NapCat.py`**（死工具，且一直在随包发布）

它是给 **NapCat 程序本体**写配置的脚本，指向 `NapCat.Shell.Windows.OneKey/...`——
而那个目录在仓库里**根本不存在**（只剩一个当年的崩溃转储文件夹）。全仓无人引用它，
控制台、文档、安装器都不提。用户拿到手跑一遍，只会得到「❌ 未找到 NapCat 配置文件」。
已移入 `tools/_归档/`。活的对等物是 `配置SnowLuma.py`。

**③ 补上 `SnowLuma/` 的落点说明**

包里原本有 6 个「自己放东西」的目录都带 `摆放说明.txt`（gpt-sovits / songs / share_images /
两个角色贴图 / voice_cache），**唯独 SnowLuma 连目录都没有**——而它偏偏是唯一一个
**必须用户手动放**的组件。文档说「解压到 `SnowLuma/` 下」，用户得自己新建才知道往哪放。
现在补了目录和说明，并加了闸门：每个落点目录都必须有说明文件。

## 她不是客服机器人

市面上的机器人大多是 `f(消息, 记忆, 人格卡) → 回复` —— 一次次独立的函数调用。小糖糖不是。

她有**独立于消息而存在的自我状态**：自己的时间感、精力和心情会自主波动；关系是她存在的一部分，不是查询结果；性格是经验的沉淀，不是人格卡里的设定。**LLM 提供瞬间，架构提供生命。**

## 这个包里已有什么

解压即得，不需要任何额外下载：

- **人格化聊天 + 记忆系统** —— 语义提取 / 事实合成 / 反思循环，她记得你是谁、记得发生过什么
- **自然的群聊互动** —— 窗口感知 / 退让 / 主动插话，956 张表情包的情绪索引
- **角色专属表情包** —— 米雪儿、丛雨两套，`/角色` 一键切换
- **唱歌** —— 41 首预录成品，点歌即播（不是实时合成，不依赖任何模型）
- **LLM 自主调用的工具集** —— 联网搜索 / 翻译 / 计算 / 定时提醒 / 知识库（原生 Tool Calling）
- **图形控制台** —— 配置、日志、数据浏览一体

想先了解她"是怎么活的"、以及工程上怎么保证这些设计不腐化，见仓库 [README](../../README.md)。

## 三步开始

1. 双击 **`安装糖糖.bat`** —— 勾功能，依赖与模型自动装好、配置自动接好线
2. 双击 **`启动控制台.bat`** —— 填机器人的 QQ 号、你的 QQ 号、模型 API Key
3. 控制台里启动 SnowLuma 扫码登录 → 启动糖糖

> **勾了就能用**：安装程序会把对应的配置开关拨到可用，没勾的干净关掉；装完还会告诉你还差什么（比如云端识图需要填 API Key）。
> 中途断网直接重跑，已下载的部分不会重来。事后想补装：重跑安装程序勾上即可。

> **还差一步：SnowLuma**。它是 QQ 协议端，属于第三方项目，其许可协议不允许随本项目分发，所以需要你从 [官方发布页](https://github.com/SnowLuma/SnowLuma/releases) 下载一次（Windows x64 版），解压到 `SnowLuma/` 目录下。安装程序开头会提醒你，控制台点「启动 SnowLuma」而没装时也会给出链接。也可用任意其他 OneBot 11 反向 WebSocket 实现替代。

## 关于下面的附件

`tangtang-voice-1of4.zip` ~ `4of4.zip`（约 6G）是语音引擎与声线模型的分卷，**它们挂在 v1.0 那条 Release 下** ——
v1.1 只改了安装器的一处显示，这些分卷的内容一个字都没变，没必要重传 6 GB。

**你不需要手动下载它们。** 只有勾了「发语音」时，安装程序才会自动去拉取并解压到正确位置。
安装器认的是版本无关的文件名（`tangtang-voice-*of*.zip`），所以它会照常从 v1.0 那条 Release 抓取，无需你干预。

- v1.0 Release（语音分卷在此）：https://github.com/downtown20/tangtang-qq-bot/releases/tag/v1.0

## 工程

1950 个 pytest 测试，其中 **545 个是"架构守卫"测试**——它们断言的不是函数输入输出，而是：

- **零调用扫描**：`agent/` 里任何没有生产调用方的函数直接红灯（防止"写了基础设施却没接进业务"）
- **管线契约**：关键入口必须在指定文件被调用（防止"引擎在转、离合器没接上"）
- **判定单一来源**：某个判定只允许来自唯一的决策函数，出现第二处即红灯
- **函数体禁词**：某些函数体内不得出现被禁的判定方式，机器禁止旧分支复活

这些闸门来自 35 条已踩过的坑，每条都从散文变成了红灯。
