## v1.07.00（2026-09-20）

- **fix(连接)** 控制台点「启动 SnowLuma」只弹出一个空白窗口。子进程的输出被丢弃，
  而它的网页面板初始密码**只在启动时打印那一次、且不进日志文件**——一旦丢弃就再也拿不回来，
  只能删掉 `config/webui.json` 重启
- **fix(连接)** SnowLuma 出厂配置自带一个占着 `3001` 的「WS 服务端」节点，与糖糖抢同一端口；
  糖糖启动即报端口被占用，而那句报错把它归因成「旧糖糖进程」，照着想永远找不到
- **fix(连接)** 使用说明与 README 让用户去「QQ 设置 → WeUI」配置反向 WebSocket——
  那是上一代协议端的界面，SnowLuma 里没有这个东西
- **fix(文档)** 两份文档都没写两个前置：要先装 Python 3.10；要先装 QQ 客户端并登录机器人账号
  （SnowLuma 靠注入已运行的 QQ 进程工作，它自己不登录、也没有二维码登录）
- **feat(控制台)** 新增「连接自检」：QQ ↔ SnowLuma ↔ 糖糖 逐项体检，
  每项给一句带具体数值的下一步（自检模块同时接入 `tools/体检.py`）
- **feat(控制台)** 新增「打开网页面板」按钮；密钥管理里 SnowLuma Token 加「生成 / 复制」，
  Tooltip 说明它在面板里叫「授权 Token」、在哪两栏填——原先的提示让人去找一个新装时还不存在的字段
- **fix(控制台)** 糖糖起来后 SnowLuma 一直没连过来时，卡片永远停在「启动中」且不解释；
  现在会自动说明原因并指向连接自检
- **fix(控制台)** SnowLuma 状态区分「在跑」与「已接入」——原先只探 3000 端口，
  SnowLuma 开着但没登录 QQ 会显示成「离线」，再点一次会开出第二份实例
- **fix(控制台)** 自动重启杀错进程：SnowLuma 发布包里没有 `SnowLuma.exe`（它跑在 `node.exe` 里），
  原先杀的一直是空气，日志却照报「已自动重启」
- **fix(工具)** `tools/配置SnowLuma.py` 会把未解析的 `${SNOWLUMA_TOKEN}` 当作 token
  写进 SnowLuma，并且带一个写死的兜底 token；也不清理占着 3001 的出厂节点
- **fix(发布)** `.env.example` 的键名写的不是运行期实际读的那个，照抄的用户白填
- **fix(安全)** 脱敏扫描增加第二道判据（拿 `.env` 真值直接比对）——第一道按形状认，
  认不出「没有固定形状的密钥」；同时把「命中只提示」改成「命中即中止」

## v1.06.00（2026-09-20）

> 版本号规则变更：本版起改用三段式 `v1.MM.PP`。旧的 `v1.0`~`v1.5` 已一并
> 改名为 `v1.00.00`~`v1.05.00`（两位式那样很快就数到 2.x）。
> 中号两位递增，还有 93 个位子才到 2.0。

- **perf(安装包)** 主包 1128 M → 702 M（−38%）。`songs/audio/` 那 40 首是
  40kHz 单声道 PCM16，共 712 M、占整包 67%，而唱歌通过 `[CQ:record]` 发出，
  即 QQ 语音消息、QQ 侧会转成 SILK 低码率编码——存无损是白背。改成 128kbps mp3
- **fix(翻唱)** 自动安装通道接上：控制台「一键全流程」发现缺件时可直接下载模型包
  （Release 附件）并**在本机创建** demucs 环境。此前 HuTao 模型/索引的下载地址是空的，
  弹窗只会说「待作者提供」
- **fix(翻唱)** RVC 的 Python 依赖补进安装器「唱歌」组
  （`pyworld` / `torchfcpe` / `librosa`；`fairseq` 只有源码包、走 soft）
- **fix(翻唱)** 新增 import 自检：装了 ≠ 能用——`faiss` × NumPy 2 那次就是
  「包在、动态库加载不了」，只看文件在不在查不出来
- **chore** 新增 `tools/歌唱组件.py`：控制台与安装器共用的单一实现

> 以上几项经一轮独立复核后补修（复核用真包/真输入跑出触发路径，逐条有证据）：
>
> - **fix(翻唱)** 模型包解压落点修正到 `Retrieval-based-Voice-Conversion-WebUI/`。
>   原先解到项目根，而包内布局是「一个 RVC 根」（顶层 `assets/ configs/ infer/ tools/`），
>   于是装完 401 MB 缺件判据**一项都没满足**——每次点「自动安装」都白下一次
> - **fix(翻唱)** 解压加**条目名白名单**（只放行包该有的四类）、**sha256 校验**
>   （GitHub 的 `assets[].digest`，白拿的）、**总量/单条目上限**。
>   此前一个被替换的附件能覆盖 `agent/handler.py`、`config.yaml`、`.env`，
>   以及 `venv_demucs/Scripts/python.exe`（那个下一步就会被 subprocess 执行）
> - **fix(翻唱)** demucs 环境加**哨兵**：venv 的 python.exe 在 pip 之前就落盘，
>   原先只看它 → 装到一半失败会被永久判为「已就绪」，pip 再也不重跑
> - **fix(翻唱)** 自动安装的完成判据改为覆盖**整张依赖表**。原先只看模型包那 4 项，
>   会误报「已就位」，失败时弹窗原因是空白
> - **fix(打包)** ffmpeg 不在 PATH 时不再抛异常中断（原先会在输出目录留下一个
>   有贴图没有歌、却叫 `tangtang-vX.zip` 的残缺包）
> - **fix(打包)** 转码改「写 `.part` 再原子改名」。原先 ffmpeg 被中断留下的
>   截断文件，会因为 mtime 更新而在**下次打包时被当成缓存成品**打进包
> - **fix(打包)** 原声段补上 mp3 分支（原先只 glob `*_FINAL.wav`）
> - **fix(歌曲)** `has_any_audio` 的兜底分支与 `get_section_audio` 对齐到同一 mp3 口径
> - **feat(安装器)** 菜单加「翻唱组件」入口（原先文档说安装器会用共享模块，实际没有）

## v1.05.00（2026-09-20）

- **fix(唱歌)** 歌唱工作室依赖链卡在 NumPy 2——`faiss` / `pyworld` / `numba` 都是
  NumPy 1.x 时代编译的，`from infer.modules.vc.modules import VC` 直接 ImportError。
  requirements 改钉 `numpy>=1.23.5,<1.24` + `faiss-cpu==1.7.4`
- **fix(唱歌)** RVC 索引在中文路径下静默加载失败——faiss 的 C++ 端用窄字符 `fopen`，
  绝对路径含中文时打不开；索引不生效也不报错，只是音色相似度降低。改为传相对路径
- **fix(控制台)** 「打开目录」四个按钮原先只弹「找不到目录：`<路径>`」，
  未说明原因与下一步。现按功能分别说明，并在歌唱工作室顶部预告缺失组件
- **fix(控制台)** 密钥管理第二项 `千问 VL API Key` → `识图 API Key`（选本地识图不需要 Key）
- **fix(安装器)** 「唱歌」选项说明补上「仅播放，不含翻唱制作工具」
- **chore** 新增翻唱制作组件 `tangtang-singing-models.zip`（可选）
