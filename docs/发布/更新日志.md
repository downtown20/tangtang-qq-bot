## v1.08.00（2026-09-20）

- **fix(密钥)** 出厂模板把 `llm.api_key` / `llm.vision.api_key` / `napcat.access_token`
  写成了「你的DeepSeek或Claude的API密钥」这类**中文提示文字**，而不是 `${DEEPSEEK_KEY}`
  这样的环境变量引用。运行期只替换整串形如 `${VAR}` 的值，于是配置文件里那句话胜出、
  `.env` 从被创建起就没人读过——**在控制台「密钥管理」里填的 Key 落在了没有人读的文件里**。
  默认供应商恰好有一条兜底路径，所以症状不是"整个不能用"，而是"换一家供应商就 401"。
  出厂模板改成 `${VAR}`；老配置在启动时于内存中自动纠正，打开一次控制台并保存即写回文件
- **fix(密钥)** 同一根因也命中 SnowLuma 令牌：控制台填的 Token 从来没到过运行期。
  该项**没有**任何环境变量兜底，所以两边不一致时链路静默走不通
- **fix(密钥)** `tools/体检.py` 的密钥检查只枚举"已经是 `${VAR}` 形态"的引用——
  形态错的那些它一个字都不报，**越坏越安静**。现在改为判断"运行期是否真的拿得到可用值"
- **fix(密钥)** 控制台保存时会把"仍等于环境变量值"的字段还原成 `${VAR}`，
  但它按写死的路径清单工作，且值被物化成空串时不再还原——那会让引用悄悄退化成空字符串
- **feat(控制台)** 仪表盘新增「记忆自动同步」卡片（控制卡片右侧）：
  关掉之后不再打包、不再解包，也不再弹任何同步提示；选择存进 `config.yaml`
- **fix(控制台)** 直接看 `3000` 端口判断 SnowLuma 是否在跑，并在开机 8 秒后于界面线程里
  同步执行一次最长 30 秒的网络检查——网络不通时界面会**冻结约 20 秒**且不显示任何结果。
  改为后台线程、超时 8 秒
- **fix(控制台)** 启动时的 SnowLuma 更新检查**永久静默**且不报错。
  两个独立成因：本地版本号绑死了一个具体目录名（用户装别的版本就读不到）；
  取线上版本时未指定子进程编码，Windows 中文版用 GBK 解码 GitHub 的 UTF-8 响应直接抛错被吞
- **fix(日志)** 「某某模型没就位」的提示把 `python -c "from modelscope import snapshot_download…"`
  这类命令原样打印给终端用户（相对当前目录、用户无从执行），且不说明该模型属于哪个功能。
  现在按安装时勾选的功能说话
- **feat(安装)** 安装清单落盘（`installed_features.json`）：安装器记下这次勾了哪几项，
  运行期据此区分「你没装这个功能」和「你装了但没就位」——在那之前两者在磁盘上都是"目录不存在"
- **fix(日志)** StructBERT 情绪模型被无条件加载，而它**不在任何安装项里**——
  每台新机器都会看到一条自己无法修复的警告。已加入模型下载清单（可选，会先问）
- **fix(安装)** 只勾「发语音」不勾「聊天+高质量记忆」时不会安装 `torch`，
  而本地语音引擎入口顶层就导入它——6.4G 模型下完后得到一个启动即退出的服务
- **fix(诊断)** `tools/体检.py` 与安装器的目录检查把 BGE 向量模型和重排序模型
  当成同一条来判（任一存在即打勾），用户跳过 2.2G 的重排模型后安装器照样报"已就位"，
  与启动日志互相矛盾。两者拆开，各自判 `config.json`
- **fix(诊断)** 健康自检的 21 项里没有一项涉及模型层：语义向量模型没加载时，
  记忆去重、语义检索、知识库混合检索已全部退化为关键词匹配，而 `/状态` 仍报「全部正常」
- **fix(诊断)** 新装机器第一次启动会把三项"数据还没攒够"的检查报成故障
  （主人记忆数为 0「最严重的系统失败」、陈旧清理"从未"、今日提取"可能阻塞"）
- **fix(安全)** `/状态` 的输出里带着主人 QQ 号，而该命令的权限是「主人**或群主」——
  糖糖被拉进陌生群后，群主发一条 `/状态` 就能读到
- **fix(控制台)** `voice.enabled` 为 `false` 但 `provider` 是 `gpt-sovits` 时
  仍会去启动本地语音服务（出厂模板就是这个组合），换回一条"进程意外退出"

## v1.07.00（2026-09-20）

- **fix(连接)** 控制台点「启动 SnowLuma」只弹出一个空白窗口。子进程的输出被丢弃，
  而它的网页面板初始密码**只在启动时打印那一次、且不进日志文件**——一旦丢弃就再也拿不回来，
  只能删掉 `config/webui.json` 重启
- **fix(连接)** SnowLuma 出厂配置自带一个占着 `3001` 的「WS 服务端」节点，与糖糖抢同一端口；
  糖糖启动即报端口被占用，而那句报错把它归因成「旧糖糖进程」，照着想永远找不到
- **fix(连接)** 使用说明与 README 让用户去「QQ 设置 → WeUI」配置反向 WebSocket——
  那是上一代协议端的界面，SnowLuma 里没有这个东西
- **fix(文档)** 两份文档都没写两个前置：要先装 Python 3.10；要先装 QQ 客户端并登录机器人账号
  （SnowLuma 靠注入已运行的 QQ 进程工作，它自己不登录、也没有二维码登录）
- **feat(控制台)** 新增「连接自检」：QQ ↔ SnowLuma ↔ 糖糖 逐项体检，
  每项给一句带具体数值的下一步（自检模块同时接入 `tools/体检.py`）
- **feat(控制台)** 新增「打开网页面板」按钮；密钥管理里 SnowLuma Token 加「生成 / 复制」，
  Tooltip 说明它在面板里叫「授权 Token」、在哪两栏填——原先的提示让人去找一个新装时还不存在的字段
- **fix(控制台)** 糖糖起来后 SnowLuma 一直没连过来时，卡片永远停在「启动中」且不解释；
  现在会自动说明原因并指向连接自检
- **fix(控制台)** SnowLuma 状态区分「在跑」与「已接入」——原先只探 3000 端口，
  SnowLuma 开着但没登录 QQ 会显示成「离线」，再点一次会开出第二份实例
- **fix(控制台)** 自动重启杀错进程：SnowLuma 发布包里没有 `SnowLuma.exe`（它跑在 `node.exe` 里），
  原先杀的一直是空气，日志却照报「已自动重启」
- **fix(工具)** `tools/配置SnowLuma.py` 会把未解析的 `${SNOWLUMA_TOKEN}` 当作 token
  写进 SnowLuma，并且带一个写死的兜底 token；也不清理占着 3001 的出厂节点
- **fix(发布)** `.env.example` 的键名写的不是运行期实际读的那个，照抄的用户白填
- **fix(安全)** 脱敏扫描增加第二道判据（拿 `.env` 真值直接比对）——第一道按形状认，
  认不出「没有固定形状的密钥」；同时把「命中只提示」改成「命中即中止」

## v1.06.00（2026-09-20）

  即 QQ 语音消息、QQ 侧会转成 SILK 低码率编码——存无损是白背。改成 128kbps mp3

  不需要任何模型（详见 `docs/发布/已删除内容清单_20261015.md`）。下面这些记录只反映当时的版本

> 以上几项经一轮独立复核后补修（复核用真包/真输入跑出触发路径，逐条有证据）：
>
> - **fix(翻唱·制作侧)** 模型包的下载/解压/校验在这一版逐条修过：解压落点、条目名白名单、
