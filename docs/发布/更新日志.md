## v1.08.01（2026-11-14）

> 本节合并原先 `v1.08.01`–`v1.08.12` 的全部改动。那 12 个版本是「一个小修就占一个
> 版本号」发出去的，已于 2026-11-14 全部撤销（GitHub 上的 release 与 tag 均已删除），
> 合并重发为这一个 `v1.08.01`。**编号看着比 v1.08.12 小，内容却是它的全量。**
> 上一版仍是 `v1.08.00`。下一个小版本记 `v1.08.02`。

**发布链：装不上的根因在这三处**

- **fix(发布)** 随包 `tools/` 是白名单制，而白名单只按 `import tools.X` 扫引用。项目里另有
  `from tools.X import …` 这种写法，扫描器看不见 → 该模块没进包 → 运行期
  `ModuleNotFoundError: No module named 'tools.scenario_rename'`，后端桥直接 `code=2` 退出。
  改为「白名单 ∪ 被引用模块的传递闭包」，两种导入写法都识别
- **fix(发布)** 敏感扫描（盘符绝对路径、本机目录名）命中时**只打印不阻断**，带病出包。
  现在写快照标记 `.release-blocked`，打包脚本据此拒绝出包
- **fix(发布)** 曲库闸门缺失：源目录 41 首、进包 0 首也照样出包，用户下到的是没有歌的包。
  现在进包数量小于源文件数量即中止
- **fix(发布)** `.lnk` 快捷方式进包——里面是打包机的绝对路径，换台机器必成死链。一律剔除，
  启动指引改回「双击 exe」

**安装器：`装了跑不起来` 的十个真因**

- **fix(安装)** 升级到新包目录后依赖根丢失，重新下载 4.5 GB 模型。依赖根改为四级解析
  （环境变量 → 项目内 `依赖位置.json` → 全局 `%LOCALAPPDATA%\tangtang\依赖位置.json` →
  项目内 `依赖/`），并首次扫描附近已有的依赖目录
- **fix(安装)** 依赖位置每次都弹系统目录框。已配置就沿用，只留「回车=沿用 / 输入新目录」
- **fix(安装)** `No module named pip` / `FileNotFoundError: …distutils-precedence.pth`：
  `Lib\site-packages` 指向依赖目录的**悬空联接**（判据要用 `lexists and not exists`，
  `islink` 对 junction 返回 False）。新增 `ensure_pip()` 自愈
- **fix(安装)** 模型下载到进度 100% 却判「未完成」：落点写的是标准目录，modelscope 1.40
  实际落在 `<deps>/models/models/<ns>--<name>/snapshots/<rev>/`。改 `local_dir` 直下 +
  认缓存布局兜底；判「就位」也从只看 `config.json` 改成 config + 权重都在
- **fix(安装)** `ModuleNotFoundError: No module named 'sympy'`：torch 用 `--no-deps` 装，
  缺 `torch.fx` 需要的运行期依赖。新增 `TORCH_RUNTIME_DEPS`（sympy / networkx / fsspec），
  每个 torch 组自动补
- **fix(安装)** 日志里出现 `j i e b a - f a s t > = 0 . 3 9`：可选包列表是 `list[str]`
  被整条投给了「装一个包」的函数，于是逐字符展开。改成逐个装 + 函数内类型防御
- **fix(安装)** `Could not find a version that satisfies torchaudio==2.11.0.dev20260727+cu130`：
  dev 轮子被上游删了。改钉 `2.11.0+cu130`
- **fix(安装)** 可选模型下载是**反向提问**（回车/y 等于跳过），用户以为在确认。改正向「现在就一并下载？[Y/n]」
- **fix(安装)** 装完不验证：勾选全过、模型全下完，`import transformers` 仍然可能失败。
  新增 `check_runtime_imports()`，勾了就真 import 一次
- **fix(安装)** 只勾「发语音」不勾「聊天+高质量记忆」时不装 torch，而语音引擎入口顶层就导入它
  → 6.4 GB 模型下完得到一个启动即退出的服务

**PySide6 图形控制台整体下线**

- Qt 控制台（`运维/糖糖控制台_qt.py` 及其外观模块 `color_panel` / `icons` / `ui_anim` /
  `theme_palettes`、35 个 svg、`启动运维控制台.bat`、外观预览器）全部删除；
  `requirements.txt` 不再声明 `pyside6`，安装器的功能菜单与运维组同步去掉
- 界面只剩 `desktop/`（React + Electron）。`start.py` 的 `console` 目标一并去掉

**运行期**

- **fix(模型)** 依赖根有三处各自拼路径，导致换机器/换盘后模型「明明在却报没就位」。
  收敛到 `agent/paths.py` 的 `find_model_dir(repo)`：依赖根四级 + `___` 转义 +
  modelscope 缓存布局 + `~/models`，每级都要求 `config.json` 才认。
  `embeddings` / `reranker` / `mood_tracker` 三处统一改调它

**桌面端**

- **feat** AI 模型页压平成 `provider` 组表 + 档位引用：连接信息（地址 / Key）只在
  `llm.providers` 存一份，档位只写 `provider: <组id>`；识图与打标都走同一个
  `resolve_conn()`，不再各翻各的
- **feat** Ollama 模型自动获取 + 下拉选择（对齐 DSH Harness 的 `provider.models` 形状，
  每个模型带 `input: [text, image]` 决定能不能识图）
- **fix** Ollama 没启动时「选模型」下拉转圈 6 秒——它是 `/api/models/picker` 的串行前置，
  端口被占/正在启动会把超时吃满，连带云端档位一起被拖住。改本机 TCP 预检
- **fix** 选模型面板点空白关不掉、当前模型名白底白字（教训 #57：前端改完只跑 `tsc` + `build`
  不算验过，得在浏览器里真点一遍）
- **fix** 数字输入框输不进 `0.0x` 与负数（`<input type="number">` 的 DOM 存不下 `0.`/`-`，
  受控渲染还把它写成 0）→ 一律 text + inputMode + 本地 draft、失焦兜底提交
- **fix** 新建 provider 填完 Key 回车后被清空并显示「没填」；401 提示语改为指向 Key

## v1.08.00（2026-09-20）

- **fix(密钥)** 出厂模板把 `llm.api_key` / `llm.vision.api_key` / `napcat.access_token`
  写成了「你的DeepSeek或Claude的API密钥」这类**中文提示文字**，而不是 `${DEEPSEEK_KEY}`
  这样的环境变量引用。运行期只替换整串形如 `${VAR}` 的值，于是配置文件里那句话胜出、
  `.env` 从被创建起就没人读过——**在控制台「密钥管理」里填的 Key 落在了没有人读的文件里**。
  默认供应商恰好有一条兜底路径，所以症状不是"整个不能用"，而是"换一家供应商就 401"。
  出厂模板改成 `${VAR}`；老配置在启动时于内存中自动纠正，打开一次控制台并保存即写回文件
- **fix(密钥)** 同一根因也命中 SnowLuma 令牌：控制台填的 Token 从来没到过运行期。
  该项**没有**任何环境变量兜底，所以两边不一致时链路静默走不通
- **fix(密钥)** `tools/体检.py` 的密钥检查只枚举"已经是 `${VAR}` 形态"的引用——
  形态错的那些它一个字都不报，**越坏越安静**。现在改为判断"运行期是否真的拿得到可用值"
- **fix(密钥)** 控制台保存时会把"仍等于环境变量值"的字段还原成 `${VAR}`，
  但它按写死的路径清单工作，且值被物化成空串时不再还原——那会让引用悄悄退化成空字符串
- **feat(控制台)** 仪表盘新增「记忆自动同步」卡片（控制卡片右侧）：
  关掉之后不再打包、不再解包，也不再弹任何同步提示；选择存进 `config.yaml`
- **fix(控制台)** 直接看 `3000` 端口判断 SnowLuma 是否在跑，并在开机 8 秒后于界面线程里
  同步执行一次最长 30 秒的网络检查——网络不通时界面会**冻结约 20 秒**且不显示任何结果。
  改为后台线程、超时 8 秒
- **fix(控制台)** 启动时的 SnowLuma 更新检查**永久静默**且不报错。
  两个独立成因：本地版本号绑死了一个具体目录名（用户装别的版本就读不到）；
  取线上版本时未指定子进程编码，Windows 中文版用 GBK 解码 GitHub 的 UTF-8 响应直接抛错被吞
- **fix(日志)** 「某某模型没就位」的提示把 `python -c "from modelscope import snapshot_download…"`
  这类命令原样打印给终端用户（相对当前目录、用户无从执行），且不说明该模型属于哪个功能。
  现在按安装时勾选的功能说话
- **feat(安装)** 安装清单落盘（`installed_features.json`）：安装器记下这次勾了哪几项，
  运行期据此区分「你没装这个功能」和「你装了但没就位」——在那之前两者在磁盘上都是"目录不存在"
- **fix(日志)** StructBERT 情绪模型被无条件加载，而它**不在任何安装项里**——
  每台新机器都会看到一条自己无法修复的警告。已加入模型下载清单（可选，会先问）
- **fix(安装)** 只勾「发语音」不勾「聊天+高质量记忆」时不会安装 `torch`，
  而本地语音引擎入口顶层就导入它——6.4G 模型下完后得到一个启动即退出的服务
- **fix(诊断)** `tools/体检.py` 与安装器的目录检查把 BGE 向量模型和重排序模型
  当成同一条来判（任一存在即打勾），用户跳过 2.2G 的重排模型后安装器照样报"已就位"，
  与启动日志互相矛盾。两者拆开，各自判 `config.json`
- **fix(诊断)** 健康自检的 21 项里没有一项涉及模型层：语义向量模型没加载时，
  记忆去重、语义检索、知识库混合检索已全部退化为关键词匹配，而 `/状态` 仍报「全部正常」
- **fix(诊断)** 新装机器第一次启动会把三项"数据还没攒够"的检查报成故障
  （主人记忆数为 0「最严重的系统失败」、陈旧清理"从未"、今日提取"可能阻塞"）
- **fix(安全)** `/状态` 的输出里带着主人 QQ 号，而该命令的权限是「主人**或群主」——
  糖糖被拉进陌生群后，群主发一条 `/状态` 就能读到
- **fix(控制台)** `voice.enabled` 为 `false` 但 `provider` 是 `gpt-sovits` 时
  仍会去启动本地语音服务（出厂模板就是这个组合），换回一条"进程意外退出"
