# Codex 长期工程增量审查：并发、定时动作与记忆失败风暴

日期：2026-08-28  
范围：`agent/handler.py`、`agent/tasks.py`、事实簇提取、相关测试与运行观察器  
判定：**Request Changes（生产尚未验收）**

## 已修复并有回归

### Important — 群/私聊忙线持有者互相覆盖

- 位置：`agent/handler.py` 忙线入口与收尾。
- 证据：并发探针可见私聊覆盖旧 `_busy_owner` 并提前清空 `_busy`。
- 根因：单 owner 字段无法表达并发回合。
- 修复：按 asyncio Task 引用计数的 `_busy_holders`，guard/取消/异常均只释放当前任务；定向并发回归通过。

### Important — 排队回合插队、取消丢失与异常 marker 泄漏

- 位置：`_schedule_pending_reply`、`_process_pending_reply`。
- 证据：首个 await 前新回合可获准入；等待 holder 时取消会使队列为空且 reservation 卡住；异常 probe 曾使完成 Task 留在释放集合。
- 根因：预约只写布尔状态，没有 admission token 的原子接管与回滚。
- 修复：reservation→holder token、取消前回滚 FIFO、完成任务 marker 显式清理；回归覆盖首 await、等待取消和异常，已验证。

### Important — 高优先级队列无限增长

- 位置：`handle_group_message` 忙线分支。
- 证据：历史观察出现 LLM 等待 P50 9s/P95 54s/最大 337s；原队列无容量上限。
- 根因：只入队不做背压策略。
- 修复：默认 64 条上限；相同平台事件合并；满载按优先级淘汰/拒绝并写 `pending_queue_*` 指标与 warning。不同消息不会按用户静默合并。

### Important — 定时 payload 结构化对象泄漏与盲重试

- 位置：`agent/tasks.py:_parse_payload/_execute_payload`、`handler.py:set_reminder`。
- 证据：对象值曾被 `str()` 转为 `{'internal': ...}` 并实际发送；发送异常可能已到达 QQ，按 failed 释放会重放。
- 根因：字段仅验 key，不验类型/空动作；外部异常事实不确定。
- 修复：只接受字符串、非空、长度≤4000；坏 payload→`uncertain`；外部发送异常→`uncertain`，不自动重试；回归通过。

### Important — 事实簇 LLM/格式失败风暴

- 位置：`handler.py:_extract_fact_clusters_task`。
- 证据：旧 boot `8efc3169` 于 17:22:24 记录“事实簇提取失败（LLM/格式）→ 游标不推进”。
- 根因：游标为 at-least-once 停留，但失败没有按游标退避。
- 修复：新增 `fact_cluster_retry:<qq>` 状态，指数退避（5 分钟起步、上限 6 小时）；成功/合法空结果清除。原始消息与游标安全性不变。
