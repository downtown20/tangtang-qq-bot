# Codex 对话质量终审（2026-08-17）

## 结论

**Request Changes — 总体风险：High。**

本批方向正确，`build_system_prompt()` 内部的 normal / minimal / overlay / replace / voice override / reload 六类基础组合均能带上 `CORRECTION_CONTRACT`，背景选择也已实现“按优先级选择、按原 index 展示”。但最终请求仍存在契约被下游裁掉的路径；voice override 与 replace 组合会丢场景 tone；背景优先级表遗漏了生产中实际使用的“姿态”和低估了“补读”。这些会分别破坏不可绕过契约、场景协议和当前轮证据，因此不能 Approved。

## 审查方法与限制

- 以 `2026-08-17 Codex 对齐` 注释为变更边界，向上下游追踪了群聊、私聊、遥控、主动消息、工具装配、发送与持久化路径。
- 本地 GitNexus 索引时间为 2026-08-15，早于本批改动；只用于旧调用图交叉验证。其结果显示 `_checked_send`、`_call_llm_with_skills` 直接影响群/私主路径，风险标为 LOW，但旧索引找不到新增 `fit_backgrounds`，且对 `build_system_prompt` 的 caller 明显漏报，故不把图结果当最终事实。`detect_changes` 因项目不是 git 仓库无法执行。
- 项目 Python/pytest 入口在当前会话不可用：两个 venv 均指向已删除的系统解释器。使用项目嵌入式 Python 加现有依赖逐个执行了 `tests/test_dialog_quality.py` 的 20 个测试体，20/20 通过；所列 7 个改动文件及该测试文件通过 `compileall`。用户提供的“453 测试全绿”未在本次环境中冒充复跑结果。

## 问题清单

### High

1. **[agent/context_builder.py:218] 最终 system prompt 的截尾安全网仍可删除 `## 必须遵守`，所以契约并非最终请求级不可绕过。** `build_system_prompt()` 在 agent/personality.py:326 正确追加契约，但 ContextBuilder 超预算后只保护末尾 capability marker，对 marker 之前的 `_head` 直接从尾部截断。overlay sensitivity、无长度上限的 voice role、群风/权力等都在契约之前；探针构造长前缀后，`build_system_prompt` 含契约，而 `ContextBuilder.build()` 的最终 `system_prompt` 已不含契约。为什么是问题：normal/overlay/replace/voice 的真实群私路径都会经过 ContextBuilder，单测只检查了上游中间产物。建议修复：把身份/纠正契约作为不可裁核心分别保留，裁剪只作用于明确可裁动态块；增加“经过 ContextBuilder 后”的六组合预算溢出测试，不能只断言 personality 返回值。

2. **[agent/personality.py:281] voice override 与 replace 场景组合会把 `scenario.tone` 一起抹掉，违反“只换身份、不覆盖协议”的本批目标。** replace 分支把 role 和 tone 都放在 `if not role_override` 内；实测 voice+replace 有纠正契约，但 ROLE、TONE 均缺失。跳过 replace role 可以解释为身份覆盖，跳过 tone 没有同样理由。为什么是问题：活动管理者/程序专家等替换场景的行为姿态会因切音色而静默消失，测试只覆盖 voice+默认场景，形成假绿。建议修复：只让 override 替换身份 role，场景 tone/非身份协议始终装配；补 voice×replace、voice×overlay、voice×minimal 组合测试。

3. **[agent/protocols.py:210；agent/handler.py:1900；agent/handler.py:1989] 背景优先级表遗漏生产标签“姿态”，并把用户当前明确请求的“补读”排在旧记忆/画像/日记之后。** 群插话的“短、轻、接一句就走”使用未知标签“姿态”，会按默认优先级 9 处理，低于记忆 7；预算紧张时旧记忆可保留而姿态被丢，重新出现长篇打断群聊。补读摘要优先级 12，甚至低于日记 11；用户问“我不在时聊了什么”时，真正答案可能被旧材料挤掉。为什么是问题：选择器算法正确，但分类表把两类当前轮任务信号归错层，结果仍会答非所问。建议修复：显式登记“姿态”为协议/当前轮指令级，“补读”为当前轮直接证据或至少窗口级；增加真实 handler append 顺序下的预算竞争测试。

### Medium

4. **[agent/personality.py:310；tests/test_personality.py:41] 缓存前缀的代码顺序和测试边界都没有钉住本批宣称的完整契约。** 实际顺序是角色卡→权力→群风格→思考链→契约，不是角色卡→群风格→权力→思考链→契约；既有 `_stable_prefix()` 又在思考链尾句截止，完全不包含新加的 `## 必须遵守`。此外群风每 50 条可更新、权力结构也会变化，因此只能说“同一群且输入值不变时稳定”，不能说跨调用无条件静态。为什么是问题：顺序回归或契约变成动态文本时现有测试仍会绿。建议修复：明确缓存作用域；把契约尾部作为 stable prefix 结束标记，分别断言相对顺序、内容字节级稳定以及群/场景切换时预期失效。

5. **[agent/handler.py:7430；agent/store.py:390] reply_metrics 主链路安全，但观测字段、覆盖率和隐私口径不完整。** 写入仅在 `sent_ok` 后发生且异常被隔离，这是正确的；但 `target_id` 原样保存 QQ/群号，不是方案中的匿名会话键；表里的 model/scenario 从未由 `_checked_send` 传入，实际恒为空；被自检拦截后实际发送的 fallback 以及 `/说`、遥控唱歌等直发 LLM 文本不入指标；异常完全静默会让遥测永久失效而无人知道。为什么是问题：分桶无法按模型/场景解释，声称“每条已发送回复”也不成立。建议修复：使用稳定哈希会话键，填充或删除永远为空的字段，明确覆盖范围；异常限频告警，继续保证不影响发送主链路。不要保存正文这一点应保留。

6. **[agent/context_builder.py:279] “近 3 天窗口”对空或非法 `updated_at` fail-open，旧格式叙事仍可能永久常驻。** 有合法时间戳时逻辑正确，当前状态文件也是合法值；但时间为空时直接注入，解析异常也被吞掉后注入。为什么是问题：迁移/损坏状态恰是窗口最需要兜底的情况，且当前新增测试没有走 `_get_self_narrative_context()`。建议修复：有 summary 但无可解析更新时间时默认不常驻，或做一次明确迁移；补 3 天内、超过 3 天、空值、非法值、带时区五类测试。

7. **[tests/test_dialog_quality.py:22] 新测试修掉了永真断言且关键选择测试确实会失败于旧实现，但覆盖矩阵仍不足以阻止上述回归。** `test_priority_selection_not_append_order` 真正制造了预算竞争，`test_display_order_restored` 也验证了稳定展示序；然而没有 unknown label、同优先级稳定序、包装预算上界、短块小余量、保护块 overflow 记录、群/私调用点、voice+replace tone、ContextBuilder 后契约、reply_metrics、tools TokenReport、3 天窗口测试。风格锚测试也只查两个字符串，无法证明“五形态分布”。建议修复：优先补前三个 High 对应的路径级测试，再补遥测与窗口边界；自然度仍应由盲测/线上指标判定，不由字符串单测宣称成功。

## 六个审查维度结论

1. **契约不可绕过性：未通过。** Personality 层六种基础组合通过；最终 ContextBuilder 裁剪可绕过，部分主动/传话提示词还直接使用 `_cached_base`（如 agent/handler_commands.py:562、agent/handler_autonomy.py:241），未经过统一契约出口。若契约只要求“可纠正的对话主路径”，应在代码与测试中明确范围；若宣称所有用户可见生成出口，则这些也要统一。
2. **fit_backgrounds：算法主体通过，分类表未通过。** 保护块计量、同优先级排序键、原 index 恢复、空块清理均正确；标签包装估算对现有标签是保守高估，不会超支。群/私主路径均已接入。问题是“姿态”“补读”的语义优先级，以及 overflow 没有按原方案返回/记录。
3. **缓存前缀：部分通过。** `CORRECTION_CONTRACT` 常量内容静态，普通路径位于动态时间/情绪之前；但相对顺序与测试定义不一致，minimal 又把动态时间放在契约之前，不能把契约计入 minimal 的最长稳定前缀。
4. **回归风险：部分通过。** capability_note 保留 marker、全能/简约差异与“工具列出才做得到”，工具 schema 也保留能力和隐私描述，未发现“答应做不到”边界被完全删除；`_get_tier_prompt` 只有内部单一调用点，签名兼容。画像/关系档案只在私聊构造并进入预算，群聊没有遗留同类 capability 豁免。voice+replace tone 是主要回归。
5. **遥测落库：主链路安全，数据质量/隐私未完成。** 成功后写、异常不影响发送、不存正文均正确；原始会话 ID、空 model/scenario、覆盖缺口需要修正。
6. **测试质量：结构单测有价值，但存在新的未覆盖真绿。** 本次实际执行新增 20 个测试体均通过；High 问题均可在绿测下复现。

## 明确未发现问题的方面

- 用户原文仍无标签且最后；群聊、私聊都在组装前调用 `fit_backgrounds()`。
- 引用/协议保护块允许 overflow 且恢复原展示顺序；空块会丢弃；未知标签行为确定为默认优先级 9，而不是随机顺序。
- `_bg_wrap_tokens()` 对当前所有标签均保守高估；截断后重新估算正文并累计，没有发现包装漏算导致的实际超预算。
- capability marker 仍与 ContextBuilder 截断豁免一致；私聊画像/关系档案不再拼进该豁免串。
- tools schema 使用 `ensure_ascii=False` 序列化估算，并累加到 `TokenReport.total_tools/total`；群私正常工具路径都经过该装配点。
- anti-tell 的括号动作只诊断、不阻断、不改写回复；没有引入危险的后处理规则。
- reply_metrics 建表幂等，写入参数化，不存回复正文；数据库异常不会反向破坏已成功发送的主链路。
