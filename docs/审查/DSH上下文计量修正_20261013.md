## 一、要解决的问题（先记结论，细节见 `~/.dsh/memory/MEMORY.md` 2026-10-13 条）

cainiao 中继把 **含缓存的全文 prompt** 放进 Anthropic 格式的 `input_tokens`，而 DSH 的 `TokenUsage` 契约要求三个 prompt 侧字段**互不相交**。结果：

| 症状 | 实测 |
|---|---|
| 上下文百分比 | **2.00× 虚高**（压缩前 585,322 vs 真 292,419） |
| 缓存命中率显示 | **49.4% vs 真 97.7%**（分母被灌了一倍水） |
| 隐藏风险 | 压缩阈值读同一个被放大的量 |

判别证据（三条独立）：① 缓存预热后 `input` 不降反平；② `cacheRead/input` 锁死在 0.999（子集特征，对照官方 0.926~2302）；③ 同一会话换路由立刻恢复正常口径。

## 二、为什么不能只改 `api:` 一行

`cainiao.baseURL = https://buddybackend.cloud/` 是**站点根**，两个 SDK 各自拼路径：

| 请求 | 结果 | 含义 |
|---|---|---|
| `POST /v1/messages` | 401 `new_api_error` | Anthropic 端点存在 |
| `POST /v1/chat/completions` | 401 `new_api_error` | **OpenAI 端点也存在** |
| `POST /chat/completions`（baseURL 不动时 SDK 真正会打的） | **200 `text/html`** | 落进 SPA，不是 API |
| `GET /v1/models` | 401 | 存在 |

⇒ 只改 `api` 会打到 `/chat/completions` 拿到 HTML；把 baseURL 改成 `/v1` 又会让 anthropic 端去打 `/v1/v1/messages`（已实测 404）。**所以必须新增第二个 provider 条目。**

## 五、一个必须记下的坑：手写模型只认 `off`

第一次端到端尝试直接失败：

```
dsh: UNSUPPORTED_REASONING_EFFORT: provider "cainiao-oai" model
     "deepseek-v4.1-flash" does not support reasoning effort "high"
```

根因（`dsh-llm-pi-ai/lib/index.js:567-590, 1700-1708`）：手写 model 没有 pi-ai 的 catalog 元数据 ⇒ `getSupportedThinkingLevels()` 只返回 `off` ⇒ 任何显式 effort 都被拒。**必须在 model 里声明 `reasoningEfforts`。**

补充实测：该中继的 `reasoning_effort` **接受 minimal / low / medium / high / xhigh / max 六个值全部 200**，也接受 `thinking:{type:enabled}`。本次只声明了 low/medium/high 三个（够用即可，避免把未验证的档位暴露到选择器）。

## 六、验收（**2026-10-13 实测修正：原写「数值应掉一半」是错的**）

**正确判据**：面板的 `pressureTokens` 必须**恰好等于** provider 报的 `prompt_tokens`（= `input + cacheRead`），且 `input` 此时是**未命中残留**——会出现 `input=309 / cacheRead=512,896` 这种形状。

**不要**用「百分比有没有掉一半」验收，原因见下节。

## 六之二、切换后的实测结果

| 项 | cainiao（anthropic 端点） | cainiao-oai（OpenAI 端点） |
|---|---|---|
| `input` 字段语义 | **总 prompt** | **未命中残留** |
| `cacheRead` | 总 prompt 的**子集** | 总 prompt 的**子集** |
| 面板 `input + cacheRead` | **= 2× 真值** ✗ | **= 真值** ✓ |
| 样例 | seq 4065 `259,410 + 258,432 = 517,842`（真值 259,410） | seq 4218 `309 + 512,896 = 513,205`（真值 513,205） |
| 缓存命中显示 | 49.4%（= 真 99.6% 的一半） | **99.9%（真值）** |
| 面板百分比 | 51.8%（虚高：虚的 2× 撞上了小的真值） | **51%（准确）** |

**计量修好了**：面板 `pressureTokens` 与 provider 的 `prompt_tokens` 相等。
**但面板没有掉一半**（51.8% → 51%），因为**路由切换本身让真实 prompt 涨了 ~1.8×**（259K → 513K），两个效应互相抵消。

### 为什么真实 prompt 涨了一倍

`@earendil-works/pi-ai/dist/api/transform-messages.js:68-90`：

```js
const isSameModel = assistantMsg.provider === model.provider &&
                    assistantMsg.api      === model.api &&
                    assistantMsg.model    === model.id;
// thinking 块：
if (isSameModel && block.thinkingSignature) return block;   // 保留为 thinking
if (!block.thinking || block.thinking.trim() === '') return [];
if (isSameModel) return block;
return { type: 'text', text: block.thinking };              // ← 跨路由时降级成正文
```

`isSameModel` 要求 **provider + api + model.id 三者全等**。切到 `cainiao-oai` 后，所有切换前产生的消息 `api='anthropic-messages'` ≠ `'openai-completions'` ⇒ 判定为 false ⇒ 它们的**思维链被改写成正文重新发出**。

本会话保留面里思维链占 **52.6%（773,760 字符 ≈ 193K tokens）**，与实测跳变 **+205K** 量级吻合。

**阳性对照（区分「降级成正文」与「重放 thinking」）**：给同一历史加一个 60,000 字符的 thinking 块，两个端点的 prompt 计数**都 +0**（期望 ~15,000）。⇒ 中继**丢弃** thinking 块、但**照收正文**，所以只有「降级」才会涨。

### 可证伪预测

这 ~200K 来自**切换前的历史**，不是永久的。当那些消息离开保留面（做一次 `/compact`，或持续对话把旧消息挤出去）后，`isSameModel` 对全部保留消息恢复 true ⇒ 思维链重新以 thinking 块发送 ⇒ 被中继丢弃 ⇒ **prompt 应回落到 ~250–300K、面板回到 ~25–30%**。
**若压缩后 prompt 仍停在 500K 量级，则上述机理被推翻**，需另找原因。

### 成本提示

每轮输入从 ~259K 涨到 ~513K（约 +1.8×）。缓存命中 99.9%，多数按缓存价计费，但未命中部分与缓存写入仍按更高价计。若成本敏感，压缩一次即可拿回。
