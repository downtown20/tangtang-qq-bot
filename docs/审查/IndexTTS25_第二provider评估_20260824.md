## 二、对糖糖的三维评估

### 情绪控制：唯一实质增量
我们现在用「LLM 标签 → 7 情绪 speaker 各一份 ref.wav」的方式做情绪。IndexTTS 只需**一份 ref + 情绪向量**（强度 0-1 连续可调），情感-音色解耦——长期看情绪表达上限更高、维护更省（不用录 7 份参考音频）。这是真实增量。

### 实时性：硬伤
糖糖的语音是 QQ 语音消息——GPT-SoVITS 现在 1-2s/句。IndexTTS-2.5 估算 5-6s/句（3060 级显卡），用户点开语音要等几秒，实时感崩掉。批 1 刚把「情绪突变」和「截断」修稳，换引擎后等待时长反而成为新体验 bug。

### 部署：成本与新栈风险
- +6GB VRAM。本机已跑 GPT-SoVITS(cuda) + BGE + Reranker，双 TTS 并存需实测总显存。
- 官方 serving 走 vLLM-Omni，recipe 发布 2 周，Windows 下成熟度未知；自建 API server 是新增基础设施。

## 三、结论与观察项

**结论：现在不接入。** 三个理由：
1. 它不解决任何现存 bug（批 1 + cut5 已修根因）——只换情绪实现方式，属「拆东墙补西墙」风险；
2. 实时性是糖糖语音场景的硬约束，RTF 慢 5 倍不可接受；
3. vLLM recipe 2 周新，Windows 案例少，踩坑成本高。

**再评估条件（满足任一即重启评估）：**
- IndexTTS RTF 优化到与 GPT-SoVITS 同量级（BigVGAN2 直建波形路线已起步，2.28x 是第一步）；
- 糖糖要上情绪强度连续控制（向量化），而 7 情绪 ref 方案不够用时；
- 本机换更快 GPU / 或 vLLM recipe 有 Windows 成熟案例。

**优先级建议：** 若想提升语音上限，先做 GPT-SoVITS v2→v4 升级（权重已在本机，见批 2-①）——零下载、音色同源、稳定性和少重复受益，代价只是需要试听确认音色漂移可接受。
