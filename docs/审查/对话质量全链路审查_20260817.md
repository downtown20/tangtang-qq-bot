## 三、诊断：为什么「塞满」=「表演」

1. **关于自己的手册太厚 → 自我意识过载**：CoT 教它「先想什么」、情绪块教它「数值仅供参考」、
   四个状态块用第三人称描述它自己的内在状态。模型不是在当猫娘，是在执行「如何当猫娘」的说明书。
   表现：回复带清单体（「记住了：1. …2. …」）、括号动作描写、过度解释自己。
2. **状态叙事层互相重叠**：关系层级（tier 参数）+ 关系场（现在和你说话的人）+ 关系档案
   （rel_summary）+ 交叉窗口 + 记忆块——五个「你和他是什么关系」来源，措辞各不相同。
   模型被迫在文档之间做综合（synthesis），而不是在聊天（chat）。synthesis 模式输出 = 演讲腔。
3. **背景块的前言是「演讲教学」**：memory_block「像老朋友聊天一样顺嘴带过，但不要说
   『我记得你』…」——这些元指令让模型把「自然」当成一项被检查的作业去表演。
   表演出来的自然最不自然。
4. **能力手册常驻 + 截断豁免**：8-15 审查把 capability_note 设为不可截断（防「答应做不到的
   事」）——代价是每轮 1000t 的说明书，即使这条消息只是「嗯嗯」。
5. **自己的市场调研结论被自己违反**：「自适应思考预算：只在困难轮次分配思考，无脑长 CoT
   有害」（protocols.py 注释明写）——但 CoT 6 条常驻每轮。

## 四、市场调研结论（SillyTavern / bae.ppl.studio / speak-human-tw / instruction-compliance-ceiling）

与诊断完全咬合的关键原则：
1. **常驻 system 越短越好**（身份 50t + 约束 80t 量级）——每条常驻规则都在跟「糖糖是谁」抢权重；指令遵从天花板 ≈68%，规则一多就「半执行」＝每条回复都「对但不自然」
2. **绿灯优先**（World Info）：背景按需注入不常驻；背景注入设 token 预算 + 优先级淘汰
3. **show don't tell**：3-5 轮示例对话胜过一切「语气要自然」指令——模型模仿示例远强于服从指令
4. **状态块用感受口吻**，不要输出数值/字段——模型看到状态数据会「汇报状态」，看到感受会「处于状态」
5. **罐装反应镜头**（「我愣了一下」「沉默几秒」）是表演感判据；助手腔（很乐意/作为AI）是底层对齐泄漏
6. **DeepSeek 专属**：长上下文关键信息保持率 50 轮跌到 ~30%——短上下文是刚需不是优化
