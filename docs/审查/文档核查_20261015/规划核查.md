## B. 规划合理性评估

### B.1 站得住的部分（建议原样保留，不要动）

1. **状态机 + 唯一事实源 + 层级分工**（`任务台账.md:3`–`:5`；`README.md:232`–`:238`）：队列管状态、`记录/Tn-*.md` 管细节、`快照/` 管数值，职责不重叠。
2. **验收纪律成文且成体系**：`README.md:120`–`:145` 三档门槛（硬门槛/棘轮/行为门槛）+ `复盘…:359`–`:371` 九条自我约束 + `README.md:311`–`:384` 十条方法论沉淀。其中「改动行为参数必须同批提交观测点」「新闸门必须给阴性+阳性对照」「判机制没生效前必须先证明观测窗口 ≥ 一个时间常数」三条是本项目最有价值的制度产物。
3. **失败处置预先钉死**（`复盘…:298`）：写明 T4.1/T4.3 未达成即回退参数，「不得以再观察观察延后」——这条把「延长观察」这个最常见的逃避路径提前堵住。
4. **风险表带证据列与关闭动作**（`复盘…:192`–`:201`）：X1 有明确的「已关闭」终态判定（`:194`），不是只列不结。
5. **已知不修的否定结果也落盘**：`记录/T38-CQ正则重复审计.md` 标题即写「结论是不修」，并在 `:78` 给出「同类两份拷贝为何 T10/T12/T25/T35 要修而这个不修」的对照——否定结论带理由，可防重复讨论。

### B.2 机制缺陷（根因层，共 4 条）

**B-1｜状态与证据分家，且无回填机制（主要矛盾）**
队列行以「见『已完成』表」代替完成判据（`任务台账.md:26`–`:46`），判据只存在于第二个表；同一编号可以在两处得到两种状态（`:63`/`:66`、`:56`/`:62`）。计划表一经分节，中间层永不回填——`复盘…:233`/`:252`/`:680` 三处计划表在后续章节（`:618`/`:703`/`:758`）已被推翻却仍以原样留在文档中。**根因是「多张表承载同一状态」+「没有回填义务」两条同时成立。**

**B-2｜通过数是手写数字，未接采集工具（数字漂移的必然来源）**
`README.md:131` 声明棘轮由 `tools/长期优化快照.py` 采集，`快照/` 确有 8 份 json；但台账里的通过数是人从输出里抄的（`任务台账.md:13`–`:15`、`:86`–`:122`），**人工抄写与机器采集之间没有任何一致性校验**。实测结果就是同一天出现 2759/2634/2712/2839/2845/2851 六个数字（A-3）。这属于本项目自己的教训 #30 家族：**检查器写了，但被检查的对象没接上**。

**B-3｜章程与项目主文档双源漂移（三处已实证）**
章程自称唯一事实源，但它与被核查范围外的 `CLAUDE.md` / `AGENTS.md` 在**同一事实**上给出相反陈述：git 状态（`README.md:151`/`:163` vs `AGENTS.md`「本仓是 git 仓库」）、静态检查命令（`README.md:126` vs `CLAUDE.md`「不要手写那条 pyflakes 命令……82 个文件只真扫了 2 个」）、发布仓（`README.md:260` 仍列 `D:\小糖糖-发布` vs `AGENTS.md`「旧发布仓已弃用」）。**「唯一事实源」的自我定位与它未被同步的事实并存，是这次核查最危险的模式**：读者按章程执行硬门槛，会拿到绿灯与假安全感。

**B-4｜待拍板项堆积且缺一页汇总**
`任务台账.md:41`（T4.8 改 `_apply_mood_report` 观测点）、`:72`（T20 喵会话级自锁，实测 80% vs 40%）、`:141`（T2.2 私有方法扩覆盖，15 条存量）、`:142`（T2.3 第二档 3 条）四项等主人决定，散落在队列与阻塞表两处，且「进行中」栏为空（`:20`）。主人需要的是**一页「等你点头」清单**，当前形态要读两张表才能拼出来。

### B.3 最小改进建议（三条，均为文档级）

1. **编号唯一化 + 状态单一化**：T30、T32 的重复行合并为一行，或给冲突行加显式后缀（T30a/T30b）并写清二者关系；队列行不再以「见已完成表」代替状态以外的内容。
2. **通过数改为引用快照文件名**（如「见 `快照/20261014-124828.json`」），不手抄数字——一次性把 B-2 从源头切断；同时把 `README.md:126` 的硬门槛命令替换为现行 `tools/静态检查.py`（并保留原命令的失效原因一行）。
3. **计划表加「已作废 / 已被 X 章节取代」标记**：对 `复盘…:233`/`:252`/`:680` 这类已被后续章节推翻的计划块，只加一行指向取代者的标注（不删原文，符合该文档「不删历史」的既有作风）。
