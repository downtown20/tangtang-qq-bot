## 一、事故

2026-08-16 17:46，用户（主人，QQ 2524950083）问「查一下我们的记忆…总结我们聊天过程」，糖糖回复总结里说「会画画、爱特摄、迷时政」。17:49 用户纠正：「我不爱特摄也不迷时政，我一直是你的开发者，蓝发小妹Agent其实就是你自己，我们的关系其实是主仆关系」。糖糖道歉说「记住了」——但 DB 核查：people.notes、memories 里「特摄仙人」「对时政感兴趣」原样未动；17:50 的画像合成继续写入「特摄仙人」。糖糖自诊「把画像行当成真事儿了」。

**取证（已核实）**：
- 种子：06-27 用户单句「特摄仙人」→ like 记忆 confidence=0.55；07-01「我说我对时政方面比较感兴趣」→ like 记忆 confidence=0.9
- 放大：画像合成输出名义 confidence=0.7 的 profile → people.notes（现含「自称特摄仙人…对时政感兴趣」）
- 触发频率：2026-08-06 日志实证 17:45:10 与 17:45:31 两次合成间隔 21 秒（Codex 复审修正：此为 08-06 旧日志段，非事故当天；事故当天 17:50 后未再合成主人画像，纠正后污染的直接证据是 DB 完全未改、后续注入继续用旧 notes）；用户 profile_synthesis 存量 15 行（每行 200-300 字近似重复）、fact_synthesis 63 行、全库 13,718 行（审查时快照）
- 注入：事故轮 LLM 实际调用了 get_first_met、三次 search_episodes、get_last_conversation、get_messages_by_date（返回内容均不含画像）——「爱特摄、迷时政」唯一载体是 people.notes 注入（handler.py:2581-2582 全文注入、借 capability_note 豁免机制免 token 截断）
- 纠正后：17:49:24 回复「记住了」，17:50 画像合成继续写错；无任何写回工具被调用（工具列表 30+ 全是检索/动作类）

## 二、四线审计汇总（20 项发现）

### P0（六项，已获代码证据）
1. **纠正闭环完全缺失**：工具列表零写回（handler.py:3427-3483 `_build_memory_tools`）；store 的 delete_memory_by_id(:901)/update_memory_value(:926)/set_memory_importance(:935) 现成但 LLM 够不着；纠正信号链止于「复述→道歉」提示词（protocols.py:24-43 CORRECTION_SIGNALS → handler.py:2695-2701 只注 COMPREHENSION/THINKING 协议）
2. **画像合成自激循环无冷却**：handler.py:6461-6468 触发计数 `total_mem - last_syn >= 10`，而 get_memory_stats 统计全表（含合成自己写的行）——每次合成把下一次触发推近一半；三路触发（计数/反思整合 memory.py:1521-1523/autonomy 每10分钟 handler_autonomy.py:1087-1116）无任何冷却
3. **合成行只增不换**：insert_memory 纯 INSERT（store.py:827-841）、表无唯一约束；_deduped_remember 语义去重只在 `query_memories(limit=100)` importance DESC 窗口内（memory.py:647）——imp=4 的旧合成行被挤出窗口；去重合并取 max importance 只升不降
4. **LLM 元话术直入 notes**：memory.py:1003-1009 只按 KEY_FACTS 切分无前缀剥离；prompt（:975-990）无「只输出画像正文」契约；「这是个人群像的增量更新版…」已实际存进 154875246 的 notes 且全量注入系统提示词、下次合成回喂自我复制；relationship.py:53-68 同源污染（「对方是否喜欢这种称呼未知」元评论入库）
5. **提取质量契约缺失**：memory.py:898-903 `if confidence == 0.7: confidence = 0.55` 恰好压过 0.5 丢弃线（事故数据精确吻合）；禁用清单（:797-839）无玩笑/测试语句/引用转述/否定判别（事实簇 prompt :1044-1071 反而有「🚫 RP/测试」条款，两路径规则不一致）；提取批次零对话上下文（store.py:1061-1062 只取目标用户非 bot 消息，memory.py:786-789 只拼 `[{ts}] {nick}: {msg[:150]}`）；speaker attribution 缺失（用户引用他人话→被提取成用户事实，DB 实证「@蓝发小妹 奶奶的，我丢你老」成了 2470404655 的 fact）

## 三、拟议修复集（P0 六项的最小修法）

**A. correct_memory / forget_memory 工具**（修复 #1）
- 注册：_build_memory_tools 末尾追加两个工具定义；执行：_execute_tool 加分支
- 参数：`subject_qq`（纠谁的记忆）、`query`（旧错误事实关键词）、`correction`（正确陈述）、可选 `forget_only`
- 写库：BGE 语义匹配命中项 → set_memory_importance(id, 0)（或加 memories.status 列 'denied'）→ remember(subject_qq, "fact_correction", correction, importance=8, origin="corrected")；若命中的是 notes/fact_clusters 内容，触发一次带纠正注入的画像重合成
- 权限：纠自己相关事实=本人即可；纠第三人事实=仅 owner（复用 handler.py:3880/:4232 两级模式）
- 检索联动：recall/search_fact_clusters 跳过 denied/imp=0 条目
- 配套：protocols.py 新增 CORRECTION_CONTRACT（被纠正→必须调工具写回，写回前不许说「记住了」）+ 闸门测试（仿 TestGroundingContract）

**B. 合成冷却 + 计数排除合成行**（修复 #2）
- `synth_done:{qq_id}` kv 落盘 24h 冷却（持久化铁律）；计数触发改 `COUNT(*) WHERE key NOT IN ('profile_synthesis','fact_synthesis')`

**C. 合成行替换式写入 + 去重窗口修复**（修复 #3）
- 合成前 DELETE 同 (qq_id, key) 再 INSERT；Phase 2b 查重按 key 过滤全量而非 top-100 窗口

**D. prompt 输出契约 + 入库前缀剥离**（修复 #4）
- 合成 prompt 加「只输出画像正文，禁止开头语/解释」；入库前正则剥离常见前缀；notes 回喂前用同一清洗函数；relationship.py 入库前过滤「未知/不确定」元评论

**E. 提取质量契约**（修复 #5）
- `confidence == 0.7` 默认值直接丢弃（不降权）；主提取 prompt 补「玩笑/测试语句/引用转述/否定句不提取」条款（与事实簇 prompt 合并共享常量）；identity/alias 要求自述句式证据；提取批次尽量并入糖糖相邻回复作语境

**F. 注入侧收口**（修复 #6）
- notes 截断 ~120 字 + PROFILE_CAVEAT 升级为独立警告行；protocols.py 加 `profile_line(notes, max_len)` 统一 helper，三处调用点（2582/7279/recall_formatted 🖼️）收口
