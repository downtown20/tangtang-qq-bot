# DSH 上下文自动压缩：启用 billion-context-dsh（2026-10-26）

> 主人原话：「我需要你拥有一个 billion-context-dsh 模型驱动的上下文压缩的功能，
> billion-context-dsh 已经不兼容了，但他已经存在，你魔改后自己使用，**上下文自动压缩很重要，优先做**。」

---

## 一、诊断：不是「不兼容」，是「被 peer 区间挡住」

**事实链**（全部实测）：

| 项 | 值 | 怎么查到 |
|---|---|---|
| 本机 DSH | **0.2.1-rc.2** | `node <cli>/bin.js --version` |
| 插件 | `billion-context-dsh@0.2.27`，**已安装**在 `~/.dsh/profiles/web/node_modules/` | profile `package.json` 的依赖里就有 |
| 插件声明的 peer 区间 | `>=0.1.5-alpha.1 **<0.2.1-0**` | 插件自己的 `package.json` |
| 为什么挡 | `0.2.1-rc.2` **超出上界**（上界是 `0.2.1-0`） | 见下 |
| 插件 README 的说法 | `0.2.1-0` 上界是**故意的**——「keeps the next unverified line rejected (house rule)」，即 **0.2.1 是「未验证线」，不是「已知坏」** | `README.en.md:71-81` |
| 运行时有没有硬检查 | **没有**。`dist/index.js` 里搜不到 `satisfies` / `SEMVER` / `unsupported` | grep |

**决定性证据**——`dsh --profile web --dump-config` 直接把它跳过了：

```
dsh: skipping profile bundle "billion-context-dsh": Error: Plugin billion-context-dsh@0.2.27
is incompatible with dsh 0.2.1-rc.2: requirements {... ">=0.1.5-alpha.1 <0.2.1-0" ...}.
Running it may cause crashes or data loss.

To accept this risk explicitly, grant the exact-version exemption for
billion-context-dsh@0.2.27 on dsh 0.2.1-rc.2 with `dsh plugin allow-version`
or the plugin manager, then retry the installation or restart dsh.
Exact-version exemption: not active.
```

**所以本来不需要「魔改」**——DSH 自带官方逃生阀（精确版本豁免）。
改 `package.json` 的 peer 区间反而是下策：会被 pnpm 重装覆盖，而且绕过的是同一道闸门。

## 二、做了什么（只动了一处，官方方式）

```bash
node D:/Deepseek/resources/runtime/cli/bin/node_modules/@deepseek-ai/dsh/lib/bin.js \
  plugin --profile web allow-version billion-context-dsh@0.2.27 \
  --dsh-version 0.2.1-rc.2 --accept-risk
```

输出：

```
dsh: allowed billion-context-dsh@0.2.27 for DSH 0.2.1-rc.2
dsh: warning: allowing incompatible plugin versions can break the application or
     corrupt data. Approval applies only to the exact package and DSH versions.
```

**落盘位置**（回滚就是删这一行）：`~/.dsh/profiles/web/compatibility.json`

```json
{
  "billion-context-dsh@0.2.27": [
    "0.2.1-rc.2"
  ]
}
```

## 三、验证（不重启就能验的两层）

**① 配置合成层** —— `dsh --profile web --dump-config`：

- 不再出现 `skipping profile bundle "billion-context-dsh"` ✅
- 合成树里出现 `# == billion-context-dsh` + `- id: compaction-acp` ✅
- 它自带的 patch 生效：根层 `compaction-basic` 被 `disabled: true`（各 preset realm 内仍保留各自的
  `compaction-basic` 兜底——这是插件设计，不是漏改）

**② 模块加载层** —— 直接 `import` 编译产物：

```
导出键: ACP_SETTINGS_NAMESPACE, ACP_SYSTEM_PROMPT, AcpCompactionEngine, PRESETS,
        SETTINGS_KEYS, makeTools, runCompactionTransaction, …（50+ 个）
OK 模块可加载
```

**③ 服务契约层（还没验）** —— 需要真正启动 DSH 才知道 cordis 挂载是否成功。
`--dump-config` 只证明「配置对」，不证明「运行时不炸」。

## 四、生效：需要重启 DSH（**我没有擅自重启**）

⚠ **AC P 引擎在启动时挂载，改配置不重启不生效。**

我没有主动重启，原因写在明处：**重启会杀掉正在执行这次任务的会话本身**，
而如果 cordis 挂载失败（0.2.1 是未验证线），你回来会面对一个**起不来的 DSH**——
这个代价不该由「你睡了一觉」来承担。**配置已就绪，你下次打开 DSH 自动生效。**

### 重启后怎么确认它活了

看**工具列表**里有没有这四件（插件的模型工具）：

| 工具 | 作用 |
|---|---|
| `compress` | 主动压缩一段历史 |
| `decompress` | 还原被压缩的块 |
| `search_context` | 在被压缩掉的内容里检索 |
| `acp_status` | 看当前压缩状态/窗口用量 |

还有 `/acp-prune` 命令、以及 system prompt 里多一段 ACP 指引（`ACP_SYSTEM_PROMPT`）。

**如果重启后 DSH 起不来**（黑屏/报插件激活失败）：

```bash
# 1) 先撤回豁免（最轻）
#    删掉 ~/.dsh/profiles/web/compatibility.json 里那一行，或整文件清空成 {}
# 2) 还不行就用救援 profile 重建
node <cli>/bin.js rescue --from-default-profile web
```

profile 配置本身有多个 `.bak`（`cordis.patch.yml.bak-*`），这次**没有改**
`cordis.patch.yml` / `package.json` 的任何内容——只新增了 `compatibility.json` 一行。
所以回滚面极小。

## 五、风险（如实说）

- 插件 README 说 0.2.0 线改过两种**读侧形状**（tool result 的 call id 移到 message 级、
  host 写 `developer/message` tool-registry 行），引擎读这些。0.2.1 是否再改，**未验证**。
- 已给的官方警告：「may cause crashes or **data loss**」。数据损失指的是**会话记录被压缩后
  丢失原文**（ACP 是「剪枝」，剪掉的块要靠 `decompress`/`search_context` 找回）。
  → **建议**：刚启用的头几天，别在「不能重来的长会话」上单独依赖它；
  真要压缩前先确认 `acp_status` 能查到块、`search_context` 能搜回内容。
- 本项目自己的会话有 `~/.dsh/sessions/` 持久化，压缩不会动那个目录（ACP 只改**上下文投影**）。

---

## 六、这台机器上「还有一层压缩」要知道（别重复造）

`~/.dsh/profiles/web/cordis.patch.yml` 里已经挂了一条 **context-mode**（`jeff-filter` 那套）：

> 「与 billion-context-dsh 的区别：后者管**会话什么时候压缩**，这个管**单次工具输出先别进上下文**。」

两者不冲突、互补：
- **ACP（本次启用）**：会话长了以后，模型驱动地决定压哪段；
- **context-mode**：单次工具输出（日志、大文件）在**进上下文之前**就过滤/索引。

另：`cordis.patch.yml` 里那段注释说「billion 在本机 dsh 0.2.1-rc.2 上超出 peer 区间，
所以这一层现在只能靠 context-mode」——**这条注释已过期**，本次豁免后 ACP 可以上了。
