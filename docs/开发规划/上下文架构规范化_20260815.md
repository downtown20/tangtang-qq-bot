# 上下文架构规范化（2026-08-15）

> 本文件是 CLAUDE.md 的补充技术细节——为什么这么做、每个决策的完整依据与规格。
> 涉及模块：protocols.py / handler.py（群/私组装）/ reply_pipeline.py / self_check.py / onebot/ws_client.py / SnowLuma 1.14.8

## 1. 上下文来源标记化（wuhu-core 原则）

**问题**：LLM 面对短问题（"这条呢？"）时从背景材料取样作答——编出歌单当引用内容。
**根因**：记忆/自忆/情绪/知识等框架注入块与用户原文同构混在 user message 里，模型无法按来源校准。
**方案**（调研 wuhu-core/SillyTavern World Info/AstrBot/Redis context assembly）：

- 框架注入一律 `<背景·标签>...</背景·标签>` 包裹（protocols.bg()，单点净化 `</背景`→全角防注入）
- **用户原文永不包裹、永远是最后一块**——"无标签 = 对方说的"
- 已解析的引用并入用户块（自然语言：「{nickname} 引用的消息是「...」」）——引用是 ta 语境的一部分
- 组装：`protocols.assemble_user_message(backgrounds, user_text)` 纯函数，群/私两条路径共用

**标签清单与组装顺序**（自上而下）：协议（困难轮次）→ 引用（未解析时）→ 窗口 → 关系 → 交叉 → 日记 → 记忆 → 情绪 → 自忆 → 知识库 → 图片 → 文件 → 姿态（群插话）→ **用户原文**。

**有原则例外**：主动插话路径（handler_autonomy._check_private_initiative）不贴标签——那条消息是「生成简报」而非「对话回合」，无用户原文可混淆，取样材料开口是期望行为。例外已写入 protocols.bg docstring。

## 2. 引用解析状态机

`_resolve_quote_prefix(text, raw, nickname) → (prefix, clean_text, status)`
status ∈ {QUOTE_RESOLVED, QUOTE_MISSING, QUOTE_NONE}（protocols.py 常量）。

- resolved：内联 `[引用内容：x]` 或 get_msg 拉取成功 → 自然语言 prefix 并入用户块 + **写回 short_term 历史**（占位符替换为实际内容，后续轮次自洽）
- missing：占位符但 get_msg 失败/空、或指代无锚点（SnowLuma 丢引用）→ 【注意】警告走 bg(引用) + 触发 hard_turn
- none：无引用

**教训（教训表 #19）**：此前用 `"没取到" in prefix` 字符串分流——引用原文里出现「外卖没取到」会误判。状态标志是唯一正解（魔术字符串反模式 #13 的变体）。

## 3. 困难轮次协议（protocols.py）

- CORRECTION_SIGNALS：15 个元对话/纠正专用短语（Codex 复查后删了 5 个宽泛短语——「我要的是草莓蛋糕」类误报代价是糖糖为不存在的错误道歉）
- COMPREHENSION_PROTOCOL（5 步：停→复述→承认跑偏→问不猜→禁止换措辞复读）+ 2 个 show-don't-tell 微示例
- THINKING_PROTOCOL：`<思考>...</思考>` 隐藏段，reply_pipeline.clean() 剥离（含未闭合标签补刀、回退分支同样剥离）
- hard_turn 判定 = 纠正信号 or quote_status == MISSING → 注入协议 + `_get_llm_config(hard_turn=True)` 模型升级（hard_turn_model → seductive 栈兜底；seductive 场景在栈内换模型，端点不动）
- 复读自检（self_check._check_intent_alignment）：仅 hard_turn 轮次，jieba 词重叠 ≥0.5 且双方 >60 字 → 警告（诊断指标，不阻断）
