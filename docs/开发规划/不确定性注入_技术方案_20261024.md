# 不确定性注入 —— 技术方案（待实施）

> 对应 `糖糖的存在方式_战略与设计_20261024.md` 设计二 / 判据 2。
> 状态：**方案已定，未实施**。原因见文末「为什么不在这轮做」。

## 一、要解决什么

现在信任门是**二值**的：`verified/manual/corrected` 注入，其余（legacy/unverified）
**静默丢弃**。后果是 10,063 条活跃记忆在对话里完全不存在。

但真实的人不是这样。人会说「我印象里你提过去医院，是不是我记错了」——
这是**元认知**：知道自己记得的东西有多可靠。系统现在两种极端：
「确定地说」和「完全不提」，缺中间那一档。

## 二、机制已经有了雏形

`search_memories` 工具对 `confidence < 0.6` 的记忆会加 `~` 标记
（`agent/handler.py` 里那段 `tag += "~"`）。也就是说**「用符号表达不确定」
这件事系统已经会做**，只是注入路径（`format_compact_memories`）没接。

所以这不是新发明，是**把已有机制推广一层**——这一点很重要，它让风险从
「造新东西」降到「接一条已有管线」。

## 三、设计

### 3.1 三档

| 档 | 数据 | 注入表现 |
|----|------|----------|
| 确定 | `trusted_levels` | 正常 `💭 内容` |
| 模糊 | `legacy_unverified` / `unverified` / NULL | `💭~ 内容` + 块尾提示 |
| 遗忘 | `retracted` | 不注入（`status` 已排除） |

### 3.2 两路召回（关键：不要让模糊记忆挤掉可信记忆）

**不能**简单把 `trusted_only=False` 打开——那样 legacy 占 58%，BGE 排序后会把
原本可信的记忆挤出前 25 条。正确做法是两路取、后合并：

```
可信路：recall(qq_id, trusted_only=True,  limit=25)   ← 现有逻辑，不动
模糊路：recall(qq_id, untrusted_only=True, limit=5)   ← 新增，独立配额
合并  ：可信在前、模糊在后，总量仍受 max_facts 控制
```

模糊路限 5 条 + `importance >= 6` + `confidence >= 0.7`（排除「0.55 种子」那类
脏数据），把噪声面收窄到可控。

### 3.3 改动点（预估 5 个文件）

| 文件 | 改动 |
|------|------|
| `agent/store.py` | `query_memories(..., untrusted_only=False)`：加一个反选条件（与 `trusted_only` 互斥，同时为真直接抛错） |
| `agent/memory.py` | `recall(..., untrusted_only=False)` 透传；新增 `recall_uncertain()` 薄封装；`format_compact_memories` 按 `trust_level` 打 `~` + 块尾加一行提示 |
| `agent/handler.py` | 私聊注入（`handle_private_message` 的 `mem_candidates_f`）改为两路合并 |
| `config.yaml` / 控制台 | 开关 `memory.uncertain_injection`（默认 `false`）。⚠ 按铁律 #4，改 config 必须同步控制台预设值 |
| `agent/console_api.py` | 剖面页的「可注入」旁边加「模糊」计数（可选，便于观察） |

### 3.4 提示语（决定成败的一段）

块尾必须有一句**行为契约**，否则 LLM 会把 `~` 当装饰：

```
（带 ~ 的是你只模糊记得、没有原话佐证的事。可以提，但要留余地：
「我印象里…」「是不是你说过…」。不确定就不要当成事实说。）
```

这句写进 `protocols.py`（背景块/协议文本的唯一来源），不要在 memory.py 里硬编码。

## 四、验收

1. **闸门测试**：注入文本里，凡是 `trust_level` 不在可信集合的记忆必须带 `~`；
   可信的必须不带（双向断言，防「全都加」和「全都不加」）。
2. **配额测试**：模糊路最多 5 条，且不得挤占可信路的 25 条（构造 30 条可信 +
   30 条模糊，断言结果里可信 25 条全在）。
3. **变异**：
   - M1 去掉 `~` 标记 → 红
   - M2 模糊路不限量 → 红
   - M3 合并顺序反过来（模糊在前）→ 红（防挤占）
4. **观察指标**：私聊里「她主动提到过去的事」的次数（人工计 3 天）；
   以及「把模糊记忆当确定事实说」的误报（抽样看她有没有说「你说过 X」而 X 是
   legacy 记忆）。

## 五、风险与缓解

| 风险 | 缓解 |
|------|------|
| LLM 忽略 `~`，把模糊记忆当事实 | 提示语 + 观察抽样 + 开关可随时关 |
| 模糊记忆挤掉可信记忆 | 两路独立配额（3.2） |
| legacy 里有「糖糖自己的话被错误归属」的脏数据 | `importance≥6` + `confidence≥0.7` 双筛；先只开私聊（一对一，错配影响面小） |
| 群聊也开 → 把某人的模糊记忆说给全群 | **第一版只开私聊**，群聊保持二值门 |

## 六、回滚

纯配置开关（`memory.uncertain_injection: false`）+ 代码里 `if not enabled: return ""`，
关掉即回到当前行为。无需数据回滚。

## 七、为什么不在这轮做

它改的是**每一轮对话的注入内容**——影响面比今天所有批次都大（今天动的是数据，
这个动的是她的「嘴」）。需要：设计定型（已做）+ 代码 + 三向闸门测试 + 变异 +
真实对话观察。仓促合并等于拿线上对话做实验，而这个项目的教训里已经有一条
「框架先行/功能先上，接线没做完」（#6/#14）。

下一轮专门做，留足验证时间。
