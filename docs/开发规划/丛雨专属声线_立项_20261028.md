# 丛雨专属声线（微调）——立项

> 2026-10-28 主人提出：「丛雨的音频也可以根据不同音频学习对吧？如果可以就作为以后的升级项」
> 结论：**可以**。本文记录可行性依据、现有条件、缺口和实施路径。暂不排期。

---

## 一、现状：丛雨是 zero-shot，米雪儿是微调

`agent/voice.py` 的 `MODEL_PROFILES` 只有两套权重：

```python
MODEL_PROFILES = {
    "v4":      {"gpt": ".../s1v3.ckpt",                  "sovits": ".../gsv-v4-pretrained/s2Gv4.pth"},
    "michele": {"gpt": "models/michele/MiXueErV3-e10.ckpt", "sovits": "models/michele/MiXueErV3_e100_s4900.pth"},
}
```

`/角色` 命令（`agent/handler_commands.py:284-307`）的对应关系：

| 角色 | 权重 | 语言 | 参考音 |
|---|---|---|---|
| 丛雨 | `v4` 公开底模 | ja | `speakers/murasame/ref.wav`（927 KB，**单条**） |
| 糖糖本体 | `v4` 公开底模 | zh | `speakers/murasame/ref.wav`（同上） |
| 米雪儿 | `michele` 私有微调 | zh | `""` → 按情绪选 12 个中文 ref |

差别就在这里：

- **米雪儿**：229 MB 的**微调权重**，音色是"训练出来的"，稳定、可多情绪
- **丛雨**：v4 底模 + 一条参考音做 **zero-shot 克隆**——模型当场模仿那 927 KB 的音色。相似度受参考音质量、录音条件、句长影响，长句和情绪切换时不如微调稳

---

## 二、可行性：米雪儿就是同一流程的产物

GPT-SoVITS 的微调是标准能力，米雪儿的 `models/michele/`（`MiXueErV3-e10.ckpt` 148 MB + `MiXueErV3_e100_s4900.pth` 81 MB）就是证据：同一套引擎、同一套目录结构，只是换了一批训练素材。

所以丛雨要升级，**不需要改推理链路**——只要产出 `models/murasame/` 两个文件，然后在 `MODEL_PROFILES` 加一项、`/角色 丛雨` 分支把 `switch_model("murasame", ...)` 换过去即可（改动量约 10 行）。

## 三、现有条件与缺口

### 已有

| 项 | 数量 / 体积 | 位置 |
|---|---|---|
| 丛雨素材音频 | **400 个 wav / 323 MB** | `音频/丛雨/`（`mur001_*.wav`，不在 git 里，本地保留） |
| 推理引擎 | GPT-SoVITS（vendored） | `gpt-sovits/` |
| GPU | RTX 5070（实测语音 100 字 5.4 秒） | 本机 |
| 现成参考 | 米雪儿的微调产物可作为目录结构样板 | `gpt-sovits/models/michele/` |

### 缺口（这是真正的成本所在）

**1. 文本标注（关键阻塞）**

GPT-SoVITS 微调要求「音频 + 逐条转写文本」。现在 400 个 wav **全是裸音频**，没有 `.txt` / `.list`：

```
音频/丛雨/mur001_001_0.wav   667 KB
音频/丛雨/mur001_002_0.wav   350 KB
音频/丛雨/mur001_003_0.wav   962 KB
...（共 400 个，无任何标注文件）
```

两条路：

- **自动转写 + 人工校对**：用已有的 `asr_models`（sherpa-onnx sense-voice，中日英韩粤）批量转写，再逐条校对。400 条校对是**几小时的人工活**，而且丛雨是日语角色——日语 ASR 的准确率决定校对量
- **WebUI 标注工具**：`gpt-sovits/webui.py` 自带「ASR 批量标注 + 人工修」的界面，比命令行顺手

**2. 训练流程没有沉淀成文档**

`tools/`、`docs/` 里搜不到微调脚本或步骤记录——米雪儿那次的经验没有写成可复用的清单。要重做一遍，等于重新摸。

**3. 素材质量未知**

400 条里有多少是「干净无 BGM、无叠音、单句」的？GPT-SoVITS 对素材要求：单声道、无明显底噪、每条 3~10 秒、情绪一致。如果 323 MB 里有一半带 BGM 或多人对话，有效量会缩水。**这一点没测过**，是排期前必须做的第一件事。

---

## 四、实施路径（若排期）

| 阶段 | 内容 | 产出 | 估计 |
|---|---|---|---|
| 0. 素材体检 | 统计时长分布、采样率、有无 BGM（听 20 条抽样 + 脚本量时长） | 有效条数报告 | 1 小时 |
| 1. 标注 | ASR 批量转写 → 人工校对 400 条 | `murasame.list`（音频路径 \| 说话人 \| 语言 \| 文本） | 3~6 小时 |
| 2. 训练 | GPT-SoVITS 微调（SoVITS + GPT 两段） | `models/murasame/*.pth` + `*.ckpt` | GPU 2~4 小时 |
| 3. 接入 | `MODEL_PROFILES` 加 `"murasame"`；`/角色 丛雨` 换成它 | 代码 ~10 行 | 30 分钟 |
| 4. 盲听对比 | 同一句话分别用 zero-shot / 微调生成，本地保存对比 | 主观评分 | 30 分钟 |
| 5. 发布 | `models/murasame/` 进 `准备发布.py` 的 4b 步 | 发布物 +230 MB | 10 分钟 |

**总代价**：一次 6~10 小时的连续投入（大半在标注），GPU 占用 2~4 小时，发布物从 748 MB 涨到约 980 MB。

---

## 五、验收标准

1. 同一段文本，微调版与 zero-shot 版的盲听对比**能分辨出前者更稳**（长句不跑调、情绪切换不崩）
2. `/角色 丛雨` 切换后 `set_gpt_weights` / `set_sovits_weights` 均 200，合成正常
3. 切回糖糖/米雪儿时权重能正确换回（不残留丛雨权重）
4. 缺 `models/murasame/` 时 `/角色 丛雨` 降级为「语音切换失败，角色保持不变」而不是静默出声——现有代码已经是这个行为，回归测试要钉住

---

## 六、风险

| 风险 | 说明 |
|---|---|
| 标注成本被低估 | 400 条日语校对，若 ASR 准确率只有 80%，等于每条都要改 |
| 素材有效量不足 | 若大量带 BGM / 多人，可能只剩 100 条可用，微调效果不如 zero-shot |
| 发布物膨胀 | +230 MB。若将来再加角色，每个 +230 MB——需要考虑「声线包」是否单独发 |
| 与米雪儿的取舍 | 两个微调模型共存时，切换要换两套权重（现有 `switch_model` 已支持，但要测来回切 10 次的稳定性） |

---

## 七、结论

**技术上没有障碍**（米雪儿已经证明这条路通），**成本主要在标注**（400 条日语转写校对），不是模型训练本身。

建议排期前先做第 0 步「素材体检」——如果 400 条里干净单句不足 150 条，这个升级的性价比就要重新算。

在没做的这段时间里，丛雨继续用 zero-shot（`speakers/murasame/ref.wav`），音色可用，只是不够稳。
