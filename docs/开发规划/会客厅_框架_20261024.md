# 会客厅框架（2026-10-24）

> 目标：把桌面端从「一个裸模型试话框」变成**糖糖的驾驶舱**——QQ 里所有对话都能在这里
> 看到，而且看得见「她这句话是怎么想出来的」。
>
> 本文只定框架。内容（更多面板、更多交互）后续再加。

---

## 一、要解决的事

| # | 需求 | 本框架的答案 |
|---|---|---|
| 1 | 旁观模式没必要 | 删掉底部的只读横条 |
| 2 | 输入端要能加我（用户本人） | 每个会话窗口底部有输入框 |
| 3 | 对话写进真实记忆 | 保留——走 `MessageHandler` 生产路径 |
| 4 | 采纳内心独白 | 新增「独白」频道（不是对话） |
| 5 | QQ 聊天镜像到桌面（左侧群聊位置） | 左侧改为**会话源列表**：私聊 / 群聊 / 本地 |
| 6 | 看到糖糖的思维链和工具调用 | 新增 `turn_traces` 表 + 消息下方可展开的「回合痕迹」卡片 |

## 二、数据模型：三个数据源 + 一张新表

好消息是**镜像和回合轨迹的地基已经存在**，不需要从零搬数据。

### 已有（直接读，不改）

| 表 | 内容 | 规模（实测） | 用途 |
|---|---|---|---|
| `chat_log` | 所有入站/出站消息：`qq_id`、`group_id`、`is_bot_reply`、`message`、`timestamp`、`event_key` | 298,619 行 | **消息流正文** |
| `decision_runs` | 每次 LLM 回合：`run_id`、`event_key`、`scope_id`、`model`、`status`、`decision`、`tool_calls_json`、`started_at`/`finished_at` | 2,009 行 | **决策事实 + 耗时** |
| `people` / `group_info` | 昵称、群名、成员数 | — | 会话元信息 |

### 新增 `turn_traces`（本框架唯一新增表）

```sql
CREATE TABLE turn_traces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL UNIQUE,      -- 与 decision_runs 同键（一回合一条）
    event_key TEXT NOT NULL DEFAULT '', -- 回挂 chat_log
    scope_id TEXT NOT NULL DEFAULT '',  -- private:<qq> / group:<gid>
    model TEXT NOT NULL DEFAULT '',
    reasoning_text TEXT NOT NULL DEFAULT '',   -- 思维链原文（截断 8000 字）
    tool_steps_json TEXT NOT NULL DEFAULT '[]', -- [{name,args,result,ms}]
    prompt_chars INTEGER NOT NULL DEFAULT 0,
    duration_ms INTEGER NOT NULL DEFAULT 0,
    recorded_at TEXT NOT NULL
);
```

**为什么不塞进 `decision_runs`**：那张表是**决策事实契约**——frozen dataclass、
`status`/`decision` 的 CHECK 约束、还有接线闸门盯着它。思维链是**观察数据**：
可能几千字、可能含内部策略、要能按天清理。混进审计表会让契约跟着 UI 需求变形。

**三者构成一条链**：`chat_log.message` ← `decision_runs.event_key` ←
`turn_traces.reasoning_text`，也就是「这句回复 ← 这次决策 ← 她当时怎么想的」。

### 捕获点（已实现）

| 位置 | 捕获什么 |
|---|---|
| `handler.py::_call_deepseek` 流式循环 | `reasoning_content` 逐 token 累积（原先只累加字符数） |
| `handler.py` 工具循环 `_execute_tool` 调用处 | 工具名 / 参数 JSON / 结果摘要 / 耗时 |
| `handler.py::_begin_turn_trace()` | 回合开始时重置容器 |
| `handler.py::_persist_turn_trace()` | 回合结束时写库，消费即清，失败只警告 |

**覆盖面**：QQ 群聊/私聊全部 + 会客厅 `say`（都走 `_call_llm_with_skills`）。
自主回合（`turn`，走裸 `_call_llm`）暂不记录，因为那里没有 `DecisionRun`。

## 三、会话模型

### scope 统一

| scope_id | 来源 | 可输吗 | 输入含义 |
|---|---|---|---|
| `private:<qq>` | `chat_log` 私聊镜像 | 待定 | 见「待拍板」 |
| `group:<gid>` | `chat_log` 群聊镜像 | 待定 | 同上 |
| `desktop:<sid>` | `状态/.会客厅.db` | 是 | 你对糖糖说话（走真身，已实现） |
| `monologue` | 独白事件流 | 否 | 只读 |

### 左侧栏结构

```
会客厅
├─ 本地
│   └─ 桌面会话（desktop:*）            ← 现在这个,可多开
├─ 私聊（按最近消息倒序）
│   └─ @忽热忽冷  · 3小时前 · 你最近在忙...
├─ 群聊（按最近消息倒序）
│   └─ 夢中の秘密花圃 2.0 · 9分钟前 · ...
└─ 独白                                  ← 内心独白频道
```

每项显示：名称、最后一条消息预览、相对时间、消息数（或未读数）。

**未读判定**：客户端记住每个 scope 最后看到的 `chat_log.id`，新 id 出现即未读。
（不新增服务端状态，浏览器 localStorage 足够）

## 四、中栏：消息流 + 回合痕迹

```
        ┌─ 09:41   @忽热忽冷
        │   帮我查一下现在几点
        │
        │   现在凌晨两点五十七了，星期六…
        │   ┌─────────────────────────────────┐
        │   │ ▶ 她怎么想的 · 3 步工具 · 20.4s │  ← 默认折叠
        │   └─────────────────────────────────┘
        │     展开后：
        │       🧠 思维链（等宽小字，可滚动）
        │       🔧 get_time({}) → 现在… [0ms]
        │       🔧 search_memories({...}) → … [22ms]
        │       📊 reply · deepseek-v4.1-flash · 376 字思考
```

规则：
- 入站消息靠左，糖糖回复靠右（或统一靠左 + 图标区分，视觉上更像 IM）
- **痕迹卡片挂在糖糖那条回复下面**，默认折叠，点开才看
- `decision=skip` 的回合不产生消息，但要在流里留一行淡色注记（「这一轮她决定不说话」）——这是真实发生的事，不该消失
- `status=failed` 显示错误码 + 那一轮的思维链（如果抓到了）——失败往往最有信息量

### 输入框

- `desktop:` 会话：发送 → `POST /api/console/say` → 真身回复
- 镜像会话：行为待定（见「待拍板」）
- 统一支持 Enter 发送 / Shift+Enter 换行

## 五、内心独白

一个**不是对话**的频道。数据来源（按可靠度排序）：

| 来源 | 内容 | 现状 |
|---|---|---|
| 驱动力变化 | 「承诺压力 62%→78%」「回复后释放 -12%」 | 日志里有，需结构化 |
| 反思整合 | 每日反省产出 | 日志里有 |
| 记忆提取 | 「从最近 6 条提取到 2 条记忆」 | 日志里有 |
| 自主循环决策 | 「想找人说话，但冷场太多次 → 放弃」 | 日志里有 |
| 自发生成 | 让她定期说一句内心话 | 需新增（消耗 token） |

**建议做法**：新增 `monologue_events` 表 + 在关键点写一行（驱动力阈值穿越、反思完成、
自主决策放弃/发起、记忆提取）。比解析日志可靠——解析日志是「事后猜」，
写入事件是「当场记」。

第一版只做**已有信号的搬运**（驱动力/反思/提取/自主决策），不做 LLM 自发生成。

## 六、API 设计（bridge 转发到 bot 进程内）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/console/sources` | 会话源列表（scope / 名称 / 最后消息 / 时间 / 未读基数） |
| GET | `/api/console/feed` | 某 scope 的消息流（`scope_id` + `after_id` + `limit`），支持增量拉取 |
| GET | `/api/console/trace` | 某条消息的回合痕迹（`event_key` 或 `run_id`） |
| GET | `/api/console/monologue` | 独白事件（`after_id` + `limit`） |
| POST | `/api/console/send` | 统一发送入口（`scope_id` + `text`），按 scope 类型路由 |
| GET | `/api/console/status` | 已有 |
| GET | `/api/console/snapshot` | 已有（右栏状态面板） |

**实时性**：先做**轮询**（3 秒一次 `/feed?after_id=`），够用且无新依赖。
后续若需要更顺，再上 SSE（`/api/logs` 已有 SSE 基础设施可抄）。

## 八、待拍板

### 1. 镜像会话里的输入，语义是什么？

- **A. 真发出去**：在「@忽热忽冷」窗口里输入 → 以主人身份真的发到 QQ 私聊
- **B. 只进她脑子**：只在桌面端显示 + 她会看到（上下文注入），但不发 QQ
- **C. 镜像只读**：只有 `desktop:` 会话能输入

风险提示：A 最自然（所见即所发），但一个误按就会真的给群里发消息；
B 最安全但会让你困惑「我说了话她怎么没回」；C 最保守但违背「输入端加上我」。

### 2. 思维链要不要默认展开？

- 默认折叠（点开看）——界面干净，符合 DSH 风格
- 默认展开——信息密度高，但长回复会很难看

建议折叠。

### 3. 独白第一版的范围

建议只搬运已有信号（驱动力穿越阈值 / 反思完成 / 记忆提取 / 自主决策放弃或发起），
不新增 LLM 调用。
