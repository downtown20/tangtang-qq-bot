# 决策质量机制

> 2026-10-24 立。触发：一天之内我（AI）错了三处预测，三处都错在同一个地方——
> **用一个听起来对的代理指标，代替了回到代码/数据里核对真实口径**。
> 本文是「怎么让判断更准」的机制，不是「怎么更努力」的鸡汤。
> 它同时是给主人用的：你不需要读代码，但你可以用这套机制检查我的判断。

---

## 零、为什么需要机制，而不是「更小心」

两个结构事实：

1. **我的上下文每次会话都会重置。** 我今天知道的、犯过的错、量过的口径，
   下一次会话不一定还在。所以「提升决策质量」的第一条不是让我更聪明，
   是**把口径、判据、既往错误写进文件**——文件是我的外部记忆，
   也是你的可审计对象。
2. **人和模型对自己判断的置信度都不准**（系统性地过度自信）。唯一有效的
   解药是**可证伪的预测 + 事后回填**：写下「我预测 X = 数字 N，在下周之前」，
   到期核对。误差会自己说话，不需要谁来自责。

## 一、机制 A：预测台账（`docs/决策/预测台账.md`）

**规则**：任何「会影响决策的判断」都要先落一条记录，再执行；执行完回填。

| 字段 | 说明 |
|------|------|
| 日期 | |
| 预测 | 必须**可证伪**：给出数字、时间、判据。禁止「可能会好一些」 |
| 依据 | 数据/代码出处（文件:行号 或 SQL） |
| 置信度 | 高 / 中 / 低 + 一句话理由 |
| 实际 | 执行后回填 |
| 偏差 | 实际 − 预测 |
| 教训 | 错的那一次，错在哪一步 |

**只有可证伪的预测才有价值。** 「我觉得语义回挂会有帮助」是废话；
「语义回挂全量（6,129 条）会落地 2,000±800 条」才是预测。

## 二、机制 B：决策前四问

四问对应四种已经发生过的错误形态，**每次动重要东西前默念一遍**：

1. **这个数字的口径是什么？**
   - 查 `口径字典`，没有就先补一条再判断。
   - 今天的错：把「`source_group_id` 为空」当「私聊记忆」——名字像，定义不是。

2. **这个判据与另一处判据同源吗？**
   - 若系统里已有同一语义的判断（信任门、画像谱系、输入过滤），
     **必须复用同一个常量/函数**，不允许「看起来一样」的第二份。
   - 今天的错：画像重生候选「可信≥5 条」，而合成入口还要排除 confidence<0.75。

3. **我验证的是「关系」还是「结果」？**
   - 「原话包含记忆原文」是关系（可证）；「这条记忆是真的」是结果（不可证）。
   - 「测试绿」是关系（代码跑通了）；「路径被覆盖」是结果（要被删掉才知）。
   - 这一问防的是：把弱证据当强结论。

4. **如果这个预测错了，最可能错在哪？**
   - 强制写一句否定预演。写不出，说明还没想清楚，不许开工。

## 三、机制 C：决策分级

不是所有事都要主人拍板，但也不能都由我定。三档：

| 级别 | 范围 | 谁决定 | 必须做的 |
|------|------|--------|----------|
| **L1 自主** | 工具脚本、测试、文档、只读分析、<100 条的回填 | 我 | 事后汇报 + 留痕 |
| **L2 需复核** | 改生产数据 >100 条、改召回/信任门/画像合成、动表结构 | 我先做小规模 + 抽样 + 双闸门，再报 | 备份 + 批次号 + 回滚演练 |
| **L3 需主人拍板** | 人格表现（她怎么说话）、主动性（她要不要追问）、花钱量级、不可逆操作 | 主人 | 我说清代价与替代方案 |

**为什么要有 L2**：今天的每个批次都是 L2（411 / 1,627 / 24 条记忆改可信状态）。
做法是「小批 → 抽样 → 全量 → 可回滚」，这套已经跑通四次，0 误判。

## 四、机制 D：口径字典（`docs/决策/口径字典.md`)

同一个数字，全项目只有一个定义 + 一处 SQL。今天被坑的全是这类：
「可注入」到底是 active 口径还是全量口径？「有证据」数的是
`memories.evidence_ids` 还是 `memory_evidence` 行数？——差 8 条就能让人误判。

**规则**：任何汇报里出现的数字，必须能在字典里找到定义；找不到就先补。

## 五、机制 E：反方（红队）

重要决策（L2/L3）执行前，强制找一次反方意见。两种方式：

1. **轻量**（默认）：在决策记录里写「反方意见」一栏，至少一条、必须具体。
   写不出反方 = 没有真正评估过风险。
2. **重量**（当决定不可逆或代价大时）：派一个独立 subagent，只给它结论和证据，
   任务是**推翻它**。独立上下文比我自己想「我可能错在哪」有效——因为我带着
   自己的推理，只会找支持自己的理由。

## 六、机制 F：「她的一周」报告（给主人的掌控感）

每周一份，三栏，不写技术指标：

1. **这周她记住了什么新的**（按人分组，3-5 条）
2. **这周她忘了 / 被推翻什么**
3. **和谁的关系变了**（亲密度、未闭合事件、主线状态）

目的有两个：让主人在 5 分钟内判断「她有没有变成另一个人」；
同时它是最诚实的效果校验——比任何覆盖率数字都直接。

## 七、这套机制怎么自我检查

机制本身也会腐烂（教训 #35：文档与代码分家）。所以：

- 预测台账有「未回填」的条目超过 7 天 → 视为决策质量失守，当周必须清零；
- 口径字典里的 SQL 与实际代码不一致 → 以代码为准并修字典（字典是索引，不是真值）；
- 每 10 次 L2 决策做一次复盘：其中几次因为「四问」被拦下？低于 1 次说明四问
  流于形式。
