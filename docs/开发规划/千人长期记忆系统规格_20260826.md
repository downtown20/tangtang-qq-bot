# 千人长期记忆系统规格（2026-08-26）

**状态**：核心实现完成，功能门禁 PASS；持续生产容量认证待办。  
**技术决策人/实现人**：Codex。  
**共同顶层设计/只读复核**：Claude Code 长期会话“小糖糖”。

> 2026-08-26 实施结果：1000 用户合成隔离/召回/队列验收与真实子进程强杀恢复通过；全量 695 项测试通过。尚未完成带真实/模拟 LLM 延迟、并发生产者和稳定到达率的 soak test，因此不能把 SQLite 空结果提交吞吐解释为端到端生产吞吐。详见 `tasks/记忆系统重构_plan.md`。

## 1. 目标

为小糖糖建立可支撑约 1000 个不同 QQ 用户的长期记忆能力：

- 用户、群聊和私聊严格隔离，系统层不把第三人的原始记录放进当前用户上下文；
- 原始聊天记录优先于事实、画像、摘要和自忆，任何派生记忆都能回溯到来源；
- 重要且可信的记忆可永久保留、被纠正后保留审计历史，并能随时检索；
- 事实时间与系统获知时间分离，不能把回填/提取时间冒充事件发生时间；
- 崩溃、断电、重启和任务重试不会产生重复记忆、游标倒退或证据丢失；
- 自动召回只提供足够相关、足够可信的记忆；没有证据或相关性不足时返回空；
- 在持续群/私聊流量下，提取队列有界、可观测并最终收敛。

“零幻觉”的工程定义：**系统不得把无来源或冲突的派生记忆标成事实提供给 LLM**。LLM 本身仍是生成模型，因此所有需要核验的回答必须能回到原始聊天证据；系统提供真值边界，不用关键词替 LLM 决定是否对话。

## 2. 已确认假设

1. “千人”指约 1000 个不同 QQ 用户的长期状态，不假设 1000 路同时写入；并发压测另设上限。
2. 继续使用 SQLite/WAL、现有 BGE 与 reranker；没有证据表明需要先更换引擎。
3. `chat_log` 是对话真值源。图片识别等富化允许形成受审计的修订，但派生事实不得反向覆盖原始证据。
4. “永久”是保留策略，不是可信度。永久记忆也必须有证据或明确人工/纠正来源。
5. 永久记忆允许本人或主人纠正/撤回；物理记录保留审计，业务读路径只返回当前有效版本。
6. 无法确定来源的存量记忆一律进入 `legacy_unverified`，禁止用相似度自动认领原文。
7. 现有外部调用接口渐进兼容；行为默认变安全，迁移期间不维护两套长期实现。

## 3. 不可妥协的系统不变量

### 3.1 隔离

- 自动用户记忆背景只能读取 `subject_qq=current_user` 的可信记忆。
- bot 自忆必须同时绑定 `target_qq` 与原始 bot 消息。
- 普通私聊用户只能读取自己的原始聊天；主人可全局核验。
- 群聊缺省查询对象在执行层固定为当前说话人，不能由空字符串或 `*` 绕过。
- 昵称必须先解析成确定 QQ，再执行同一授权；解析失败即拒绝。

### 3.2 真值

```text
L0 原始聊天/修订审计
  → L1 证据关联
    → L2 原子事实/长期记忆
      → L3 画像、事实簇摘要、Episode
```

- 上层只能引用下层；无 L1 证据的自动提取只能是 legacy 线索。
- `manual` 和 `corrected` 是明确人工真值入口，但仍记录操作者与时间。
- 合并、压缩、纠正创建新版本并 union 来源，旧版本标记 superseded/retracted，不物理破坏谱系。

### 3.3 时间

- `event_time`：证据中事件发生/表达的时间；无证据时为空。
- `ingested_at`：系统写入派生记忆的时间。
- `valid_from/valid_to`：事实有效区间。
- 展示“某天/上次/昨天”时必须来自原始消息或可信 `event_time`，不得使用 `ingested_at` 代替。

### 3.4 永久与遗忘

- `retention=permanent`：不参与自动过期和低价值清理，但仍受 status、trust 和相关性控制。
- `durable/normal/transient`：按事实稳定性和使用情况治理。
- 永久不等于常驻 prompt；显式检索必须全量可达，自动背景仍只取相关的小集合。

## 4. 领域模型

### 4.1 记忆信任层

| trust_level | 含义 | 自动注入 | 画像/Episode | 工具检索 |
|---|---|---:|---:|---|
| `verified` | 证据已校验且属于目标用户/作用域 | 是 | 是 | 是 |
| `manual` | 主人或用户明确要求保存 | 是 | 是 | 是 |
| `corrected` | 用户/主人明确纠正后的当前事实 | 是，优先 | 是 | 是 |
| `legacy_unverified` | 无法证明来源的存量/兼容写入 | 否 | 否 | 仅作为待核验线索 |

信任与 `importance`、`retention` 正交；高重要度不能提升信任。

### 4.2 memories 增量字段

- `trust_level TEXT DEFAULT 'legacy_unverified'`
- `retention TEXT DEFAULT 'normal'`
- `event_time TEXT DEFAULT ''`
- `ingested_at TEXT DEFAULT ''`
- `valid_from TEXT DEFAULT ''`
- `valid_to TEXT DEFAULT ''`
- `superseded_by INTEGER`
- `idempotency_key TEXT DEFAULT ''`

保留现有 `qq_id/status/origin/target_qq/source_group_id/evidence_ids` 兼容字段。

### 4.3 证据关联

`memory_evidence(memory_id, chat_id, relation, created_at)`，唯一键 `(memory_id, chat_id, relation)`；外键级联仅用于删除未发布的新写入，业务纠错不物理删除记忆。

防重不能只依赖证据关联；`memories.idempotency_key` 对同一提取任务中的规范化事实唯一。推荐键由 `job_id + subject_qq + normalized(type,value) + sorted(evidence_ids)` 确定生成。

### 4.4 事务提取任务

`extraction_jobs` 至少包含：

- `id/job_key/qq_id/range_start/range_end/direction`
- `status=pending|leased|ready|done|dead`
- `lease_until/attempts/result_json/error/created_at/updated_at`

统一前向与历史积压，不再长期维护双游标。任务范围唯一；LLM 在事务外运行，结果先持久化为 `ready`，随后在一个 SQLite 事务中幂等写入记忆、证据并确认 `done`。崩溃后：

- `leased` 超时可回收；
- `ready` 直接重放持久化结果，不再次调用 LLM；
- 写入事务失败整体回滚；
- `done` 永不再次处理。

## 5. 授权接口

建立唯一执行层策略接口，输入是工具名、参数、会话 scope、当前调用者和主人 QQ，输出确定的目标与资源级别：

```python
@dataclass(frozen=True)
class MemoryAccess:
    allowed: bool
    subject_qq: str
    resource: str       # raw_history | trusted_memory | relationship | group_digest
    reason: str = ""
```

资源策略：

- `raw_history`：本人或主人；`search_chat_history` 归此类。
- `trusted_memory`：本人或主人返回全量；普通用户查询第三人只返回认识级信息，不返回原始内容。
- `relationship`：昵称与 QQ 走同一对象解析和第三人策略。
- `group_digest`：只能查询当前群的公开摘要；不能借此读取私聊或其他群。
- 全局 `*`：仅主人。

LLM 决定调用哪个工具，系统策略只负责安全与作用域，不参与回复意愿判断。

## 6. 读写接口兼容策略

### 写入

- `Store.insert_memory` 新参数全部可选，兼容旧调用；缺少可信来源时安全地写为 legacy。
- 新自动提取必须经统一证据校验后写 `verified`。
- manual/corrected 只能走有授权上下文的 MemorySystem 方法，不能依靠任意调用方伪造 `origin`。
- `evidence_ids` 与关联表在迁移期双写；读取以关联表为准、字符串为兼容回退。

### 读取

- `Store.query_memories` 保持诊断能力，增加显式 trust/status/retention 过滤。
- `MemorySystem.recall` 增加 `trusted_only`；自动背景、画像、Episode 强制开启。
- legacy 工具输出必须标注“待核验”，并提示查原始聊天。
- 所有检索先限定 `subject_qq/scope`，再计算相关性；禁止全局向量结果后置过滤。

## 7. 检索架构

1. 作用域与 trust 过滤。
2. 向量、jieba/关键词、事实簇实体三通道召回。
3. RRF 或等价稳定融合。
4. reranker 精排。
5. 绝对相关性阈值；低于阈值返回空。
6. importance、retention、confidence、时间只参与可信候选的业务终排。

取消 importance top-200 对语义空间的预截断。阈值必须先用中文群私聊黄金集与负例集校准；项目现有 0.3/0.4/0.7 只能作为对照起点，不能直接成为永久常量。

## 8. 实施顺序

### P0-A：统一授权入口

先写会失败的权限矩阵测试，再实现统一对象解析与授权。关闭私聊第三人原始记录、昵称关系绕过和群工具缺省对象误拒绝。

### P0-B：信任层与存量隔离

幂等增加字段/证据表；确定性迁移已有 `evidence_ids`；其他存量标 legacy。自动背景、画像、Episode、强化只读 trusted。

### P0-C：dirty 与来源闭环

所有画像消费者只走 `active_notes()`；合并/去重先保证 evidence union，不再让可信记忆降级。

### P1：事务化单队列与正确时间

建立 jobs，镜像观察后导入 JSON 游标并退役双游标；新增记忆使用 event_time；从可信事实重建 Episode。

### P2：全量混合检索

先建黄金集，再消除 top-200 盲区、加入拒绝阈值和最终索引；修通群私聊显式核验工具。

### P3：千人持续流量验收

1000 用户 × 群/私 × 记忆类型 × 权限角色合成验证；故障注入、恢复、队列稳定、检索质量和延迟同时达标。

## 9. 测试策略

- 小型单元测试：对象解析、授权矩阵、trust/retention 状态机、阈值、时间选择。
- 中型 SQLite 集成测试：DDL 幂等、证据外键、迁移、任务租约、ready 重放、事务回滚。
- 端到端测试：群/私聊工具 schema → 授权 → Store → LLM 可见结果。
- 故障注入：写记忆前后、确认任务前后、截断旧 JSON、进程强杀、重复迁移。
- 规模验证：1000 用户合成库，记录队列深度、最老等待、召回正负例、P50/P95/max。

每个行为修改遵循 RED→GREEN→REFACTOR；测试断言业务结果，不只检查源码字符串。

## 11. 代码风格与边界

- Store 是 SQLite 唯一访问层；上层禁止新增裸连接。
- 中文注释说明“为什么”和事故契约，不重复代码表面。
- 新接口优先 dataclass/枚举和结构化结果，错误语义 fail-closed 且一致。
- 不增加外部依赖；不换引擎；不使用关键词替 LLM 决定行为。
- 不物理清理生产存量，除非有可恢复快照、dry-run 和单独授权。
- 不同时大改 `handler.py/store.py/memory.py`；按可独立验证的薄切片推进。
- 角色卡不承载记忆规则；行为契约进入协议/代码边界。

## 12. 完成标准

- 普通用户跨用户原始记录泄漏为 0；群/私聊合法本人核验均可执行。
- 自动注入、画像、Episode 与强化中的 legacy 数量为 0。
- 每条 verified 自动记忆有有效证据；证据用户、群和 bot/user 身份校验通过。
- 永久可信记忆不被清理且显式检索全量可达；纠正后只返回当前版本。
- 事实时间来自证据；无证据不声称日期。
- 强杀/重启/重试后无重复、无进度倒退、无来源丢失。
- 持续目标流量下 extraction queue 不发散，健康检查展示全量分布。
- top-200 盲区为 0；零相关查询返回空；黄金集达到冻结后的召回/拒答门槛。
- 全量 pytest、pyflakes、体检和千人端到端验收通过。
