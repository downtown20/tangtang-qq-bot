# 唱歌说话融合——实施与状态

> 合并自《唱歌说话融合规划与可行性评估》《唱歌说话自然融合方案》
> 2026-08-14 整理 | 含实施现状对照表 | 历史见文末

---

## 一、目标回顾

糖糖在对话中自然哼唱——不是点歌台模式，是唱歌作为表达方式融入聊天。

- **当前状态**：群友说"唱首歌" → LLM 调 `sing` tool → 放整首歌。唱歌和说话是两个独立模式。
- **目标状态**：群友说"今天下雨了" → LLM 联想到《晴天》→ 引用两句歌词 → 系统放 2 句音频 → 继续说下一句话。

---

## 二、核心洞察（两个矛盾）

**主要矛盾：LLM 不知道歌词。**

LLM 知道曲库里有歌名（「会唱的歌：晴天、稻香、小幸运...」），但不知道每首歌的歌词内容。当群友说「今天下雨了」时，LLM 无法联想到「晴天里有一句『消失的下雨天，我好想再淋一遍』」——因为 LLM 根本不知道《晴天》里有这句歌词。

**次要矛盾：没有段落级音频。**

代码架构支持 `[SING:副歌]` 播放 `songs/audio/晴天/副歌.wav`——但文件不存在。audio 下全是整首歌 WAV，唱两句 = 放整首。目前最常用的降级路径是 TTS 朗读歌词——但朗读不是唱。

**两个矛盾同时解决 → 唱歌自然融入对话。**

### 目标效果示例

**现在**（点歌机模式）：
```
群友: "唱首歌"
糖糖: [调 sing 工具] [返回"好的，准备唱《晴天》"]
糖糖: （文字）为你翘课的那一天...
系统: [放整首歌音频]
```

**目标**（自然哼唱）：
```
群友: "今天下雨了好烦"
糖糖: "确实呢...不过下雨天也有它的好～（轻轻哼）『消失的下雨天，我好想再淋一遍』——哈哈，周杰伦写的这句我每次下雨都会想起来 ☔️"
系统: [放 2 句音频片段，群友听到糖糖真的唱了这两句]
```

关键是：**不是群友要求唱歌 → 糖糖唱歌。是歌词恰好能表达她此刻想说的 → 她自然而然地唱出来。**

## 三、技术方案（原设计，2026-07-31 / 08-02）

### Phase 1：让 LLM 知道歌词（~80 行）

#### 1.1 song_list 升级为 song_lyrics_snippets

每首歌提供标题 + 每段的首句/精选句（1-2 行），共约 1500-2000 字：

```
## 你的曲库（你可以在对话中自然哼唱）
晴天（周杰伦）
  主歌1: 故事的小黄花 从出生那年就飘着 / 童年的荡秋千 随记忆一直晃到现在
  副歌: 为你翘课的那一天 花落的那一天 / 刮风这天 我试过握着你手
  主歌2: 但偏偏 风渐渐 把距离吹得好远
稻香（周杰伦）
  主歌1: 对这个世界如果你有太多的抱怨 跌倒了就不敢继续往前走
  副歌: 还记得你说家是唯一的城堡 随着稻香河流继续奔跑
...
```

LLM 看到这些就能在相关话题中自然地联想到对应的歌词。

#### 1.2 系统提示词新增"自然哼唱"指导（原文）

```
## 关于唱歌
你是会唱歌的。不是只有被要求时才唱——当你想到一句歌词恰好能表达此刻的心情时，
自然地唱出来。像真人在 KTV 里突然哼起一句那样——不是表演，是表达。

两种情况：
- "唱首歌" → 用 [SING:歌名,副歌] 正式唱
- 自然引用 → 在回复里提到歌词，同时用 [SING:歌名,段落] 让群友真的听到你唱

唱完后继续正常说话，不用切换模式。
```

#### 1.3 sing 工具升级（schema 草案）

```json
{
    "name": "sing",
    "description": "唱歌——可以是正式唱一整段，也可以随口哼两句。歌词和旋律都是你真正的歌声。",
    "parameters": {
        "song": {"type": "string", "description": "歌名"},
        "section": {"type": "string", "description": "段落名，如'副歌'、'主歌1'。不填则选最合适的"},
        "style": {"type": "string", "description": "唱歌风格：'自然哼唱'、'正式表演'、'随口唱两句'。默认'自然哼唱'"}
    }
}
```

Tool 返回值也改进——不只返回"好的，准备唱"，而是返回歌词片段供 LLM 在回复中引用：

```
→ sing("晴天", "副歌", "随口唱两句")
← {"status": "ok", "title": "晴天", "section": "副歌",
   "lyrics": "为你翘课的那一天...刮风这天 我试过握着你手...",
   "audio_available": true,
   "hint": "在回复中自然地引用歌词，末尾加 [SING:晴天,副歌] 触发播放"}
```

### Phase 2：段落级音频（切分已有翻唱干声）

用已有翻唱干声（`songs/covers/htdemucs/`）切段落音频，输出到 `songs/audio/歌名/段落名.wav`：

- `songs.py` 的 `get_section_audio()` 已能读这个路径——无需改代码
- `_send_sending_reply` 已能解析 `[SING:段落]` 并调 `_send_song_section()`——无需改代码
- 音频落盘后立即生效；不实时合成，预生成

### Phase 3：说话和唱歌的连贯回复（~50 行）

#### 3.1 回复标记升级

- 现状：`[SING:副歌]` 只有段落名，系统从 `_pending_sing` 取歌名
- 问题：LLM 想在一段回复中先唱《晴天》两句，再唱《稻香》两句——`_pending_sing` 只能存一首歌
- 改为：`[SING:歌名,段落]` 精确指定歌名（向后兼容旧格式 `[SING:段落]`）

#### 3.2 回复流示例

```
LLM 生成:
"下雨天也有它的好呀～我记得有首歌就是这么唱的——（哼）『消失的下雨天，我好想再淋一遍』[SING:晴天,副歌前两句]——周杰伦写的这句我每次下雨都会想起来 ☔️"

系统处理:
1. 发送文字: "下雨天也有它的好呀～..."
2. 解析 [SING:晴天,副歌前两句] → 查 songs/audio/晴天/副歌前两句.wav → 没有 → 降级处理 → 发送音频
3. 群友看到糖糖提到了歌词 + 听到了歌声
```

## 四、可行性评估与决策（2026-08-02）

### 技术可行性：高 ✅

所有改动都在现有代码路径上。没有新依赖、没有新模块。本质上是一次 prompt engineering + tool design 优化。

### 质量标准

| 维度 | 评估 |
|------|------|
| LLM 能否在对话中引用歌词 | ✅ 歌词注入后自然能做到 |
| 音频能否播放片段 | ✅ 用已有翻唱干声切段落 |
| 唱歌语音质量 | ⚠️ 取决于用的 RVC 模型 |
| 用户体验 | ✅ 从"点歌机"到"自然哼唱"，体验质变 |

### 决策结论：值得做

改动小（~150 行）、风险可控、解决真正的体验问题。最坏情况是唱歌音色不够完美，但 LLM 能自然引用歌词、系统能放片段——这个交互框架本身已经有价值。RVC 模型随时可以换。

---

## 五、风险与降级

| 风险 | 概率 | 影响 | 降级策略 |
|------|:--:|------|------|
| 歌词注入 token 太多 | 中 | LLM 响应变慢 | 按相关性筛选注入 5-8 首；只在群聊中注入，私聊按话题匹配注入 3-5 首 |
| LLM 过度使用唱歌 | 低 | 每条消息都唱 | 提示词加频率约束：「唱歌是调味品，不是主菜」 |
| 段落音频生成慢 | 低 | — | 预生成、后台批量跑，不实时合成 |
| RVC 唱歌音色不满意 | 中 | 效果打折但不影响功能 | 先跑通，后换模型 |

---

## 六、不做的事

- **不做实时合成**：段落音频预生成，不在对话中实时合成
- **不做乐谱编辑**：不引入乐谱文件编辑——太复杂，当前不需要
- **不新增模型/依赖**：RVC 已在项目中，不引入新引擎
- **不改变唱歌的基础架构**：`sing` tool → `turn_actions["sing"]` → `[SING:]` → `_send_singing_reply` 的链路不变，只增强

## 八、历史：唱歌系统进度（2026-07-02）

> 来自《唱歌系统进度_20260702.md》，数字已过时：**21 首 txt / 18 首 WAV → 现 22 首 txt / 40 首 WAV**。

当时的架构链图（最终态设计，链路本身仍有效）：

```
用户点歌 → handler.py 检测
  → SongLibrary 搜索曲库 + 段落
  → LLM 选段 + 回复 [SING:段落名]
  → handler 解析标记
  → 发送 songs/audio/歌名/段落名.wav
  → 无音频则 TTS 降级
```

当时已完成：歌词分段系统（段落标记 `[主歌1]` `[副歌]` `[主歌2]` `[尾声]` + `agent/songs.py` 段落解析）、唱歌控制器（`[SING:段落名]` 检测 + 分段发送 + 三条路径）、DiffSinger 环境（MiniEngine + 莲华 ONNX 声库，音质一般）、控制台唱歌面板。

旧系统共存：RVC 生成 WAV 与 SongLibrary 向后兼容（当时的 18 首 → 现 40 首整曲 WAV）。
