# 开源架构参考摘要（2026-08-28）

本次调研只提取可迁移的架构原则，不把第三方项目当作糖糖的现成实现。

| 项目 | 可借鉴 | 不直接照搬 |
|---|---|---|
| Nekro Agent | 工具语义分层、系统事件触发 Agent、历史漫游先定位再取原文 | 插件市场、部署体系、其媒体适配缺口 |
| Mem0 | 用户/会话/代理作用域、实体关联、增量记忆与混合检索 | 无证据事实必须继续受糖糖的 verified 闸门约束 |
| Letta | core/recall/archival 分层、持久 agent state | 摘要不能替代原始消息；不引入第二个决策脑 |
| Graphiti/Zep | Episode、事件时间、关系随时间演化 | 当前 SQLite 规模先不引入重型图数据库 |
| LangGraph | checkpoint、interrupt、恢复后继续执行 | 不把工作流图用来替代糖糖的单脑决策 |
| Temporal/Celery | durable execution、idempotency、late ack、重试/死信 | 不为当前规模贸然引入外部 broker |
| OpenTelemetry | correlation id、固定低基数指标、p95/p99、症状型告警 | 当前先用本地脱敏观测器，后续再接 OTLP |

## 已确认的架构结论

1. 原始事件、派生记忆、LLM view 和发送结果必须是不同数据层。
2. 任何可产生副作用的步骤都必须有幂等键、尝试次数、确认状态和可重放边界。
3. 历史检索必须返回原文来源和时间；摘要只能是导航，不是证据。
4. 后台任务可以触发 Agent，但不能跳过持久化事件和 ActionReceipt。
5. 多用户持续流量的核心指标是 oldest age、service rate、失败率、重复率和跨作用域泄漏，而不是平均耗时。
