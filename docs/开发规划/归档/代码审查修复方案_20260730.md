### CRIT-4: `memory.py` 变量名冲突——内层循环覆盖外层索引

- **文件**: `agent/memory.py:1342-1344`
- **确认**:
  ```python
  for i, m1 in enumerate(all_mems):       # 外层 i = 索引
      for m2 in all_mems[i + 1:]:
          ...
          for wlen in range(2, min(shorter, 8) + 1):
              for i in range(len(m1.value) - wlen + 1):  # 内层 i = 字符位置
                  if m1.value[i:i+wlen] in m2.value:
  ```
  内层循环变量 `i` 覆盖了外层 `enumerate` 的索引 `i`。如果内层循环后还需要使用外层 `i`（当前代码在 break 后不需要），暂无实际影响。但 break 逻辑 `if len(similar_pairs) >= 5: break` 只跳出最内层循环，外层继续——这是另一个小 bug。
- **影响**: 当前代码由于 break 位置，内层覆盖后外层不再使用 `i`，**暂无运行时错误**。但代码极脆弱——任何人修改 break 逻辑都可能引入隐蔽 bug。
- **修复**: 内层循环变量改名为 `pos` 或 `j`。外层 break 改为跳出两层循环（用 flag 或抽出函数）。
- **风险**: 低。纯重命名。

### CRIT-5: `drives.py` alpha 值每次 tick 被永久覆盖

- **文件**: `agent/drives.py:163, 167`
- **确认**:
  ```python
  for name, drive in self.drives.items():
      if name == "avoid":
          mod = energy_mod.get(energy, 1.0)
          drive.alpha = 0.005 * mod      # ← 永久覆盖！
      elif name == "social":
          mod = 2.0 - energy_mod.get(energy, 1.0)
          drive.alpha = 0.015 * mod      # ← 永久覆盖！
  ```
  构造函数中 `alpha` 是初始值（如 `social.alpha=0.015`），但 `tick()` 每次都用 `0.015 * mod` 覆盖它。问题：如果 mod 因为精力浮动而变化（如 `high→low→high`），`alpha` 会来回变化——但这是**永久修改**，不是临时调整。下次 tick 时基础值已经变了（因为上次 tick 覆盖了）。
- **影响**: `social` 和 `avoid` 的 alpha 值会随着精力不断漂移，而不是在基础值附近波动。其他 4 种驱动的 alpha 保持不变。
- **修复**: 不在 tick 中永久修改 `drive.alpha`。改为 `tick()` 接受可选的 `energy_mod` 参数，用局部变量计算有效 alpha：`effective_alpha = drive.alpha * mod`。
- **风险**: 低。逻辑修正，不改变数据流。

### CRIT-6: `reflection.py` 用子串匹配判断 LLM 输出

- **文件**: `agent/reflection.py:376-378`
- **确认**:
  ```python
  if "更近" in change or "亲密" in change or "信任" in change:
      self._self_state.update_relationship(qq_id, closeness_delta=0.03, trust_delta=0.02)
  elif "疏远" in change or "冷" in change or "距离" in change:
      self._self_state.update_relationship(qq_id, closeness_delta=-0.02)
  ```
  这是 CLAUDE.md 错误七（调参数而不是换方法）和错误九（关键词替 LLM 做决策）的精确再现。LLM 说"关系变得更亲近了"→ 不匹配"更近"（多了"得"和"了"）。LLM 说"有些疏远了"→ 匹配"疏远"。精确度全靠运气。
- **影响**: LLM 反思产生的关系变化描述，很多情况下不会被正确解析，关系自动调整静默失效。
- **修复**: 在 `_reflect_social` 的 JSON 输出中让 LLM 直接输出 `direction` 字段（`"closer"` / `"distant"` / `"unchanged"`），而非从自然语言反推。
- **风险**: 低。需要改 LLM prompt 和解析逻辑。

### CRIT-7: `voice.py` ffmpeg 子进程超时时变成孤儿

- **文件**: `agent/voice.py:381-396`
- **确认**:
  ```python
  proc = await asyncio.create_subprocess_exec("ffmpeg", ...)
  await asyncio.wait_for(proc.communicate(), timeout=30)
  ```
  `wait_for` 超时时抛出 `TimeoutError`，但 **proc 没有被 kill**。`proc.communicate()` 被取消但 ffmpeg 进程仍在运行，占用 CPU/内存。下次调用时旧进程可能还活着。
- **影响**: 积累的孤儿 ffmpeg 进程持续消耗系统资源。在生产环境中可能累积数十个进程。
- **修复**: `except asyncio.TimeoutError` 或 `except Exception` 中加 `proc.kill()` + `await proc.wait()`。
- **风险**: 零。标准子进程管理实践。
