# 唱歌说话自然融合方案

> 2026-07-31 | 目标是「既能唱歌又能说话」——不是两个模式切换，是自然融合

---

## 一、核心洞察

**主要矛盾：LLM 不知道歌词。**

LLM 知道曲库里有 21 首歌的歌名（「会唱的歌：晴天、稻香、小幸运...」），但不知道每首歌的歌词内容。当群友说「今天下雨了」时，LLM 无法联想到「晴天里有一句『消失的下雨天，我好想再淋一遍』」——因为 LLM 根本不知道《晴天》里有这句歌词。

**次要矛盾：没有段落级音频。**

代码架构 100% 支持 `[SING:副歌]` 播放 `songs/audio/晴天/副歌.wav`——但文件不存在。36 首 WAV 全是整首歌，唱两句 = 放整首。目前最常用的降级路径是 TTS 朗读歌词——但朗读不是唱。

**两个矛盾同时解决 → 唱歌自然融入对话。**

---

## 二、目标效果

**现在**（点歌机模式）：
```
群友: "唱首歌"
糖糖: [调 sing 工具] [返回"好的，准备唱《晴天》"]
糖糖: （文字）为你翘课的那一天...
系统: [放整首歌音频]
```

**目标**（自然哼唱）：
```
群友: "今天下雨了好烦"
糖糖: "确实呢...不过下雨天也有它的好～（轻轻哼）『消失的下雨天，我好想再淋一遍』——哈哈，周杰伦写的这句我每次下雨都会想起来 ☔️"
系统: [放 2 句音频片段，群友听到糖糖真的唱了这两句]
```

或者更即兴：
```
群友: "我好想他"
糖糖: "唉...有时候就是会这样。（哼）『原来你是我最想留住的幸运』——抱歉突然就想唱了..."
系统: [放 1 句音频]
```

关键是：**不是群友要求唱歌 → 糖糖唱歌。是歌词恰好能表达她此刻想说的 → 她自然而然地唱出来。**

---

## 三、技术方案

### Phase 1: 让 LLM 知道歌词（零新依赖，改动 ~80 行）

#### 1.1 song_list 升级为 song_lyrics_snippets

**现状**（`context_builder.py:188`）：
```
## 你的曲库
会唱的歌：晴天、稻香、小幸运、...
```

**改为**：每首歌提供标题 + 每段的首句/精选句（1-2 行），共约 1500-2000 字：
```
## 你的曲库（你可以在对话中自然哼唱）
晴天（周杰伦）
  主歌1: 故事的小黄花 从出生那年就飘着 / 童年的荡秋千 随记忆一直晃到现在
  副歌: 为你翘课的那一天 花落的那一天 / 刮风这天 我试过握着你手
  主歌2: 但偏偏 风渐渐 把距离吹得好远
稻香（周杰伦）
  主歌1: 对这个世界如果你有太多的抱怨 跌倒了就不敢继续往前走
  副歌: 还记得你说家是唯一的城堡 随着稻香河流继续奔跑
...
```

LLM 看到这些就能在相关话题中自然地联想到对应的歌词。

#### 1.2 系统提示词新增"自然哼唱"指导

在 `context_builder.py` 或 `personality.py` 中加入：

```
## 关于唱歌
你是会唱歌的。不是只有被要求时才唱——当你想到一句歌词恰好能表达此刻的心情时，
自然地唱出来。像真人在 KTV 里突然哼起一句那样——不是表演，是表达。

两种情况：
- "唱首歌" → 用 [SING:歌名,副歌] 正式唱
- 自然引用 → 在回复里提到歌词，同时用 [SING:歌名,段落] 让群友真的听到你唱

唱完后继续正常说话，不用切换模式。
```

#### 1.3 `sing` 工具升级

**现状**：`sing(song="晴天")` — 只有歌名，LLM 不知道系统会唱哪段

**改为**：
```python
{
    "name": "sing",
    "description": "唱歌——可以是正式唱一整段，也可以随口哼两句。歌词和旋律都是你真正的歌声。",
    "parameters": {
        "song": {"type": "string", "description": "歌名"},
        "section": {"type": "string", "description": "段落名，如'副歌'、'主歌1'。不填则选最合适的"},
        "style": {"type": "string", "description": "唱歌风格：'自然哼唱'、'正式表演'、'随口唱两句'。默认'自然哼唱'"}
    }
}
```

Tool 返回值也要改进——不只返回"好的，准备唱"，而是返回歌词片段供 LLM 在回复中引用：
```
→ sing("晴天", "副歌", "随口唱两句")
← {"status": "ok", "title": "晴天", "section": "副歌",
   "lyrics": "为你翘课的那一天...刮风这天 我试过握着你手...",
   "audio_available": true,
   "hint": "在回复中自然地引用歌词，末尾加 [SING:晴天,副歌] 触发播放"}
```

这样 LLM 知道了：(1) 歌词是什么 (2) 有音频可用 (3) 该怎么写标记。

---

### Phase 2: 生成段落级音频（用 DiffSinger，~150 行脚本）

#### 2.1 批量生成脚本

新建 `tools/generate_section_audio.py`：

```python
"""
批量生成段落级音频。
为 songs/*.txt 中每首歌的每个段落，用 DiffSinger 合成 WAV，
输出到 songs/audio/歌名/段落名.wav。
"""
```

流程：
1. 遍历 21 首 .txt 歌词文件
2. 对每首歌的每个段落（主歌1、副歌、主歌2、尾声）
3. `diff_singer.text_to_phonemes(lyrics)` → 音素序列
4. `diff_singer.synthesize(phonemes, output_path)` → WAV
5. 输出到 `songs/audio/晴天/副歌.wav`

**优点**：
- `songs.py` 的 `get_section_audio()` 已经能读这个路径——无需改代码
- `_send_singing_reply()` 已经能解析 `[SING:副歌]` 并调 `_send_song_section()` ——无需改代码
- 音频落盘后立即生效

#### 2.2 音质处理

DiffSinger 合成的音质有上限（当前莲华声库）。两件事可以改善：
- 合成后用 **RVC** 转一次（把莲华声线转成糖糖声线，自然度会提升）
- 对于已有整首翻唱音频的 36 首歌，可以考虑用 **音频切分**（按歌词时间戳手动切），质量高于 DiffSinger 合成

优先级：**先用 DiffSinger 生成，能唱起来再说。** 音质可以后面迭代。

---

### Phase 3: 说话和唱歌的连贯回复（改动 ~50 行）

#### 3.1 回复标记升级

**现状**：`[SING:副歌]` — 只有段落名，系统从 `_pending_sing` 取歌名

**问题**：如果 LLM 想在一段回复中先提到《晴天》，唱两句，再提到《稻香》，再唱两句——`_pending_sing` 只能存一首歌。

**改为**：`[SING:歌名,段落]` 精确指定歌名（向后兼容旧格式 `[SING:段落]`）：
```
[SING:晴天,副歌]
[SING:稻香,主歌1]
[SING:副歌]  ← 旧格式继续工作（从 _pending_sing 取歌名）
```

#### 3.2 回复流示例

```
LLM 生成:
"下雨天也有它的好呀～我记得有首歌就是这么唱的——（哼）『消失的下雨天，我好想再淋一遍』[SING:晴天,副歌前两句]——周杰伦写的这句我每次下雨都会想起来 ☔️"

系统处理:
1. 发送文字: "下雨天也有它的好呀～我记得有首歌就是这么唱的——（哼）『消失的下雨天，我好想再淋一遍』——周杰伦写的这句我每次下雨都会想起来 ☔️"
2. 解析 [SING:晴天,副歌前两句] → 查 songs/audio/晴天/副歌前两句.wav → 没有 → DiffSinger 实时合成（缓存）→ 发送音频
3. 群友看到糖糖提到了歌词 + 听到了歌声
```

## 四、实施顺序

| 序 | 阶段 | 改动量 | 效果 |
|:--:|------|:--:|------|
| **1** | Phase 1: LLM 知道歌词 + 工具升级 + 系统提示词 | ~80 行 | LLM 能在对话中自然引用歌词 |
| **2** | Phase 2: DiffSinger 批量生成段落音频 | ~150 行脚本 | 群友能真的听到糖糖唱片段 |
| **3** | Phase 3: 标记格式升级 + 连贯回复 | ~50 行 | 多首歌/多段混在一条回复里 |

**总共 ~280 行。没有新依赖。没有新模块。** 全部改动在现有文件中。

## 五、风险与降级

| 风险 | 降级策略 |
|------|---------|
| DiffSinger 合成音质太差 | 有的听比没得听好；后续可以用 RVC 改善或手动切已有翻唱音频 |
| 歌词注入 token 消耗太大（21首歌 × 每首~80字 = ~1700字） | 按相关性注入——只在群聊中注入；私聊按话题匹配注入 3-5 首 |
| LLM 过度使用唱歌（每条回复都唱） | 系统提示词加频率约束：「唱歌是调味品，不是主菜」 |
| 段落音频生成时间长（21首 × 4段 ≈ 84次 DiffSinger 合成） | 后台批量跑，不需要实时；生成后永久缓存 |

---

## 六、不做的事

- **不做实时合成**：段落音频预生成，不在对话中实时调 DiffSinger（太慢）
- **不做乐谱编辑**：不引入 `.ds` 乐谱文件编辑——太复杂，当前不需要
- **不新增模型/依赖**：DiffSinger + RVC 已在项目中，不引入新引擎
- **不改变唱歌的基础架构**：`sing` tool → `_pending_sing` → `[SING:]` → `_send_singing_reply` 的链路不变，只增强
