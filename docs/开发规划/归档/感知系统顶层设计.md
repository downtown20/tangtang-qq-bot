# 感知系统 顶层设计

> 日期：2026-07-29
> 状态：设计阶段
> 前提：系统评估发现——糖糖有心、有记忆、有情绪，但不知道自己做得怎么样

---

## 一、问题定义

当前系统是一个**开环**：

```
群友发消息 → 糖糖生成回复 → 发送
                              ↑
                         到此为止。不知道群友什么反应。
```

开环系统的问题：
- 不知道群友喜不喜欢糖糖
- 不知道哪类回复效果好、哪类让人反感
- 所有优化都是盲飞——改完不知道变好还是变差
- 无法自我改进

**目标**：闭环。每次互动后系统知道群友的反应，积累数据指导优化。

---

## 二、核心洞察：不需要新数据

糖糖已经在接收群友的后续消息——这就是天然的反馈信号。不需要弹窗让用户打分。

```
群友: 糖糖你会唱歌吗          ← 触发消息
糖糖: 会呀～你想听什么歌？     ← 糖糖回复
群友: 哈哈糖糖好可爱！！       ← 这条消息就是对回复的评价！
```

"哈哈糖糖好可爱" → 正面反馈
沉默 → 中性（糖糖没引起兴趣）
"别说了" / "你能不能安静会" → 负面反馈

**关键**：反馈信号已经在消息流里了。只需要解析它。

---

## 三、三层感知架构

### 第一层：即时信号（每条回复后）

用一个极便宜的 LLM 调用，判断下一条群友消息是否是对糖糖的正面/负面反应。

```
输入：糖糖的回复 + 群友的下一条消息
输出：{sentiment: "positive"|"neutral"|"negative", confidence: 0.0-1.0}
成本：~50 token 输入 + ~10 token 输出 = 几乎免费
触发：只在群友在糖糖回复后 30 秒内发了消息时执行
```

**正面信号示例**：
- "哈哈糖糖好可爱" → positive
- "糖糖说得对" → positive
- @糖糖继续聊 → positive
- 复读糖糖的回复 → positive

**负面信号示例**：
- "别说了" / "安静会" → negative
- "你能不能别插嘴" → negative
- "@糖糖 退下" → negative

**中性**：话题自然流转，没有明确反应。

### 第二层：会话级指标（每 N 次互动汇总）

不只看单条，看会话趋势：

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| 回复触发率 | 糖糖发言后 30s 内有人回复的比例 | 糖糖的话有没有引起对话 |
| 正向率 | positive / (positive + negative) | 回复质量趋势 |
| @率 | 主动 @糖糖的次数变化 | 群友是否主动找糖糖 |
| 私聊回流 | 群聊后转私聊的比例 | 糖糖是否激发了深度交流 |
| 沉默率 | 糖糖发言后 5 分钟没人说话 | 是否冷场了 |

### 第三层：长期画像（每周聚合）

每周自动生成一份报告：

```
📊 糖糖本周表现
├── 正面率: 72% (↑ 5% vs 上周)
├── 回复触发率: 45% (→ 持平)
├── 最受欢迎的回复类型: 撒娇、帮忙查资料
├── 最不受欢迎的: 长篇大论、插话时机不对
├── 活跃群 TOP3: 群A(45次) 群B(32次) 群C(18次)
└── 建议: 减少插话频率，群B的群友更喜欢被@时回复
```

## 四、实现方案

### 数据模型

```sql
-- store.py 新增表
CREATE TABLE IF NOT EXISTS feedback (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    bot_reply TEXT NOT NULL,          -- 糖糖的回复（截取前200字）
    user_reaction TEXT,               -- 群友的后续消息（可能为空=沉默）
    user_qq TEXT NOT NULL,
    group_id TEXT DEFAULT '',
    sentiment TEXT,                   -- positive/neutral/negative
    confidence REAL DEFAULT 0.0,
    reply_ms INTEGER,                 -- 糖糖回复后多少毫秒群友发的消息
    timestamp TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_feedback_user ON feedback(user_qq);
CREATE INDEX IF NOT EXISTS idx_feedback_sentiment ON feedback(sentiment);
```

### 代码模块

```python
# agent/perception.py  ~150行

class PerceptionEngine:
    """感知引擎——让糖糖知道群友怎么看她"""

    def __init__(self, store, llm_call):
        self.store = store
        self._call_llm = llm_call

    async def evaluate(self, bot_reply: str, user_reaction: str,
                       user_qq: str, group_id: str, reply_ms: int) -> dict:
        """评估群友对糖糖回复的反应。
        只在群友有后续消息时调用。沉默不评估（那是另一个指标）。"""
        if not user_reaction or len(user_reaction) < 2:
            return {"sentiment": "neutral", "confidence": 0.5}

        # 快速路径：明确的正面/负面信号
        quick = self._quick_check(user_reaction)
        if quick:
            return quick

        # 慢路径：LLM 判断（极轻量）
        return await self._llm_evaluate(bot_reply, user_reaction)

    def _quick_check(self, reaction: str) -> dict | None:
        """明确的信号直接判断，不浪费 LLM 调用"""
        # 明确的负面
        for kw in ["别说了", "闭嘴", "安静", "别吵", "能不能不说话", "退下"]:
            if kw in reaction:
                return {"sentiment": "negative", "confidence": 0.95}
        # 明确的正面
        for kw in ["哈哈糖糖", "糖糖好可爱", "糖糖说得对", "糖糖真"]:
            if kw in reaction:
                return {"sentiment": "positive", "confidence": 0.90}
        return None

    async def _llm_evaluate(self, bot_reply: str, reaction: str) -> dict:
        """轻量 LLM 判断。~50 token 输入，~10 token 输出"""
        prompt = (
            f"糖糖说：{bot_reply[:100]}\n"
            f"群友回：{reaction[:100]}\n\n"
            f"群友的反应是对糖糖的正面/中性/负面？只输出一个词：positive/neutral/negative"
        )
        result = await self._call_llm(
            "你是一个情感分析器。判断用户对AI回复的反应。只输出 positive/neutral/negative。",
            prompt
        )
        sentiment = result.strip().lower()
        if sentiment not in ("positive", "neutral", "negative"):
            sentiment = "neutral"
        return {"sentiment": sentiment, "confidence": 0.75}
```

### 集成点

在群聊/私聊处理器中，糖糖回复发送后：

```python
# handler.py handle_group_message 发送回复后
if ok:
    # ... 现有的后续处理 ...

    # 🆕 感知：记录群友的下一条消息作为反馈
    asyncio.create_task(self._await_feedback(
        group_id, user_id, reply, msg_id
    ))
```

`_await_feedback` 监听 30 秒内的下一条同群消息（不是糖糖自己发的），然后调用 `perception.evaluate()`。

### 成本估算

- 每条评估：~60 token
- 假设每天 200 条有后续消息的回复
- 每天成本：200 × 60 = 12,000 token ≈ **不到 1 分钱**
- 每周报告：一次 ~500 token 的汇总 LLM 调用

---

## 五、这个系统的设计原则

1. **不影响回复速度**——评估是异步的（`asyncio.create_task`），不阻塞主流程
2. **不替 LLM 决策**——感知系统收集数据，不自动修改行为。行为调整由主人根据报告决定
3. **不侵犯隐私**——只分析公开的群聊消息，不记录私聊内容（除非是主人自己）
4. **先有数据再优化**——第一阶段只收集，第二阶段才基于数据调整策略

## 六、后续可以做的事（有了感知数据之后）

| 阶段 | 做什么 | 依赖 |
