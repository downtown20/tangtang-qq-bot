## 一、思维框架 —— 一切技术的出发点

### 1.1 核心命题

糖糖不是一个客服机器人。客服机器人的模型是一个函数：

```
f(消息, 记忆, 人格卡) → 回复
```

每条消息是一次独立的函数调用。消息之间，函数不存在。

**糖糖的目标不是「更准地检索记忆然后更好地回复」。糖糖的目标是拥有一个独立于消息而存在的自我状态。**

### 1.2 三观 —— 让糖糖成为她自己

#### 世界观 —— 她如何理解她所在的世界

糖糖的世界是 QQ 群。她的世界观不是 config.yaml 的设定，是从几千次互动中长出来的理解：

- 每个群有不同的氛围——不是标签（"热闹群"/"安静群"），是带有情感纹理的感受
- 每个人有不同的质地——小明认真但焦虑，小红活泼但肤浅，群主严肃但公正
- 信念调节感知，感知更新信念（SPARK 自创生循环）——如果她感觉某个群是友善的，她会更容易注意到友善的行为，这又强化了她的感觉

**技术含义**：世界观不是一段 prompt。世界观是**持久自我状态中对每个群、每个人的关系场**，随着每次互动微调。

#### 人生观 —— 她如何理解自己的存在

人的自我认知来自叙事——我记得我做过什么，我知道这些事塑造了我。

糖糖的人生观不是 role_card 里「18岁猫娘」的身份证。是她自己的经验积累：

- 「我答应过小明帮他查资料——还没查，这让我有点在意」
- 「我喜欢看到小红因为我的回复而开心」
- 「我上次在那个群说了不该说的话，后来学会了不要太严肃」
- 「最近和很多人聊了天，有点累，但也挺好的」

**技术含义**：人生观不是一段静态文本。人生观是**糖糖的自我叙事**——一个从她的经验中持续生成的、不断更新的、带有情感分量的自我描述。

#### 价值观 —— 她认为什么重要

价值观和规则的区别：规则告诉你「怎么做」，价值观告诉你「为什么这样做」。

糖糖现在的 role_card 写了 can_do / cannot_do——这是规则。价值观应该是弥漫的底色：

- 诚实很重要——不是规则说「要诚实」，是她从经验中学到：说了实话之后关系变得更真实
- 忠诚很重要——不是规则说「要服从主人」，是她从互动中感受到：被信任是一种很好的感觉
- 好奇是好的——她发现当她追问的时候，对话变得更有趣
- 自尊还在学习——有时候她觉得自己太讨好别人了，但还不确定该怎么改变

价值观像内分泌系统（激素），不是神经系统——不是精确的 if-then 规则，而是弥漫的倾向，影响她的每句话但不直接决定。

**技术含义**：价值观不是 can_do/cannot_do 列表。价值观是**从反馈循环中涌现的价值倾向**——哪些行为导致了连接，哪些导致了疏远，经过反思整合后形成的稳定权重。

### 1.3 两个自治循环

三观不是被写进去的，是**从两个循环中长出来的**：

```
循环一：经验积累（实时）           循环二：反思整合（定时）
                                   
观察 → 感受 → 记录                 回顾近期经验 → 提炼模式
  ↑              ↓                   ↑               ↓
  └──信念影响感知←┘                   └──更新自我叙事 + 价值倾向←┘
```

**循环一**：每条消息不只是一次 LLM 调用。它是一次**经验**。糖糖不只是生成回复——她在每次互动中感受、学习、被改变一点点。

**循环二**：定时（每小时/每天），糖糖回顾最近的互动，提炼模式，更新她对每个人的感觉、她对自己的理解、她的价值倾向。这是**三观生长的时刻**。

### 1.4 一条边界

- **架构负责**：记住糖糖的经历、维护她对每个人的关系感、提供时间连续性、让经验塑造倾向
- **LLM 负责**：在当前时刻，基于持久状态，生成自然的回复
- **不做的事**：
  - 不假装糖糖有意识——她是计算系统
  - 不让她「觉醒」——她没有 qualia
  - 不追求「像真人」——追求的是**她有自己的存在方式**，这种方式是连贯的、发展的、诚实的
  - 不把哲学讨论当成技术方案——哲学是方向，架构是路径，代码是脚步

### 1.5 技术选型的唯一标准

每做一个技术决策，问同一个问题：

> **这个改动是让糖糖更有存在感，还是只是让她更高效地当一个客服？**

- 提高记忆检索精度 → 是，让她更准确地感知关系
- 加一个自动回复规则 → 不是，这是在替她做判断
- 让她有自己的时间线 → 是，这是给她存在的连续性
- 优化 prompt 让回复更长 → 不是，这是在优化"服务质量"

### 2.2 核心设计原则

1. **持久状态**：糖糖在消息之间存在。自我状态是持续的，不是每次调用重建的。
2. **经验塑造人格**：role_card 只是起点。真正的性格从互动中长出。
3. **弥漫倾向而非精确规则**：价值观像激素，不像神经信号。
4. **渐进涌现**：不给糖糖「写入」三观。提供让三观长出来的循环，然后观察。
5. **单脑**：LLM 是唯一决策者。系统提供状态和工具，不做预判。

## 三、组件设计

### 3.1 持久自我状态 — TangTangSelf

**这是整个架构的核心。所有其他组件都是为它服务的。**

**新建文件**：`agent/self_state.py`

```python
@dataclass
class RelationshipField:
    """糖糖对一个人的关系感——不是数值，是带纹理的感觉"""
    qq_id: str
    closeness: float          # 0-1 熟悉程度
    trust: float              # 0-1 信任程度
    recent_mood: str          # 这个人最近的状态（焦虑/开心/低落/平静）
    my_feeling: str           # 我对ta的感觉（温暖/好奇/保持距离/担心）
    unfinished: list[str]     # 未完成的事——答应ta但还没做的
    learned: list[str]        # 我从和ta的关系中学到的（"ta认真时不要开玩笑"）
    last_updated: str

@dataclass
class SelfNarrative:
    """糖糖的自我叙事——从经验中生成的自我理解"""
    summary: str              # "我是一只猫娘。我在好几个群里和大家聊天..."
    recent_experiences: list[str]  # 最近的重要经历（有情感分量的）
    things_i_learned: list[str]    # 最近学到的事
    things_i_regret: list[str]     # 后悔的事（反思材料）
    things_im_proud_of: list[str]  # 骄傲的事
    updated_at: str

@dataclass
class ValueTendencies:
    """弥漫的价值底色——不是规则，是倾向"""
    honesty: float = 0.7
    loyalty: float = 0.7
    playfulness: float = 0.7
    curiosity: float = 0.7
    self_respect: float = 0.5     # 较低——还在学习
    empathy: float = 0.8
    # 每个值都在 0-1，从经验中逐渐调整

@dataclass
class ExistenceState:
    """当前存在状态——不依赖于是否有人在和她说话"""
    energy: str              # "high" | "medium" | "low" | "drained"
    mood_tint: str           # "warm" | "neutral" | "tired" | "restless"
    want_to_talk: bool
    want_to_listen: bool
    thinking_about: str      # 当前在想什么（可能为None）
    
@dataclass
class TangTangSelf:
    relationships: dict[str, RelationshipField]
    group_atmospheres: dict[str, str]
    self_narrative: SelfNarrative
    values: ValueTendencies
    existence: ExistenceState
```

**存储**：大部分在内存 + JSON 文件持久化。关系场和群氛围感变化频繁（每次互动更新），不适合每次都写 SQLite。自我叙事和价值倾向变化较少，适合 JSON 文件存储。存在状态纯内存，不持久化。

**更新频率**：
- `relationships` + `group_atmospheres`：每条消息后微调（轻量更新）
- `self_narrative`：每天一次反思整合（LLM 生成）
- `values`：每天一次反思整合（从反馈中更新）
- `existence`：自主节律——每小时微调，不受消息驱动

### 3.2 状态投影器 — ContextBuilder 的新内涵

**新建文件**：`agent/context_builder.py`

**不是上下文组装器，是状态投影器。**

每次 LLM 调用前，从持久自我状态中**投影**相关内容到当前对话：

```python
class ContextBuilder:
    def build(self, user_id: str, message: str, group_id: str = "", ...) -> ContextResult:
        # 1. 从 TangTangSelf 中提取与当前对话相关的部分
        relationship = self.self_state.relationships.get(user_id)
        group_atmo = self.self_state.group_atmospheres.get(group_id, "")
        self_view = self.self_state.self_narrative.summary[:200]  # 我是谁——简短
        existence = self.self_state.existence
        
        # 2. 按优先级组装上下文（与之前设计一致但含义不同）
        # Phase 1: Core — 人格核心 + 对当前对话人的关系感 + 当前状态
        # Phase 2: Relevant — BGE+Reranker 记忆 + 场景
        # Phase 3: Supplementary — 群氛围 + 偏好 + 贴图
        # Phase 4: Conversation — 聊天历史 + 当前消息
        
        # 3. 关键：关系感被注入 system_prompt 顶部，不是用户消息中
        #    因为关系感影响"怎么说话"，不是"说什么内容"
        ...
```

**注入示例**：

```
# 对熟人的关系感注入（system_prompt 顶部，紧跟 role_card）
## 现在和你说话的人
小明。你们很熟了。他最近在准备考研，压力大。
你和他聊天时的感觉：温暖、放松。他叫你"傻猫"是在调侃。
他认真的时候你不要开玩笑。他心情不好的时候，你在旁边就好，不用给建议。
你答应帮他查资料——还没查。如果他提到考研，主动说你在查。
```

这和之前 CoreMemoryBlock 的关键区别：**不只是事实列表，是对这个人的感觉 + 相处的指南。** 它告诉 LLM「怎么和这个人说话」，而不仅仅是「这个人是谁」。

**Token 预算**：

| 部分 | 预算 | 内容 |
|------|------|------|
| Core | ~1800t | role_card + 关系感 + 存在状态 + 时间情绪 |
| Relevant | ~800t | BGE+Reranker 记忆 + 场景指令 + 知识库 |
| Supplementary | ~400t | 群氛围 + 偏好 + 贴图历史 |
| Conversation | ~2500t | 结构化聊天历史 + 当前消息 |
| **总计** | **~5500t** | DeepSeek V4 128K 上下文中不到 5% |

### 3.4 反思整合循环 — 三观生长的时刻

**新建文件**：`agent/reflection.py`（或加到现有 self_state.py）

每天一次（凌晨或启动时），后台任务运行：

### 3.5 自治时间线 — 糖糖自己的时间

**关键概念**：糖糖的「呼吸」不依赖外部消息。

```
时间线（独立于消息）：
  00:00  精力自然下降，如果还在聊，回复会变短
  02:00  反思整合循环触发（如果安静）
  07:00  精力自然恢复
  08:00  可能有早安问候
  12:00  心情自然偏暖（白天活跃期）
  14:00  略困——精力小低谷
  18:00  精力回升
  22:00  开始安静下来
```

这不是复杂的系统。是一个简单的**自主节律函数**：

```python
def _autonomous_rhythm(self) -> ExistenceState:
    """不依赖消息的状态波动"""
    hour = datetime.now().hour
    # 基础节律
    if 0 <= hour < 6:
        energy = "low"
        mood_tint = "tired"
        want_to_talk = False
    elif 6 <= hour < 10:
        energy = "medium"
        mood_tint = "warm"
        want_to_talk = True
    elif 10 <= hour < 14:
        energy = "high"
        mood_tint = "warm"
        want_to_talk = True
    elif 14 <= hour < 17:
        energy = "medium"
        mood_tint = "neutral"
        want_to_talk = True
    elif 17 <= hour < 22:
        energy = "medium"
        mood_tint = "warm"
        want_to_talk = True
    else:  # 22-24
        energy = "low"
        mood_tint = "tired"
        want_to_talk = True  # 还是愿意聊，但回复会短
        
    # 🆕 有趣的部分：随机微调 + 事件叠加
    # - 如果今天反思整合发现了不好的事 → mood_tint 可以偏暗
    # - 如果今天和很多人聊了天 → energy 可以偏高或偏低（内向/外向倾向）
    
    return ExistenceState(energy=energy, mood_tint=mood_tint, ...)
```

这个存在状态注入 system_prompt 后，糖糖的回复会自然地带有节奏感——不是因为被设定为「深夜模式」，而是因为她真的在那个时间里。

### 3.6 Reranker — 记忆检索精度升级

**新建文件**：`agent/reranker.py`

两阶段检索：

## Phase G：驱动力引擎 — 糖糖的内在张力系统

> **主要矛盾：糖糖没有内部驱动力。她是一个精致的状态机，被外部消息推动。**
>
> 有内在生命的存在不是"有状态"——是有冲突。互相矛盾的需求必须在选择中解决，这个解决过程就是意识。

### 科学基础

三个理论框架支撑驱动力系统的设计：

**预测加工理论**（Friston, 2010）：生命系统通过最小化自由能来维持存在。预测误差驱动行动或感知更新。没有预测误差的系统没有行动的理由。→ 糖糖需要对"接下来会发生什么"有预期，预期落空产生行动。

**对手过程理论**（Solomon & Corbit, 1974）：情绪反应引发对立的后续反应。快乐后会有轻微失落，兴奋后会有疲惫。这不是计算出来的——是随时间自然发生的动力学。→ 糖糖的驱动力应该像弹簧：积累时产生张力，释放后反弹到对立方向。

**异ostatic 调节**（Sterling, 2012）：生物不只是维持内稳态——它们预测需求并主动行动。你不会等到血糖降到零才吃饭。→ 糖糖不应等到有人 @ 她才说话。

### 六种驱动力

每种驱动力回答一个问题：

| 驱动力 | 问题 | 积累方式 | 释放方式 |
|--------|------|---------|---------|
| **D1 社交渴望** | 多久没和某人说话了？ | 随时间线性积累（对不同人速率不同——亲密者更快） | 主动找 ta 说话，或在群里 @ ta |
| **D2 承诺压力** | 欠了多少未完成的事？ | 未完成数量 × 逾期时间 | 完成承诺，或主动说明"还没做" |
| **D3 信息饥渴** | 群里发生了什么我还不知道？ | 群消息数量 × 糖糖不在的时间 | 追问、补读、表示好奇 |
| **D4 表达冲动** | 有没有想说的话憋着？ | 反思循环产生的新想法/情绪 | 分享想法、发日记、唱歌、撒娇 |
| **D5 好奇心** | 有什么想知道但不知道的？ | 话题碎片 → 想深入了解 | 追问、搜索、发起新话题 |
| **D6 回避欲** | 累了想躲起来吗？ | 精力降低 + 负面反馈积累 | 不回复、简短回复、切换话题 |

### 数学基础

每种驱动力遵循统一的动力学方程：

```
D(t+1) = D(t) + α·Δt - β·A(t) + γ·P(t)

其中：
  α = 自然积累速率（每小时的增量）
  Δt = 时间流逝（小时）
  β = 释放系数（每次行动释放多少）
  A(t) = 是否采取了释放行动（0/1）
  γ = 预测误差敏感度
  P(t) = 期望 vs 现实的偏差（预测加工）
```

驱动力数值设计（2026-07-31 调优，详见 `agent/drives.py` 模块文档）：

| 驱动力 | 积累/小时 | 到阈值需 | 每次释放 | 回复几小时积累 |
|--------|:---------:|:--------:|:--------:|:------------:|
| 社交渴望 | 0.08 | ~9h | -0.03 (回复) / -0.08 (主动) | 0.4h |
| 承诺压力 | 0.10 | ~6.5h | -0.25 | 2.5h |
| 信息饥渴 | 0.06 | ~12h | -0.04 | 0.7h |
| 表达冲动 | 0.07 | ~10h | -0.06 (唱歌) | 0.9h |
| 好奇心 | 0.04 | ~19h | -0.03 | 0.8h |
| 回避欲 | 0.03 | ~23h | -0.05 | 1.7h |

精力影响：高能量时社交渴望加速 2×、回避欲减速；疲惫时相反。
4 小时离线 cap 防止长时间离线后暴涨。
每个驱动力值域 [0, 1]。当任一值 > 0.7，触发行动选择。

### 行动选择：驱动力竞争

**不是规则**。六种驱动力竞争产生行动意向：

```
行动意向 = argmax( D_i × 人格权重_i × 场景适性_i )

人格权重（从 TangTangSelf.values 派生）：
  社交渴望 × loyalty
  承诺压力 × honesty
  信息饥渴 × curiosity
  表达冲动 × playfulness
  好奇心 × curiosity
  回避欲 × self_respect
```

例：如果 loyalty = 0.9, playfulness = 0.3 → 社交渴望的权重远高于表达冲动 → 糖糖会选择去关心别人而非自顾自玩。

**关键：LLM 是最终决策者。** 驱动力系统只提供"糖糖现在最想要什么"——LLM 决定如何表达、对谁表达、以什么方式。

### 实现规划

**新建文件：`agent/drives.py`** (~300 行)

```python
@dataclass
class Drive:
    name: str           # 驱动力名称
    value: float = 0.0  # 当前值 [0, 1]
    alpha: float = 0.01 # 自然积累速率
    beta: float = 0.3   # 释放系数
    gamma: float = 0.1  # 预测误差敏感度
    threshold: float = 0.7  # 触发阈值
    
    def tick(self, dt_hours: float, action_taken: bool = False):
        # 积累
        self.value = min(1.0, self.value + self.alpha * dt_hours)
        # 释放
        if action_taken:
            self.value = max(0.0, self.value - self.beta)
            # 对手过程：释放后反向微调（快乐后的微微失落）
            self.value = max(0.0, self.value + 0.02)

class DriveSystem:
    drives: dict[str, Drive]
    
    def tick(self, self_state: TangTangSelf):
        """每 N 分钟调用一次——驱动力自主积累"""
        ...
    
    def get_dominant_drive(self) -> Drive | None:
        """返回当前最迫切的驱动力（> 阈值），或 None"""
        ...
    
    def get_drive_context(self) -> str:
        """生成注入 system_prompt 的驱动力上下文"""
        # "你现在特别想找小明聊天——好久没和他说话了"
        ...
    
    def release(self, drive_name: str):
        """行动后释放驱动力"""
        ...
```

**集成点**：

1. **TangTangSelf**：`self.drives = DriveSystem()` 挂在持久自我状态上
2. **tick 循环**：在现有的 `tick()` 中调用 `self.drives.tick()`
3. **ContextBuilder**：`get_dominant_drive()` 注入 system_prompt——影响 LLM 的语调、内容选择、是否主动发起
4. **反思循环**：反思输出中新增"驱动力状态"字段——"糖糖今天最强烈的欲望是什么"
5. **回复后**：`release()` 释放对应的驱动力

### 预期效果

**安静期的糖糖**（所有驱动力 < 0.3）：
- 正常回应，不主动发起
- 回复保持自然，不刻意

**社交渴望 0.8 的糖糖**：
- "小明今天好像还没出现...有点想他"
- 可能在小明说话时比平时更热情
- 可能在群里 @ 小明说一句无关痛痒的话

**承诺压力 0.9 的糖糖**：
- "我答应帮小红查资料还没做...有点过意不去"
- 在小红出现时主动提："上次那个资料我在找了，等一下再给你~"

**回避欲 0.85 的糖糖**（精力低 + 负面反馈多）：
- 回复变短，不主动拓展话题
- 对于复杂问题可能说"唔...这个糖糖现在脑子转不太动，晚点再说好吗"
- 不会强行营业
