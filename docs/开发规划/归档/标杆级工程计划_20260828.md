## 1. 北极星目标

小糖糖不是“能回复的客服”，而是一个在 QQ 群聊和私聊中长期运行的、有持久状态的 LLM 人格系统。标杆级的最低定义是：

- 任意消息、用户、群、私聊作用域都不串；重投、重启、崩溃不重复执行或丢失事实。
- 记忆只在有原文证据时进入可信层，能够回答“谁在何时说过什么”，也能明确拒答未知内容。
- LLM 是唯一行为决策者；系统只负责提供能力、执行动作、持久化状态和报告事实。
- 文本、语音、图片、贴图、定时和主动行为都走同一套上下文、回执、重试和观测契约。
- 在真实持续流量下，前台对话可用、后台积压收敛、失败可定位、恢复可验证。

“完全胜任”只能由真实窗口、故障注入和长期数据共同证明，不能用单次单测或端口在线替代。

## 2. 框架先行：先冻结契约，再扩展功能

长期不再直接给 `handler.py` 叠加分支。所有新增能力先落入以下稳定对象，再接入业务：

```text
InboundEvent
  ├─ scope (private/group + id)
  ├─ actor (qq_id/nickname)
  ├─ event_id/message_id (幂等键)
  ├─ raw_message + typed segments
  └─ received_at/source

ChatContext
  ├─ current scope and actor
  ├─ ordered source messages
  ├─ media references (short TTL, same scope)
  ├─ trusted memory/evidence blocks
  └─ window state and relationship projection

DecisionRun
  ├─ LLM request/response/tool calls
  ├─ decision (reply/skip/fade/action)
  └─ correlation id + model diagnostics

ActionEnvelope → ActionReceipt → ProactiveEvent
  ├─ typed payload (text/sticker/voice/relay/reminder)
  ├─ idempotency key and attempt
  ├─ requested/actual/status/message_id
  └─ only confirmed effects enter self-memory/feedback
```

事实层、证据层、派生摘要层、展示层必须分离；状态机必须显式表达 `received → normalized → decided → executing → confirmed/uncertain/failed`。任何“成功式日志”都必须有实际回执。

## 3. 依赖顺序与阶段

### Phase 0：工程底座与生产基线（P0）

目标：让每一次修改都可测、可追、可回滚。

- 建立全链路架构图、契约目录、状态机和错误枚举。
- 固化 `pytest`、pyflakes、GitNexus、体检、脱敏运行观察器为统一门禁。
- 运行重启后的 2h 生产冒烟，再运行 ≥12h 持续观察；功能未触发必须标记 `INSUFFICIENT`。
- 形成消息、LLM、媒体、动作、记忆、队列、窗口的 RED/USE 指标和最小 runbook。

晋级：观察器能从日志和只读数据库还原一次请求的完整生命周期，且不保存正文、QQ 号和群号。

### Phase 1：消息与副作用可靠性（P0）

依赖 Phase 0，优先消灭“看似成功但实际错/重复/丢失”。

- 完成 `event_id/message_id` inbox 幂等和原始事件不可变存档。
- 统一 `ChatContext`，批处理只生成 LLM view，不覆盖原始 segments。
- 统一动作 outbox、幂等键、租约、重试、死信和 `ActionReceipt`。
- 统一主动事件入口：定时/自治/生日/提醒都先持久化，再开窗，再由 LLM 决策。

晋级：重复投递、发送超时、进程强杀、工具二次回合均有确定性测试和回放报告。

### Phase 2：记忆真值与长期容量（P0/P1）

- 事实、承诺、已完成动作、偏好、画像、Episode 分层存储。
- 每条可信记忆带 `subject/scope/event_time/evidence_quote/source_message_id/confidence/status`。
- 原始历史查询与记忆检索分离；检索结果显示来源、时间、置信度和可拒答原因。
- 建立黄金集：跨用户、跨群、纠正、时间、否定、无证据、重启、重放。
- 解决公平调度、毒丸任务、尾批、embedding backlog 和 1000 用户持续流量收敛。

晋级：黄金集全绿；真实窗口中积压不发散，最老任务年龄下降；不能证明的记忆不进入可信注入。

### Phase 3：单脑对话自治与关系状态（P1）

- 窗口内 `reply/skip/fade` 由 LLM 决策，系统只提供 `skip_response` 和窗口事实。
- 用结构化 `DecisionRun` 记录候选、直接进入、续接、跳过、渐退和最终路由。
- 驱动力、心情、亲密度、反馈和主动意图统一为持久状态机，不以关键词抢答。
- 主动行为必须有“发起→等待反馈→结束/冷却”生命周期，失败或不确定不得消费成功状态。

晋级：真实样本各累计至少 100 条，再一次只调整一个变量；无刷屏、无重复打扰、无反馈错配。

### Phase 4：多模态与体验质量（P1/P2）

- 图片、语音、贴图、唱歌、角色切换共享 typed segments、媒体引用和动作回执。
- 语音质量只在真实样本和可测参数下优化；先筛选参考音频，再做模型/情绪 A/B，不用主观猜测替代引擎。
- 知识库、识图、语音和角色卡都必须有能力可用性、失败原因和降级链。

晋级：每个功能域都有成功/失败/未触发三态证据，不能用服务端口代替端到端成功。

### Phase 5：性能、容量与运维（P1/P2）

- 先测量事件循环阻塞、SQLite 写锁、LLM 锁、embedding、网络和发送 outbox 的 p50/p95/p99。
- 逐个消除同步阻塞和 N+1；所有优化必须有前后数据和回归测试。
- 故障注入 429/5xx/超时/非法 JSON/断线/重启/半写 payload，验证恢复和死信。
- 形成启动、重启、回滚、数据备份、清理和报警 runbook。

晋级：≥12h soak 达到 `service_rate > arrival_rate`，积压和 oldest age 趋降，前台/后台延迟满足路线图 SLO。

### Phase 6：标杆发布与持续改进

- 生成版本化能力评分、风险登记、变更影响和生产样本报告。
- 只修生产数据证明的瓶颈；每次只改一个主要变量。
- 保留可回滚快照、迁移脚本和恢复演练结果。

## 4. 每个切片的 Definition of Done

1. 先用日志、DB、探针或红测证明问题；无证据只能列为假设。
2. 先做 GitNexus impact，HIGH/CRITICAL 显式报告；共享契约优先补接口测试。
3. 先红测，再最小实现；每个切片不超过约 5 个核心文件。
4. 谁写、谁读、谁执行、谁报告都能在端到端回放中确认。
5. 通过 `python -m pytest tests/ -q`、pyflakes undefined、compileall、体检和必要的真实 canary。
6. 记录变更范围、指标前后、失败样本、回滚方式和剩余未知；不以“测试绿”宣称生产认证。

## 6. 开源参考的取舍

- Nekro Agent：借鉴工具执行语义分层和主动系统事件入口，不照搬其插件/部署体系。
- Mem0：借鉴实体/关系关联、增量记忆和用户/会话/代理作用域，但保留糖糖的证据闸门。
- Letta：借鉴 core/recall/archival 分层和持久 agent state，不把摘要当原始事实。
- Graphiti/Zep：借鉴带事件时间的 Episode/temporal graph，不立即引入重型图数据库。
- LangGraph / Temporal / Celery：借鉴 checkpoint、durable execution、租约、晚确认和幂等重试。
- OpenTelemetry：借鉴固定低基数指标、trace/correlation id、p95/p99 和症状型告警；当前先用轻量本地实现。
