# 窗口对话优化方案

> 2026-07-31 | 10 项优化，其中 3 项已实施

糖糖的本质是"在合适的时机，以合适的方式，参与合适的对话"。所有优化都围绕**对话窗口**展开——窗口是糖糖和某人一次连续互动的最小单元。

---

## 已实施 ✅

### 1. 对话状态机（conversation_tracker.py）
**做了什么**：三态模型（旁观/对话中/退让），自动切换
**效果**：叫一次名字后 60 秒内自然连续对话，不硬插别人的聊天
**文件**：`agent/conversation_tracker.py`

### 2. 消息批处理（message_batcher.py）
**做了什么**：2 秒窗口内多条消息合并成一段回复
**效果**：多人同时@不刷屏，同一人连续发不逐条回复
**文件**：`agent/message_batcher.py`

### 3. 驱动力引擎 + 自治循环
**做了什么**：6 种驱动力随时间积累，超阈值主动发起对话
**效果**：糖糖有自己的社交节奏，不完全被动
**文件**：`agent/drives.py`, `agent/handler.py` (_autonomous_loop)

## 待实施 🔲

### 4. 窗口内意图追踪

**问题**：糖糖知道"在和某人对话"，但不知道"在聊什么"。
```
浪浪：唱首歌
糖糖：想听什么？
浪浪：日语的           ← 糖糖不知道上一条是"想听什么"的延续
```

**方案**：
- `ConversationTracker` 新增 `topic_summary: str` 字段
- 每次 `on_reply_sent` 后，用轻量规则提取本次回复的话题标签（如 `唱歌|日语`）
- 窗口内新消息到达时，把话题标签注入 LLM 上下文："你们刚才在聊 XX，对方现在说 YY"
- 窗口关闭时清空

**实现**：
- 不用 LLM 提取话题——用 jieba 分词 + 规则
- 取回复的前 30 字 + 对方消息中的关键词
- 存储在 `_engaged[user_id]["topic"]`

**改动**：`conversation_tracker.py` ~15 行，`handler.py` ~5 行

### 5. 窗口记忆显式注入

**问题**：糖糖不记得自己上一条回复说了什么，导致连贯性差。
```
糖糖：我不太懂数学哦          ← 上一条回复
浪浪：帮我算个题                               ← 当前消息
糖糖：好的我来算！            ← 不应该——刚才说了不懂
```

**方案**：
- `ConversationTracker` 记录糖糖最近的 2 条回复文本
- 窗口内新消息处理时，在 LLM user_message 前追加：
  ```
  【对话上下文：你刚才回复 ta 说"XXX"。现在 ta 说"YYY"】
  ```
- 让 LLM 看到自己的回复，自然保持连贯

**实现**：
- `_engaged[user_id]["my_replies"]: list[str]` 最多 3 条
- `_engaged[user_id]["their_msgs"]: list[str]` 对方最近 3 条消息
- 组装上下文时注入

**改动**：`conversation_tracker.py` ~10 行，`handler.py` ~2 行（注入点）

### 6. 窗口内记忆偏置

**问题**：群友说"那首也不错"，记忆系统可能召回半年前的"那首"，而不是刚才聊到的。

**方案**：
- 窗口内消息做记忆召回时，话题关键词权重翻倍
- 窗口内话题词（如"稻香""周杰伦"）优先匹配，远距离记忆降权
- 不是修改 recall 逻辑——是在调用 `recall()` 前追加话题词到 query_text

**实现**：
- 从窗口的 `topic` 和 `their_msgs` 提取关键词
- 拼接到记忆查询的 query_text 前面：
  ```
  query_text = " ".join(window_keywords) + " " + original_message
  ```

**改动**：`handler.py` ~10 行（记忆查询前追加）

### 7. 回复连贯窗口

**问题**：糖糖一条回复认真、下一条突然卖萌——两条回复之间没有一致性。

**方案**：
- LLM 上下文注入："你现在正在和 XX 聊天。你上一条回复的语气是【认真的/撒娇的/调皮的】，请保持一致的语调。"
- 用轻量规则判断上一条回复的语气（问号多→认真，喵/呼噜多→撒娇，感叹号多→活泼）
- 不强制，只是提示——LLM 可以主动切换

**实现**：
- `ConversationTracker` 新增 `detect_tone(reply_text)` → 返回语调标签
- 构建 system_prompt 时追加一行语调提示

**改动**：`conversation_tracker.py` ~15 行，`handler.py` ~3 行

### 8. 情绪动量

**问题**：情绪三维（精力/心情/耐心）独立于对话窗口波动。实际上窗口内的互动应该形成情绪惯性。

**方案**：
- 对话窗口内，心情向窗口平均值靠拢
- 对方连续秒回 → 糖糖心情 +5
- 对方隔很久才回 → 心情不变
- 被冷落 → 心情 -3
- 窗口关闭时，情绪恢复到自由波动模式

**实现**：
- `ConversationTracker` 记录窗口内情绪事件
- 每次 `on_reply_sent` 时计算窗口内互动频率
- 高频互动 → 心情微增
- 不影响 mood.py 的基础情绪模型——只是在 handler 层做叠加

**改动**：`conversation_tracker.py` ~20 行，`handler.py` ~5 行

---

### 9. 亲密动量

**问题**：现在每次互动 closeness +0.005，不管是不是在窗口内。窗口内的 10 分钟连续对话和偶尔说一句话涨得一样多。

**方案**：
- 窗口内每次互动 +0.01（翻倍）
- 窗口内连续互动 ≥5 次（深度对话）→ 额外 +0.02
- 窗口持续 >10 分钟 → 窗口关闭时 +0.03 亲密奖励
- 不修改现有 `accumulate_experience` 逻辑——在 tracker 中计算窗口内计数，handler 用更大的 delta

**实现**：
- `_engaged[user_id]["message_count"]` 已存在
- handler 的 `accumulate_experience` 调用处检查窗口内计数
- 窗口关闭时结算亲密奖励

**改动**：`conversation_tracker.py` ~15 行，`handler.py` ~10 行

### 10. 窗口关闭反思

**问题**：现在的反思循环每天一次。很多小事情（"答应帮查资料""刚聊到一半被打断"）来不及记录就忘了。

**方案**：
- 窗口关闭时（过期/退让/对话结束），花 0.5 秒让 LLM 做微型反思
- 输出：窗口摘要（1 句）、是否有承诺（0/N）、对方的情绪（正面/中性/负面）、下次见到该说什么（1 句）
- 存入 `TangTangSelf._experience_buffer`，供每日反思循环消费
- 成本：每个窗口 ~0.001 元，每天 ~0.01 元

**实现**：
- `ConversationTracker` 新增 `on_window_close(user_id, context)`
- 收集窗口内所有消息文本
- 调用 `_call_llm_light`（轻量 LLM）生成窗口反思
- 写入经验缓冲

**改动**：`conversation_tracker.py` ~30 行

### 11. 群氛围感知窗口

**问题**：群氛围只在反思循环里更新（每天一次）。群突然变安静/变热闹，糖糖感知不到。

**方案**：
- 滑动窗口：最近 50 条消息的情绪分布
- 每次消息到达时更新，不额外调 LLM
- 指标：消息密度（条/分钟）、问号密度、emoji 密度、平均消息长度
- 氛围变化 > 阈值时调整插话策略：
  - 突然热闹 → 降低插话门槛（大家都在聊，加入更自然）
  - 突然安静 → 提高插话门槛（大家都走了，别自言自语）

**实现**：
- 复用现有的短期记忆缓冲 `self.memory.short_term`
- 每秒从缓冲计算氛围指标
- 指标作为 `interjection.evaluate()` 的额外输入

**改动**：新建 `agent/group_vibe.py` ~50 行，`handler.py` ~5 行集成

### 12. 主动开窗

**问题**：自治循环触发后糖糖主动说话，但说完就完了——没有进入对话窗口。

**方案**：
- 糖糖主动发言 → 被回复的人自动进入对话窗口（如果是多人话题，所有人都进）
- 如果没人回复 → 窗口只持续 30 秒（缩短的窗口）
- 如果多人回复 → 选最先回复的人进入全窗口

**实现**：
- 自治循环在 `_check_autonomous_action` 发送消息后调用 `tracker.on_reply_sent`
- 标记为"主动开窗"，窗口时长减半
- 如果 30 秒内无人回复 → 记录"主动搭话失败"，下次主动前多犹豫

**改动**：`handler.py` ~5 行（自治循环发送后），`conversation_tracker.py` ~10 行

## 私聊窗口优化 🔲

> 私聊天然是对话窗口——没有"该不该说"的问题，但有"说得好不好"的问题。

### 13. 私聊永久窗口

**问题**：群聊窗口 60 秒过期——私聊不应该。对方可能去倒了杯水，回来继续聊。

**方案**：
- 私聊窗口**永不过期**
- 只在明确结束信号时关闭：对方连续 24 小时无消息
- 窗口状态持久化到 `.tangtang_self.json`，重启后恢复
- `ConversationTracker` 新增 `_private_windows: dict[str, dict]`，独立于群聊窗口

**实现**：
- `on_reply_sent` 增加 `ctx_type` 参数区分群聊/私聊
- 私聊窗口存储对方最近 20 条消息摘要 + 糖糖最近 5 条回复
- 重启时从 TangTangSelf 恢复

**改动**：`conversation_tracker.py` ~30 行，`handler.py` ~5 行，`self_state.py` ~10 行

### 14. 私聊上下文纵深

**问题**：群里窗口只注入最近 2 条回复。私聊一聊几十条，两句话远远不够。

**方案**：
- 私聊窗口维护完整的对话摘要（不是原文，是压缩摘要）
- 每 10 条消息触发一次轻量摘要更新（用 `_call_llm_light`）
- 摘要注入 LLM 上下文："你和 XX 之前聊了这些：..."
- 承诺和未完成事项高亮

**实现**：
- `_private_windows[user_id]["summary"]: str`，每 10 条更新
- 每次 LLM 调用前注入
- 窗口关闭时写入关系档案

**改动**：`conversation_tracker.py` ~25 行，`handler.py` ~3 行

### 15. 私聊情绪共振

**问题**：群聊情绪波动快。私聊是一对一的情绪场——对方焦虑时糖糖应该一直温和。

**方案**：
- 私聊窗口内跟踪情绪均值，不每句重置
- 对方连续负面 → 糖糖情绪偏"安抚"
- 对方连续开心 → 糖糖情绪偏"活泼"
- 不修改 mood.py 的基础模型——在 handler 层把窗口情绪作为 LLM 提示注入

**实现**：
- `_private_windows[user_id]["mood_tone"]: str`（warm/gentle/playful/neutral）
- 基于对方最近 5 条消息的简单词频判断（不需要 NLP）
- 注入 system_prompt："对方最近心情似乎是 XX，你的语气应该 XX"

**改动**：`conversation_tracker.py` ~20 行，`handler.py` ~5 行

### 16. 窗口关闭写入关系档案

**问题**：群里窗口关闭反思是"刚才聊了什么"。私聊更有价值——应该写入和这个人的关系档案。

**方案**：
- 私聊窗口关闭时（24 小时无消息），LLM 做一次窗口总结
- 输出：
  - 窗口摘要（和 ta 聊了什么）
  - 对方情绪趋势（焦虑→放松 / 开心→低落 / 平稳）
  - 是否有未完成的承诺
  - 关系变化（更亲近了 / 有点疏远 / 没变化）
  - 下次见到该聊什么
- 写入 `people.notes` 和 `TangTangSelf.relationships`

**实现**：
- `ConversationTracker.on_private_window_close(user_id)`
- 收集窗口内所有消息（最多 200 条）
- `_call_llm_light` 生成总结
- 写入 `self.h.memory.store.update_person(notes=...)`

**改动**：`conversation_tracker.py` ~40 行
