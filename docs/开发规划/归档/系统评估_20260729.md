## 一、本轮改造回顾 (Phase 1-5 + 流式 + auto_learn退役)

### 消灭的旧系统

| 旧模式 | 替换为 | 效果 |
|--------|--------|------|
| `{"skill":"name"}` JSON 嵌入文本 | 原生 OpenAI Tool Calling | LLM 自主调工具，不再正则提取 |
| `{"act":"sing"}` 动作前缀正则 | `sing` / `send_voice` 原生 tool | 统一调度路径 |
| `if "关键词" in text` × 7 处 | 工具调用 / 客观信号 / 始终注入 | 系统不再替 LLM 决策 |
| `asyncio.sleep(1-6)` 伪造延迟 | SSE 流式输出 | 自然 token-by-token 节奏 |
| `auto_learn` 60+ 正则规则 | LLM 语义提取频率翻倍 | 少而准 > 多而杂 |
| `framework/` + `plugins/` 死代码 | 删除 | ~1600 行消失 |
| `personality_drift` | 删除引用 | 从未调用的死实例化 |

### 新增能力

- 群聊 LLM 可搜索记忆/聊天记录/群活跃（之前只有私聊有）
- `send_voice` 工具——LLM 自主决定发语音
- 环境变量密钥覆盖（`.env` → `DEEPSEEK_KEY`）
- 流式生成实时日志（控制台可见"正在输入"过程）

## 二、对齐度——距离目标还有多远

### 🟢 做得好的

**人格设计**：role_card.md 定义了具体、立体、有处世哲学的角色。不是"友好、乐于助人"的通用 AI——是"18 岁猫娘、老群友从容、刀子嘴豆腐心"。

**单脑架构**：LLM 是唯一决策者。系统只提供能力和执行，不判断时机。

**三层个人化**：怎么聊（场景）→ 她是谁（people.notes）→ 聊什么（memories）。

**情绪引擎**：mood.py 提供数值不给结论——`精力 65/100`，LLM 自己决定怎么表达。

### 🟡 有偏差

**插话策略**：仍是打分公式（问号+30、长度+10、熟人+15），不是 LLM 自主决策。

**知识库检索**：先关键词打分再语义兜底，顺序反了。

### 🔴 明显偏离

**无反馈闭环**：系统不知道群友喜不喜欢糖糖。所有优化都是盲飞。

**CG 触发**：16 个性词 + 30% 概率。最后的硬编码关键词触发。

**testing_mode: true**：生产环境忘了关就是灾难——所有非主人消息静默丢弃。

## 四、风险矩阵

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| testing_mode 留在生产 | 高 | 🔴 所有人消息被丢弃 | 改 false + 加启动警告 |

| GPT-SoVITS 服务挂掉 | 中 | 🟡 语音全断 | edge-tts fallback 仍在 |
| 记忆关键词兜底污染 | 中 | 🟡 错误记忆注入上下文 | 删除兜底 |
| DeepSeek API 故障 | 低 | 🔴 完全停摆 | 无备用模型 |
| LLM 生成质量退化 | 低 | 🟡 无自动检测 | 待建监控 |

## 五、结论

**方向没有偏离。** 糖糖正在从"功能堆砌的 QQ 机器人"走向"有独立人格的聊天智能体"。

**但核心 gap 不是技术问题——是没有反馈机制。** 糖糖有性格、有记忆、有情绪，但不知道自己做得怎么样。下一步不是加功能，是加感知。

最诚实的评价：**她是一只有心但有点盲的猫娘。给她一双眼睛，她会从"能聊"变成"会聊"。**
