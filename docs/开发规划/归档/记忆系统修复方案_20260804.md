## Phase 1：修系统级缺陷

> 目标：修四个架构设计层面的缺陷。每项修完后 `/状态` 可见改善。

### 1.1 自忆 BGE 相关匹配 ⭐ P0 — 设计缺陷

**问题**：`_get_self_memory_context()` 用 `recall_formatted(bot_qq)` 取 5 条自忆，**无条件注入每条消息**——群聊、私聊、跟任何人聊天。糖糖跟 486 聊考试时脑子里飘着「外套牛奶摸摸头」。

这不是"取太多了"——是**注入方式本身就是错的**。自忆应该像用户记忆一样按相关性检索，不是全局常量。

**修复**：`_get_self_memory_context` 改为接收当前对话对象的信息，用 BGE 做语义匹配，只注入与当前话题/对象相关的自忆。

```python
async def _get_self_memory_context(self, target_qq: str, message: str) -> str:
    """只注入与当前对话相关的自忆——通过 BGE 语义匹配"""
    query = f"{message[:100]}"
    candidates = self.memory.recall(
        self.bot_qq, limit=10,
        query_text=query,
        embed_engine=self.embed_engine
    )
    # BGE 会自然过滤无关自忆——「外套摸摸头」vs「考试考砸了」→ similarity 极低
    ...
```

**效果**：
- 跟 486 聊考试 → 自忆中如果有「答应帮486查资料」会命中，「外套摸摸头」不会
- 跟主人聊私密话题 → 自忆中与该主人的承诺会命中
- 纯粹闲聊 → 可能 0 条自忆注入

**文件**：`agent/handler.py` — `_get_self_memory_context`

**验证**：`/状态` 看不出直接变化，但对话中糖糖不会再在无关场景提「外套牛奶」。

### 1.2 `_llm_busy` 改排队 ⭐ P0 — 架构冲突

**问题**：`_call_llm_light` 检测到 `_llm_busy` → 等 3 秒 → 还忙 → `return ""`。群聊活跃时 LLM 持续回复，提取永远被跳过。提取和回复共享一个 LLM 资源，回复总是赢——这是架构层面的资源争抢。

**修复**：不改架构，加一个轻量等待队列。`_call_llm_light` 第一次遇到 busy 时等 8 秒（覆盖大部分 LLM 回复周期），仍 busy 则放弃——但不计入 `extract_busy_skipped`（因为确实等了）。

同时，提取任务（`_extract_memories_with_llm`）在 `_llm_busy` 时改为延迟 15 秒重试一次，而不是直接放弃整个提取周期。

```python
# _extract_memories_with_llm 入口处：
if self._llm_busy:
    self.metrics.incr("extract_busy_skipped")
    await asyncio.sleep(15)  # 等一轮回复完成
    if self._llm_busy:       # 还在忙 → 真放弃
        return
```

**文件**：`agent/handler.py` — `_extract_memories_with_llm`

**验证**：`/状态` → `extract_busy_skipped` / `extract_attempts` < 30%

### 1.3 reinforce 加冷却 ⭐ P1 — 设计缺陷

**问题**：群主「买过蓝果手账笔」被 reinforce 262 次。`reinforce()` 无冷却——每次被 recall 并命中就 +1 importance。越老的记忆在库里越久，被 reinforce 次数越多，权重越滚越高——形成"旧记忆霸榜"的正反馈循环。

**修复**：同一条记忆 30 分钟内不重复强化。

```python
def reinforce(self, qq_id, memory_entries):
    now = datetime.now()
    for m in memory_entries:
        key = f"last_reinforce:{m.id}"
        last = self.store.kv_get(key)
        if last:
            last_dt = datetime.strptime(last, "%Y-%m-%d %H:%M:%S")
            if (now - last_dt).total_seconds() < 1800:  # 30分钟冷却
                continue
        self.store.reinforce_memory_by_id(m.id, now.strftime(...))
        self.store.kv_set(key, now.strftime(...))
```

**文件**：`agent/memory.py` — `reinforce`

**验证**：运行 1 天后查数据库，`recall_count` 最高值不再增长。

### 1.4 去重有效化 ⭐ P1 — 设计缺陷

**问题**：`_deduped_remember` 声称用 BGE 语义去重，但「不是gay」×3、「最喜欢异世界小说《无职转生》」×3 安然入库。去重要么没触发、要么阈值太高、要么 embedding 缺失导致静默跳过。

**排查步骤**：
1. 读 `_deduped_remember` 完整代码，追踪从 `remember()` → `_deduped_remember()` → `batch_get_embeddings()` 的完整路径
2. 确认：新记忆写入时 embedding 是否同步写入？如果 embedding 异步写入（后台任务），去重时可能读不到
3. 确认：去重比较范围是什么？只跟同 qq_id 比还是全库比？
4. 确认：similarity 阈值是多少？

**预期修复**：
- 如果 embedding 写入是异步的 → 改为同步，或去重时重新计算当前 value 的 embedding
- 如果阈值太高（>0.9）→ 降到 0.80
- 如果只跟最近 N 条比 → 改为跟同 key 类型的所有记忆比

**文件**：`agent/memory.py` — `_deduped_remember` + `remember` + embedding 写入路径

**验证**：重复记忆清零。`/状态` 中 `dedup_hits` 值合理增长。

## Phase 2：关校验盲区

> 目标：补全防御层——不再有 LLM 推理文本、截断碎片进入数据库。

### 2.1 拦截 LLM 推理泄露 ⭐ P1

**问题**：数据库中存在 `"SKIP（前者有"买过蓝果手账笔"的限定，后者仅说"做了零个手账"，缺少购买信息）"` —— LLM 在输出 JSON 前的自言自语被当成记忆值存储。

**修复**：在 `extract_semantic_memories` 校验层加规则——含以下推理标记的直接丢弃：

```
SKIP, 前者, 后者, 注意：, 备注：, 说明：, 此处, 这个用户, 该用户
```

以及以 `(` `（` 开头且含解释性文字的条目。

**文件**：`agent/memory.py` — 后置校验层

### 2.2 记忆值自然截断

**问题**：`value[:100]` 硬截断切碎句子。

**修复**：在 100 字限制内找最后一个自然断点（`。` `；` `，` ` `）处截断。如果 100 字内无断点，取前 100 字。

```python
def _truncate_natural(text: str, max_len: int = 100) -> str:
    if len(text) <= max_len:
        return text
    for sep in ['。', '；', '，', '、', ' ']:
        pos = text.rfind(sep, 0, max_len)
        if pos > max_len * 0.6:  # 至少保留 60%
            return text[:pos + 1]
    return text[:max_len]
```

**文件**：`agent/memory.py` — 校验层 value 截断

### Phase 2 完成标志
- [ ] 数据库无含 SKIP/前者/后者的记忆值
- [ ] 所有记忆值以自然标点结尾

## Phase 3：提吞吐量

> 目标：提取效率从 3% 提升到 10%+。零记忆用户归零。
> 前提：Phase 1+2 完成后质量已有保障，此时提高数量才有意义。

### 3.1 降低触发阈值 ⭐ P2

**现状**：群聊 15 条/人，私聊 12 条/人。

**改为**：
- 群聊：每 10 条触发（原 15）
- 私聊：每 6 条触发（原 12）
- 首次提取门槛：3 条（原 5）

不改太激进——新 flash 的提取质量好，但每次提取仍然消耗 token。从 15→10 是合理的折中。

**文件**：`agent/handler.py` — `handle_group_message` / `handle_private_message`

**验证**：`/状态` → `extract_attempts` 日均 > 30

### 3.2 新鲜度加权 ⭐ P2

**问题**：`recall()` 中时间衰减从 30 天后才开始。但 7 天内的记忆应有明显优势。

**改为**：在 `recall()` 终排中，7 天内记忆 +1.0 分。

**文件**：`agent/memory.py` — `recall()` 评分逻辑

### Phase 3 完成标志
- [ ] `/状态` 日均 `extract_attempts` > 30
- [ ] 所有聊>50次用户至少 5 条记忆
- [ ] 主人记忆 > 10 条
