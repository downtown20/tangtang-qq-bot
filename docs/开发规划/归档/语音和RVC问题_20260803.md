# GPT-SoVITS & RVC 问题记录 (2026-08-03)

## 问题一：GPT-SoVITS 输出截断

### 现象
语音发送成功（HTTP 200），但用户听到的是"叽"一声空音频。日志正常无报错。

### 诊断过程

1. 用 curl 直接测 TTS API，发现不同文本长度输出差异极大：
   - "测试语音喵" (5字) → 1.18s, max amp=13120 ✅
   - "今天天气真好呀我们出去玩吧" (13字) → 1.26s, max amp=10472 ✅
   - "刚才的话已经用语音发给你啦 听到了喵" (18字) → 0.48s, max amp=392 ❌

2. 验证了参数组合（cut0/cut2/cut5 × parallel_infer true/false）——结论是 **当前参数（cut0 + parallel_infer=true）是最优的**，问题出在模型本身。

3. 样本率测试：同样 18 字，无论什么参数都是 ~0.74s。拆分后分别生成能得到正常时长（前半 1.58s + 后半 1.06s = 2.64s），说明模型对单次推理的文本有隐形时长上限。

### 根因推测
GPT-SoVITS v2 的 T2S（text-to-semantic）阶段对超过 ~15 字的输入产生截断的语义序列。不是代码 bug，是模型行为。

### 已实施的缓解措施
[voice.py](agent/voice.py#L326-L338) — 音频时长检测：
- 如果输出 < 字数 × 0.06s（~16字/秒，中文语音上限），判定截断
- 自动重试最多 3 次
- 3 次后仍截断 → 降级 edge-tts

### 待研究（明天）
- [ ] 单次推理的字数上限到底是多少？需要二分测试找精确阈值
- [ ] 能否在 voice.py 里做**预分段**：超过 N 字自动拆成多段，分别 TTS 后拼接？
- [ ] 检查 GPT-SoVITS 仓库是否有已知 issue（parallel_infer + 长文本）
- [ ] 检查 t2s_weights 模型文件是否需要更新（gsv-v2final-pretrained）
- [ ] voice.py `_EMOTION_SPEAKER` 映射中，不同 speaker 的 ref.wav 长度是否影响输出？
- [ ] 考虑换用 edge-tts 作为主力 TTS？微软晓伊/晓晓对任意长度文本都稳定

## 问题二：RVC 转换失败 — av 模块缺失

### 现象
```
ModuleNotFoundError: No module named 'av'
  File "...\infer\lib\audio.py", line 6, in <module>
    import av
```

### 已确认
- `av` (PyAV 17.1.0) 已安装在主 Python 3.10
- `pkg_resources` 恢复（setuptools 83→79，修复了 pyworld 的 import）
- 命令行 `python -c "import av"` 正常

### 可能原因
- **控制台未重启**：`py = sys.executable` 的 subprocess 可能继承了旧的 Python 环境/PATH
- **subprocess 环境隔离**：`subprocess.run([py, ...], cwd=rvc_dir)` 时，cwd 切换到 RVC 目录，可能影响了 `sys.path`
- RVC 的 `infer_cli.py` 可能在运行时修改了 `sys.path`，导致 site-packages 不可见

### 待验证（明天）
- [ ] 重启控制台后重试 RVC 转换
- [ ] 在 subprocess 中显式设置 `PYTHONPATH` 或 `env` 参数
- [ ] 检查 RVC 是否自带 venv（有 venv.sh 但 .venv 可能未创建）
- [ ] 对比：`python -c "import av"` vs `python tools/infer_cli.py --help` 是否都能 import
- [ ] 检查 `sys.executable` 在控制台进程和 subprocess 中是否一致
