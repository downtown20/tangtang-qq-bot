# 跨窗口记忆方案

> 2026-07-31 | 糖糖记住和每个人"上次聊到哪了"

## 为什么重要

现在的对话窗口关闭后，所有上下文丢失。下次同一个人说话时，糖糖从零开始——像第一次见面。

这不是技术问题，是体验问题。人和人的关系不是每次对话独立计算的——是连续的。"上次聊到一半"的感觉，比任何记忆检索都更有温度。

## 核心设计

### 窗口关闭 → 提取上下文 → 存储 → 下次注入

```
对话窗口关闭
  → 提取：糖糖最后说了什么？对方最后说了什么？
  → 存储：写入 RelationshipField.last_conversation
  → 下次对话开始：注入 LLM 上下文
```

### 存储结构

在 `RelationshipField` 中新增：

```python
last_conversation: dict = {
    "topic": "糖糖最后一条回复的前60字 + 对方最后一条消息的前60字",
    "timestamp": "2026-07-31 20:30",
    "unanswered": ["对方问了但糖糖还没回答的问题"],
    "tone": "playful/serious/gentle/warm",
    "group_id": "1092609076",  # 发生在哪个群
}
```

### 注入时机

当一个新的对话窗口**被打开**时（force_engage 被调用——有人 @糖糖或叫名字）：

1. 查这个人的 `last_conversation`
2. 判断是否应该注入：
   - 7 天内 → 注入
   - 7-14 天 → 如果当前消息和上次话题相关，注入；否则不提
   - 14 天以上 → 遗忘
3. 注入格式：

```
【跨窗口记忆——你们上次聊到一半的事】
{time_ago}，从最近 20 条对话中提取的关键片段：
  「{extractive_sentence_1}」
  「{extractive_sentence_2}」
  「{extractive_sentence_3}」
（这是你们上次对话的精华——如果当前话题相关，自然接上；完全不相关就不提）
```

### LLM 上下文注入示例

```
浪浪 @糖糖：今天有什么新歌推荐吗

LLM 看到的上下文：
【跨窗口记忆——你们上次聊到一半的事】
上次聊天：7小时前，你在帮他找日语歌，他说"想要轻松一点的"
（如果当前话题相关，自然接上）

浪浪说：今天有什么新歌推荐吗
```

糖糖可能自然地回："上次帮你找日语歌的时候好像看到几首新出的，我翻翻～"

### 不做什么

- 不强制 LLM 提上次的话题——只是给上下文，LLM 自己判断
- 不存储完整对话（隐私）
- 不跨群共享（群A的话题不带到群B）
- 不存储超过 14 天

### 窗口关闭时如何提取

**用 BGE 做抽取式摘要——零 LLM 成本，零延迟。**

窗口关闭时：

1. 从 `ConversationTracker` 窗口数据中取双方最近消息（各 ≤10 条，共 ≤20 条，窗口不够就全取）
2. 过滤纯语气词（嗯/好/哦/知道了/哈哈哈）
3. BGE 编码过滤后的每条消息 → 计算所有消息的"中心向量"（平均值）
4. 取和中心向量最相似的 3 条消息作为摘要（top-3 extractive）
5. 拼接成 ≤500 字的 `topic` 字段
6. 检测语调：复用已有的 `_last_tone`
7. 检测悬而未决的事：对方消息中所有以"？"结尾的，且糖糖之后没有明显回答的

**为什么 BGE 够用**：
- 抽取不需要"理解"——只需要"找代表性句子"
- BGE 已加载在内存中，编码 20 句 <50ms
- 和 LLM 总结不同：保留原文，不失真
- 零额外成本

### 过期机制

```
0-3天： 完整注入（"你们上次在聊XX，ta问了你YY你还没回答"）
4-7天： 简短注入（"你们前几天聊过XX"）
8-14天：仅当新消息和旧话题相关时注入
14天+： 删除
```

### 示例场景

**场景一：隔天续聊**
```
昨天：浪浪 @糖糖 "帮我查个快递"
糖糖："单号给我~"
浪浪："忘了...明天给你"

今天：浪浪 @糖糖 "糖糖，单号是SF1234567890"
注入：【跨窗口】昨天你在帮他查快递，他说"忘了明天给你"

糖糖回复："终于想起来啦！我帮你查查SF1234567890...哦已经到了！"
→ 自然的连续对话，不需要浪浪重新解释
```

**场景二：不相关的话题**
```
昨天：浪浪 @糖糖 "帮我查个快递"
今天：浪浪 @糖糖 "今天天气怎么样"
注入：【跨窗口】昨天你在帮他查快递

糖糖回复："今天晴天哦~"
→ 不提快递的事——话题不相关，LLM 自己判断不提
```

**场景三：已回答的问题不再提**
```
窗口内：浪浪 "帮我查个快递" → 糖糖 "单号给我" → 浪浪 "SF123" → 糖糖 "查到了，明天到"
窗口关闭 → 提取：双方最后的互动是"查到了明天到"，没有未回答的问题

下次对话 → 注入"上次你帮他查了快递"
→ 不提"还没回答"——因为已经回答了
```

## 附：口味偏好 + 关系签名（轻量方案）

这两个方案共用同一个原则：**只给 LLM 提示，不强制行为**。

### 糖糖的口味

在 `TangTangSelf.self_narrative` 中维护一个 `topics_i_like` 列表（最多 5 个话题关键词）。反思循环中统计最近聊得好的话题（回复长度 > 50 字且对方有后续回复 → 聊得好），把高频话题词写进去。

注入时在 system_prompt 末尾轻描淡写一句："你最近发现自己挺喜欢聊XX和YY的"。

**改动**：`reflection.py` ~10 行，`personality.py` ~2 行。

### 关系签名

在 `RelationshipField` 中新增 `vibe` 字段（`playful/serious/gentle/warm/default`）。窗口关闭时，取对话窗口中的 `_last_tone` 的众数作为本次对话的 vibe，和已有的 vibe 做加权平均（旧 0.8 + 新 0.2）。

注入时在 relationship_context 中加一句："你们聊天时的自然气氛偏{playful/serious/gentle}。"

**改动**：`self_state.py` ~3 行，`conversation_tracker.py` ~10 行，`handler.py` ~3 行。
