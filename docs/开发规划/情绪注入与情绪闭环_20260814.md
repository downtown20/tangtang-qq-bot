# 情绪注入与情绪闭环 — 设计与调研文档

> 日期：2026-08-14
> 状态：✅ 已实现并验证（8 单测 + 真实模型冒烟）
> 定位：心理陪伴场景从「只有提示词」升级为「有感知、有行为」的情绪闭环。本文档供日后升级调研。

---

## 一、设计哲学

**糖糖感知对方情绪，不是为了更精准地写客服回复，而是为了「感觉到」对方。**

- 只给 LLM **状态事实**（`📊 小明这条消息的情绪：负面 0.10`），**绝不规定糖糖该怎么回应**——怎么回应是糖糖自己的事。这与场景重写哲学一致（见 psychology.yaml：只留理解+边界，不命令说话方式）。
- 情绪系统不替 LLM 做决策（不触发"如果负面就安慰"的规则），只提供感知能力。

## 二、闭环全景

```
对方消息
  → ① 感知：StructBERT 逐条分析情绪分（0=负面, 1=正面）
  → ② 存储：mood_log 按天加权平均（store.upsert_mood_log）
  → ③ 注入：同回合把「这条消息的情绪」+「近3天趋势」放进 llm_message
  → ④ 告警：持续走低 → _care_due 队列 + 通知主人
  → ⑤ 行动：私聊插话自治循环按优先级主动关心（发送成功才消费队列）
```

数据回流：第 ③ 步影响糖糖当回合的回复姿态；第 ⑤ 步的关心结果进入下轮感知。**感知→存储→注入→行动→再感知**，这才是闭环。

## 三、模型：StructBERT 中文情感分类

| 项 | 值 |
|----|----|
| 模型 | iic/nlp_structbert_sentiment-classification_chinese-base（EasyNLP 导出格式） |
| 本地路径 | `~/models/iic/nlp_structbert_sentiment-classification_chinese-base` |
| 输出 | softmax 概率；2 分类时 `probs[1]` = 正面概率（0=负面，1=正面） |
| 推理成本 | CPU 单条 ~20-80ms，110M 参数 |

**关键坑（2026-07-28 → 2026-08-14 修）**：模型是 EasyNLP 导出格式——state dict key 带 `encoder.` 前缀、config 缺 `model_type`。HF 的 AutoModel 直接加载报误导性的 **"state dictionary corrupted"**（文件其实是完好的）。修复：`mood_tracker.load()` 运行时重映射 `encoder.* → bert.*`（丢弃非持久化 buffer `position_ids`）+ `BertForSequenceClassification(BertConfig)`。期间情绪系统静默失效数周——**教训：模型加载失败必须显式告警（启动健康检查），不能只打一行 warning**。

## 四、数据流细节

### ① 感知：`MoodTracker.analyze(text)`

- 未就绪/空文本 → 返回 None（绝不抛异常阻断主流程）。
- 调用前 CQ 码先清洗：`re.sub(r'\[CQ:[^\]]*\]', '', text)`——图片/表情标记是 tokenizer 噪声。

### ② 存储：mood_log 表

```sql
CREATE TABLE mood_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  qq_id TEXT, date TEXT,          -- date = 天
  score REAL, message_count INTEGER  -- 当天新分按 message_count 加权平均累计
)
```

### ③ 实时快照：`_mood_snapshot_context(user_id, nickname, text)`（handler.py ~6428）

这是本次升级的核心：**analyze 从「回复发送之后」前移到「LLM 生成之前」**——收到消息先分析、先入库、先告警，再让 LLM 带着情绪信息生成回复。旧位置（回复后）的块已删除，避免每条消息双跑模型。

- 分数映射：`<0.35` 负面 / `>0.65` 正面 / 中间 中性（保留两位小数让 LLM 感知程度）
- 注入文案：`📊 {nickname}这条消息的情绪：负面 0.10`（一行，状态事实）
- 失败安全：模型未就绪/分析异常 → 返回空串，**绝不阻断回复链路**（外面还有 try/except）

### ③b 趋势：`_mood_trend_context(qq_id, nickname)`（handler.py ~6470）

- 近 3 天日均分，**只有走低或低谷才注入**（无信号=不打扰 LLM）：
  - `scores[-1] < 0.35` → 「ta最近在低谷」
  - `scores[-1] < scores[-2] - 0.1` → 「ta最近比前几天差」
- 数据不足 3 天不注入（积累期 LLM 靠单条快照就够了）。

### ④ 告警：`MoodTracker.check_alert(qq_id)`

三条检测（任一命中即告警）：
1. 最近 3 天持续下降且降幅 > 0.2
2. 今天较昨日骤降 > 0.3 且今天 < 0.4
3. 近 3 天均分 < 0.3

命中 → `self._care_due[user_id] = alert`（私聊插话自治循环最高优先级目标）+ 通知主人。

### ⑤ 行动：私聊主动关心

handler_autonomy `_pick_private_target` 优先级：**care_due 队列 > 心理陪伴用户沉默≥3天 > 主人 > 近期活跃用户**。6 小时 per-user 冷却 + 2 小时活跃窗口 + 黑名单/白名单过滤。发送成功才消费队列；LLM 可用 `[不说话]` 否决。

## 五、注入点（两条路径）

| 路径 | 位置（handler.py） | 触发条件 |
|------|-------------------|---------|
| 私聊 | ~2497（记忆注入后） | 私聊场景解析为 psychology（全局 scenario_targets → 所在群配置 → 群默认） |
| 群聊 | ~1845（记忆注入后） | 群场景解析为 psychology（群 scenario_targets → 群默认 → LLM 动态检测） |

- **群聊不查全局 scenario_targets**（既有设计：群聊上下文不跨群）——心理学用户只挂全局配置时群里不触发，需在群配置里挂。
- 群聊插话消息（`_is_interjection`）同样过情绪链路——路过插话也知道对方情绪。
- 范围控制：只有场景判定为 psychology 的用户消息才过模型，**不是每条群消息都推理**；批处理合并后只分析一次。
- 附带闭环：群聊告警 → `_care_due` → **糖糖私聊主动关心**（群聊感知 + 私聊行动）。

## 六、诊断记录（2026-08-14）

- **mood_log 0 行的根因**：不是链路断，是「模型修复后用户还没发新消息」（该用户最后私聊 04:36 < 模型首次成功加载 04:47）。排查教训：**先看数据流入时间线，再怀疑链路代码**。
- 修复前模型曾加载失败数周（07-28 起的 EasyNLP 问题），期间情绪数据全部丢失。

## 七、测试

- `tests/test_mood_loop.py` 8 个：分数映射、CQ 清洗、空消息跳过、未就绪 noop、分析异常安全、告警队列+通知主人。
- 真实模型冒烟：「我好难受，睡不着觉」→ 负面 0.10；「今天超开心哈哈哈」→ 正面 0.91；mood_log 入库验证通过。

## 八、未来升级方向（调研清单）

1. **情绪粒度**：StructBERT 二分类只有正/负强度，无类别（愤怒/悲伤/焦虑/孤独）——可换多分类情绪模型（如 EmoLLaMA 类）或让 LLM 二次标注类别。
2. **实时性权衡**：当前同步推理（~20-80ms）在私聊和场景用户群聊下可接受；若扩展到全群全量分析，需异步队列 + 批推理（padding 批处理可摊薄成本）。
3. **中性消息策略**：目前全注入（含中性）。可评估只注入显著情绪（|score-0.5|>0.2）以降低 LLM 噪声。
4. **覆盖范围**：目前仅 psychology 场景用户。扩展到所有用户 = 全量推理成本；可考虑只对「关系紧密用户」开启（关系场 closeness 门槛）。
5. **情绪 × 记忆联动**：情绪峰值事件（单条 < 0.1）写入 episodic memory——「ta 那天很难过」成为糖糖的记忆而非统计数字。
6. **情绪 × 语音联动**：情绪分 → TTS 语气/音调选择（与 emotional_tts 打通）。
7. **情绪 × 驱动力联动**：对方负面情绪 → 关心驱动力（drive_care）增益，让私聊插话的自然触发与情绪状态耦合，而非只靠定时队列。
8. **情绪 × 自我状态**：糖糖的 MoodEngine（她自己的情绪）与对方情绪趋势交叉——「她也会为朋友的难过而低落」，形成关系级的情绪感染。
9. **对话级情绪**：StructBERT 是单句分类；多人对话中可做窗口级情绪（把对方连续 N 条合并分析）。
10. **模型升级路径**：注意新模型的 **checkpoint 格式兼容性**（EasyNLP/HF/safetensors），加载失败要有启动级显式告警。

## 十、待观察（需长期运行验证）

- 分数阈值 0.35/0.65 是经验值，未经过真实对话分布校准——积累 mood_log 数据后应回看分布。
- 告警三条规则的敏感度（0.2/0.3/0.3）可能偏保守或偏激进，需数周数据调参。
- 快照注入对 LLM 回复质量的实际影响（会不会过度共情/过度关注）需要 A/B 观察。
