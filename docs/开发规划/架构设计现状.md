## 〇、思维框架（未变）

「LLM 提供瞬间；架构提供生命。」这部分已升格为项目指导，见 [CLAUDE.md 第零节](../../CLAUDE.md)，这里只留骨架：

- **糖糖不是客服机器人**——不是 `f(消息, 记忆, 人格卡) → 回复` 的独立调用，拥有独立于消息存在的自我状态
- **三观从经验里长出来，不是设定**——世界观是关系场，人生观是自我叙事，价值观是从反馈中长出的弥漫倾向
- **两个自治循环**：经验积累（观察→感受→记录）↔ 反思整合（回顾→提炼→更新自我叙事）
- **一条边界**：架构负责记住经历、维护关系感、提供时间连续性；LLM 负责基于持久状态生成自然回复
- **技术选型唯一标准**：这个改动是让糖糖更有存在感，还是只是让她更高效地当一个客服？

## 二、对话窗口子系统现状

> 吸收：对话连续性方案 + 窗口对话优化方案 + 跨窗口记忆方案（原三份独立文档）

### 2.1 三态状态机 + ConversationTracker

设计的窗口状态模型已落地于 `agent/conversation_tracker.py`：

```
🟢 对话中：被 @/叫名字（force_engage）或回复后续期；120s 窗口 + 10s 容差 + 300s 渐变退出
🟡 旁观：默认状态，只听不说
🔴 窗口外：只有 @、昵称、明确引用糖糖，或主动插话评分命中时才唤醒 LLM
```

实现原则：**状态切换和 LLM 唤醒边界用规则，是否真正回复由 LLM 单一决策**。
活跃窗口内同一用户的每条消息逐条进入 LLM，不再经过 waiting、消息长度、标点、随机懒回或连续回复次数门控；
LLM 可调用 `skip_response` 写入结构化 `turn_actions.respond=false`，自然选择沉默。渐变期属于窗口外，只有开启主动插话并评分命中才进入 LLM。
主动插话开关因此只控制窗口外的主动参与，不影响已经建立的对话窗口。

### 2.3 跨窗口记忆

设计：窗口关闭 → 提取上下文 → 存 `RelationshipField.last_conversation` → 下次开窗注入。已落地：

- **提取**：`conversation_tracker.py:251` `_extract_window_summary`——窗口真正关闭时（超出 300s 渐变期）触发；
  过滤纯语气词后 BGE 编码全部消息，取与中心向量最相似的 top-3 作抽取式摘要，写 `rel.last_conversation`
  （summary/timestamp/tone/group_id）。同时做两件附带事：vibe 更新（`_last_tone` 覆盖）、窗口高频词累计到 `_topic_counter`。
- **注入**：`handler_autonomy.py:399` `_get_cross_window_context` → `handler.py:1915` 组装上下文时调用；
  14 天过期、不跨群、话题无关时 LLM 自己决定不提。
- **未落地**：附案「糖糖的口味」`topics_i_like`——设计在反思循环统计聊得好的话题写入叙事，
  实际只有 `_topic_counter` 原始计数，从未转化为叙事或注入提示。
- **简版落地**：附案「关系签名」vibe——实现为 `_last_tone` 直接覆盖，没有设计中的 0.8/0.2 加权平均。

## 六、批处理现状

> 吸收：群聊消息批处理方案。**设计与实现有实质分歧，需明确认知**。

### 设计

- 问题一：多人同时 @ → 打字延迟窗口合并，**一段回复回应所有人**
- 问题二：同一人连续发 → **BGE 语义去重**（相似度 >0.5 取消前一条）+ 意图合并

### 实际：`agent/message_batcher.py`（187 行）

| 消息类型 | 设计 | 实际 |
|---------|------|------|
| @消息 | 多人@合并为一段回复 | **防抖**（`debounce_at`，1.5s）——不合并内容，只防止多次 LLM 调用：多人同时 @ → 取消前一次等待，**只处理最后一条**（handler.py:1217-1223 入口分流） |
| 非@消息 | — | 2 秒窗口合并（`BATCH_WINDOW=2.0`）：多人 → `_reply_batched_group` 合并 prompt 一段回复；同一人连续 → `_reply_batched_private` 拼成对话链，一次回复回应最终意图 |
| 语义去重 | BGE 相似度 >0.5 取消前一条 | **未实现**——message_batcher.py 无 BGE 调用，改为把连续消息全拼进 prompt 由 LLM 处理最终意图 |

一句话总结：设计里的「多人@合并」变成了「@消息防抖 + 非@消息合并」；设计里的「BGE 语义去重」变成了「prompt 拼接合并」。意图合并的效果由 LLM 保证，不再有算法判定。
