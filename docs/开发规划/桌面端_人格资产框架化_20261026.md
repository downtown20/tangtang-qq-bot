## 一、事实（全部可复现，带代码位置）

### 1. 角色卡有三张，不是一个文件

| 文件 | 大小 | 谁 | 声线 | 表情包 |
|---|---|---|---|---|
| `role_card.md` | 483 B | 糖糖（猫娘本体，默认） | `v4` / 中文 | `default` |
| `role_card_murasame.md` | 601 B | 丛雨（剑灵，日语） | `v4` / 日语 | `murasame` |
| `role_card_michele.md` | 1022 B | 米雪儿（欧泊搜查官） | `michele` | `michele` |

切换入口是 QQ 命令 `/角色 丛雨|米雪儿|糖糖`（`agent/handler_commands.py:277-309`），
**一次切三样**：

```python
# handler_commands.py:284-291
await self.handler.voice.switch_model("v4", voice_lang="ja", current_speaker="murasame")
self.handler.personality.load_role_file("role_card_murasame.md")
self.handler._set_sticker_role("murasame")
```

⚠ **隐患 1：切完重启就丢**。`personality.py:304/316` 把身份卡存在
`self._voice_role_override`（**纯内存**），没有 `_save`/`_load`——
重启之后回到 `role_card.md`（糖糖），而声线/表情包是另一套持久化
（`voice.py` 的模型配置在 config.yaml）。这是教训 #15「持久化做一半」的现存实例。
界面必须如实显示「当前进程用哪张 / 重启后回到哪张」，不能假装它是个持久设置。

### 2. 场景卡的「叠加 / 替换」不是你选的，是**字段**决定的

`agent/scenario.py`：

| type | 用哪个字段 | 语义 | 上限 |
|---|---|---|---|
| `overlay` | `sensitivity:` | 不删任何猫娘内容，追加一层敏感度 | 2000 字（超了只 warn，不裁） |
| `replace` | `role:` | 替换 role_card 的「你是谁/性格/说话」章节 | 500 字（同上） |

**写错字段 = 静默不生效**：`type: overlay` 配 `role:` → 加载时进 `elif scenario.is_replace`
分支不成立，那条卡什么也不做，而界面一切正常。

⚠ **隐患 2：`display` 同时是挂载键**。`scenario.py:138-150`：

```python
# 先用 ID 精确匹配，再用 display name 模糊匹配
if s.display == name:            # 匹配 1
display_no_emoji = s.display.split(" ", 1)[-1]   # 「❤️ 亲密模式」→「亲密模式」
if display_no_emoji == name:     # 匹配 2
```

而 `config.yaml` 里 `scenario_targets: {'<owner_qq>': '亲密模式'}` 存的就是
**display 去 emoji 后的名字**。所以：**改 display 名 = 断开所有已挂载的群/人**。
界面允许改名就必须警告，或者改名时同步改写 `scenario_targets`。

（写这份文档时我第一版把「差 14 篇」当成了缺陷——差点又踩「把设计当 bug」这一条。

## 二、框架设计：把「你的设定」抽成三层注册表

主人第 7 条的核心：`色色模式` 这个名字、这批内容，都是**实例**，不是架构。
架构只要认三层机制：

```
第 1 层  她是谁      角色（role）      = 身份卡 + 声线 + 表情包   ← 可切换，互斥
第 2 层  怎么相处    模式（mode）      = 叠加一层 / 替换一段       ← 可挂载，可叠加
第 3 层  知道什么    知识包（pack）    = 注入方式               ← 直投 / 检索 / 蒸馏进协议
```

三层都**从数据读**，代码里不再出现任何内容名：

```yaml
# config.yaml 新增 assets 节（也可以独立成 assets.yaml，见第三节的取舍）
assets:
  # ① 她是谁：一张身份卡 + 配套的声线与表情包，切一张就是换个人
  roles:
    - file: role_card.md            label: 糖糖     voice: {model: v4, lang: zh}      sticker: default
    - file: role_card_murasame.md   label: 丛雨     voice: {model: v4, lang: ja}      sticker: murasame
    - file: role_card_michele.md    label: 米雪儿   voice: {model: michele, lang: zh} sticker: michele
    - file: role_card_<新>.md       label: <你取名>  ...            # 加一张就是加一行

  # ② 怎么相处：每张卡自己声明 overlay/replace，界面按「功能」引导生成正确字段
  modes:
    dir: scenarios/            # 每张卡 = display + description + type + (sensitivity|role)

  # ③ 知道什么：一个知识包 = 一个目录 + 一种注入方式
  packs:
    - name: 亲密范本   root: knowledge/色色参考   injection: pinned      # 每轮直投
    - name: 检索资料   root: knowledge            injection: retrieval   # 查了才有
    # 第三种 injection: distilled 不单列——它就是 prompts/ 里被标注来源的那几条
```

关键点：

1. **`name` 是主人自己起的**，跟目录名无关。想叫「深夜档」也行，想换一批
   「职场沟通」语料也行——只改 `root`。
2. **`injection` 决定它在界面的位置和警告文案**，不靠目录名猜。
3. **角色卡三层一起切**（身份 + 声线 + 表情包），因为只切一样会得到一个
   「米雪儿的人格里说着丛雨的声音」的缝合怪。
4. **`display` 改名要联动 `scenario_targets`**，否则挂载断掉——界面必须处理。

### 这张表和「他现在的设定」的关系

主人的目录结构（`knowledge/恋爱军师`、`knowledge/色色参考`）只是 `packs` 里
**两个实例的 `root` 值**。换掉它们不需要改一行代码，也不需要改界面文案。

## 三、取舍：注册表放哪

| 方案 | 好处 | 代价 |
|---|---|---|
| **A. 塞进 `config.yaml` 的 `assets:` 节** | 只有一个配置文件；已有备份/恢复/热重载链路 | `config.yaml` 已经 300+ 行，再长会难读；配置是「参数」不是「资产清单」 |

「她怎么长成这样」的一部分，跟人格配置同源。

### 顺带修掉的三处真缺陷

1. **`delete_asset` 只判 `kind == "file"`** → `delete_asset("role_card.md")` 会**真删默认身份卡**。

2. **`write_asset` 同理**：glob 型文件不存在时会静默创建。改成「保存只能改已有文件，

   `role_card.md` 在树里整行消失过一次。已修并写明原因。

### 7.3 P2 落地：注册表 + 改名自动同步

主人：「注册表和场景卡改名自动同步都不是价值判断吧？怎么方便、怎么最优怎么来。」

两件事都按「最优」自己定了：

**① 注册表是独立 `assets.yaml`，不是 `config.yaml` 的 `assets:` 节**

理由具体：`config.yaml` 有大量注释（每段都在解释「为什么这么配」），
而程序化写入（`yaml.safe_dump`）会把注释全部丢掉。改名同步那件事我可以用
**文本级替换**绕开（只动 `scenario_targets` 块的缩进范围），但「整段注册表重写」
做不到字节级安全。所以注册表独立成文件，`config.yaml` 一个字节都不碰。

```yaml
# assets.yaml —— 可选文件，不存在就用代码默认值
assets:
  - key: knowledge_scenario
    label: 深夜档语料        # 界面叫它什么
    root: knowledge/色色参考  # 它在哪
    desc: 只在对应模式激活时注入
```

只能覆盖 `label` / `root` / `desc` 三样。`kind` / `exts` / `injection` 属于**机制**，
数据里改不了——机制一改，界面显示的和真实行为就分叉，而分叉之后没人能一眼看出哪个是真的。

**② 改名自动同步 `scenario_targets`（不是警告，是真改）**

`agent/scenario.py:138-150` 用 display 名匹配场景，而 `config.yaml` 里存的就是那个名字。
所以改 display 不同步 = **场景静默失效**：没有报错，只有「她怎么不像那个模式了」。

`tools/scenario_rename.py` 的做法：

1. 找到 `scenario_targets:` 块的行范围（止于下一个顶层键）；
2. **只在这个范围里**替换值，块外的同名值（比如别的字段恰好也叫「亲密模式」）不动；
3. 用文本逐行替换而不是 `yaml.safe_dump` —— 注释必须活下来；
4. 返回受影响的键（QQ 号 / 群号），界面保存后显示「已把 N 个挂载点改到新名字」。

闸门：`tests/test_scenario_rename.py` 8 条 + `tests/test_asset_registry.py` 7 条
+ `TestScenarioRenameWiring` 3 条接线测试（单测绿 ≠ 被调用了，教训 #14）。

### 9.5 多包 + TTL（主人选的 B）

三件事必须一起说清：

### 10.3 知识库加文档后怎么建索引（答主人第 3 问）

```

        ↓ _load()      agent/knowledge.py:270

   ② 逐篇读全文 → _split_file 切块
```
