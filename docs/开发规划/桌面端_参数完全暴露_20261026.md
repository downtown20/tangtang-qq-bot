## 一、先盘清楚：所谓「参数」其实是七类东西，可改性完全不同

这不是「再加几个开关」的活。实测盘点（脚本见 `_backups/参数调研_20261025/`）：

| # | 资产 | 在哪 | 体量（实测） | 形态 | 现在能不能改 | 改完怎么生效 |
|---|---|---|---|---|---|---|
| 1 | **她的身份** | `role_card.md` | **483 B / 10 行 / 4 个小节** | Markdown | 只能手改文件 | `/人格 重载` |
| 2 | **行为准则** | `config.yaml` → `personality.*` | `can_do` **18 条** / `cannot_do` **6 条** / `core` 184 字 / `relationship_tiers` 3 档 / `tease_level` 5 | YAML | 只能手改文件（设置页只显示一行说明） | 重启 |
| 3 | **她的档案** | `config.yaml` → `profile.*` | 8 个键（age/appearance/birthday/dislikes/habits/likes/location/secrets） | YAML | 只能手改文件 | 重启 |
| 4 | **行为协议文本** | `agent/protocols.py` | **54 个大写常量**，其中 **22 个是长文本**（理解协议/纠正契约/背景块标记/心情自报…） | **Python 代码** | **不能**（改了要动代码） | 重启 |
| 5 | **场景规则** | `scenarios/*.yaml` | 3 个场景：`psychology`(17 行) / `seductive`(29 行) / `event_manager`(32 行)，每个有 name/type/display/description/sensitivity/tone/behavior | YAML | 只能手改文件（群管理页只能**挂**场景，不能**改**场景） | 重载场景 |
| 6 | **色色参考** | `agent/intimate_reference.py` + 槽位包目录 | `SLOT_BUDGETS` / `TOTAL_BUDGET=13500` / 槽位 md 文件若干 | Python 常量 + Markdown | 只能手改文件 | 重启 |
| 7 | **恋爱军师** | `knowledge/恋爱军师/` | **43 篇**（知识 20 + 话术 23） | Markdown | 只能手改文件 | `/知识库 重载` |

**三条结论**

1. **「参数」这个词在这里不准确**——七类里只有 2/3 是键值对，其余是**文本资产**
   （人格卡、协议条文、场景剧本、范本、知识文档）。所以这不是「表单」工程，是
   **「带版本、带校验、带回滚的文本编辑器」**工程。
2. **最难的是第 4 类**（22 个协议文本躺在 `.py` 里）。它决定了「规则自由度」的天花板——
   不让改协议，前面几项改了也没用（行为仍被写死的契约约束）。
3. **「能改」必须配「改坏了能回来」**。这些文本直接进 system prompt：改坏一条，
   她可能从「有点别扭」变成「说话跑偏/答非所问」。所以备份与校验不是附加功能，
   是**前置条件**。

## 二、设计：三层暴露，按「风险与收益」排序

### L1 — 文本资产直接可编辑（风险低、收益最高）

`role_card.md` / `scenarios/*.yaml` / 亲密范本槽位 / `knowledge/恋爱军师/*.md`

- 后端：通用文件端点（list / read / write / backup / restore / 恢复默认）
- 校验：`.yaml` 必须能被 `yaml.safe_load` 解析；`.md` 只限长度上限
- 备份：每次写入前落到 `_backups/编辑_<时间戳>/`，保留最近 N 份
- 前端：左边文件树 + 右边编辑器（等宽、行号、保存/回滚/恢复默认）

### L2 — 协议文本外置（这一层决定「自由度」的上限）

**做法**：把 `protocols.py` 里 22 个长文本常量**抽成 `prompts/*.md` 文件**，
代码改成「文件存在则读文件，不存在用内置默认值」，并保留
`DEFAULT_PROMPTS` 作为兜底（文件被删/读失败时零退化）。

```
prompts/
  thinking.md                  ← THINKING_PROTOCOL
  comprehension.md             ← COMPREHENSION_PROTOCOL
  correction_contract.md       ← CORRECTION_CONTRACT
  grounding.md                 ← GROUNDING_CONTRACT
  memory_evidence.md           ← MEMORY_EVIDENCE_CONTRACT
  window_reply.md              ← WINDOW_REPLY_PROTOCOL
  style_anchor.md              ← STYLE_ANCHOR
  conversation_craft.md        ← CONVERSATION_CRAFT
  …（共 22 个）
  _meta.json                   ← 每个文件的：对应常量名、字符数、是否被改过、默认值 sha
```

**为什么不是把文本塞进 `config.yaml`**：22 段几千字的文本会让配置变成一坨
（现在 208 行/9.7KB 已经够长），而且 YAML 的引号转义会让标点变形——
协议文本里的「」、——、换行都必须原样保住。用独立 `.md` 文件，**字节级保真**。

**为什么不直接编辑 `protocols.py`**：那是代码。一个引号错位就整个模块 import 失败，
糖糖直接起不来，而且她起不来的时候你正好在睡觉。

### L3 — 数值参数可调（原执行顺序第 2 步「参数来源面板」升级）

`protocols.py` 的数值常量（`UNCERTAIN_RECALL_LIMIT` / `BACKGROUND_BUDGET_TOKENS` /
`MAX_BACKGROUND_BLOCK_TOKENS` / `EVIDENCE_RESERVE_TOKENS` / `PROFILE_MAX_LEN` /
`MAX_REPLY_PARTS` …）+ 45 个模块常量里确实该让人调的。

**做法**：搬进 `config.yaml` 的新节 `tuning:`，代码读配置、缺省用内置值。
前端设置页加「高级调参」节，每个值显示 **当前值 / 默认值 / 作用 / 文件:行**。

⚠ 这一层**排在 L1/L2 之后**：数值改错的后果比文本改错更隐蔽（例如把
`BACKGROUND_BUDGET_TOKENS` 调到 3000，她会塞进一堆材料、注意力稀薄，
而界面上一切正常）。

## 三、安全设计（这些不是可选项）

| 机制 | 规则 |
|---|---|
| **备份** | 每次写入前把原文件复制到 `_backups/编辑_<YYYYmmdd_HHMMSS>/<相对路径>`；同一次会话同一文件只备份一次（避免刷屏） |
| **校验** | `.yaml` → `yaml.safe_load` 必须成功且是 dict；`.md` → 长度上限（默认 64KB，协议文本单条 8KB）；**校验失败拒绝写入**，返回具体行号 |
| **恢复默认** | `prompts/` 里的文件可以一键删除 → 代码回落到 `DEFAULT_PROMPTS`；`role_card.md`/`scenarios/*.yaml` 有原始版本备份可回滚 |
| **试运行提示** | 保存后提示「已写入，**重启糖糖后生效**」——不假装热更新（`config.yaml` 的既有语义也是如此） |
| **改动可见** | 每个可编辑资产标注「上次修改时间 / 改过几次 / 是否改过」，别让人不知道自己在改一个被改过 8 次的文件 |
| **不允许** | 从界面删除 `role_card.md` 主文件（可以清空内容但保留文件）；不允许把 `.yaml` 改成非 dict；不允许写超过上限的文本 |

## 四、接口设计（后端）

新增端点（`tools/desktop_bridge.py`，与既有 `/api/config` 同风格）：

```
GET  /api/assets                    → 可编辑资产清单（按 §一 的 7 类分组）
GET  /api/assets/read?path=…        → {content, mtime, size, backups:[…], changed}
POST /api/assets/write {path, content}  → 备份 → 校验 → 写入 → {ok, backup, warnings}
POST /api/assets/restore {path, backup} → 从备份恢复
POST /api/assets/reset {path}       → 恢复到默认（删文件 / 写回内置默认）
GET  /api/prompts                   → 22 条协议文本清单（常量名/字数/是否被覆盖/默认值预览）
```

**白名单**：`path` 只允许 §一 里列出的根（`role_card.md` / `scenarios/` / `prompts/` /
`knowledge/恋爱军师/` / 亲密范本目录），**拒绝任何 `..`、绝对路径、未列出的根**。
这是唯一的安全边界，必须**白名单而不是黑名单**（教训 #31：按类型开天窗）。

**B6 落地的三条设计决定**（后来的改动别推翻）：

1. **台账是唯一事实源，不生成前端 JSON**。`GET /api/tuning` 直接返回
   `agent/tuning.py:ui_payload()`；前端只手写 TS 类型，不存第二份 schema。
   多一个「脚本生成 → 前端读」就多一处漂移面。
2. **代码里的形态统一为 `CONST = tuning_int("key", <原字面量>)`**。
   兜底字面量必须等于台账 `default`——AST 双向闸门
   （`test_code_fallback_matches_registry` / `test_registry_items_are_all_wired`）
   盯着，改错一边立刻红。
3. **校验失败一律回落默认 + 日志 warning，不抛异常**。「糖糖必须还能起来」优先于
   「配置绝对正确」。而**保存时**反过来：越界当场拒绝并告诉用户（不静默写默认值）。

**B5 落地的四条设计决定**（同样别推翻）：

1. **「能建」必须等于「会生效」**。这条挡住了三个看着合理、实际撒谎的入口：
   `prompts/` 禁 `＋篇`（只有 `OVERRIDABLE` 那 22 个固定文件名会被读取，
   新建 `foo.md` 不生效）；`scenarios/` 的新建带骨架（空 yaml 会被
   `scenario.py` 以「缺少 name 字段」跳过）；亲密范本的目录名必须带数字或下划线前缀
   （`discover_slot_files()` 只认首字符是数字的目录，随便建一个等于永远读不到）。
2. **删目录只允许空目录**。`rmtree` 一次删 23 篇是「误操作面」最大的操作，而它省下的
   只是几次点击——不值得剪这条保险绳。
3. **删除篇目先备份**。知识库里没有第二份原文；`delete_asset` 走
   `_backup_dir()` 与 `write_asset` 同一条备份路径，删错了能用「从备份恢复」捞回来
   （端到端实测过）。
4. **树按目录分组渲染，不平铺**。44 篇平铺时，「知识 / 话术」两个分类只剩两行空目录，
   用户看不出哪篇属于哪类——分类目录功能等于白做。

### 第 4 条到底错在哪（这一条值得记住）

我原来的做法是把 `knowledge/恋爱军师` 44 篇和 `knowledge/色色参考` 15 篇**全列进界面**，
分组名直接用了这两个目录名。两个错：

1. **误判了「她读到什么」**。`agent/protocols.py:1372-1378` 的注释写着：那 43 篇放在
   `knowledge/` 里**几乎不会被用到**（`search_knowledge` 跨 10-01~10-14 只调 10 次，
   10-07 之后 8 天零调用），而且「说话方式」是行为不是知识——所以要蒸馏进 prompt。
   真正强制进上下文的是 `prompts/conversation_craft.md` 与 `prompts/knowledge_boundary.md`。
   亲密模式同理：`discover_slot_files()` 只认数字前缀目录，`_原文/` 一次都不进注入。
2. **把内容名写进了信息架构**。叫「恋爱军师 / 色色参考」的话，换一套语料就要改代码——
   所谓「通用范式」就是假的。

### 现在的结构（按注入方式，不按内容）

```
必要背景知识   ← 她「知道的东西」，三种进入方式
├─ 常驻直投    knowledge/色色参考   数字前缀目录 = 整篇进上下文；_原文/ = 归档不进
└─ 检索命中    knowledge/（排除上面那个包）  默认折叠成一行：她基本不读，只供检索深挖
（第三种「蒸馏进提示词」不在这里——它就是「规则」里那两条协议，不设第二入口）
```

四条约束（闸门会盯着）：

1. **界面文案（分组 / 名称 / 说明）不得出现具体内容名**，内容名只允许出现在 `root` 路径里。
   `test_ui_copy_has_no_content_specific_names` 机检——这条把主人的要求变成了可执行的规则。
2. **同一批文件只有一个归属**。`knowledge/色色参考` 归「常驻直投」，`knowledge_retrieval`
   用 `exclude` 把它排掉；否则同一批文件在两个分节各显示一次，改一处另一处不同步。
3. **「检索命中」默认折叠**。摊开 56 篇会让人以为「改这里就能改变她的话术」——
   而她压根不查。收起不等于藏起来，点开就能改。
4. **蒸馏进提示词不设第二入口**。它在 `prompts/` 里，就在「规则」分组改；
   再造一个「背景知识 → 蒸馏产物」的入口，就会变成同一份文本两个编辑点。

## 七、验收判据（怎么算今晚的活干完了）

1. 七类资产里 **6 类**（除 §一 第 7 类只做文件树浏览）都能在桌面上：**列出 → 读 → 改 → 存 → 回滚**；
2. 每次写入都在 `_backups/编辑_<时间戳>/` 留下原文件，且「恢复默认」真的能回到内置值；
3. 白名单拒绝测试（`..` / 绝对路径 / `agent/protocols.py` 本身）全部 403；
4. **端到端**：改一条协议文本（例如把「回复分寸」那句改成明显不同的语气）→ 重启 →
   跟她说话 → 她的回复**真的按新条文走**；然后回滚 → 再说话 → 恢复旧行为。
   这条是唯一能证明「自由度拉满」不是口号的验证。
5. `pytest tests/ -q` 全绿 + 静态检查 undefined 0 + 每批的变异对照至少 2 条真红。

## 八、不做（写清楚，避免今晚跑偏）

- **不做**：任意文件浏览/编辑（只白名单七类）。给一个通用文件管理器 = 给一把能删
  `memory.db` 的刀。
- **不做**：热重载（改完即时生效）。`config.yaml` 的既有语义就是「保存后重启」，
  新增热重载会造出第二套生效语义（#38 同族）。B4 端到端验证时人工重启即可。
- **不做**：多版本 diff / 版本树（那是 `MemoryHistory` 的活）。备份目录 + 时间戳够用。
- **不做**：把 `agent/*.py` 的 45 个常量全部 config 化。只做 L3 里「确实该让人调」的一批，
  其余保持只读——**能改全部 = 能搞坏全部**。
