# 统一交互契约目录

日期：2026-08-29  
状态：P0-1a 已完成（纯事实契约）；P0-1b 业务接线进行中；P1-4a 来源持久化已完成

## 目的

把入站消息、LLM 回合和主动入口先收敛为不可变事实对象。契约层不判断是否
回复、不负责重试、不调用 QQ；这些决定仍由 LLM、outbox 和执行器分别负责。

## 对象目录

## 不可破坏的约束

1. `group:<id>` 与 `private:<id>` 作用域不能互换；私聊作用域必须绑定 actor/target。
2. 入站 `raw_message` 与 `segments` 永不被批处理合并视图覆盖；合并视图只能作为
   LLM 输入，真实来源事件键逐条保留。
3. `ChatContext` 的历史、媒体引用和可信记忆只携带来源，不把摘要提升为事实。
4. `DecisionRun` 终态只能写一次；`skip_response` 工具不能与 `reply` 终态并存；技术
   `failed` 终态不冒充 `fade` 等行为决策。
5. `ProactiveEvent` 只是“待决策/待执行”的来源事实，不代表已发送；发送成功必须
   由 `ActionReceipt.status=confirmed` 证明。

## P1-4a 主动事件来源持久化（2026-08-29）

- 来源：`Store.record_proactive_event` 只接受 typed `ProactiveEvent`，将来源、
  scope、target、幂等键和规范化 payload 写入不可变 `proactive_events`；同事件一致
  重入返回原状态，event/idempotency key 撞上不同身份或 payload 时
  `PROACTIVE_EVENT_CONFLICT` fail-closed。
- 状态：独立 `proactive_event_state` 以 `pending` 起步，预留 claim/决策/执行/确认/
  失败终态字段，但本切片不推进状态、不调用 LLM/QQ。Handler sink 持久化异常只记结构化
  错误，不改变旧 scheduler/autonomy 发送状态机。
- 恢复：`pending→claimed→executing` 由唯一 lease token 推进；启动恢复时 claimed
  回到 pending，executing 变为 `uncertain` 并清除租约，禁止把可能已触发副作用的回合
  自动重放。Handler 在绑定 Store 后执行恢复钩子，旧 Store 兼容时安全跳过。
- 观测：`ReadOnlyStore.get_runtime_observer_snapshot` 新增主动事件总量、状态、open、
  payload 损坏和 schema 缺失计数，不暴露正文；相关 10 条专项与全量 **1530 passed**，
  pyflakes undefined=0、compileall=0。boot `6bf68064` 已加载恢复钩子，但当前无真实

## P0-1b 首个业务切片（2026-08-29）

- 入站：NapCat 在回调前写入 `_inbound_event`；Handler 对历史直调消息按同一
  `normalize_inbound_event` 规则补齐。该对象只承载事实，不改变路由、去重或回复判断。
- 上下文：群/私 Handler 将当前消息、结构化历史、筛选出的记忆 ID 和窗口状态封装为
  `ChatContext`；`ContextBuilder` 以它为事实来源，再输出原有 `ContextResult` 字段。
- 决策：带 `ChatContext` 的 LLM 回合在成功/异常边界分别生成 `DecisionRun`；空回复且
  无动作记录为技术失败，`skip_response` 只记录已发生的 skip，不由系统替 LLM 决定。
- 限制：`DecisionRun` 尚未写入持久表，工具调用清单当前覆盖行为工具/回合动作，
  ProactiveEvent 尚未接 scheduler/autonomy；这些是后续 P0-1c，不把本切片标为全链路完成。
- 回归与部署：相关定向 99 项、全量 **1518 passed**，pyflakes undefined=0、
