## 一、现行架构（实际实现，`agent/voice.py`）

### 1.1 Provider 体系（三引擎并存）

| Provider | 状态 | 说明 |
|----------|------|------|
| `gpt-sovits` | **主力**（config.yaml `voice.provider: gpt-sovits`） | 本地 API `http://127.0.0.1:9880`，支持运行时模型 profile 切换 |
| `cosyvoice` | **保留**（未删除） | `VoiceEngine` 有完整 cosyvoice 分支和 `_cosy_tts`；config.yaml `cosy_speaker: murasaki_normal` 仍在 |
| `edge-tts` | 兜底 | 微软晓伊/晓晓，免费零配置 |

### 1.2 GPT-SoVITS 参考音（米雪儿 10 情绪 + 丛雨）

`gpt-sovits/speakers/` 目录实测内容：

```
normal/ gentle/ happy/ excited/ coquettish/ tsundere/ sad/
surprised/ angry/ disgust/                                      ← 米雪儿中文情绪参考音
murasame/                                                       ← 丛雨日语参考音
```

每个目录一个 `ref.wav` 参考音频。**GPT-SoVITS 的情绪传递机制**：参考音频的情感直接传递到生成语音——嘶吼的参考 → 嘶吼的输出；悲伤的参考 → 悲伤的输出。不需要调参数，选对参考音频就完成了一半。

### 1.3 `_EMOTION_SPEAKER` 情绪 → speaker 映射（voice.py）

```python
_EMOTION_SPEAKER = {
    "开心": "happy", "兴奋": "excited", "得意": "tsundere", "鼓励": "happy",
    "搞笑": "excited", "惊讶": "excited",
    "害羞": "tsundere", "撒娇": "coquettish",
    "难过": "sad", "伤心": "sad",
    "温柔": "gentle", "认真": "gentle", "悄悄话": "gentle",
    "生气": "normal", "愤怒": "normal", "无语": "normal", "无奈": "normal",
    "傲娇": "tsundere",
}
```

情绪标签来自 LLM 回复中的 `[开心]` 式方括号标签：`extract_emotion_tag()` 取第一个有效情绪并清除所有方括号标签。合法标签表 = `EMOTION_SPEED` 的 18 个键。

### 1.4 语速微调 `_EMOTION_SPEED_RATIO`（GPT-SoVITS 用）

开心 1.05 / 兴奋 1.08 / 得意 1.03 / 鼓励 1.03 / 搞笑 1.06 / 惊讶 1.05 / 生气 1.08 / 愤怒 1.10 / 害羞 0.95 / 撒娇 0.95 / 温柔 1.00 / 认真 1.00 / 悄悄话 0.90 / 难过 0.92 / 伤心 0.92 / 无语 0.97 / 无奈 0.97

### 1.5 current_speaker 覆盖机制（2026-08-14 修复）

```python
# voice.py _resolve_speaker
speaker = self.current_speaker if self.current_speaker else self._EMOTION_SPEAKER.get(emotion_tag, "happy")
```

`current_speaker` 为空时按 LLM 情绪标签选择米雪儿参考音；糖糖与丛雨固定使用 `murasame`：

| /角色 | current_speaker | 附加效果 |
|-------|----------------|---------|
| 丛雨 | `murasame` | 通用 V4 + voice_lang=ja + role_card_murasame.md + 丛雨贴图 |
| 米雪儿 | `""`（情绪自动） | 专属模型 + voice_lang=zh + role_card_michele.md + 米雪儿贴图 |
| 糖糖（默认） | `murasame` | 通用 V4 + voice_lang=zh + 本体角色卡 |

实现位置：`agent/handler_commands.py` `_cmd_role` + `agent/voice.py` `_resolve_speaker`。

模型切换与语音合成由同一把异步锁串行保护，避免 GPT-SoVITS 全局权重在并发请求中串音；运行时切换不改写 V4 启动配置。

### 1.6 降级链

1. **合成失败降级**：GPT-SoVITS 3 次尝试失败 → 触发 `_on_gptsovits_failure` 回调（service_manager 重启 GPT-SoVITS 进程）→ `tts()` 返回 None → 上层降级 edge-tts
2. **截断检测重试**：输出时长 < 字数 × 0.06s（~16 字/秒，中文语音上限）判定截断，自动重试最多 3 次
3. **发送端兜底**：TTS 全部失败 → 降级发文字（`handler.py` `_send_voice_reply`）
4. **长文本规则**：`tts_streaming` ≤100 字全文合成；>100 字只合成第一段（发送端只发第一段，多合成白费）
5. **speaker 缺失降级**：指定 speaker 无 ref.wav → 用 normal，normal 也没有 → 返回 None 走 edge-tts

### 1.7 缓存管理

语音缓存按 `模型profile+文本+speaker+lang+语速` 的 md5 命名；启动时清理——超过 500 文件 / 200MB 上限按 mtime 删最旧（2026-08-10 加，防磁盘无限膨胀）。

## 二、情绪设计（7 情绪，源自《语音情绪系统设计》）

7 情绪方案与现行代码完全一致，保留设计依据：

| 情绪 | 场景 | 参考音频要求 | 语速（设计→实际） |
|------|------|------------|------|
| **开心 happy** | 被夸、打招呼、分享有趣的事 | 音调高、轻快活泼 | +5% → 1.05 ✅ |
| **兴奋 excited** | 惊喜、激动、群里有好玩的事 | 音调很高、语速快 | +8% → 1.08 ✅ |
| **撒娇 coquettish** | 对主人、亲密的人 | 软糯、拖长音 | -5% → 0.95 ✅ |
| **难过 sad** | 安慰人、深夜陪伴 | 低沉、语速慢 | -8% → 0.92 ✅ |
| **温柔 gentle** | 认真聊天、关心问候 | 平稳柔和 | 正常 → 1.00 ✅ |
| **傲娇 tsundere** | 被戳穿、害羞嘴硬 | 假装生气、语调起伏 | +3% ✅ |
| **日常 normal** | 普通聊天、插话 | 中性自然 | 正常 ✅ |

参考音频制作流程（历史）：丛雨 400 条音频 → SenseVoiceSmall 日语情绪识别 → 按 7 情绪分组 → 每组选质量最好的 1 条注册为 speaker。

## 三、角色制（《语音系统顶层设计》v3）——演进方向

> ⚠️ 原设计的角色制**未完全落地**，且有一条论断与代码相反。保留作为演进方向参考，逐条标注：

### 3.1 原设计

- 核心原则：**声音决定人格。切换声音 = 切换角色。**
- 三角色：`murasaki`（丛雨，傲娇日语）/ `tangtang`（糖糖本体，猫娘）/ `penguin`（凑企鹅，搞笑鬼畜）
- 三种用途：角色扮演（主）/ 搞笑效果 / 语音消息
- 技术：`/语音 角色 丛雨 → voice.current_speaker = "murasaki"`

### 3.2 与实际的偏差（逐条标注）

| 设计项 | 实际 |
|--------|------|
| 角色注册表（murasaki/tangtang/penguin + 参考音频 + 人格特征） | 未采用独立注册表；现由 `/角色` 原子联动模型 profile、参考音、角色卡与贴图库 |
| 「情绪标签：复杂多情绪 → 简化单标签或不加」 | **与代码相反**。代码采信的是 7 情绪方案——`_EMOTION_SPEAKER` 18 个中文情绪标签 → 7 个 speaker 的完整映射 + 语速微调 |
| `/语音 角色 xxx` 命令 | 实际命令是 `/角色 xxx`（`_cmd_role`），且切换的不只是声音——**声音+人格卡+贴图一起切**（超出原设计的联动） |
| LLM 自动感知当前角色 | 未实现系统提示词告知；LLM 感知靠人格卡切换 |
| 语音通话（远期） | 未实现，仍为远期 |

结论：v3 的「语音 = 角色扮演工具」方向与现行 `/角色` 命令同源；现行角色体系为糖糖/丛雨/米雪儿三元组。

## 五、故障记录（《语音和RVC问题_20260803》吸收）

### 问题一：GPT-SoVITS 输出截断（记录准确，缓解措施仍在代码中）

- **现象**：语音发送成功（HTTP 200），用户听到"叽"一声空音频，日志无报错
- **诊断**：curl 直测发现文本长度差异极大——5 字 → 1.18s ✅；13 字 → 1.26s ✅；18 字 → 0.48s max amp=392 ❌。参数组合验证结论：cut0 + parallel_infer=true 已最优，问题在模型本身。同样 18 字无论什么参数 ~0.74s，拆分生成可正常（1.58s + 1.06s）
- **根因**：GPT-SoVITS v2 T2S 阶段对 >~15 字输入产生截断的语义序列——模型行为，不是代码 bug
- **缓解**（现行代码）：输出时长 < 字数×0.06s 判定截断 → 自动重试最多 3 次 → 仍截断降级 edge-tts

### 问题二：RVC 转换失败——av 模块缺失（**已结案**）

- **现象**：`ModuleNotFoundError: No module named 'av'`（infer/lib/audio.py），当时 av 17.1.0 已装在 Python 3.10、命令行 import 正常
- **根因（结案）**：**py 启动器版本漂移**——机器上新装了 Python 3.14，`py` 默认指向 3.14，而 av/faiss 只装在 3.10 环境。控制台/主进程用 `py` 启动时 subprocess 继承了 3.14 解释器
- **修复**：`main.py` 与 `糖糖控制台_qt.py` 文件头加 `#!python3.10` shebang（main.py 注释注明本体依赖 sentence-transformers/BGE 只在 3.10；控制台注明 RVC 依赖 av/faiss 只在 3.10）。**shebang 只能写 `#!python3.10`，不能带行内注释**——launcher 会把 `#` 当文件打开报错
- **复发记录**：08-10 复发一次，再修——shebang 是脆弱的入口约束，机器 Python 环境再变动时此问题可能第三次出现

## 六、质量验收标准（原设计，供回归参考）

| 维度 | 标准 |
|------|------|
| 音色一致性 | 7 种情绪听起来是同一个人（丛雨），不是 7 个不同的人 |
| 情绪准确性 | 开心=轻快、难过=低沉、傲娇=嘴硬——不能串味 |
| 文本匹配度 | 中文文本+日语口音=自然萌，不能听起来像机器翻译 |
| 延迟 | TTS < 5 秒（GPT-SoVITS 参考值 ~3 秒/句） |
