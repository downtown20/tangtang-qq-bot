## 三、决策：三个维度压平成一个字符串

改之前是**两个维度相乘**：「方式(main/local/api) × 模型」。组合里大半是坏的：

- 选 `api` 但没 Key → 一路 401；
- 选 `local` 但没装模型 → 一路空串；
- 选 `main` 但主档是纯文本 → 打标必失败（2026-10-28 实测：`model_ref=default`
  把打标模型换成了 `deepseek-v4.1-flash`）。

现在只有一个 `model_ref`，三种写法：

| 值 | 含义 | 面板里的项 |
|---|---|---|
| `''` | 当前聊天档位（`llm.active_model`） | 「当前聊天模型」 |
| `'<档位 id>'` | 那个档位（连接信息走 `llm.providers` 组表） | 云端档位分组 |
| `'ollama:<模型名>'` | 本机 Ollama，端点 `{host}/v1` | 本机 Ollama 分组 |

**解析唯一入口**：`agent/model_refs.py::resolve_conn()`。`vision_router` 与
`image_tagger` 都只调它（新闸门 `tests/test_model_ref_conn.py` 里有一条 AST 断言：
这两个文件不许自己下标 `["providers"]`）。

### 为什么不是「再加一个 provider 字段」

那还是两个维度。主人的判据更狠：**「总要选一个模型，没有别的选择」**——
如果一件事必然发生，它就不该是一个可选项。`kind` 由值的形状决定，而不是由
另一个字段声明。

### 内部仍保留两条路（这是对的）

`image_tagger` 内部还有 `provider = off | ollama | api` 这个字段，但它是
**推导出来的**，不是用户填的：

- `model_ref` 以 `ollama:` 开头 → `provider="ollama"`，走 Ollama 原生 `/api/chat`；
- 否则 → `provider="api"`，走 OpenAI 兼容 `/chat/completions`。

两条路真的不一样（超时、图片编码、错误形状），合并会把打标的诊断信息吃掉。
**区别只在配置表面消失，不在实现里消失。**

## 五、迁移

`config.yaml` / `config.example.yaml`：

```yaml
llm.vision:      { enabled: true, model_ref: 'ollama:minicpm-v:latest' }
image_tagging:   { model_ref: 'ollama:qwen3-vl:8b-instruct-q8_0',
                   dir: stickers_cg, ollama_host: http://127.0.0.1:11434,
                   max_side: 768, timeout_s: 300, rename: true }
```

删掉的键（`llm.vision` 4 个、`image_tagging` 5 个）由文本行编辑完成，保留注释与
CRLF，写完 `yaml.safe_load` 自检；备份 `config.yaml.bak_20261028_031402`。

**老配置不迁移也能跑**（教训 #21：有原则的例外要写明为什么）：

- `load_config()`：`model_ref` 空且 `provider: ollama` + `ollama_model` → 原样沿用；
  `provider: api` + `api_base` + `api_model` → 原样沿用；`provider: 'off'` → 尊重关闭。
- `_load_vision_cfg()`：`model_ref` 空且老结构里有 `base_url` + `model` → 原样沿用。

迁移只是**推荐写法**，不是「不迁移就坏掉」。

## 六、界面（照 dsh 的真实形状）

```
┌─ provider 卡（收起）──────────────────────────────┐
│ ● 自建中转（OpenAI 兼容）  [OpenAI Chat…] [1 个模型]  ⌄  🗑 │
└──────────────────────────────────────────────────┘
```

展开后才有：名称 / API 地址 / API 协议 / Key（已绑 .env + 写值框）/ 模型目录 /
每行模型（显示名｜模型 ID｜窗口徽标｜可看图｜当前）→ 展开是上下文窗口 /
最大输出 tokens / 温度 / 思考 / 思考强度 / 输入类型 / 用途 / 添加模型。

设置页里的识图、图库打标两处，现在都只有一个「选模型」按钮 → 弹出
`ModelPicker`（搜索 + 三组 + 当前打勾 + 窗口徽标 + 可看图标签）。

## 七、还留着的（不是漏了）

- `llm.base_url` / `llm.model` / `llm.api_key` 这几个扁平字段仍随当前档位同步写出，
  **只服务没有 `models` 的老配置**（状态灯和 `/api/status` 还在读）。没有独立写入口。
- `image_tagger.DEFAULTS` 里仍有 `provider: "off"`——它是「解析不出来时的安全值」，
  不是可配置项。
- 模型行的左右顺序与 dsh 相反（我们左 = 显示名、右 = 模型 ID）。dsh 的显示名允许
  留空（留空用 ID），我们的 `label` 是主字段。**刻意不改**：改顺序会让已经配好的
  人对着两个框重新认一遍，收益只是「像」。
