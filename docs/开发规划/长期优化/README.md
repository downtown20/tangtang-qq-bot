# 小糖糖 · 长期自主优化 · 章程

> **这是本长期任务的唯一事实源。** 状态在 `任务台账.md`，数值基线在 `快照/`。
> 上下文会被压缩、会话会更换模型——**任何不落在这三个文件里的结论都视为不存在**。
> 建立于 2026-10-14。

---

## 0. 任务是什么 / 不是什么

**是**：由执行者**独自**、**长期**、**分阶段**地发现本项目（QQ 机器人「小糖糖」）的缺陷并逐步优化。
每个阶段 = 一个可独立验收的任务；做完一个，压缩上下文，再做下一个。

**不是**：
- 不是"一次性重构"——禁止大爆炸式改造；
- 不是"看到什么改什么"——**发现与修复分离**（见 §4）；
- 不是"让代码更好看"——**没有测量的优化不算数**；
- 不是"推翻既有架构"——既有有效积累有清单（§8），越线即错。

**北极星（唯一裁判）**：`CLAUDE.md` 第零节——**这个改动是让糖糖更有存在感，还是只是让她更高效地当一个客服？**
技术债、死代码、静默失败、可观测性缺口都属于"让她更像个活人"的前置条件：**她得先真的在跑，才谈得上在活着**。

### 0.1 优化边界（2026-10-14 主人增补，纪律条款）

主人对任务的三条要求（原文）：① **充分挖掘项目缺点并实施优化**；
② **明确优化边界，避免盲目扩张，避免在一个点上无休止消耗**；
③ **自主组织团队，自主设置计划与目标，稳步推进**。

据此定下六条边界。**每条都是一票否决项**——触发即停，不靠现场判断：

| # | 边界 | 量化判据 | 触发后动作 |
|---|---|---|---|
 | B1 | **单任务预算** | 一次会话内做完并验收（§1）；**同一任务的探索轮次 ≤ 5**；取证探针 ≥ 3 个仍无结论 → 判定「取证不足」 | 降级为「待验证假设」记台账，**换下一个任务**，不纠缠 |
 | B2 | **单次改动面** | 一个任务的改动文件数 ≤ 3；超过即证明没找到主要矛盾 | 停下来重找共因（CLAUDE.md 教训 #1） |
 | B3 | **一次只做一件事** | 本任务范围内禁止顺手修别的缺陷（§1 已定）；发现即登记 | 登记后继续本任务，不扩散 |
 | B4 | **禁止完美主义返工** | 同一处代码**二次返工即冻结**——写进 §11 已否决并说明理由 | 冻结后不再回头，接受当前状态 |
 | B5 | **只做北极星内的事** | 改动必须能回答「让糖糖更有存在感」或「让她真的在跑」；纯风格/纯重构无测量收益 → 不做 | 记 §11 已否决 |
 | B6 | **范围不超过项目本体** | 只动 `agent/` `onebot/` `tests/` `tools/` `main.py` `糖糖控制台_qt.py` `config.yaml` 与 `docs/`；**不碰 DSH 安装、不碰发布仓、不碰 vendored 依赖**（§8/§12 已覆盖的部分不重复） | 越界需求单独登记，需主人授权 |

**B1 是本 long-task 的防爆阀**：探索成本本身要有上限，否则「充分挖掘」会退化成「在一个点上无限挖」。

### 0.2 团队组织（2026-10-14 主人增补）

主人已授权「必要时可以创建团队共同完成任务」。本任务的组织原则：

- **默认单人（我）执行**。团队只在**收益明确大于协调成本**时启用。
- **启用的判据（满足其一）**：
  - (a) 任务可切成 ≥2 个**互不重叠的写范围**，且每块都需要**独立深度取证**（如全项目普查、多模块对照审）；
  - (b) 存在**明显可并行的只读取证**（读不同文件集、跑不同口径扫描），串行做纯浪费时间；
  - (c) 需要**对抗式复核**（doubt-driven-development：高风险改动由独立上下文再审一遍）。
- **不启用的情形**：改动面小（B2 内）、需要共享同一份压缩后的上下文、或协调成本高于执行成本。
- **hard rule（不可协商）**：
  1. **写范围必须 disjoint**——拆分时在共享任务板上写明每人的 `write_scopes`，重叠即冲突；
  2. **只有 Lead 做最终验收**——队友的产出必须由我独立复核（跑测试/重取证），**不采信队友的自报结论**；
  3. **子代理继承同一套纪律**——派活时把 §3 证据协议、§5 验收门槛、B1–B6 一并写进 brief；
  4. **队友报告落盘**——结论必须能落到 `.trash/<日期>-<任务>/` 或台账，不可只留在对话里。

### 0.3 计划与目标（自主设置，稳步推进）

- **目标分层**：北极星（§0）→ 阶段目标（当前在攻克哪一类缺陷）→ 任务目标（台账 Tn 行）。
- **阶段目标由我自主设定并记入台账**：每完成一个阶段，在台账「阶段」表追加一行（目标 / 完成日 / 证据）。
- **节奏**：每轮做 1 个任务 → 落盘 → 压缩 → 下一轮。**不并行开多个进行中任务**（§1）。
- **稳步**优先于**快**：宁可一轮只推进一个小任务，也不为凑进度跳过高价验门槛。

## 1. 工作单元：阶段任务制

- 一个任务 = **一个缺陷类**或**一项能力**，能在一次会话内做完并验收。
- 任务编号 `Tn`，写在 `任务台账.md`，字段固定：目标 / 证据 / 验收判据 / 状态 / 回滚锚点。
- **一个任务只做一件事**。中途发现新缺陷 → **记进台账**，不在本任务里顺手修（除非它是本任务的直接阻塞，且已在台账登记为 `Tn.1`）。
- 任务结束必须回答三问（`CLAUDE.md` 第四节）：主要矛盾是什么？最小改动是什么？改完怎么验证？

### 任务状态机

```
待取证 → 取证中 → 待拍板 → 实施中 → 待验收 → 已完成
                     ↘ 已否决（写明理由，防重复讨论）
                     ↘ 阻塞（写明阻塞条件与解除条件）
```

**只有"已完成"能写 [x]。** 代码写完 ≠ 完成；测试绿 ≠ 完成；**验收判据全部为绿才算完成**（§5）。

## 2. 上下文协议（每个任务收尾必做，不做视为任务未完成）

1. **落盘优先于记忆**：结论 → 台账；数值 → 快照；过程 → `docs/开发规划/长期优化/记录/Tn-*.md`。
2. **收尾即压缩**：任务完成 → 立刻压缩该任务的探索过程，只留结论。压缩摘要必须自包含（路径、函数签名、错误串、决策理由、未完成项）。
3. **开工先读**：新任务开工第一件事是读 `README.md` + `任务台账.md` 的相关条目，**不要凭记忆**。
4. **不重复探索**：已否决/已知不修清单（§11）里的东西不再论证。

## 3. 证据协议

沿用技能 `evidence-review` 的四段式，**无证据的发现降级为「待验证假设」，不得进 Critical/Important**：

```
位置(file:line) → 证据（日志行 / DB 查询结果 / 运行时探针输出 / 会红的测试）→ 根因 → 最小修复建议
```

**强制阳性对照（`CLAUDE.md` 教训 #30/#31）**：任何"检查器/扫描器/闸门/告警"声称"零命中/全通过"时，
必须**种一个真样本进去看它报不报**。只测"跑起来没报错"等于没测——它本来就不会报错。

**观测点前置（教训 #34）**：凡改阈值/速率/释放量/配额/行为分支，**必须同批提交观测点**（日志行或 DB 可查事实），
否则该任务在验收上直接判红。

**锚点唯一（2026-10-23 T68 轮踩出来的）**：凡用脚本改**结构性文档**（台账 / 清单 / 表），旧文本锚点必须**恰好出现一次**——
改前断言 `count == 1`，否则不猜、先看上下文。本轮我拿 `| T2.2 | 私有方法零引用闸门扩覆盖 |` 当锚点，而它在台账里出现两处
（已完成表的原登记行 + 阻塞登记行），`findIndex` 静默取了第一处，**覆盖掉一行验收依据**。
这与 `tools/变异对照.py` 的铁律是同一条：**锚点不唯一就不是"改对了"，是"改到了某处"**。

## 4. 发现与修复分离

- **发现任务**（`Dn`）：只读，产出缺陷清单（含证据与分级），**不改一行代码**。
- **修复任务**（`Tn`）：只修清单里已取证的一条，附带回归测试。
- 两者可以交替，但**不允许**在同一任务里既"发现"又"顺手修"——那是范围失控的入口。

## 5. 验收门槛（Definition of Done）

### 5.1 硬门槛（每次改动后必跑，缺一不可）

```bash
python -m pytest tests/ -q          # 必须全绿，数字不得低于基线
python tools/静态检查.py            # 必须清零（脚本自己 glob，并打印实际扫描的文件数）
```

> ⚠ **不要手写 `python -m pyflakes agent/*.py ...` 那条命令**（本节曾长期这么写，
> 2026-10-15 核查时改正）。pwsh / cmd **不展开 glob**，pyflakes 收到字面量 `agent/*.py`
> 会报 `Invalid argument` 并把整个目录跳过——T54 §四实测 **82 个文件里只真扫了 2 个，
> 而输出照样是「undefined = 0」**。这是教训 #30 同族的「检查器没生效但看不出来」：
> 命令能跑、能返回 0，只是什么也没检查。
> `tools/静态检查.py` 由 Python 自己 glob，**打印实际扫描的文件数**，
> pyflakes 一抱怨参数就立刻红灯——这才是那条硬门槛该有的形态。

### 5.2 棘轮（只许变好，不许变坏）

由 `tools/长期优化快照.py` 采集，与上一份快照对比，**任何一项变差必须在台账里写明理由**：

| 指标 | 方向 |
|---|---|
| pytest 通过数 | ↑ |
| pyflakes undefined | 0 |
| vulture（min-confidence 90）命中数 | ↓ |
| radon CC≥25 函数数 | ↓ |
| 零调用方法数（闸门基线 `CLASS_METHOD_BASELINE`） | ↓ |
| 关键文件行尾一致性（CRLF/LF 不得被改） | 不变 |

### 5.3 行为门槛

改行为 → 必须**模拟场景端到端走一遍**（不是只跑单测），并把走查输出贴进记录文档。
测试绿只证明不回归，**不证明行为正确**。

## 6. 回滚与写者互斥

- **回滚锚点前置**：改动前先 `Copy-Item x.py x.py.bak-<YYYYMMDD>-<tag>`。本仓**不是 git 仓库**，锚点是唯一的回滚手段。
- **锚点必须留在原目录**（与文件同级），以便逐字节 diff：`git diff --no-index -- x.py x.py.bak-<tag>`。
- 若启用协作（可选），**写作用域必须互斥**；**最终验收必须等所有写者停止**——并行写同一文件时
  `inspect.getsource` 类断言会读到中间态，产生假红（2026-10-13 Stage 2 实测 9 条）。

## 8. 不要动清单（继承审计第五节 12 条，逐条仍然有效）

1. `uncertain` 永不自动重放；前段未确认不发后段
2. legacy 12k 记忆不自动注入
3. `role_card.md` 只写身份，规则进 `protocols.py`
4. 无标签 = 对方说的；用户原文永不包裹且永远最后
5. `[分段]`/`[引用]` 决策权在 LLM（`[分段]` 只开私聊）
6. **别把 @ 防抖的 `cancel` 修成真的**
7. 窗口内不得二次门控（沉默由 `skip_response` 工具）
8. 意图解析单一决策源（自然语言意图只有 LLM 能解析）
9. 情绪不做关键词检测；不让状态引擎接管"回不回"
10. `health_check` 只读
11. 不加无条件常驻的「近况叙事」摘要
12. 媒体/文本 outbox 唯一 retry owner；任务不直发

**另加（2026-10-14）**：
13. **单脑架构**——LLM 是唯一决策者；`if "关键词" in text` 做行为分流 = 反模式，见到即视为 bug
14. **发送协议必须在 `ReplyPipeline.clean()` 之前冻结**（标记剥掉就读不到了；语音路径会念出标记）
15. **识图统一走中转 `deepseek-v4.1-flash` 原生视觉**（2026-10-14 主人定案）——不再依赖本地 MiniCPM-V 与额外识图 API
17. **`config.yaml` 的 `personality` 是规则层、`role_card.md` 是身份层，两层都进 prompt**（2026-10-14 T14）——
    不许改回二选一。`_build_cache()` 与 `reload_role_card()` 都必须走 `_compose_base()`；
    谁再把 `_cached_base` 直接赋成 role_card，那 26 条规则（can_do/cannot_do/core/tiers/tease）
    就会静默消失，`tests/test_personality_two_layer.py` 会红。
16. **新文件/新函数的顶层名不得与任何既有类公共方法同名**（2026-10-14 T2.3 实测）——
tests/test_integration_contract.py 的零调用闸门原本按**裸标识符名**收集引用，
新工具里一个模块级 snapshot() 就把基线 ('agent/knowledge_index.py','snapshot')
撞成「已接线」假红。已于 T2.3 修好类方法闸门（不吃裸名证据），
但**函数闸门仍靠裸名判定**，所以这条对函数名依然成立：新起名字先 grep 一遍全项目。

## 11. 已否决 / 已知不修（防重复讨论）

| 项 | 结论 | 理由 |
|---|---|---|
| 让系统正则解析自然语言意图（定时/位置/内容） | **已否决** | 意图解析单一决策源；`TestPreciseCommandsBoundary` 闸门钉死（教训 #24） |
| 恢复关键词门控做行为分流 | **已否决** | 反模式 #9/#10 |
| 本地 MiniCPM-V + 额外识图 API 双后端 | **已否决**（2026-10-14） | 中转 4.1flash 原生视觉已足够；见 §8-15 |
| 用 `impact` 返回 0 判定死代码 | **已否决** | 教训 #36：图会漏边 |
| 删除 `tests/test_gpt_launcher.py` 整个文件 | **已否决** | 其中 4 条用例有效，只删死用例那 1 条 |

## 14. 方法论沉淀（S1–S5 全阶段实测得出，2026-10-14）

> 这些不是原则声明，是**本轮真的踩过、且反复踩**的东西。每条都附了现场。

### 14.1 「零命中 / 全通过」是关于工具的事实，不是关于代码的事实

`impact()` 报「0 调用方」而 grep 实测有 1 个（教训 #36）；vulture 60 口径 239 条生产命中里
**222 条是假死（误报率 92.9%）**；T18 差点让我以为 `_send_reply` 这类转发壳「可删」——
直到四源交叉验证（文本 / AST 属性 / AST 裸名 / getattr 动态派发 / 引号字符串）才敢动手。

**动作**：任何闸门/扫描器报「零」时，先种一个真样本看它报不报（§3 已强制）；
**删代码前必须多源交叉验证**，单一来源不足以判死。

### 14.2 变异不变红，先证明它打中了目标

这条在本轮**四次**救了判断：

| 现场 | 表面现象 | 真相 |
|---|---|---|
| T9 变异 | 测试不变红 | `find()` 命中了 191 行的 `logger.error(`，不是 helper 的 1557 行——**没打中** |
| T18 M2 | 不变红 | 我改的是**测试断言**（`>` 改 `>=0`），改弱后条件仍真——**不是有效变异** |
| T3.3 M2 | 不变红 | 打中了，但**被测行为没覆盖那条边界**（放宽 `isupper` 多出的 5 个成员恰好都非零引用）|
| T21 M3 | 不变红 | `find('mode=ro')` 命中了模块 docstring——**改的是注释** |

**动作**：变异不变红时，先打印「变异是否真的改了目标行」，再判断测试有效性。

### 14.3 数字反常时，先怀疑口径，再怀疑假设

T19：`handler.py:13392` 是 `meow=committed_reply.count("喵")`——**是次数不是布尔**。
我按布尔算出「两组都是 97%、差值为 0」，**据此否证了自己正确的假设**；
正是因为 97% 本身荒谬，才回头查口径，然后发现了「喵的会话级自锁」（40 个百分点差值）。

**动作**：算出一个「不可能」或「太漂亮」的数字，先回去读产出这个数字的那一行代码。

### 14.4 谈因果前，先证明变化发生在改动之后

T19 差点报「长度降 61%」——逐条核时刻后发现那 16 条**全在改动之前**。
**动作**：已机器化。`python tools/长期优化快照.py --quality-split '<部署时刻>'`
按时刻切分前后窗口；**单侧为空时工具拒绝给差值**（把「修复后 0 条」渲染成下降数字，是同一类错误的另一形态）。

### 14.5 锚点一律从文件读，不凭记忆拼

本轮**三次**因凭记忆写 `old_string` 而失败：T2（多行替换弄坏中间行 → `SyntaxError`）；
T4.9（漏了空行不匹配）；T4.9 变异（文件是 **CRLF** 我拼 `\n`，永远匹配不上）。

**动作**：多行替换先把实际行打印出来；写脚本时锚点用 `next(i for i, l in enumerate(lines) if pred(l))` 动态取。

### 14.6 用 `chr()` 拼中文极易算错码点

连犯两次：T14 把「别」（U+522B=21030）写成 21035；T15 把「括号写动作」拼成「拼号写动作」。
**这条早已写进记忆却仍在犯**——说明「知道教训」与「动作上改掉」是两件事。

**动作**：中文一律用**字面量**，不拼 `chr()`。写测试断言尤其如此。

### 14.7 长中文多行字符串用脚本生成整块，不要手拼

本轮**第三次**同类错误（T13/T15/T16）：手拼时漏 `\n"` 与下一行的 `"`，
导致 `agent/protocols.py:429` `SyntaxError: unterminated string literal`。
**动作**：长中文块用 Python 脚本按行生成（数组 join），中文标点用字面量。

### 14.8 假红会训练人忽略红

T3.2 加维度时，`test_memory_golden_eval.py` 的硬编码 `case_count == 70` 当场变红。
**硬编码计数的代价不是「改一次」，是「每次加维度都假红一次」**。

**动作**：断言钉**不变量**（每条都跑了且都过了），不钉**计数**（一共几条）；
计数从数据源推导（`Counter(case['dimension'] for case in cases)`）。

### 14.9 记录现状要诚实，包括「0 条」

T17/T21 都遇到「修复后样本为 0」。工具如实输出「某一侧样本为 0，不算差值——先积累数据」，
而不是给一个好看的数字。**对主人报进度同理**。

### 14.10 改渲染层与改语义层要分清

T3.2 修相对时间时，审计明令 `event_time` 语义被衰减 / Episode 分组 / 黄金集依赖。
所以做法是**只在渲染层加**——原字段照旧存、照旧用，只改显示。
**动作**：动一个字段前，先查有几个消费者依赖它的**语义**（不是只查谁读它）。
