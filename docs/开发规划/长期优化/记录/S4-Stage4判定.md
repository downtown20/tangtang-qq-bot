## 二、T4.5 FAIL 的根因（本次最重要的发现）

### 接线是完整的，我逐点核过

| 位置 | 作用 |
|---|---|
| `agent/handler.py:4017-4021` | 群聊注入点（`if _mood_report_turn:` → append 协议 + `logger.info`）|
| `agent/handler.py:5116-5118` | 私聊注入点（同口径）|
| `handler.py:4381` / `5351` | 回灌调用点（群/私），都传 `injected=_mood_report_turn` |

### 分母为 0 的真正原因在闸门

```python
feedback_candidate = self._take_feedback_candidate(group_id, user_id, 60)   # 群：60 秒
feedback_candidate = self._take_feedback_candidate(priv_key, user_id, 120)  # 私：120 秒
_mood_report_turn = bool(feedback_candidate)
```

位置：`handler.py:3122`（群）/ `4587`（私）。

**只有「她刚说完、对方在 60s（群）/120s（私）内接着回」才注入协议。** 而生产 15 天里这个窗口一次都没满足。

### 这不是缺陷，是刻意设计

审计「不要动」第 11 条明写：不加无条件常驻注入（2026-08-17 同形注入被实测有害）。
代码注释 4014-4016 的原话：**「这里的条件是闸门本身，不是优化」**。

### 所以 T4.5 的真实问题是：完成标准与设计约束冲突

规划假设「注入回合数」是个可观测量，但它被 60s 闸门挡死、**恒为 0**，于是比值永远算不出来。

### 这个发现反过来解释了审计 C3 的误判成因

C3 当年把「心情自报回灌=0」读成「LLM 没遵从协议」——**真相是分母从来就是 0**。
T1.2 加注入日志正是为了把「没注入」和「注入了但没遵从」分开，而数据现在证明：分开之后，分母确实是 0。

## 三、三条口径修正（有据偏离，显式记录）

仿 Stage 1 §7.2 的先例：规划与实际不符时，**改规划并写明为什么**，不静默偏离。

### 修正 1：T4.3 的表名是错的

| | 规划写的 | 实际 |
|---|---|---|
| 表名 | `commitments` | **无此表** |
| 判据 | `status='fulfilled'` | `tasks.status` 取值是 `done`/`failed`/`cancelled`（**无 `fulfilled`**）|

**真实的承诺闭环形态**是 `tasks` + 一条归账链：

- `tasks` 26 行（done 24 / failed 1 / cancelled 1）= 承诺本体
- `confirmed_action_facts` 23 行（kind: text 15 / sticker 8，`source_id LIKE 'task:%'` 占 23/23）= 平台确认后的永久事实
- `task_action_confirmations` 23 行 = 确认记录
- `action_receipt_mailbox` 112 行 = 回执邮箱

**为什么改**：规划写这条时凭猜测填了表名。实际架构是「承诺（task）→ 执行（action）→ 平台确认（receipt）→ 永久事实（confirmed_action_fact）」四段链，
单查一张表既查不到闭环、也会因为表名不存在而永远 FAIL。

### 修正 2：T4.1 的「每日」降级为「单点快照 PASS + 待 soak 补序列」

**为什么改**：完成标准里「每日至少一条」需要时间序列，而本次是单点。
三条理由说明不必因此判 FAIL：

1. 判定标准的核心是「**不总是 social/avoid**」（防退化成单一驱动力驱动），这一条**单点即可验证**——现值 6 条全部低于 0.85、非 social/avoid 占 4 条；
2. 序列数据可以**用 T4.9 的采样器在日常运行中积累**，不需要占用一个专门的 soak 周期；
3. `drives` 的参数（alpha / 阈值 0.7）属「长期观察项」（CLAUDE.md §二点五），本就不该由一次 7 天 soak 下结论。

### 修正 3：T4.5 的判据改为「证明分母为 0 的成因 + 给出补救观测点」

**为什么改**：原判据（注入数/回灌数的比值）**在设计约束下不可计算**——分母被 60s 闸门挡死。
判据本身要能被满足，否则它不是判据，是永远红着的灯。
改后：本条判据变成「已定位成因 + 已给补救路径」，这**已经达成**（成因见 §二；补救＝T4.8）。
