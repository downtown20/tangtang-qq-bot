## 一、摸底结论（先看清现状，再决定补什么）

### 各维度机制现状

| 维度 | 现状 | 判定 |
|---|---|---|
| 1 回复长度 | agent/personality.py 无任何长度引导；config.yaml:96 max_tokens 64000 只是 LLM 输出上限不是长度引导；self_check.py 的 _check_runaway_length 只在 >1500 字警告、>3000 字阻断 | 缺提示词层 |
| 2 消息密度 | 发现真 bug：agent/reply_pipeline.py:402 用 random.random() > 0.50 决定拆不拆——系统用随机数替 LLM 做决策，违反单脑架构（CLAUDE.md 教训 #9/#10），是「密度不合理」的直接机制原因。已有正机制：分段 标记（protocols.py:426，只开私聊，LLM 自主拆）、maybe_split_reply（群聊按长度拆 ≤2 段）| 有 bug 要修 |
| 3 语言自然度 | 已有 STYLE_ANCHOR（protocols.py，261 字符，5 组对话示例，show don't tell）；已有 anti-tell 诊断（self_check.py 7 模式 + 括号动作镜头）。但 2026-08-17 已实测「旧七模式对 983 条基线 0 命中，真实分布是括号动作 11.8%」；生产日志 anti-tell 仅命中 1 次 | 有地基，缺覆盖 |
| 4 上下文记忆 | 已有记忆证据纪律（protocols.py:115-120「不确定，不补写人物、时间、地点或动作结果」）、「你记得的事」注入段（personality.py:387，含 ID 尾号只作心理识别的说明）| 有纪律，缺追问机制 |
| 5 人格一致性 | role_card.md 只有 181 字符 / 11 行（你是谁/性格/说话 三节），无兴趣、无口头禅、无说话示例。personality.py 有 nicknames/tease_level/relationship_tiers 但 role_card 没用上 | 最大结构性缺口 |
| 6 质量目标 | 完全没有度量——tools/长期优化快照.py 无 dialog/quality 采集；tests/test_dialog_quality.py 26 条全是机制回归，没有长度分布/气泡数分布/模板命中率指标 | 完全缺失 |

### 关键实证（不是猜的）

1. 随机门控是密度问题的机制根因：reply_pipeline.py:396-436 的 maybe_split_reply 在 40-80 字区间用 random.random() > 0.50 决定拆不拆。同一句话两次发送行为不同——这正是「密度不合理」的来源。
2. anti-tell 的真实主源已取证过：self_check.py 的 docstring 原话「旧七模式对 983 条基线 0 命中……真实分布是括号动作 11.8%」。所以「少模板话术」的主战场是括号动作镜头，不是助手腔。
3. STYLE_ANCHOR 已被验证有效（test_dialog_quality.py:145 test_style_anchor_in_full_prompt），且 personality.py:148-149 注释明确「示例直接定义像糖糖说话，胜过一切语气要自然类指令」——扩写它是正路。
4. 生产日志 anti-tell 只命中 1 次，说明当前 7+1 模式在生产几乎不触发，不能作为质量指标（没有区分度）。

## 二、任务拆分（6 个任务，按「先修 bug → 再补地基 → 后建度量」排序）

### T13 · 删掉群聊拆分的随机门控（P0，最小且最该先修）

- 位置：agent/reply_pipeline.py:402
- 改什么：把 if len(reply) < 80 and random.random() > 0.50: return [reply] 改为纯长度决断（去掉随机项）。
- 为什么最小：一行；不新增机制，只是把已有的「基于长度决断而非随机」注释（L401 自己写着）变成事实。
- 不做的：不改 maybe_split_reply 其它逻辑，不动 分段 私聊路径（那是 LLM 自主，正确）。
- 验收：
  - 新测试：同一输入连续调用 N 次，结果完全一致（随机性归零的阳性对照）；
  - 保留原有长度边界行为（<40 不拆、>80 必拆、40-80 现在恒定按段落拆）；
  - 全量 pytest 全绿 + pyflakes undefined 0；
  - 变异阳性对照：把随机项加回去，新测试必须红。
- 回滚：锚点 .bak-20261014-T13；改动 1 文件 1 行。B2 合规

### T14 · 扩写 role_card.md 到「人格完整定义」（P1，维度5 主战场）

- 位置：role_card.md（181 字符 目标 600-800 字符）
- 加什么（严守 §8：role_card 只写身份，不加规则）：
  - 兴趣：她真的会主动聊的东西（游戏/音乐/猫/吃的）——这是人格一致性的锚；
  - 口头禅与语气节奏：2-3 个固定口癖 + 什么时候用；
  - 说话示例扩组：把 STYLE_ANCHOR 的 5 组扩到覆盖短答/中答/长答/被逗/低落五种场景，让长度有示例可依（同时服务维度1）；
  - 明确不做的：不写「回复要少于 N 字」这类量化规则（那是规则，进 protocols.py）。
- 注意 §8 边界：role_card.md 只写身份不加规则。长度/密度/口语化这类行为规则进 agent/protocols.py（T15）。
- 验收：
  - tests/test_personality.py 与 test_dialog_quality.py::test_style_anchor_in_full_prompt 仍绿；
  - 新增闸门：role_card 必须包含兴趣、口头禅两节 + 至少 8 组说话示例（防回退到 181 字符）；
  - _split_minimal 精简路径仍保留称呼/@提及/风格锚（已有测试 test_reload_keeps_tail_sections 钉住）；
  - 全量 + pyflakes + 变异对照。
- 回滚：锚点 .bak-20261014-T14；改动 1 文件 + 1 测试。B2 合规

### T15 · 在 protocols.py 补「自然度行为规则」（P1，维度1/3）

- 位置：agent/protocols.py（新增一个常量，仿 STYLE_ANCHOR / COMPREHENSION_PROTOCOL 的既有形态）
- 加什么（show don't tell 优先，每条配正反示例）：
  - 长度：默认一两句；对方问具体事才展开；不为了礼貌凑长度（对齐用户「减少」）；
  - 口语化：允许停顿（省略号/破折号）、语气词（啊/呢/吧/嘛/喵）；不写书面语长句；
  - 反模板：不写「作为AI」「很乐意」「我理解你的感受」；不用括号动作描写代替说话（这是已取证的真实主源，11.8%）；
  - 表情：适度，一句最多一个，不堆 emoji；
  - 不编造：复用已有的记忆证据纪律，不重复造。
- 注入点：在 build_system_prompt 里与 STYLE_ANCHOR 同层加入（personality.py 的 _load_role_card L150 附近）。
- 验收：
  - 新测试：prompt 里含新常量；精简模式（minimal）也含，或明确说明为何不含；
  - 阳性对照：给一条模板腔回复，self_check 能标出来（括号动作已在；助手腔三条旧七模式里已有，重点是验证它们在生产真的不触发，而不是新加）；
  - 全量 + pyflakes + 变异对照。
- 回滚：锚点 .bak-20261014-T15；改动 2 文件。B2 合规

### T16 · 上下文记忆：把「主动追问」机制化（P2，维度4）

- 现状：已有记忆证据纪律（不确定不补写），但没有主动追问的机制。
- 做什么（最小）：在 protocols.py 加一段 FOLLOW_UP_PROTOCOL——
  - 对方提到的事如果你记得前文，就接一句前文（你上次说……）；
  - 不记得就直接说不记得，不编；
  - 想继续聊就问一个具体问题，不要问「还有吗」这种开放式收尾。
- 注意：前文关联不新造检索机制——复用已有的 recall 与历史窗口，只在提示词层规定该怎么用。
- 验收：prompt 含新常量 + 有正反示例 + 全量 + 变异对照。改动 1-2 文件。B2 合规
- 风险：追问过度会变成查户口/索取隐私，协议里明确写「不问隐私、不问不愿答的」，对齐用户边界。

## 三、不在本阶段做的事（边界，防扩张）

1. 不真跑盲测——盲测需要真人（主人）参与，本阶段只建可机器化的代理指标（T17/T18）。
2. 不改 LLM 本身（不换模型、不调 temperature）——那是另一个决定，且模型刚配好 fallback 链。
3. 不动 分段 私聊路径——那是 LLM 自主拆，符合单脑架构；T13 只修群聊的随机门控。
4. 不新增记忆检索机制——T16 只在提示词层规定怎么用已有的 recall。
5. 不追求「零 anti-tell」——anti-tell 是诊断不是阻断（self_check.py 明确「只诊断不阻断，观测先行」），保持原样。
6. 不设数值目标——用户明说不设具体数值，T17 只做可观测。
7. 不混入 S2 剩余的 T10/T11/T12 与 S4 的 T4.8（B3 一次只做一件事）。
