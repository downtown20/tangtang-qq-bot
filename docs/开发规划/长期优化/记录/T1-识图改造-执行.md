## 二、设计要点（为什么这么做）

1. **保留唯一入口 `_call_vision`**——它的取图（`get_image` → 本地文件 → URL 兜底）、
   `run_bounded_blocking` 非阻塞读、`(sha256(bytes), prompt)` 缓存全部不动。6 个调用点**零改动**。
2. **`provider=main` 走主 LLM 原生视觉**——复用 `self.llm`（httpx AsyncClient）、`_endpoint()`
   的 `/v1` 归一、`_stream_deepseek()` 的流式解析。**不挂 tools**（识图是纯生成，工具循环徒增延迟）。
3. **MIME 用魔数嗅探**（jpeg/png/webp/gif）——URL 兜底路径**没有文件名**，靠扩展名必错；
   中转按 data URL 前缀解析，标错 MIME 会被服务端拒（实测 HTTP 400）。
4. **旧双后端保留为回退路径**——`provider=local/api` 时行为与改动前完全一致。
   不删 `vision_router.py`/`vision_local.py`：删除是不可回退的破坏性改动，
   且 `provider=local` 曾是生产值。**先让 main 成为默认并验证，再另立任务退役旧后端**（`deprecation-and-migration`）。
5. **`_get_vision_router()` 模块级包装**——`provider=main` 路径**完全不 import** `vision_router` 模块，
   同时让测试能 monkeypatch 模块级名字（既有测试打的是 `agent.vision_router.get_vision_router`，那一路仍生效）。

## 四、顺带发现的独立缺陷（已登记台账，未在本任务里修）

### T2.3 · 零调用闸门按「裸名」收集引用 → 假红

**位置**：`tests/test_integration_contract.py` 的 `_references()` / `_zero_ref_class_methods()`（line 288–303）

**证据**：新增 `tools/长期优化快照.py`（含模块级 `def snapshot()`）后，
`TestClassMethodGate::test_baseline_entries_are_still_valid` 报
`AssertionError: agent/knowledge_index.py :: snapshot`（"已被接线，需要收紧"）。
探针 `.trash/长期优化/probe_gate2.py` 实测：`_references(parsed)['calls']['snapshot'] == {'tools/长期优化快照.py'}`
—— **闸门把 tools/ 下的同名函数当成了 `agent/knowledge_index.py::snapshot` 的调用方**。

**根因**：`_references` 按**裸标识符名**收集（`ast.Name` / `ast.Attribute.attr`），不做接收者类型消解，
也不限定命名空间。任何文件（含 `tools/`、`tests/`）出现同名裸名，就把**所有**同名基线条目判成"已接线"。

**影响**：假红（不是假绿）——方向安全，但会**阻断无关改动**，且与 P3 已记录的别名 bug **同族**
（"存键用规范名、查键用裸名"）。**副作用**：有人为了过闸门而删基线，等于把真死代码洗白。

**最小修法**（待评估，不在本任务内）：引用收集时对 `ast.Attribute` 保留接收者文本，
对裸 `ast.Name` 只在**同文件**或**已导入该模块**时登记；或给基线条目加文件约束。

**本任务的规避**：把 `tools/长期优化快照.py` 的 `snapshot()` 改名为 `collect_all()`，
并在该处写明原因（**零生产影响**）。
