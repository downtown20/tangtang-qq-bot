## 一、问题（四段式）

**位置**：`tools/发布前检查.py:51,54`

```python
# 修复前
KEY_RE = re.compile(r"sk-[A-Za-z0-9]{16,}|api[_-]?key\s*[:=]\s*['\"]?[A-Za-z0-9]{16,}")
WIN_RE = re.compile(r"[Dd]:[\\/][^\s\"'，。、]+")
```

**证据**（`.trash/20261014-s5/t10_probe4.py`，实证两个扫描器的逐用例判定）：

| 用例 | `准备发布.py` | `发布前检查.py` |
|---|---|---|
| `C:/Users/John/a.txt` | HIT | **miss** |
| `E:\secret\a.db` | HIT | **miss** |
| `Z:/backup/a.txt` | HIT | **miss** |
| `file:///C:/Users/John/a.txt` | HIT | **miss** |
| `access_token = "..."` | HIT | **miss** |
| `VOLC_TOKEN=...` | HIT | **miss** |
| `SNOWLUMA_TOKEN=...` | HIT | **miss** |
| `sk-...` | HIT | HIT |

**根因**：`准备发布.py` 的路径/密钥正则经过 2026-09-19、09-20 两轮加固（任意盘符 + 1~2 分隔符 + 三类 token），
而 `发布前检查.py` 停在加固前——它自己那行注释还写着「2026-09-19 修」，但只改了反斜杠笔误，没跟上口径扩展。

**后果**：准备发布.py 拦住的东西，发布前检查.py 会报「安全通过」——**发布闸门的第二道形同虚设**。

## 二、更严重的问题：那个声称「两份必须一致」的测试是失效的

`tests/test_release_sanitizer.py` 里已经有一条测试专门防这个漂移：

```python
def test_both_scanners_share_the_same_path_pattern():
    """准备发布.py 与 发布前检查.py 各有一份路径正则——两份漂移过一次，钉住。"""
    other = (BASE / "tools" / "发布前检查.py").read_text(encoding="utf-8")
    assert "WIN_RE" in other, "发布前检查.py 里找不到 WIN_RE"
    assert r"[Dd]:[\\/]" in other, \
        "发布前检查.py 的 WIN_RE 与 准备发布.py 不同口径——两份必须一致"
```

**它从不比对两个对象。** 它只断言「另一个文件里有那个字面量字符串」，
而那个字符串（`[Dd]:[\/]`）在 `准备发布.py` 加固后**已经不存在了**——
所以这条测试在「只有 发布前检查.py 还留着旧字符串」时**依然全绿**。

**这正是 CLAUDE.md 教训 #30 的同形**：「检查器写了但从没生效」——
安全检查必须做阳性对照，只测「跑起来没报错」等于没测。

## 三、修法（2 个文件）

### 1. 口径对齐（`tools/发布前检查.py`）

把两处正则改成与 `准备发布.py` **逐字同形**：

```python
KEY_RE = re.compile(r"sk-[A-Za-z0-9]{16,}|api[_-]?key\s*[:=]\s*['\"]?[A-Za-z0-9]{16,}"
                    r"|access[_-]?token\s*[:=]\s*['\"]?[A-Za-z0-9]{10,}"
                    r"|VOLC_TOKEN"
                    r"|^[ \t]*(?:#|;|export[ \t]+)?[ \t]*[A-Z][A-Z0-9_]*_TOKEN=['\"]?[A-Za-z0-9_~.\-]{12,}['\"]?[ \t]*$")
WIN_RE = re.compile(r"(?<![A-Za-z0-9])[A-Za-z]:[\\/]{1,2}[^\s:*?\"<>|]{2,}")
```

### 2. 让一致性检查真的检查（`tests/test_release_sanitizer.py`）

- 旧测试改名 `test_both_scanners_share_the_same_patterns`，**真的加载另一个模块并比对 `.pattern` 字符串**；
- 新增 `test_both_scanners_agree_on_a_planted_leak`：**阳性对照**——种 7 条真泄漏，要求两边都报且判定一致；另加两条干净行要求不误报。

## 五、一个方法论纠错（我自己先走错了）

复核 T10 时我**先得出「登记不成立」的结论**，依据是：

- 探针 1：直接测 `准备发布.py` 的 `KEY_RE`/`WINPATH_RE` → 8 类用例全部 HIT；
- 探针 2：真实 config 的 scrub → check 往返 → 零命中；
- 探针 3：阳性对照 → 8/8 命中 + 干净样本 miss。

**三条都对，但结论错了**——因为我搜的是 `准备发布.py`，而登记写的是
「prep 用 `WINPATH_RE`/`KEY_RE` 比 chk 用 `WIN_RE`/`KEY_RE` 宽」。
`WIN_RE` 这个名字我第一遍全项目搜索时**扫过去了**（先搜了 `WINPATH_RE`），
直到去读那条一致性测试的断言，才看到 `tools/发布前检查.py` 这个第二扫描器。

**教训：登记里的每一个符号名都要逐个搜，不能因为「主文件的检查器是好的」就收工。**
「找到了一个健康的检查器」不等于「找到了登记里说的那个检查器」。
