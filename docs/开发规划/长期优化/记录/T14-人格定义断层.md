## 二、实施（最小改动：1 个新方法 + 2 行改动）

### 新增 PersonalityEngine._compose_base(role_card) -> str

把 role_card（身份层）与 config.yaml（规则层）拼成完整静态提示词。docstring 里写明分层理由防复发：**role_card.md = 身份层（§8 只写身份不加规则）；config.yaml personality = 规则层；两层都进 prompt，缺一层都不是完整的糖糖。**

拼接内容：
- core 非空 → 追加「## 你是谁（完整设定）」
- can_do 非空 → 追加「## 你的能力和行为边界」
- cannot_do 非空 → 追加「## 以下行为会让群友觉得你不像真人」
- profile 非占位 → 追加「## 你的个人档案」
- relationship_tiers 非空 → 追加「## 关系档位（亲密度由系统算，这里只说每一档该怎么相处）」
- tease_level 为正整数 → 追加「## 撩的程度」

### 两处调用点

| 位置 | 改动 |
|---|---|
| _build_cache() | self._cached_base = role_card 改为 self._cached_base = self._compose_base(role_card) |
| reload_role_card() | 先算 composed = self._compose_base(role_card)，锁内 self._cached_base = composed（热重载也不能再丢规则层）|

### 为什么这些拼接块不破坏缓存契约

全部是静态内容（can_do/cannot_do/core/tiers/tease 都不随关系、情绪、时间变化），因此 tests/test_personality.py 钉住的「稳定前缀跨调用完全一致」仍然成立（已实测为 True）。

### 顺带修的过期断言

tests/test_personality.py:135 原断言 assert eng._cached_base == 'NEW ROLE CARD'（期望 base 是纯 role_card）——T14 后 base 是拼接结果，改为 assert 'NEW ROLE CARD' in eng._cached_base。该测试的核心断言（重载不暴露半成品、读取不被慢 I/O 阻塞）未动，仍有效。

## 四、踩坑（记入环境事实）

1. B1 止损：写 test_minimal_keeps_identity_and_anchor 时消耗轮次超出单任务预算。双重原因：
   (a) pytest traceback 的中文源码显示在 UTF-8/GBK 之间错位——报的失败行文本与磁盘内容不一致，我一度误判为缓存问题，白查了 4 轮（__pycache__ / 复制新文件名 / --assert=plain / 清 .pytest_cache）；
   (b) 我自己用 chr() 拼中文断言时算错码点（「别」是 U+522B 即 21030，我写成 21035 即 U+523B）。
   处置：按 B1 纪律删掉该冗余测试——它的价值已被 test_minimal_has_no_rule_layer 与既有 test_reload_keeps_tail_sections 覆盖，保留 12 条有独特价值的。
   教训两条：chr() 拼中文极易算错码点，直接用字面量；pytest 中文失败行显示不可尽信，以磁盘内容为准。
2. _cached_minimal 里没有「## 你是谁」节——_split_minimal 会砍掉 你是谁/性格/说话 三个章节，只保留铁律+称呼+@提及+风格锚。我最初的断言写错了对象。
3. Edit 工具在 CRLF 文件上工作正常：personality.py 是 CRLF 文件（440 变为 577），多行替换后行尾保持 CRLF。
