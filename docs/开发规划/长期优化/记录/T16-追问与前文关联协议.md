## 一、定位：补的是同一枚硬币的另一面

摸底时发现，「承认不确定」已经有纪律了：

- protocols.MEMORY_EVIDENCE_CONTRACT：查不到可靠来源就直说不确定，不补写人物、时间、地点或动作结果
- protocols.GROUNDING_CONTRACT：材料里没有的具体细节（地点、事件、时间）不要编
- agent/personality.py:387 的「你记得的事」注入段（含 ID 尾号只作心理识别的说明）

缺的是反面：记得的时候，要真的用起来。所以 T16 不是加一条新纪律，而是把 FOLLOW_UP_PROTOCOL 补在既有「不确定」纪律旁边，两者成对。

## 二、做什么

agent/protocols.py 新增 FOLLOW_UP_PROTOCOL（363 字符），四段：

| 段 | 内容 | 对应用户反馈 |
|---|---|---|
| 接住前文 | 材料里真有就顺一句「你上次说……」；一句话就够，不要复述整段；材料里没有的细节不补；不记得就直接说不记得（编的会被拆穿，拆穿一次，之前所有的记得都打了折扣）| 长期关联前文 + 承认不确定 |
| 该追问的时候 | 想让对话继续，就问一个具体的问题，问那件事本身、问对方刚提起但还没说完的部分；不要问「还有吗」「然后呢」这种谁都能接的收尾句（那不是在聊，是在把球踢回去）| 主动追问 |
| 不该追问的时候 | 对方明显不想聊（只回嗯/哦/没事）、在说正事、在发泄情绪，接一句就够了，别连珠炮；沉默和一句「我在」也是回应 | 避免刷屏与压迫感 |
| 边界 | 不问收入、不问住址、不问家里的事、不问健康和身体的细节；对方自己愿意说的可以接，对方没提的不要挖 | 用户边界：不主动索取隐私 |

### 为什么追问协议必须带边界段

用户的六维度里，「主动追问」和边界里的「不主动索取隐私」直接冲突——不加边界的追问协议会把「问一个具体的问题」执行成查户口。所以边界不是附加说明，是协议的必要组成部分。

### 不新造检索机制

协议里明确写「上面的材料里真有」，只规定怎么用已经注入进来的材料（记忆/画像/历史窗口），不新增任何检索路径。这符合 B5（只做北极星工作）与 CLAUDE.md 教训 #6（框架是抽出来的，不是建出来的）。

## 五、踩坑

1. edit 的 old_string 锚点写错一次：我按记忆拼 REPLY_NATURALNESS 的尾部作锚点，但把双引号写成了转义形式，实际文件里是裸双引号。改用短锚点（只锚一行加收尾右括号）后成功。教训：锚点要短、要刚读过。
2. NL.slice(0) 返回空串：我在 new_string 里写了一个拼接表达式，本意是拼注释行，结果井号后面直接跟了空，产出一行没有井号的裸中文，ast.parse 报 invalid character。用脚本补井号前缀修好。教训：要拼接分隔符时，别用 slice(0) 这种看似聪明的空操作，直接写完整字符串。
3. 变异探针第一版锚点找错文件：FOLLOW_UP_PROTOCOL 的定义在 protocols.py，我却去 personality.py 里找，断言直接失败。改成两个文件分别持基线后通过。教训：变异要改定义处和注入处两处，脚本要把两个文件都冻结加还原。
4. 多行 Python 字符串拼接又漏括号：变异脚本里 gut 赋值的续行缺加号，报括号未闭合。这是本轮第三次同类错误（T13/T15/T16 都犯过），长拼接一律用数组 join，不用隐式或显式续行。
