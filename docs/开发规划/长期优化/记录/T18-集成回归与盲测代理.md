## 一、两件事

### 1. 集成网：T13-T17 必须同时在场

T13-T17 各自有单元测试，但**没有任何测试断言它们共存**。
本文件补上：拆分确定性（T13）、两层人格（T14）、自然度规则（T15）、追问协议（T16）、遥测接线（T17）
在同一个 prompt / 同一次调用里全部生效，且三个「怎么说话」的块顺序正确（说话示范 → 回复的分寸 → 接住前文）。
另有 `test_prompt_budget_sane` 守住提示词不被无限膨胀（3000 < len < 8000）。

### 2. 机器化盲测代理

用户的质量目标里有「盲测真人误判率」——那需要真人。本代理**不替代它**，是一个廉价的替身：

- 7 条**刻意机器味**样本（每条命中一种已取证的模板特征）；
- 6 条**自然口语**样本（短、有停顿、无模板特征）；
- 用**既有的** `ReplySelfCheck` 判它们，断言机器味那组明显更差。

它客观回答一个问题：**我们自己的质量闸门还分得清这两者吗？**
如果哪天两组都绿，说明闸门失去区分度——那才是真问题。

## 二、代理发现的两个真实缺陷（已如实记录为「已知张力」）

建代理时踩到两个不是测试数据问题的真实现象，按取证纪律**记录而不是掩盖**：

### 张力 1：括号动作判定的词表不对称

`agent/self_check.py:260-261` 的括号动作正则是**内联写死**的，词表只有 10 个猫相关词：
`耳朵|尾巴|猫耳|眼睛|蹭|呼噜|炸毛|歪头|小爪|耳朵抖`。

**它不覆盖通用舞台动作**——`（笑了笑）`、`（叹气）`、`（眨眼）` 全部漏检。
（`（歪头）` 能抓到，`（笑了笑）` 抓不到。）

**而采集侧不对称**：`reply_metrics.bracket_action` 统计的是通用括号动作。
⇒ **写入方和判定方对「括号动作」的定义不一致。**

而且这违反 `_ANTI_TELL_PATTERNS` 自身的组织原则——模式应在常量里，不该有内联正则。
测试 `test_bracket_catcher_only_covers_cat_words` 钉住**当前行为**，缺陷修好后它会红，提示「更新这个测试」。

### 张力 2：风格锚教她说的话，自检器会拦

`protocols.STYLE_ANCHOR` 的第一条正面示例是「群友：糖糖在吗 → 糖糖：**在的**」。
而 `ReplySelfCheck._check_blank` 会把任何短于 `_MIN_REPLY_LENGTH` 的回复 **hard-block**（「回复过短或为空」）。

⇒ **风格锚树立的范本，如果 LLM 真照做，会被自检拦下。**
测试 `test_style_anchor_short_example_is_flagged` 钉住这个张力，并注明「解决需要主人拍板」（提高下限豁免直答，或删掉那条示例）。

### 变异对照 v1 的失败与纠正（值得记录）

第一版变异**改的是测试断言**（`assert mech_warn > nat_warn` 改成 `>= 0`），结果**三次都不变红**。
原因：**改弱断言后条件仍为真**（`mech_warn > nat_warn` 本身就是真的），这不是有效变异。

第二版改为**改产品代码**（把 random 加回去 / 摘掉注入 / 禁用判定），立刻变红：**S5 的结论**

**教训：有效变异必须破坏被测行为，不是弱化断言。** 只有「把产品改坏 → 测试必须红」才叫阳性对照。
