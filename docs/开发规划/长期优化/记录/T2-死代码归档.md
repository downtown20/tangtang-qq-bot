## 三、删除中发现的结构性缺口（重要）

### 零引用闸门只覆盖公共方法

`tests/test_integration_contract.py` 的 `CLASS_METHOD_BASELINE` 闸门扫描条件是：

```python
if (isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef))
        and not node.name.startswith("_")):
```

**`not node.name.startswith("_")` —— 私有方法全在覆盖外。**
而这次删的 7 条**全是私有方法**，所以闸门从头到尾没见过它们、也不会因为删除而报「基线腐烂」。

⇒ **私有方法零引用无人管。** 这不是本次要修的（B2：一次一件事），但本任务留下测试钉住这个缺口，
并把它写进台账待办，避免它悄悄消失。

## 五、踩坑

1. **`edit` 工具把三行一起替换时把中间行弄坏了**——我一次给的三行 old_string 与实际不符，
   结果修复后第 72 行残留 `'gpt-sovits', ...)):` 造成 `SyntaxError: unmatched ')'`。
   最终用脚本按行号精确替换（`lines[70:73] = [...]`）修好。
   **教训：多行替换要先把实际行读出来核对，不要凭记忆写 old_string。**
2. **测试文件扫到自己**：`test_symbol_has_no_reference_at_all` 用 `ROOT.rglob('*.py')` 扫全项目，
   而测试文件自己把 7 个符号名当数据写着 ⇒ 自指失败。加 `skip` 名单（同时排除 `.trash` 里我自己的探针）。
3. **`_copy_json` 是模块级函数**，我的删除脚本正则要求行首有缩进（`^\s+def`），第一次直接 `NOT FOUND`。
   改为按行号定位（先打印找到再删）。
