## 二、处置①：`tools/变异对照.py`

把「故意改坏 → 必须红 → 还原」做成一命令：

```
python tools/变异对照.py --target agent/foo.py --tests tests/test_foo.py \
    --mut "M1:旧串=>新串" --mut "M2:旧串=>新串"
python tools/变异对照.py --spec 变异.json        # 串里有换行时用这个
```

关键约定（每一条都对应一次踩坑）：

- **锚点必须恰好出现一次**：0 次（写错/文件已改）或 ≥2 次（不唯一）直接报错退出，**绝不尽量匹配**；
  自动适配 CRLF（本仓多数文件 CRLF，锚点写 LF 会 count=0）。
- **无论红绿都还原**，并核对 sha256 **逐字节一致**；还原失败立刻非零退出（宁可不跑，也不留脏文件）。
- **GREEN 的变异一律算不合格**（退出码 2）——这是本工具存在的理由：把假变异变成一次失败，
  而不是一句「这次变异没红，可能是我改得不够狠吧」。想显式接受必须写 `--allow-green M1`。
- 子进程编码**两端钉死 UTF-8**（与 T2.9 的 `_run_capture` 同口径）；**工具自己的 stdout/stderr 也 reconfigure 成 UTF-8**
  ——不然外部注入 `PYTHONIOENCODING=latin-1` 时它会打印中文时自己崩（与要防的形态 ③ 同一个病）。
- `--root` 可指向临时目录（自测用）；默认仓库根，且拒绝仓库外的目标。

## 三、处置②：工具自己的自检 `tests/test_mutation_harness.py`（6 条）

**判据的判据也要有对照**，所以每一条都是阳性对照：

| 用例 | 断言 |
|---|---|
| 真变异 | 报 `RED OK`，退出码 0，目标文件逐字节还原 |
| **空变异（只改注释）** | **必须报「假变异」并以退出码 2 失败** —— 不许当成通过 |
| `--allow-green` | 显式接受后退出码才回到 0（唯一例外通道） |
| 锚点不唯一 | 拒绝执行（退出码 1），且不得改动文件 |
| 外部注入 `PYTHONIOENCODING=latin-1` | 工具仍能打印中文并正确判定 |
| 基线就红 | 拒绝继续（变异对照无意义） |

## 六、边界

- 只支持**同一文件内的锚点替换**变异；不支持「新增文件 / 整文件替换 / 多文件联动变异」。
- 一次变异只跑一个 `--tests` 目标（够用：变异对照按判据粒度做，不是按全套做）。
- **它治不了形态 ①②③**——那三种要靠 T2.12 的闸门体检逐个补阳性对照。
