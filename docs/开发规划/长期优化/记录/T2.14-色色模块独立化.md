# T2.14 色色模块独立化（亲密范本不再走背景池）

> 2026-10-16 晚。主人判定：**色色模式依赖的框架本身有问题**，不能只在框内做局部调整，
> 色色模块必须解耦成独立模块；并明确「预算无需削减」。本文件是实施记录。

## 一、要解决的是什么

「进入色色模式后不够色」——取证结论（T2.13 + 子代理报告，两路独立）：**不是没学进去，是学进去了也一个字到不了她**。

| 层 | 事实 |
|---|---|
| 磁盘 | `knowledge/色色参考/` 29,011 字（数字槽位 11,529 + `_原文` 归档 17,601） |
| ① 索引 | 整目录被 `SENSITIVE_DIRECTORY_NAMES` 排除（防越权，设计正确） |
| ② 取材 | 只吃数字槽位 → 11,529 字 |
| ③ 交付 | 走 `knowledge_block()`（为**检索结果**写的函数）→ `[:1500]` 砍掉 **86.3%** |
| ④ 分配 | 以 `知识库=P15`（全表**最低**优先级）进 1200t 公共池 → 上限 600t，池紧即整块丢 |

**实测后果**：06:21–07:02 共 **33 条色色回合，33/33 全部整块淘汰**；孤立复现也只剩 258 字（2.2%）。
性质是**框架错配**：把一份 1.15 万字的风格教材，当成一条会被优先级淘汰的检索片段投递。

## 二、设计：独立模块 + pinned 投递

**新增 `agent/intimate_reference.py`**（唯一拥有者）：三条数字槽位的发现/加载/格式/逐槽位字数告警/cache；
自己的 caveat（不是检索那套「参考观点/防编造」——那会把她推向「转述资料」的腔调），**没有任何字数上限**。

**投递走新通道** `protocols.assemble_user_message(backgrounds, user_text, pinned=...)`：

- pinned 块 **不进 `fit_backgrounds`** ⇒ 既不按优先级被丢，也不受单块 600t 上限；
- 位置固定在最前（内容随版本稳定 ⇒ 前缀缓存友好），仍用 `bg()` 包裹（维持「无标签 = 对方说的」契约）；
- 标签单一事实源 `protocols.INTIMATE_REFERENCE_LABEL = "色色范本"`。

**排除的三个替代方案**：
1. **把优先级从 P15 提前**——那会让 11.5k 字直接吃穿 1200t 池，等于用别的东西换（记忆/窗口/关系全被挤掉）；
2. **给 `knowledge_block()` 加参数上限**——形态仍错（检索用 caveat + 背景池语义），只治标；
3. **塞进 system prompt**——前缀缓存随范本变动失效，且 system 中段的遵从度低于 user 末段。

## 五、边界与未决

1. **记账缺口（已知，未修）**：pinned 在 `fit_backgrounds` 之外，token 报告不统计它 ⇒ 色色回合真实上下文比报告大 ~1.8 万 t。
   主人已明确「预算无需削减」，所以不裁；但**账要看得见**，下一步应在日志/报告里补上这一项。
2. **归档不作自动检索**：`_原文/` 里有蒸馏刻意排除的内容（`CG系统说明`、`睡奸与醉奸…`），
   开放按需检索等于绕过那条决定 ⇒ 模块里不接线，注释写明需主人拍板白/黑名单（测试钉住 `hasattr(IR, 'search_archive') is False`）。
3. **两条不在本条链路的原因仍未处理**（都不是知识库问题）：
   ① `config.yaml:100-103` 的色色栈是 deepseek 官方 + `deepseek-v4-flash`，而主栈是 custom + `deepseek-v4.1-flash`；
      日志只打印全局 provider，**不能反证**它没影响风格 ⇒ 换不换要主人定（一行配置）。
   ② `handler.py` 的色色引导里写着「呻吟比脏话色 100 倍」（同时说「脏话不是禁忌」）——语气偏软，是否调整取决于主人取向。
4. **需要重启才生效**：本次改了 `agent/`（handler/protocols/新模块），运行中的 bot 不受影响也不会自动加载。
