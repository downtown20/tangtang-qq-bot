## 一、问题：92.9% 的噪声让棘轮失去意义

T2.1 普查实测：vulture 60 口径 239 条生产命中里 **222 条是假死**（误报率 **92.9%**）。

而章程 §5.2 把「vulture 命中数」列为**棘轮指标（只许降）**。
**一个 92.9% 都是噪声的指标，无法用来发现真回归**——数字在 315 附近随机波动，
真死代码增删 1 条完全淹没在里面。

## 二、做了什么

新建 `vulture_whitelist.py`：只声明**结构上必然活跃**的名字（即「活了但不经静态引用到达」）。
按 T2.1 记录的四个结构类别生成：

| 类 | 数量 | 判据（可机械核对）|
|---|---|---|
| 1 技能注册 | 8 | 函数名以 `_skill` 结尾且上下文有 `@register_skill` |
| 2 Qt 回调 | 3 | 名字在 Qt 事件回调白名单内（`paintEvent`/`mousePressEvent`/`sizeHint`…）|
| 3 实例属性 | 21 | 定义行匹配 `self.X = …` |
| 6 导入绑定 | 6 | 定义行是 `import` / `from … import` / 类定义 / 模块级赋值 |
| 7 类定义 | 5 | 定义行是 `class X` |

合计 **42 个名字**。

接入 `tools/长期优化快照.py` 的 `collect_vulture()`——带白名单一起跑，棘轮用过滤后的数。

## 四、关键陷阱：全量白名单 = 把闸门关掉

生成过程中我实测了一个危险做法：

```
把 315 条命中**全部**写进白名单  ->  vulture 永久报 0
```

**一个永远报 0 的闸门，和没有闸门无法区分**——而且更糟，因为它看起来是绿的。
这正是教训 #30 的变体（「检查器写了但从没生效」）。

所以白名单的准入规则写进了文件头注释，三条必须同时满足：

1. 属于普查记录的四个结构类别之一；
2. 定义行形态**经核对**（不是看着像）；
3. 加完后**重跑阳性对照**：种一个真死函数仍要被抓到。

### 阳性对照（每次改白名单都要跑）

```
M0 未种植       -> 243 命中，planted 0   （期望 0）
M1 种 _planted_dead_zzz -> 244 命中，planted 1   ✅ 仍被抓到
M2 移除         -> 243 命中，planted 0   （回到基线）
阳性对照: PASS
```

## 五、过程中修正的两次自己的错误

### 错误 1：按**名字**猜类别（不是按定义行）

第一版分类器写的是「以下划线开头 ⇒ 实例属性」。结果 9 个名字被判「类别外」，
一看全是 `active_conversations` / `total_tools` / `image_gen` / `daily_report` 这类
**不带下划线的实例属性**。

**名字不是它是什么的证据，定义行才是。** 改成读 vulture 报的 `(file:line)` 取真实定义行后对了。
这条也写进了测试的 docstring，防止后人再按名字猜。

### 错误 2：模块归属靠猜

`MessageHandler` / `QDialog` / `Property` 被归到了错误的模块（它们是跨模块导入或类定义）。
修正为：从定义行解析真实来源（`from X import N` 取 X），并对 `import A, B, C` 这种
多名导入列表做了专门处理。

### 错误 3（测试侧）：绑定判据太窄

测试最初只认 `class X` 和 `import X as _alias`，漏掉 `from x import A, Property, B`
（名字在列表中间）。放宽为「该名字在这个模块里被绑定」的通用判据后通过。

**三次都是「判据太窄产生假红」，而不是白名单有问题**——假红先怀疑判据。
