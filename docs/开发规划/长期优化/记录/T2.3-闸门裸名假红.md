# T2.3 · 零调用闸门按「裸名」收集引用 → 假红 —— 执行记录

> 完成日：2026-10-14 ｜ 状态：**已完成**
> 上游任务：T1 识图改造完成后跑全量测试时暴露（非主动排查命中，是棘轮自己在工作）

---

## 一、现象

T1 验收跑全量测试时，`tests/test_integration_contract.py::TestClassMethodGate::`
`test_baseline_entries_are_still_valid` 报红：

```
AssertionError: 基线登记的**已被接线**的方法，需要收紧删除，或从项目里删掉
    agent/knowledge_index.py :: snapshot
```

而 `agent/knowledge_index.py` 的 mtime 是 2026-08-31——**我根本没动过它**。

## 二、根因（一行）

`tests/test_integration_contract.py` 的 `_references()`（line 110-126）按**裸标识符名**
收集引用，`_zero_ref_class_methods()`（line 288-303）把裸名调用也当作
「类方法被调用」的证据：

```python
if calls.get(name) or attrs.get(name) or strs.get(name):   # calls 桶里混着裸名调用
    continue                                                # → 判成「已接线」
```

我在 T0 新建的 `tools/长期优化快照.py` 里有一个模块级函数 `def snapshot()`，
于是 `_references(parsed)['calls']['snapshot'] == {'tools/长期优化快照.py'}`——
**闸门把 tools/ 下的同名函数当成了 `agent/knowledge_index.py::snapshot` 的调用方**。

探针实测（`.trash/长期优化/probe_gate2.py`）：

```
_references(parsed)['calls']['snapshot'] = {'tools/长期优化快照.py'}
```

### 为什么这是假红（不是真发现）

**类方法必须经接收者到达**——裸名 `snapshot()` 只可能指向模块级函数，
不可能指向 `SomeClass.snapshot`。所以裸名调用对类方法而言**从来不是有效证据**，
把它并进 `calls` 桶是纯错误：既永远抓不到真的（真的都在 `attrs` 桶），
又会对外来同名标识符假红。

### 与 P3 的关系（同族）

2026-10-13 P3 已记录过同一份文件的另一半病：`_global_aliases`（line 52）原先
ast.walk 整个文件，把函数内局部赋值也当全局别名 → **函数闸门**假红。
P3 把 Name 目标收窄到模块级修好了那一半；**这次是另一半**——
`_references` 的裸名口径没跟着收窄。两处合起来才是完整的「引用收集要按作用域」修复。

### 为什么危险

闸门报的文字是「需要收紧删除，或从项目里删掉」——**字面在要求删基线**。
而这条基线登记的是真死代码：它一旦被删，`('agent/knowledge_index.py','snapshot')`
就永久离开监控面。也就是说这个假红不只是吵，它**主动诱导把死代码洗白**。

## 三、被否决的修法（记录原因，防复发）

| # | 方案 | 为什么否决 |
|---|---|---|
| v1 | 裸名调用若该名在**本文件模块级已定义**就丢弃 | 实测会收窄 **636** 个名字的引用集（大量真在被调用的同文件符号被判零引用）——方向从假红变成**造假红**，且危险得多（诱导人删活代码） |
| v2 | 拆两个桶：本文件定义的进本地桶，其余进全局桶 | 全局桶仍会接纳外来裸名，对 `snapshot()` 不 import 的情形依然误判 |
| C2 | 裸名调用须该名在**本文件 import 过**才算证据 | 语义上也能修好，但比 B 复杂（要 per-file import 表），且在类方法场景收益为零——实测 B 与 C2 在真实仓库上结果完全相同 |

## 四、采用的最小修法

`_zero_ref_class_methods()` 里去掉裸名那一项证据：

```python
_calls, attrs, strs = _references(srcs)      # 原：calls, attrs, strs = ...
...
if attrs.get(name) or strs.get(name):        # 原：if calls.get(name) or attrs.get(name) or strs.get(name):
    continue
```

外加 9 行注释写明为什么（**教训 #21：有原则的例外/决定都要写进 docstring，否则会被好心修回去**）。

**函数闸门 `_agent_public_functions` 完全没动**——模块级函数**就是**靠裸名调用的，
实测有 85 个公共函数仅靠裸名证据才不被判死，那是正确口径。

## 六、顺带确认的推广结论（未修，只登记）

1. **新文件名/新函数名不得与既有类方法同名**——本次假红就是这么来的。已写进 README。
2. `_references` 按裸名收集是**整份文件**的共同口径，函数闸门靠它吃饭、类方法闸门
   不能吃它。这个「同一份数据两种正确口径」的不对称本身是个隐患，但本次只修了
   出问题的那一半（章程 §4：一次只修已取证的一条）。
