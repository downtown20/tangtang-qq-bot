# T2.7 被戳回应交权（系统不再替她说话）

> 2026-10-16 夜，T59 轮「给 LLM 减负」主线第三例（前两例：T2.4 补读门控、T2.6 社交小动作）。

## 一、问题：四条决定，没有一条是她的

取证（`agent/handler.py` 改造前的 `handle_poke`）：

| 旧行为 | 决定的是什么 |
|---|---|
| `if random.random() < 0.3:` 直接反戳 | 要不要反戳（骰子） |
| 按亲密度三档 `random.choice(replies)` | **说什么**——台词是系统写死的：「干嘛啦！」「别戳了痒...」「谁戳我」「？」「有事吗」 |
| `if random.random() < 0.5 and stickers` | 用图还是用字 |
| `if face and random.random() < 0.4` | 要不要换成 QQ 表情 |

这不是「系统没接上 LLM」，而是**系统直接冒充她说话**——比关键词门控更彻底（门控至少还让 LLM 说，只是决定要不要说）。
项目里已有对的样板：`handle_group_increase`（入群欢迎）写的正是「系统只提供信息，不替 LLM 做决策」。

## 二、处置

**给材料 → 她决定 → 系统发送**：

| 谁 | 负责什么 |
|---|---|
| 系统 | ① 材料：昵称 / 亲密度档位（很熟 / 认识但不太熟 / 基本不熟）/ 群里最近 6 条在聊什么；② 把她的意图发出去并记投递状态；③ 黑名单群直接不响应 |
| 她 | 回一句话 / 反戳回去（写 `[戳回去]`）/ 只丢表情（`[贴图:关键词]`）/ **干脆不理（空回复）** |

**协议**（`agent/protocols.py`）：
- `POKE_BACK_MARKER = "[戳回去]"`——反戳是**动作**，必须在 `clean()`/enrich **之前**解析
  （clean 会剥方括号，之后就再也读不到她的意图）；同时在 `strip_protocol_markers()`（发送前
  统一剥离出口）登记，保证它**永远不会漏到用户眼前**（解析窄、兜底宽）。
- `POKE_DEGRADED_REPLY = "？"`——**仅当 LLM 调用失败**时使用的中性兜底。
  她主动输出空回复 = 她的选择，**不走兜底、也不假装她说过话**。
  这一条是刻意区分的：教训 #27 要求「空回复不许静默」，但把失败伪装成「她说了句话」
  比说一句「？」更坏——前者会污染她的人格印象，后者只是诚实降级。

**契约**：`handle_poke` 现在也是 LLM 直发点，已登记进 `tests/test_integration_contract.py`
的 `LLM_SEND_FUNCS` 表（发送前必须过 `_enrich_reply_async`，否则 `[贴图:x]` 会原样泄露）。

## 五、边界（没做）

- **她的被戳回应没有进聊天史**（没调 `log_chat`）——与 `handle_group_increase` 同状态。
  这会让她「不记得自己回过戳」；但补进聊天史要动归账/去重口径（T2.1/T2.2 那套回执账本），
  不是本轮范围，已登记台账。
- **私聊不能反戳**：本仓没接 `friend_poke`（与 T2.6 同一条边界）。现在她若在私聊写 `[戳回去]`，
  只记一条 info 日志、不发动作，也不假装戳了。
- `QQ_FACES` / `EMOTION_TO_FACE` 两张表留在 `sticker.py`（纯数据）。
