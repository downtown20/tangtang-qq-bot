## 一、缺口

用户原话点名的三个问题：**回复长度不稳定 / 消息密度不合理 / 语言机械**。

| 症状 | 现状 |
|---|---|
| 回复长度 | `reply_metrics.reply_len` 已记（T17 接上读取方）|
| 语言机械 | `assistant_tell` / `meow` / `bracket_action` 已记 |
| **消息密度** | **没有任何字段** |

而「密度」的定义恰恰是「**同样多的字，发成几条**」——
只记 `reply_len`（正文多长）永远量不出密度。

**数据本来就有**：`ReplyPipeline.last_delivered_parts` 每次发送都会填，
`handler.py:13353` 也早就把它复制进了 `_last_checked_send_parts`。
**只是没人把这个数字写下来。**

（这是教训 #12/#14 的又一形态：数据在手上，观测链断在最后一厘米。）

## 二、做什么（3 处改动，2 个文件）

### 1. `agent/store.py` —— 建表加列 + **迁移**

```sql
CREATE TABLE IF NOT EXISTS reply_metrics (
    ...
    hard_turn INTEGER,
    bubble_count INTEGER      -- 新增
)
```

**关键：`CREATE TABLE IF NOT EXISTS` 对【已存在】的表不会补列。**
老库必须显式迁移，否则新 INSERT 会因列数不符而**整条失败**——
而遥测写入是 `try/except` 包着的，失败只会打一条 warning：
**表现就是「遥测从此静默归零」，没有任何人会发现。**

所以加了迁移（沿用本文件既有写法，见 `send_outbox`）：

```python
_rm_columns = {row[1] for row in conn.execute("PRAGMA table_info(reply_metrics)")}
if "bubble_count" not in _rm_columns:
    conn.execute("ALTER TABLE reply_metrics ADD COLUMN bubble_count INTEGER")
```

### 2. `agent/store.py` —— 写入方加参数

```python
def record_reply_metric(self, *, ..., hard_turn: int = 0,
                        bubble_count: int = 0) -> None:
```

默认 0，**保留旧调用点可用**（不破坏既有测试、不要求原子式全量改调用方）。

### 3. `agent/handler.py:13404` —— 接上数据源

```python
bubble_count=len(self._last_checked_send_parts) or 1,
```

**为什么是 `or 1`**：`_last_checked_send_parts` 极少为空（只在极端路径）；
而「发出去了」这件事本身已经蕴含「至少一条」，记 0 会是自相矛盾的数（有一条已确认送达却记 0 条气泡）。

**为什么用「实际送达」而不是「意图拆分」**：密度问题是「她**实际**发了几条」；
拿 `presplit_parts`（她想发的）会掩盖发送失败导致的差异。这不是理论洁癖——
`_last_checked_send_parts` 正是逐段确认的产物（T2.2/T2.3 的审计 P0-3），它回答的就是「真的到了几条」。

### 9 条测试覆盖

**迁移**（4）：fixture 确实**不含**新列（防 fixture 写错导致假绿）/ `Store(db)` 后列出现 /
**老行保持 NULL 且原数据不丢** / 迁移**幂等**（连开两次不炸、列不重复）；
**写入方**（4）：接受 `bubble_count` 并落库 / 旧调用点不传仍可用（默认 0）/
签名声明且默认值为 0 / `CREATE TABLE` 里也有这一列（新库不依赖迁移）；
**接线**（1）：handler 的遥测调用窗内必须有 `bubble_count=` **且** 必须引用 `_last_checked_send_parts`
（防有人改成传 `presplit_parts` 或写死数字）。

**为什么「老行保持 NULL」是一条硬断言**：历史数据**真的不知道**发了几条。
填 0 或填 1 都是**编造历史**——那会让「改动前后的密度对比」看起来有基线，而那个基线是假的。
这正是 §14.4（先证明变化发生在改动之后）要求的诚实。

## 四、踩坑

1. **写测试文件时又在字符串里嵌了真实换行**——`assert` 的消息跨了两行，
   `SyntaxError: unterminated string literal`。这是**本轮第四次同类**（T13/T15/T16/T22）。
   已用脚本把断行接回（`'... table '` + `'- the ...'`）。**工作纪律：断言消息写单行，或显式 `chr(10)` 拼接。**
2. **变异脚本锚点又漏了 CRLF**：`handler.py` 是 CRLF，我把锚点写成 `内容 + \n`，
   `assert old2 in h` 直接失败。改为**只锚行内容、不锚行尾**后通过。
   **这是 T4.9 同款第三次**——纪律已在 §14.5：锚点一律从文件读，不拼行尾。
