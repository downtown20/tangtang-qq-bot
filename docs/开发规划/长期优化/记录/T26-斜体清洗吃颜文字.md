
**「6 字变 2 字」** —— 什么文本会被削掉三分之二？顺着查下去就找到了 T26。

## 二、缺陷

`agent/reply_pipeline.py:173` 的斜体清洗：

```python
# QQ 不渲染 **bold** 和 *italic*，永远洗掉
# 但保留颜文字（如 (*^▽^*) (๑´ㅂ`๑)）——只洗掉纯文字用 * 包裹的情况
reply = re.sub(r'(?<!\*)\*(?!\*)([^*\n]*[\w一-鿿぀-ヿ][^*\n]*)(?<!\*)\*(?!\*)', r'\1', reply)
```

**注释明确承诺「保留颜文字」，但判据实现不了这个承诺**：
它要求星号之间**至少有 1 个字词字符**，而 **`_` 和 ASCII 字母都算 `\w`**。

⇒ `(*^_^*)` 中间的 `^_^` 含一个 `_` → 判定为「斜体」→ 星星被吃掉：

```
'好耶 (*^_^*) 开心'  ->  '好耶 (^_^) 开心'
```

**`(*^_^*)` 是最常见的颜文字之一。**

### 为什么注释里的例子都「测过却是对的」

注释举的两个例子 `(*^▽^*)` 和 `(๑´ㅂ`๑)`，它们星号之间的内容是 `^▽^`——
`▽` 是符号（So，非字母非数字非下划线），**不属于 `\w`**，所以**恰好**没被匹配。

**注释作者大概是拿这两个例子验的**——而过的是因为它们「恰好没有字词字符」，
不是因为判据正确。这是一个**用例子代替规则**的典型失误。

### 测量方法的坑（差点漏掉）

一开始我在**短句**上测，结果 `(*^_^*)` 显示「未变」——**是假象**：
`(*^_^*)` 剥离后只剩 2 字，触发了「洗太狠了」回退分支，
而回退分支**不执行 markdown 清洗**，于是把它「救」回来了。

⇒ **必须放在长句里测**（结果 >3 字，不走回退）才看得到真实行为。
测试里专门写明这一点。

## 三、修法

把「至少 1 个」改成「**至少 2 个连续**」：

```diff
- [\w一-鿿぀-ヿ]
+ [\w一-鿿぀-ヿ]{2,}
```

**判据**：`^_^` 里没有连续两个字词字符（`^` 隔开了唯一那个 `_`），
而 `abc` / `重点` 都有连续的两字以上 ⇒ **颜文字保住，真斜体照洗**。

### 实测对照

| 输入 | 修前 | 修后 |
|---|---|---|
| `好耶 (*^_^*) 开心` | `好耶 (^_^) 开心` ❌ | `好耶 (*^_^*) 开心` ✅ |
| `好耶 (*^▽^*) 开心` | ✅ | ✅ |
| `好耶 ヾ(≧▽≦*)o 开心` | ✅ | ✅ |
| `这是 *重点* 内容` | `这是 重点 内容` ✅ | `这是 重点 内容` ✅ |
| `*abc*` | `abc` ✅ | `abc` ✅ |
| `*a b*` | `a b`（洗）| `*a b*`（留）|

**7/7 颜文字全部保住；2/2 真斜体照洗。**

### 一个有意的行为变化

`*a b*` 不再被洗。这是**接受**的取舍：单个字母 + 空格的星号对，
更像随手打的记号而不是真正的 markdown 斜体，**误留的成本远低于误删颜文字**。

## 五、与 T25 的关系

T25 和 T26 是**同一条排查线的两站**，而且都落在 `clean()` 上：

| | T25 | T26 |
|---|---|---|
| 位置 | `clean()` 不可见字符类 | `clean()` 斜体清洗 |
| 机制 | 游离的 `-` 成了类成员 | `\w` 含 `_` 使颜文字被当斜体 |
| 症状 | 删合法字符 | 删合法字符 |
| 都违反 | 注释/文档的承诺 | 注释的承诺 |
| 都缺 | 测试覆盖 | 测试覆盖 |
| 共同教训 | **清洗管线是「静默损坏」的高发区——它跑在每条出站文本上，出错不打日志、不报警** |

**这两条合起来解释了一部分「语言机械」**：颜文字的星号被吃、连字符被删——
这些恰好是让文字看起来「像人随手打的」而非「像程序生成的」的东西。
