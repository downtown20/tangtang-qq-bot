# T3.2 · 相对时间语义（Stage 3 · M5 剩余三项之二）—— 执行记录

> 完成日：2026-10-14 ｜ 状态：**已完成**

---

## 一、问题

注入 prompt 的事实/记忆条目带的是**绝对时间戳**：

```
- [考试时间 | 2026-09-01 10:01:00 | 来源 chat_log#123] 九月一号考试
```

LLM 得自己算「这是多久以前」——**它算不好**，于是把三周前的事当昨天说。
引用路径早就修过（`handler._fmt_quote_time` 输出「08-14 21:51（5小时前）」），
但**记忆/事实路径没有**：两条路径对同一件事给出不同粒度的时间。

---

## 二、做法：只在渲染层加，**不动 `event_time` 语义**

审计明令：`event_time` 被衰减、Episode 分组、黄金集依赖，**改它语义会连锁**。
所以 T3.2 是**纯渲染层改动**——原字段照旧存、照旧用，只是显示时多附一句相对描述。

### 新增两个纯函数（`agent/protocols.py`）

| 函数 | 作用 |
|---|---|
| `humanize_age(ts_text, now=None)` | 时间串 → 「N 天前」；**解析不了返回空串，不猜** |
| `format_fact_time(ts_text, now=None)` | 「2026-09-01 10:01（43天前）」/ 超界只留绝对 / 空值→「时间未知」 |

**为什么放 `protocols.py`**：它是「面向 prompt 的文本」的单一事实源，
且 `handler.py` 与 `memory.py` 都已导入它，无循环依赖。

**分档与 `handler._fmt_quote_time` 一致**（同一件事不该因路径不同读起来不一样）：

```
<60s  刚刚       <1h  N分钟前     <1d  N小时前
1d    昨天       <7d  N天前       >=7d 空串（只留绝对）
```

**两个刻意的设计选择**：

1. **超过 7 天不给相对描述**——「43天前」不如日期直观，而且容易让人读成被翻旧账。
2. **未来时间返回空串**——时钟异常或跨机数据（T4.6 口径），不去描述一个不可能的时间差。

### 接线（`agent/memory.py` 两处）

| 位置 | 改动 |
|---|---|
| `memory.py:2102`（可信事实列表）| `memory.event_time or memory.timestamp or "时间未知"` → `_protocols.format_fact_time(...)` |
| `memory.py:2428`（候选事实）| 同上，**并去掉 `fact_time[:16]` 切片** |

那个 `[:16]` 是必须一起改的：`format_fact_time` 已经裁过绝对部分，
外面再切 16 字符会把相对描述整段切掉——**改了等于没改**。

## 四、顺带修的硬编码（黄金集自身测试）

`tests/test_memory_golden_eval.py` 原来写死：

```python
assert report["case_count"] == 70
assert report["dimensions"][d]["passed"] == 10
```

加 `relative_time` 维度后当场变红。**这不是回归，是硬编码的代价**：
每次加维度都要改两处数字，而且改之前必然假红一次——
**假红会训练人忽略红**。改为从 case 文件推导：

```python
expected_counts = Counter(case["dimension"] for case in cases)
assert report["case_count"] == len(cases)
assert report["dimensions"][d]["passed"] == expected_counts[d]
```

真正要钉的是「**每条都跑了且都过了**」，不是「一共有几条」。
