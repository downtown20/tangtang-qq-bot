# T31 · 密度问题的机制定位：**分段做对了，投递格式错了**

> 完成日：2026-10-14 ｜ 状态：**D 类只读诊断，待主人拍板**
> 用途：这是用户三个问题（回复长度不稳定 / 消息密度不合理 / 语言机械）的**同一个机制根因**

---

## 一、怎么找到的

bot 09:53 重启后只有 1 条样本，无法做前后对比。于是转去**用历史数据量密度**
（`reply_metrics.bubble_count` 历史行是 NULL——T22 刻意的，所以只能从 `chat_log` 反推）。

第一步按「8 秒内连续发送」聚成 burst，量气泡数：

```
近30天私聊 bot 回复 882 条，聚成 790 次发送
  1 个气泡: 717 次 (90.8%)
  2 个气泡:  58 次 ( 7.3%)
  3 个气泡:  13 次 ( 1.6%)
  4/6 个  :   2 次 ( 0.2%)
```

**90.8% 是单气泡。** 但看样本时，内容不对：

```
'细节全加了，还偏真实感……行吧，这话你自己说的，我记住了。
                           ← 空行
 （尾巴晃了两下）          ← 空行
 那我给你个任务：既然看不见图，你就用嘴把蕾克给我描一遍。'
```

**一个「单气泡」里塞了三段、还带一段括号舞台说明。**

于是换了个量法：不数气泡，数**段落**（`\n\n` 空行边界）。

## 三、机制（这是关键）

**段落中位数 45 字——这个长度正好是真人一条消息的长度。**

也就是说：

> **她的每一段本来就已经是一条合格的短消息，只是被打包进了一个气泡。**

**分段做对了，投递格式错了。**

### 三个问题的同一个根因

| 用户描述 | 机制 |
|---|---|
| 回复长度不稳定 | 132 字一条——因为把 2.15 段打包进了 1 条 |
| 消息密度不合理 | 该发 2.15 条，实际发 1 条；90.8% 单气泡 |
| 语言机械 | 空行分段 + 括号舞台说明 = 读起来像「文档」，不像「聊天」 |

### 意图信号存在，但被投递层丢了

她**已经在用 `\n\n` 表达「这里该换一条消息了」**——64.4% 的回复都有这个边界。
而正式的分条机制 `[分段]`（只开私聊、需 LLM 主动用）只带来 **9.2%** 的多气泡。

```
有段落边界的回复   64.4%   ← 她的意图覆盖率
实际发出多条气泡   9.2%   ← 投递后的结果
被丢掉的边界       55.2 个百分点
```

**⇒ 投递层丢掉了她 90.8% 的分条意图。** 那个信号一直在输出里，只是没人把它变成气泡边界。

**确认可见性**：`chat_log` 存的是**发送后文本**，样本里空行原样保留 ⇒ **用户看到的就是带空行的多段文本**，不是被渲染层吃掉的。

## 四、顺带确认：括号舞台说明的实测率远高于遥测

T18 已发现 `reply_metrics.bracket_action` 的判据只有 10 个猫相关词。本次直接量：

| 量法 | 比例 |
|---|---|
| 遥测 `bracket_action` | **0.97%** |
| 任何全角括号段 `（…）` | **6.7%**（92/1370）|
| 含动作动词的括号段 | **3.6%**（49/1370）|

⇒ **遥测低估 3.7~6.9 倍。** 且角色卡明确写着「不用舞台剧式动作描写」、
`REPLY_NATURALNESS` 也写着「不用括号写动作。（笑）（叹气）（歪头）是舞台剧本，不是聊天」
——**实测却在写**：

```
（尾巴晃了两下）
（眯眼凑近屏幕，然后放弃似的往后一靠）
（帽檐往下一压，链锯在手里转了半圈，咔地一声停了）
（被说中了，耳朵塌下去一点点）
```

这是「语言机械 / 像在表演」的直接证据（用户最初的反馈原话就是「说话不自然、像在表演」）。

## 五、修复方向（需主人拍板）

**共同点：都是投递层/提示词层，不需要改 LLM 行为。**

### 方向 A（最小、机械、可验证）：把 `\n\n` 当分条边界

在私聊发送路径，把空行分隔的段落拆成多条发送。

- **理由**：`\n\n` 是 **LLM 自己输出的**边界——这是**尊重她已经表达的意图**，不是系统替她决定（与 T13 删掉的 `random.random()` 性质不同：那个是系统凭空决定，这个是读她已有的输出）。
- **风险**：一条回复变多条 = 更像真人，但也可能在小群/严肃话题里显得碎。可先只开私聊。
- **可验证**：`bubble_count` 分布会从 90.8% 单气泡变成 ~2 条；段落长度中位 45 字本身就是合理气泡长度。

### 方向 B（提示词层）：明确「要分条就用 `[分段]`，不要用空行」

- 要求**她改变行为**，而她已形成用空行的习惯（且被自回放强化，见 T23）⇒ 见效慢、依赖服从。

### 方向 C（合并）：让 `\n\n` 成为 `[分段]` 的等价标记

- 与 A 同效，但把语义写进协议层（单一事实源），文档更清楚。

### 方向 D：括号舞台说明

角色卡已禁、协议已禁，但仍在写。可能原因：她的历史里全是这种写法（自回放强化），
以及**角色扮演类场景**下她自己给自己设了动作描写风格。
**建议不要直接禁**——先看方向 A 的效果（拆条后舞台说明会被孤立成单独气泡，观感变化很大，可能自然减少）。
