## 一、改什么（一句话）

`[分段]` 之外的**第二个段边界**：**空行**。

只改一个函数（`parse_split_markers`）＋一个常量（`_BLANK_LINE_RE`），
**复用已有的 `[分段]` 全套机器**（逐段 enrich、MAX_REPLY_PARTS 上限、发送路径）——
不新造第二条分条通道。

### 为什么这是「读她的意图」而不是「系统替她决定」

这是本改动最要紧的定性，因为它要和 2026-10-14 T13 删掉的东西划清界限：

| | T13 删掉的 | T32 加的 |
|---|---|---|
| 谁决定 | **系统**凭空决定（`random.random() > 0.50`）| **LLM 自己输出的空行** |
| 性质 | 同一句话随机变形态 | 读她已经表达的边界 |
| 可预测性 | 不可预测（随机）| 完全可预测（她写什么就是什么）|
| 与单脑架构 | 违反（系统替 LLM 决策）| 符合（系统只搬运她的输出）|

`[分段]` 标记是「她显式要求分条」，空行是「她隐式表达了分条」——
**两者都是她的输出，系统只负责别把它丢掉。**

## 二、边界（解析窄）

| 输入 | 结果 |
|---|---|
| `你好呀` | 1 段（**逐字节原样**）|
| `第一行\n第二行`（**单个换行**）| **1 段** ← 刻意不拆 |
| `第一段\n\n第二段` | 2 段 |
| `甲\n\n\n\n乙`（多个空行）| 2 段（只算一个边界）|
| `甲\n  \n乙`（空行夹空格）| 2 段 |
| `a[分段]b\n\nc`（两种边界共存）| 3 段 |
| `\n\n`（全是空行）| `[""]`（走既有「清洗后为空」分支）|
| 四个段落 | 3 段（受 `MAX_REPLY_PARTS=3` 约束，多出的并进最后一段）|

**单个换行不拆是刻意选择的失败方向**：「同一句话被切成两条」比
「两个想法挤在一条」更伤可读性。宁可少拆。

### 「无边界必须零变化」契约

```python
if len(parts) == 1 and not has_blank:
    return [text]
```

调用方靠 `len() == 1` 判旧路径，所以「无任何边界」必须真的逐字节零变化。

## 四、跨模块影响分析（本轮最有价值的检查）

改之前先查了一件事：**多段发送会不会破坏 T2.4 的回执/归账链**。

`agent/reply_pipeline.py:509-513` 有一条早已存在的护栏：

```python
if receipt_template is not None and multi_part:
    logger.warning("🧾 多段批次丢弃 receipt 模板（receipt.parts 聚合尚未实现，"
                   "禁止用单模板冒充一批动作）: parts=%d", len(parts))
```

**先问「谁受影响」**——查证结果分三层，结论是**影响很小且已被既有护栏挡住**：

1. **私聊路径确实会传模板**（`handler.py:5293`）——所以这条护栏会被走到。
2. **但模板只在有真实动作来源时才存在**：
   `_build_text_action_envelope` 在 `source_id` 为空时**返回 None**（`handler.py:564-567`，
   注释原话「无真实来源时返回 None，绝不伪造来源身份」）。
   **普通闲聊没有 `action_source_id` ⇒ 本来就没挂模板 ⇒ T32 对它零影响。**
3. **私聊路径还多做了一道**：`handler.py:5280-5289` 在 `send_parts` 非空时
   **直接不构造 envelope**——也就是说私聊路径**已经**知道「多段不挂模板」，与 send() 的护栏一致。
   所以 T32 提高多段比例，只是让**本来就会走到的一步**走得更频繁，不是新开一条路径。

**残留的真实代价（如实记录）**：带真实动作、且回复里恰好有空行的私聊，
它的永久归账会被跳过（消息照发，只是少一行 `confirmed_action_facts`）。
频度：全历史 `confirmed_action_facts` 仅 23 行（T4.3 实测）⇒ 低频；
且 send() 会**显式**记一条 warning，不是静默。**不修**：
要修得实现 `receipt.parts` 聚合（ADR-003:23 尚未实现的那段），那是一个独立任务，不是本任务的尾巴。

### 顺带补上一个零覆盖的护栏

上面那条「多段不许挂模板」的护栏，**此前没有任何测试**（实测 grep 0 命中）。
而它是最容易被后人「好心优化」成伪造模板的地方——
所以补了 `TestReceiptTemplateIsSingleBubbleOnly`（2 条）：
多段时**每个段都必须是 None**；单气泡时**必须照挂**（防止「多段丢弃」演变成「永远不挂」而静默断掉归账链）。

## 六、M2 第一次「变红」是**假红**

M2（让单换行也成边界）第一次跑出 `1 error`——看起来「红了」，但那是 **collection error**，
不是断言失败：我的变异脚本用 Python 单引号串写替换行，`\n` 被写成了**真换行**，
源码变成语法错误。

**这不是有效变异**——文件坏了不等于行为变了。
改法：用 `chr(92)` 拼出**字面反斜杠-n**，并在写盘前 `ast.parse(mut)` 断言语法合法。
修好后 M2 正确变红（2 条断言失败）。

**这是本轮第五次「变异不变红/假红」**，也是第二次「假红来自把文件改坏而不是改行为」
（第一次是 T32 之前的同类）。共同动作固定为两步：**先证明变异语法合法且真的改了被测行为，再看测试有效性。**
