# T4.8 · 心情自报的分母可见性（原「待拍板」项，按项目宗旨自行决策实施）

> 2026-10-23。台账原状态：**待拍板**（`阻塞登记` 表：「方案已备…**需主人点头**」）。
> 主人本轮交办「其他按项目宗旨自行决策」，故实施——但**实施内容与原方案不同**，理由见 §二。

## 一、取证：这条链路现在是「两天零触发」

先量，不猜：

| 观测点 | 当前日志实测（boot 2d902361 + 12e0fa11，17,023 行、100+ 次回复） |
|---|---|
| `🌡 心情自报协议已注入` | **0 次** |
| `💓 心情自报回灌` | 0 次 |
| `💓 心情自报未写` | 0 次 |
| `💓 忽略白名单外` | 0 次 |

⇒ **整条心情自报链路从未被触发过**。T4.5 当时说的「分母结构性恒 0」**至今仍然成立**，不是已经修好。

根因在闸门本身（`agent/handler.py:3381`）：

```python
feedback_candidate = self._take_feedback_candidate(group_id, user_id, 60)
_mood_report_turn = bool(feedback_candidate)   # 只有它为真才注入协议
```

而 `_take_feedback_candidate` 要求「她刚说完、**同一个人 60 秒内**接着回」。
人类聊天几乎不会在 60 秒内回 —— 这个条件在生产里近乎不可达。

## 二、为什么**不照原方案做**（原方案救不了这条链）

原方案（T4.8 登记原文）：「在 `_apply_mood_report` 标签非空分支补 info 日志，分母改为『LLM 输出出现过 `[心情:]` 标记的次数』」。

**推演一遍就会发现它无效**：协议从未注入 ⇒ LLM **不知道存在这个协议** ⇒ 它不会输出 `[心情:词]` ⇒ 「LLM 输出过心情标记的次数」这个新的分母**同样是 0**。
换个口径量同一个空集，答案还是空。

「改分母」救不了「分子和分母都是 0」的链路。**真正该问的问题不是「遵从率多少」，而是「这个闸门该开多大」**——而那个问题此前**完全没有数据**：候选过期时是静默 `pop` 掉的，于是「窗口没开」与「没人接着回」在日志里完全同形。

## 三、实际做了什么（两个纯观测点，不改闸门、不改语义）

| # | 改动 | 位置 | 它回答什么问题 |
|---|---|---|---|
| ① | **候选过期时分桶留痕** | `handler.py:_take_feedback_candidate` | **「窗口放大到多少会有命中」** |
| ② | **回灌日志带 `injected` 标记** | `handler.py:_apply_mood_report` | 「协议注入了她照做」vs「没注入她自发报」 |

### ① 分桶日志

```
💓 反馈候选过期: scope=<群/私> 间隔=412s(2-10min) 窗=60s
   ——这回合不注入心情自报协议（窗口够不够，看这一行的分桶分布）
```

桶边界**刻意选成** `<2min / 2-10min / 10-60min / >1h`——它们直接对应「窗口要放大到多少才够」的几档候选，读日志的人不用再算。

**为什么用日志而不是指标**：`metrics` 是**进程内计数、重启清零**（T29 的教训：重启后的假警报会训练人忽略警报）。而「窗口该多大」需要**跨重启的长期分布**。

### ② `injected` 标记

协议未注入时 `parse_mood_report` 仍会解析出标记（所以她**可以**自发报心情），但改动前这两条路径的日志完全同形，于是「她愿不愿意自发报」不可测。现在回灌日志是：

```
💓 心情自报回灌: 被夸 → 被夸（injected=False，群-<uid>）
```

## 四、刻意**没做**的（每条都有理由）

1. **没把 `60` 改成更大**——审计「不要动」第 11 条（不加无条件常驻注入），且主人的定案权在这里：有了 ① 的数据，主人才有依据决定放不放大。**先有数据，再谈拍板**——这正是 T4.8 该做的事。
2. **没改 `_mood_report_turn` 语义**——它仍是唯一闸门，本任务只观测。
3. **没动 `_apply_mood_report` 的任何判定分支**（只看不改）。
