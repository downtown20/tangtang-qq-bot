## 一、为什么需要它

T4.1 的判定标准是「**每日**至少一条 < 0.85 且不总是 social/avoid」。
单点快照证明不了「每日」——需要时间序列。

但序列**不该占一个专门的 7 天 soak 周期**（用户要求：一次做一件事、不在一个点上无休止消耗）。
所以做法是：**在日常运行中顺带积累**——每次跑快照就追加一行。

---

## 二、做什么（不新造工具，只在既有工具上加 flag）

`tools/长期优化快照.py` 新增三个函数 + 两个 flag：

| 新增 | 作用 |
|---|---|
| `_read_drives()` | 只读 `.tangtang_self.json` 的 `drives.drives` |
| `append_drives_series()` | 把当前六维驱动力追加成一行 CSV（表头只写一次）|
| `check_drives_series()` | 校验 CSV 列与表头一致 |
| `--drives-series` | 跑完快照后追一行 |
| `--check-series` | 只校验列完整性（阳性对照用，不写文件）|

输出：`docs/开发规划/长期优化/快照/drives-series.csv`

```
ts,social,commitment,curiosity_info,express,curiosity_explore,avoid
2026-10-14 07:34:45,0.064,0.798,0.709,0.728,0.673,0.35
```

### 三条硬约束（各有测试钉住）

1. **只观测**——不设阈值、不下结论（与 T17 的 `collect_dialog_quality` 同口径，用户明说不设数值）。
   测试 `test_no_threshold_in_series_code` 断言源码里没有 `0.85`、没有 `raise`。
2. **列不许漂移**——`ts` + 六个固定维度，表头只写一次。列漂移会让序列无法跨时间比较，**而那正是它存在的意义**。
3. **只读自我状态**——`.tangtang_self.json` 只读，唯一写入的是快照目录下的 CSV。

## 四、踩坑

1. **`edit` 的 old_string 第二次凭记忆写错**：我先试 `'        for line in compare(snap, prev):\n            print(line)\n    return 0'`，
   但文件里这些行之间**有空行**（`print(line)` 与 `return 0` 之间隔一行），不匹配。读实际行后成功。
   **这是本轮第二次同类错误**（T2 也有一次）——**多行替换必须先把实际行读出来**。
2. **变异脚本锚点又不匹配**：我按记忆写 `'        if new:\n            f.write(header + chr(10))'`，
   而实际文件是 **CRLF 行尾**（`if new:\r`），拼 `\n` 永远匹配不上。
   改为**从文件动态取锚点**（`find(lambda l: l.strip() == 'if new:')`）后通过。
   **这已是本轮第三次「锚点凭记忆写」导致失败**——已上升为纪律：**锚点一律从文件读，不凭记忆拼。**
