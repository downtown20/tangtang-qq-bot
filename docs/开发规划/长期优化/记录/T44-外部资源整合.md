## 二、整合办法：知识可以进，身份不能进

### 2.1 三层的边界

| 层 | 载体 | 整合时 |
|---|---|---|
| 她是谁 | `role_card.md` | ❌ **一个字节都不改**（有机器闸门）|
| 她怎么做事 | `protocols.py` | ⚠️ 只加「怎么看资料」的说明 |
| 她知道什么 | `knowledge/` | ✅ **整合目标** |

**为什么这条是核心**：上游那 46 篇是**写给「军师」的**，语气是「你应该先做 A 再做 B」。
原样进知识库又不加约束，她很可能会变成**咨询师腔**——直接违背 CLAUDE.md 第零节「她不是客服机器人」。

### 2.2 机制：用已有的递归扫描，零代码改动

两条现成通道：
1. `knowledge/` **递归扫描**（`knowledge/色色参考/` 已是子目录先例）
2. **`search_knowledge` 是 LLM 自主调用的工具**（`handler.py:3970`：「系统不替 LLM 决定『该查知识库』」）

**注入量安全**：`knowledge.py` 的 `MAX_TOTAL_CHARS=3000` / `MAX_PER_CHUNK=1500` / `MAX_RESULTS=3`
—— 无论知识库多大，**单次注入不超过 3000 字符**。

### 2.3 落地

```
knowledge/恋爱军师/
  README.md          来源 / commit SHA / MIT / 边界 / 同步方法
  知识/               20 篇（references/knowledge/）
  话术/               23 篇（references/practical/）
```

**43 篇，逐字节校验 0 差异**，未改写一字。上游 commit `6db7354a4002dc7c448a9c87ffdad8132570c9d3`。

### 2.4 明确不整合

| 内容 | 理由 |
|---|---|
| `scripts/memory_store.py` | 小糖糖有 `memory.py` + `store.py`。**两套记忆系统并存**是反模式 #8 的同形 |
| `documentation/` | 上游自己的开发文档，只会稀释检索 |
| `SKILL.md` / `agents/` / `assets/` | 消费方不存在 |

**但 `SKILL.md` 的工作流思路**（先接情绪 → 拆事实/推测/未知 → 给下一步）**值得读**，
日后改 `psychology.yaml` 可作参考。**读它，不搬它。**

## 三、两条硬教训

### 3.1 我的闸门测试抓到了我猜错的 API

写测试第一版把加载函数猜成 `load_documents` / `load_all` / `scan_documents` —— **测试当场红了**（不存在的名字）。
**这正是它该做的：拒绝凭猜测通过。**

真实 API：`discover_document_files(knowledge_dir)`（唯一文档发现器）、`resolve_document_path()`。
同轮还猜错过 `Relationship`（以为是 dataclass，实际是 `personality.py:32` 的 Enum）。

### 3.2 **Python 隐式字符串拼接吞掉了代码**（本轮最值钱的一条）

把协议接进 `personality._load_role_card` 时，生成脚本里的**列表元素漏了逗号** ——
Python 的**隐式字符串拼接**把 6 行注释和
`content += "\\n\\n" + _protocols.KNOWLEDGE_USAGE_BOUNDARY` **拼成了一行**，
于是后者变成注释的一部分、**永不执行**。

**而当时四条同时成立**：常量定义得好好的、pyflakes 干净、AST 通过、单元测试全绿。

**是端到端验证抓到的**：我组合出真实 system prompt 去 grep，发现同链上
`STYLE_ANCHOR` / `REPLY_NATURALNESS` / `FOLLOW_UP_PROTOCOL` **三个都在、只有我的不在**，才定位到。

**判据：常量可导入 != 它被注入了。**（教训 #12 / #14 同形）
**修法**：用 `chr(10).join([...])` 构造，从根上避开隐式拼接。
修后 `_load_role_card` 1302 → 1635 字，四个协议全在 prompt 里。

## 四、新增协议 `KNOWLEDGE_USAGE_BOUNDARY`

**放 `protocols.py`，注入在 `personality._load_role_card` 的风格尾段**
（与 `STYLE_ANCHOR` / `REPLY_NATURALNESS` / `FOLLOW_UP_PROTOCOL` **同层同进退** ——
那一段是 `_split_minimal` 保留的尾段，replace 型场景精简时一起走）。

五条内容：
1. 检索到的是**参考观点**不是转述结论 —— **不要变成「首先…其次…最后…」的咨询腔**，不照搬话术模板
2. **不主动索取隐私** —— 不追问创伤细节 / 家庭隐私 / 财务 / 身体隐私；对方主动说的可以接
3. **危险信号优先** —— 自伤 / 暴力 / 涉法时，「不追问细节」这条**让位**；说清能做什么不能做什么，并建议找现实中的专业帮助
4. **不是心理治疗** —— 不给诊断、不贴病理标签
