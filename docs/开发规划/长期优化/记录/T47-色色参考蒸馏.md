## 二、新契约：文件夹 = 注入槽位

```
knowledge/色色参考/
  00-核心/     1 篇  1396 字   ← 注入
  10-风格/     2 篇  3512 字   ← 注入
  20-技法/     6 篇  6375 字   ← 注入
  _原文/       5 篇 15755 字   ← 归档，不注入
```

四条规则：
1. **数字前缀的目录 = 注入槽位**，按名排序依次注入
2. **`_` 开头的目录是蒸馏溯源归档，不注入**
3. **槽位内条目全读，绝不截断** —— 截断等于静默遗漏，正是本次要消灭的
4. 每个槽位有预算，**超预算记 warning**（可见），不悄悄丢尾部

**所以字数控制发生在蒸馏阶段**（把文档放进哪个槽位、写多长），而不是运行时的截断。
这正是主人定下的「文件夹即选取方式」。

## 五、两条硬教训

### 5.1 覆盖审计第一版是**假绿**（而且原因正是 T43 修过的那个 bug）

第一次跑覆盖审计：**6 个批次里 5 个返回空**，只有 1 个返回 `NONE`，
脚本把「空」当成「没有未覆盖项」→ 报 `0 / 206`。**这是假绿。**

查真实响应：
```
finish='length'  content=0 字  reasoning=6118 字
usage: completion=4000  thinking=4000     ← 推理吃光全部预算
```

**`deepseek-v4.1-flash` 是推理模型，`max_tokens` 同时约束推理与正文** ——
与 **T43 识图的根因完全同源**。修法：`max_tokens` 提到 16000 + 批次缩到 20 + 加抑制思维链，
并**把「空返回」显式记为「未核对」而不是「通过」**。

**判据：工具报 0 是关于工具的事实，不是关于事实的 0**（本仓教训 #36 的现场复演）。

### 5.2 我的测试判据自己红了两次（都是判据不够精确）

**第一次**：`test_no_hard_truncation_in_source` 写成 `'[:6000]' not in body` ——
它把我 **docstring 里解释旧行为的那句话**也算成违规。**文本里提到截断写法 != 代码里在截断。**
→ 改用 **AST** 查真实 `Subscript` 节点。

**第二次**：AST 版把 `d.name[:1].isdigit()`（取首字符）也报了。那合法且常见。
→ 判据收窄为「AST Subscript 且上界 **>= 100**」（内容量级）。

**第三次**：插入注释时打断了 `\` 续行 → 整块重写函数。

### 5.3 同一个坑第二次踩：**Python 隐式字符串拼接吞代码**

给 handler 加预算常量时，生成脚本里的列表元素**又漏了逗号** →
4 行注释被拼接成一行。**但那行是注释，Python 对注释不检查缩进，所以 AST 通过了** ——
而常量**从未被定义**（成了注释的一部分）。
**是 pyflakes 的 `undefined name` 抓到的**（与 T44 那次同形）。
→ 固化纪律：**多行内容一律用「单个字符串 + split」构造，不用字面量列表。**
