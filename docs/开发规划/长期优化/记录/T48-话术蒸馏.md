## 三、蒸馏产物：`CONVERSATION_CRAFT`（835 字）

进 `agent/protocols.py`，注入在 `personality._load_role_card` 的**风格尾段**
（与 `STYLE_ANCHOR` / `REPLY_NATURALNESS` / `FOLLOW_UP_PROTOCOL` / `KNOWLEDGE_USAGE_BOUNDARY` 同层同进退）。

结构：

| 块 | 内容 | 来源 |
|---|---|---|
| **接的不是话，是人** | 3 个反例（漏情绪 / 掐话题 / 抢话岔题）| 巧妙接话 4 类雷区 |
| **三个具体做法** | 先接情绪再接内容 / 抓一个关键词延伸 / 笼统话要问细节 | 巧妙接话 4 类方法之三 |
| **冷场和说错话** | 自己没接住就直说；对方卡住帮 ta 圆，别调侃 | 巧妙接话·救场补位法 |
| **意见不同时** | 先认喜好不同，再问为什么，然后说自己的——**不否定对方，也不把自己抹掉** | 巧妙接话·不同意见场景 |
| **四件不要做的事** | 别顺着骂 / 别急着给方案 / 别只顾输出 / **别否定情绪** | 情绪价值 4 类误区 |
| **夸人要具体** | 夸具体的**事**不夸空泛的**词** | 万能夸人 |
| **你有边界** | 不用把所有情绪都接住——**不假装自己是个容器** | 情绪价值·守住自我边界 |
| **反模板（最重要）** | 这不是话术模板，套模板比不套更假 | 00-导读「不要机械照抄」 |

**最后一块最要紧**：这套内容没有它就会**反过来伤害「自然」这个目标** ——
所以 `CONVERSATION_CRAFT` 里明写「你不需要『巧妙地』接每一句，累了可以短，
不想聊可以岔开，被戳到可以顶回去」，并配了专门的测试 `test_no_template_smell_guard`。

## 四、教训：同一个坑第三次踩

生成脚本里**第三次**因为列表元素漏逗号导致 Python 隐式字符串拼接。
前两次（T44 的 `KNOWLEDGE_USAGE_BOUNDARY`、T47 的预算常量）我都写了「以后用单字符串 + split」，
**这次又没照做**。

第三次的具体形态更隐蔽：JS 模板字符串里的 `\n` 被当成**真换行**写进 Python 源码，
于是字符串字面量跨了行。

**修法**：用 `String.fromCharCode(92) + 'n'` 显式构造两字符序列 `\n`，
彻底避开 JS 与 Python 两层的转义歧义。

**判据**：跨语言生成代码时，不要依赖两层的转义规则叠加 —— 用字符码显式构造。
