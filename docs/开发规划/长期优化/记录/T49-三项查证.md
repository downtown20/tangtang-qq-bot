## #2 `stickers_cg` 触发机制 —— **没有关键词门控，但文档失实**

**起因**：`恋爱感_千恋万花风格.md` 的「CG系统说明」小节声称触发条件是
「对话中出现色色关键词（做爱/插/操/…) → 30% 概率」。若属实那是**关键词门控**
（CLAUDE.md 教训 #9/#10 明令的反模式）。

**实测**：

| 文档声称 | 代码实测 |
|---|---|
| 对话中出现色色关键词 | **代码里不存在这个关键词列表**（0 命中）|
| 30% 概率触发 | **零随机数**（cg 与 `0.3`/`random`/`概率` 同现 0 命中）|

**实际实现**（`agent/handler.py:5897-5912`）：
```python
# 4. CG 表情包工具（LLM 自主判断氛围到了该发图）
if (sed_active and self.cg_stickers and self.cg_stickers.has_stickers()
        and "send_cg_sticker" not in seen_names):
    ... "description": "发送一张卧室亲密场景的CG……此刻的亲密氛围下，
                      这是一种自然的表达——有时一张图比一段文字更能传达感觉。"
```

**`send_cg_sticker` 是一个 LLM 原生工具**，注册条件是 `sed_active`（色色场景激活）且图库非空，
**LLM 自主决定何时调用**。

**结论**：
- ✅ **实现是干净的单脑架构**，没有反模式
- ❌ **是文档在描述一个不存在的机制** —— 本仓教训 #35「文档说的和代码做的分家」的又一例
- 好在这次分家**没有导致行为错误**，只在文档里

**处置**：T47 已把该小节排除出蒸馏（当时理由只是「系统机制不是写作技法」——**不足**）；
现补上更强理由（**描述的是不存在的机制**）到 `knowledge/色色参考/_原文/蒸馏说明.md`。

## #3 `search_knowledge` 零调用 + `empty` 50% —— **都不是 bug**

**取证一：那 10 次调用在问什么**

```
「私聊和群聊的记忆是否互通」  「糖糖 记忆机制 隐私保护」
「糖糖是谁创造的 开发者」     「小糖糖 项目 搭建 制作人」
「记忆库保留多久 记忆保存时间」 「生成图片 点数 消耗 画图」
「内阁群 107414647…」×2       「内阁群 密保 密码 申请」
```

**10 次全部是「用户问糖糖自身功能/项目信息」** —— 那是 LLM 调用它的唯一实际动机。

**取证二：`empty` 的成因** —— 5 次查不到的是「糖糖是谁创造的」「内阁群密保密码」
「生成图片消耗点数」等，**这些根本不在知识库里**（群管理信息、点数消耗不是知识库内容）。
**不是检索算法问题。**

**取证三：知识库里到底有什么（关键）**

可检索 **56 篇**，但**混着两类语义完全不同的内容**：

| 类别 | 篇数 | 例子 | 服务什么 |
|---|---|---|---|
| **糖糖自己的功能文档** | 12（根目录）| 更新日志(20991)、千恋万花(11039)、DeepSeek 笔记(3886)、minecraft(2432)、毛选思维框架、糖糖功能、糖糖自我认知、记忆系统技术文档、语音系统经验总结… | 「问糖糖自己」|
| **外部关系心理学资料** | 44 | 恋爱军师/知识 20 + 话术 23 | 「聊关系话题」|

**结论**：
- 零调用**不是 bug** —— 是使用场景决定的（只在「问糖糖自身」时触发），10-07 后没人问，自然零调用
- `empty` 50% **不是检索质量 bug** —— 问的东西不在库里
- **但发现一个真结构问题**：两类内容**同一个检索通道、同一个语义空间**，检索时互相干扰；
  而 LLM 的**调用动机**只有前者 —— **这正是 T44 那 43 篇用不上的根因：调用动机与内容类型错配**

**处置**：**只读结论，不改代码**（同 T38 的否定结果）。分类重构会改动检索通道，超出本任务范围。

## #4 日志 `15 个文件` → `12 个文件` —— **正确行为，而且是好事**

**日志直接给了答案**：

```
2026-10-13 05:27:31  知识索引同步: +0文档 ~0变更 -3删除, +0块 ~0替换 -82清理
```

**从日志的文件名清单 diff 出消失的 3 个**（日志会列出全部文件名）：

```
更新日志.sync-conflict-20260925-230131-F2AEMAR
糖糖网页.sync-conflict-20260925-231644-F2AEMAR
语音系统经验总结.sync-conflict-20260925-231157-F2AEMAR
```

**全是 Syncthing 冲突副本**（2026-09-25 的同步冲突产物）。
10-13 有人清理了这 3 个重复文件，知识库**正确检测到并清理索引**。

**结论**：
- ✅ **不是 bug** —— 是索引同步**正确工作**的证据
- ✅ **而且是好事**：冲突副本与原文件内容近乎重复，**同样的文档被索引两遍会稀释检索**
  （同一个查询命中两条一样的，占用 `MAX_RESULTS=3` 的名额）

**顺带发现**：仓库里还留着 `tangtang.log.sync-conflict-20260925-225624-7GXRVII`（**日志**的冲突副本，
不是知识文件）—— 无害，但可清理。
