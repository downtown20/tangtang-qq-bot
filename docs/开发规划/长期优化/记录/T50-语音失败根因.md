# T50 · 语音发不出来的根因与修复（GPT-SoVITS 一直被压在 CPU 上）

> 2026-10-14。主人报「语音发不出来」。本文记录取证链、根因、与修复。

---

## 一、三条错误结论的纠正（先记自己的错）

| 我说过的 | 实际 | 错在哪 |
|---|---|---|
| 「FFmpeg 未安装」| **在 `<用户目录>\ffmpeg`** | 我把 `torchcodec` 报错文本当成了事实（教训 #36 现场复演）|
| 「GPT-SoVITS 服务起不来」| 它**起来了**，且返回了 `200 OK` | 我只看了「不可达」那半句 |
| 「torch nightly 可能是元凶」| **与 torch 无关** | 我把嫌疑锁在最近改动上，而真相在配置里 |

---

## 二、取证链（每一步都有实测）

### 2.1 日志现场

```
18:03:11  🩺 local_tts: GPT-SoVITS 端口 9880 不可达
18:05:07  GPT-SoVITS 3次尝试均失败:  (text='...')      ← 注意冒号后是空的
18:05:07  🔧 GPT-SoVITS 进程异常，强制重启…
18:06:00  POST /tts → HTTP/1.1 200 OK                  ← 但判失败
18:09:03  🔧 语音失败自动恢复次数已用尽
```

### 2.2 手动启动 GPT-SoVITS —— 模型加载 100% 成功

```
TTS Config
device              : cpu        ← 关键
is_half             : False      ← 关键
version             : v4
loading vocoder <All keys matched successfully>
Loading VITS weights ... <All keys matched successfully>
INFO:     Application startup complete.
```

### 2.3 自测 TTS（绝对路径，与 bot 一致）

```
HTTP 200 | 510254 bytes | **78.9s** | 前4=b'RIFF'
```

**22 个字用了 78.9 秒。** 而 `voice.py:526`：

```python
async with httpx.AsyncClient(timeout=60.0) as client:   # ← 60 秒
```

**⇒ 78.9s > 60s ⇒ ReadTimeout ⇒ 3 次全超时。**

**空错误串也解释了** —— `voice.py:562` 的 `last_error = str(e)[:100]`，
而 **httpx 超时异常的 `str(e)` 就是空字符串**。日志的 `失败:  (text=` 完全吻合。

### 2.4 定位设备为何是 CPU

`gpt-sovits/config.py` 的**自动判定**返回的是 `cuda:0`：
```
GPU_COUNT = 1 | IS_GPU = True | infer_device = cuda:0 | is_half = True
```

但 `api_v2.py:163` 走的是**另一条路**：
```python
config_path = args.tts_config   # 默认 GPT_SoVITS/configs/tts_infer.yaml
tts_config = TTS_Config(config_path)
```

**而 `tts_infer.yaml` 的所有 profile 都写着：**
```yaml
device: cpu
is_half: false
```

**⇒ 上游默认值把 GPU 盖住了。**（`gpt-sovits/` 是第三方项目，见 `打包发布版本.py:268`）

---

## 三、根因

```
tts_infer.yaml 硬编码 device: cpu
        ↓
GPT-SoVITS 全程 CPU 推理（RTX 5070 闲置）
        ↓
22 字 = 78.9 秒
        ↓
voice.py 的 60s httpx 超时
        ↓
ReadTimeout（str(e) 为空 → 日志显示空错误）
        ↓
3 次全超时 → 合成失败 → 降级发文字
```

**与 torch 版本无关。** 项目一直把「GPT-SoVITS 用 CPU」当可接受状态
（`tools/体检.py:15` 写着「gpt-sovits 可 CPU」），从没人质疑过。

---

## 四、修复（不阉割质量）

**A. 立即生效**：`gpt-sovits/GPT_SoVITS/configs/tts_infer.yaml` 的 `device: cpu → cuda`、
`is_half: false → true`（7 个 profile）。

**B. 持久修复**（上游文件会被重装覆盖）：在项目自己的补丁层
`gpt-sovits/start_api_patched.py` 加 `_ensure_gpu_device()`，
**只在 `torch.cuda.is_available()` 为真时切** ——
这自动尊重 `service_manager` 的 CPU 兜底（它用 `CUDA_VISIBLE_DEVICES=-1` 启动时读到 False，YAML 保持 cpu，
**不会把已识别的 GPU 原生崩溃绕过去**）。

### 实测结果

| | 耗时（同样 22 字）| 对 60s 超时 |
|---|---|---|
| **CPU** | **78.9s** | ❌ 超 31% |
| **CUDA** | **5.7s** | ✅ 余量 **10.6×** |
| | **加速 14×** | |

输出为合法 WAV（`RIFF` 头，717 KB）。

### 阳性对照

把 YAML **还原成上游的 CPU 原样**，再用打补丁的启动器启动 →
启动器自动切到 cuda，服务以 GPU 运行 ✅（证明修复不依赖我手改的那个文件）。

## 六、遗留

1. `torchcodec` 报「FFmpeg not properly installed」—— **FFmpeg 装了的**（`<用户目录>\ffmpeg\ffmpeg-master-latest-win64-gpl\bin`），
   只是**不在 PATH 里**。torchcodec 是可选依赖，不影响语音链路。要根治就把它加进 PATH。
2. **torch 版本决策**（T50 之外）：nightly `2.14.0.dev` 是 RTX 5070（sm_120）**所必需**的
   （`2.5.1+cu124` 架构表只到 sm_90）；`reranker` 守卫拦它是因为版本号含 `.dev`。
   若要同时保住 GPU 与 reranker，正解是装**稳定版 `2.13.0`**（项目自己的 RVC 文档指定它）。
