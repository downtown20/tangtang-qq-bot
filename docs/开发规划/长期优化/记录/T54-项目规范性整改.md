## 一、A · 依赖管理规范化 + 双机安装自动化落地

### 病灶（本次最实质的一条）

`tools/安装糖糖.py:440` 与 `:455` 的 GROUPS 两处**写死**：

    "extra": [(["torch"], {"index-url": "https://download.pytorch.org/whl/cpu"})]

⇒ **新装一台有独显的机器会装上 CPU 版 torch** —— RTX 5070 等于废卡、语音慢 37 倍。
这正是主人说的「写在 requirements.txt 里 ≠ 自动化落地」：文档写对了，代码没做到。

### 修法

* `tools/安装糖糖.py` 新增 `TORCH_VARIANTS`（`:102-138`）三档表 +
  `detect_torch_variant()`（`:242`）判定 + `--torch-variant cuda|xpu|cpu|auto` 人工覆盖；
  `:72-79` **按文件路径**加载 `agent/devices.py`（不 import agent 包 —— 安装器要在依赖装齐之前就能跑，
  沿用 T52 给 GPT-SoVITS 启动器定的同一条纪律）。
* 判据**不依赖 torch**（装之前当然没有 torch）：`probe_nvidia()` 走 `nvidia-smi` 读算力号，
  `probe_intel_arc()` 走 WMI 并**排除虚拟显示适配器**（IddDriver / Oray / Todesk 等）；
  判据 ① nvidia-smi 且 **sm_70 以上** → cuda ② Intel Arc / Iris → xpu ③ 其余（含 AMD）→ cpu。
* torch **单独一条 pip 命令**（cu/xpu 档带 `--no-deps`），不与 jieba/transformers 混装 ——
  混装会把它们的依赖一起掐掉。`--no-deps` 会不会造出「装完不能用」有取证：
  probe 实测 `import torch` 成功、`cuda_available: True`、matmul 通过（挡住 fsspec/networkx/sympy）。
* `:539-644`：装之前打印**档位横幅 + 判定证据 + 三档表 + 带 pip 参数的预览**。
* `tools/体检.py:312-330` 新增 `_torch_tier()`，第 6 节输出
  `torch 档位：CUDA（2.13.0+cu130）` —— **与 `devices.best_device()` 是两个问题**
  （一个是「装的是哪档轮子」，一个是「现在能用哪张卡」），刻意分开报。
* 新增 `tests/test_torch_variant_install.py`（13 条），含
  **「写死 CPU 版不许复活」**、**「torch 必须单条命令」**、**判定表与 `DEVICE_LADDER` 同源**。

### 独立复核（Lead 实跑）

    $ python tools/安装糖糖.py 安装 --dry-run --yes
      [·] torch 档位：CUDA（NVIDIA 独显，sm_70 及以上）
      [·] torch 档位表（本机判定见上；--torch-variant 可人工覆盖）：
      - torch==2.13.0+cu130   (--index-url https://download.pytorch.org/whl/cu130 --no-deps)

    $ python tools/安装糖糖.py 安装 --dry-run --yes --torch-variant xpu

全仓 `whl/cpu` 只剩 3 处，**两处是解释历史的注释**（`:86`、`:437`）、

## 四、Lead 自己做的：**pyflakes 闸门一直在静默漏扫 80/82 个文件**

hygiene-steward 报告、**我独立复现确认**：

    $ python -m pyflakes agent/*.py onebot/*.py main.py 糖糖控制台_qt.py     # pwsh
      python.exe : agent/*.py: Invalid argument          ← 整个目录被跳过
      输出 24 行（全是报错），undefined 命中 = 0

    $ （显式展开 82 个文件）
      输出 116 行，undefined 命中 = 0

**pwsh / cmd 不展开 glob**，pyflakes 收到字面量 `agent/*.py` 就报错跳过 ——
**82 个文件里只有 2 个（main.py 与 糖糖控制台_qt.py）真被扫过，而输出照样是「undefined = 0」。**

这与本仓教训 #30（检查器写了但从没生效）是同一族：**跑起来没报错 ≠ 真的扫了。**
本仓文档写的是 Git Bash（bash 会展开），所以一直没暴露；我这几轮用 pwsh 跑，等于**验证比文档还弱**。

### 修法

新增 **`tools/静态检查.py`**：

* 文件列表由 **Python 自己 glob**，不依赖任何 shell；
* **打印实际扫描的文件数**（数量对不上就是一眼可见的红，而不是静默缩小）；
* **pyflakes 一抱怨参数就立刻红灯**（`find_rejected()`）——这是本脚本存在理由的阳性对照。

闸门 **`tests/test_static_check.py`**（6 条）：两条纯函数判据各一条 + **阳性对照** +
收集数必须等于独立 glob + 端到端跑一遍并核对文件数 +
**「CLAUDE.md / AGENTS.md 里不许再出现可执行形态的 pyflakes glob 命令」**。

`CLAUDE.md:26,157` 与 `AGENTS.md:39` 已改为指向脚本，并写明为什么。

**顺带修掉第二个「两份拷贝」**：根目录同时存在 `.stignore`（1016 B，Syncthing 真正读的）
与 `stignore`（522 B，已漂移落后 10 条规则）。全仓 grep 15 处引用**全部指向带点那份** ⇒
