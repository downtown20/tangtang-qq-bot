## 四、顺带修掉一条会随时间变红的测试（本轮发现）

`tests/test_observer_absence.py::TestAbsenceDetection::test_never_run_in_warmup_is_not_an_alert` 的断言挂在**测试进程的真实存活时间**上——`hc._in_warmup()` 读 `time.monotonic() - hc._PROCESS_START`，而 `WARMUP_SECONDS = 600`。于是「整套测试跑过 10 分钟」会把它变成假红：

- 20:35 那一轮：**3025 passed 里唯一一条 FAILED 就是它**（出现在 47% 处），而同文件单跑 **19 passed**；
- 根因取证：`agent/health_check.py:966-970`——心跳为空且不在暖机期 → 返回 `warn`（「观察器从未运行过——生产观测处于盲区」）。

修法：`monkeypatch` 钉死 `_PROCESS_START`（阳性：`ok`）+ 补一条**阴性对照**（同一输入、进程已过暖机期 → 必须 `warn`）。19:59 那一轮在同样的墙钟条件下（进程年龄已远超 600 秒）无 F。

## 五、这一轮**没有**解决的事（必须一起读）

**最坏回合仍然整块淘汰关系档案——体积契约救不了它。** 复刻（真块 + 生产形态背景表，`budget=1200`）：

```
保留: ['引用', '协议', '提及']
🧺 背景块淘汰/裁剪: 保留flex=1 淘汰=4（窗口(P5,230t)、记忆(P7,230t)、反思(P7,184t)、关系档案(P9,285t)）| 预算 1377/1200 ⚠保护块已超顶 ⚠已动用证据保底
```

保护块（`引用`/`协议`，prio ≤ 1 且允许 overflow）先计量 → 预算已经 **1377/1200 超顶**；flex 只剩负数 → `limit < 120` → **整块 break**（`agent/protocols.py:365-366`），连一份 196t 的中位数档案也留不下。

所以这三项的定位是**韧性**（契约行不再先丢 / 生产者不再产出超块 / 降级不再静默），不是**解药**。解药仍是调查报告列的那条：**池子分层**（保护块不许把 flex 挤成负数）或**按需注入**——两者都动「每回合上下文的构成」，须单独评估 + 单独回归。日志里现在能一眼看到 `⚠保护块已超顶`，正是给那一步准备的分母。
