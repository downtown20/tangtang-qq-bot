# T58 — 记忆召回预算：裁决权归 LLM（2026-10-15）

> 需求（主人）：「token 预算需要根据她的裁决决定：是否给预算、给多少，都由她决定。具体预算是多少也由她决定。设计意图：模拟一个人想自主回忆多少记忆，不用一股脑全回忆一遍。」
> 排查输入：`docs/审查/记忆链路排查_20261015.md`（D1–D10）。执行要求：先排查问题，再结合优化方向集中处理。

---

## 0. 一句话

记忆块此前是「系统定死 top-6、每条 80 字」——**注入多少记忆由代码决定，她只有接收权**；
这与「系统不替 LLM 做判断」（CLAUDE.md 核心原则）同族，是同一个反模式在记忆模块的实例。
本轮把「这一轮回忆多少」交回给她：系统只留**默认冒上来的量**与**安全护栏**，
真正的用量由她调 `search_memories(limit, detail)` 决定；同时修掉排查报告里两条**仍在持续产生损伤**的缺陷（D1、D2 的告警缺失）。

## 1. 排查：先复核报告，再动手（本轮取证）

| 发现 | 报告值 | 本轮实测 | 结论 |
|------|--------|----------|------|
| D1 年份被吃 | memories 33 条（全是 `fact_synthesis`）+ people.notes 13–14 份 | 33 / 14，样本 `年7月18日有吃席的社交安排` | **确认**，且最近 10-13 仍在产生 |
| D2 提取空产出 | 219/225 = 96.9% | 10-13 之后 134 次里 129 次 `success_empty` = **96.3%**，`success_with_items` 5 | **确认**，直接原因 |
| D7 粘连/重复 | 409 组重复；粘连产出点「待查」 | 409 组确认；**产出点已定位**（见下） | 报告留白，本轮补上 |
| D9 预算打满 | 今天 10 次，89–99% | 与 T57 一致（69 次事件、91% 集中在单一会话） | **确认**，已在上一轮定案 |

**D7 产出点（报告里标「待查」的那半条）**：粘连不是第二个正则造成的，是两个写入点在**照抄 LLM 原文**：
- `key='fact'/'like'`（116 行，`origin='extracted'`）：提取器输出的 `value` 自带换行与列表编号（如 31 次重复的 `个孩子\n19.找一个女朋友\n20.让梅酱以后不要发哭的表`）；
- `key='profile_synthesis'`（29 行，`origin='summarized'`）：**整段合成回复**被当一条记忆写进去（`### 增量更新` / `---` / 「以下为确认后的完整画像：」都在 value 里）。

**本轮自查发现的第五条（不在报告里）**：降级链第三层 `_keyword_pick_memories` 名存实亡。
旧实现用 `re.findall(r'[一-鿿\w]{2,}', text)` 取「连续串」——中文句子没有空格，
整句被切成**一个 token**，于是只有「消息里那一整串原样出现在记忆里」才匹配得上：
实测 `你还喜欢画画吗` vs `喜欢画画和特摄的日常记录` **交集为空**。
而它正是 BGE/Reranker 都不可用时的最后一道回忆能力——那一刻她**一条记忆都拿不到**
（教训 #14「引擎在转，离合器没接上」同族）。已在本轮修掉（见 ⑤）。

**我自己的一处误判（记在案）**：先用 `value GLOB '*年[0-9]*月*'`（**前导通配**）数出 199 条，一度以为报告少算 6 倍；
换成报告那条**锚定**写法 `'年[0-9]*月*'` 后 = 33 条，且只落在 `fact_synthesis` 一种 key 上——**报告是对的**，错的是我的模式。
GLOB 有没有前导 `*` 决定「整串匹配」还是「包含匹配」，这一步没核对就会把正常文本（`2026年10月…`）算进损伤。

## 2. 集中处理：本轮落地四条

### ① 记忆推送量交回她（需求本体）
- `agent/protocols.py:328` `MEMORY_RECALL_DEFAULT = 3`（原为散落三处的硬编码 6）、`:329` `MEMORY_RECALL_MAX = 20`（护栏）、`:330` `MEMORY_RECALL_FETCH = 10`、`:331` `MEMORY_RECALL_DETAIL = {brief:40, normal:90, full:0}`。
- `agent/handler.py:9833` 被动推送走 `pushed = MEMORY_RECALL_DEFAULT`；`agent/handler.py:9865` `_bge_pick_memories(..., top_k=None)` 由调用点一处决定（此前三处硬编码 6）。
- `agent/handler.py:8330` `search_memories` 执行器读她的 `limit`/`detail`（旧版写死 `limit=10` + `results[:3]`）；`:8361` 按她给的条数输出，按 `detail` 决定每条露多少（`full` 不截断）。
- 工具描述（`handler.py:6685` 起）明写「要回忆几条（1-20）。**由你自己决定**」。

### ② 缺口可见化（她知道自己缺什么）
- `agent/protocols.py:225` `memory_recall_hint(pushed, available)`：只报告事实，返回
  `（另有 23 条没列出来——要回忆多少、多详细由你定：search_memories 的 limit/detail。）`
- `agent/handler.py:9849` 挂在记忆块尾部；**没有剩余候选时返回空串**（绝大多数轮次不占一个 token）。
- 同 T57 的「缺口告知」思路：系统不再**悄悄**决定她缺什么，而是把事实摊开、把下一步交给她。

### ③ D1 年份丢失（一行根因，仍在持续产生损伤）
- `agent/memory.py:30` 新正则 `^\s*(?:[-•·]\s*|\d{1,3}[.、)]\s*)\s*`、`:33` `_strip_list_marker()`；`:1647` 调用点替换旧写法。
- 旧写法 `^[\s\-•·\d.]+\s*` 锚不住「列表标记」，会吃掉**裸数字**；`\d{1,3}` 刻意排除 4 位年份与点分日期。
- 测试含**阳性对照**（旧正则必须确实吃掉年份）+ 反例（新实现不许再吃）：`tests/test_memory_recall_budget.py::TestListMarkerStrip`。

### ④ 提取空产出的告警地板（D2.3）
- `agent/health_check.py:320` `MIN_EXTRACT_PRODUCED_RATE = 0.05`、`:360` `if produced < 地板: warn`。
- 现场：这条检查**早就在 message 里印着「产出率 3%」，却因为只判协议成功率而返回 ok**——仪表在、阈值不在（教训 #30 同族：跑起来没报错 ≠ 真的在产出）。
- 5% 是**地板不是目标**：10 条消息的窗口一条也提不出来很正常；配了阳性对照（6% → 仍 `ok`）。

### ⑤ 修掉名存实亡的降级链第三层
- `agent/handler.py:9913` `_keyword_pick_memories`：改 jieba 分词取**词交集**
  （CLAUDE.md 第七节：中文匹配一律用 jieba），jieba 缺失时才退回旧连续串写法。
- 测试：阳性对照（旧写法在同一对文本上交集必为空）+ 阴性对照（真的没交集时不许硬塞）。

## 3. 实测（生产数据、生产函数）

| 项 | 旧 | 新 |
|----|----|----|
| 主人（2524950083，可信 active 候选 **26** 条）记忆块 | 6 条 = **428t**（314 字） | 3 条 + 告知行 = **409t**（318 字），含包装 **433t** |
| 告知行成本 | — | **56t**，且只在「还有没列出来的」时候出现 |
| 净变化 | — | **−19t / 轮**（省下的 75t 被 56t 的告知吃掉） |

**诚实结论：这不是一次 token 优化**——对主人这样的画像，记忆块被「标题行 + 画像行」占了大头，
砍掉 3 条事实只省 75t。**它的价值在裁决权**：她第一次能决定「这一轮回忆多少、多详细」，
而代价（多花的 56t 告知行）换的是「她知道还有 23 条可以要」。
（对材料更多的会话，省下的量会更大；对没有剩余候选的会话，新旧**逐字节相同**。）

## 4. 本轮**没有**解决什么

- **D2 的本体没修**：提示词里的「宁缺毋滥／没新信息就返回空数组」仍是 96.3% 空产出最可疑的成因；本轮只补了告警，让它在监控里**不再隐身**。提示词改法（分档期望 + 正例锚定）列入下一步。
- **D7 的数据没清**：粘连值（156 条多行 value）仍是可注入的；去重/清洗要幂等脚本 + 备份先行，另立一轮。
- **存量 33 条记忆 + 14 份画像的年份没补**：代码止血已落，数据补回要按 `evidence_ids` 回溯原文，同样另立一轮。
- **D3/D5/D6 只做了决策、没动代码**（照报告第 4 节顺序）：`valid_from` 全空、回填通道死掉、复核机制只剩 4 条记录——三件都是「误导性状态」，但都涉及列语义与调度者，属于独立批次。
- **她「主动召回」的实际使用率还未知**：`handler.py:8363` 起留了一行 `🧠 记忆召回: 她要 N 条 / detail=…` 日志。等它积累出数据，才知道默认量该不该调、缺口告知有没有人理——**默认值 3 是起点，不是结论**。
