
`（发了张图片，内容是：…）` **不是事实，是系统给的解释**——被写进永久历史、被后续每一轮当成用户说过的话。
全库含 `[动画表情]` 的行 **48606**（动画表情以 `image` + `summary="[动画表情]"` 到达，不是 `sub_type=1`），
`[表情]`（`sub_type=1`，QQ 内置表情）只有 **1** 行——即：**系统只对一种表情做了「不必识图」的判定，另一种漏了**。

## 二、根因（一表一里）

1. **表 —— 没有「发言单元」概念**：一条 QQ 消息 = 一次 LLM 回合。图/表情包是独立一条 → 走完整的
   「窗口内逐条进 LLM」契约 → 必然产生第二次回复（证据：18/18）。
2. **里 —— 系统越权替她解释图，同时失职没告诉她事实**：私聊 `handler.py:5144` **无条件**调 `_call_vision`
   （prompt 写死「这张图表达什么情绪或意思？15字以内」），再把结果**写回 chat_log**（`enrich_image_message`）；
   而她从未拿到「这是表情包还是照片、是官方表情还是动画表情、多大、谁发的」这些**事实**。
   群里更重：`3797`（按需识图）+ `3999`（自然识图）两条路径各调一次 vision 并各注入一次。

## 三、主要矛盾（复盘：上一轮没抓住的就是这一句）

> **系统在「消息身份」上失职，却在「语义解释」上越权。**

「这条消息属于哪一次发言」是**平台事实**（结构），归系统；
「这张图是什么、要不要看、要不要说」是**语义**，归 LLM。
现在的分工正好反了：系统把语义解释固化成历史，却让一条表情包单独成了一次发言。

## 四、设计（把两件事换回来）

### P0-① 发言单元：纯媒体消息并入上一次发言
- 判定：同一 scope、同一发送者、**纯媒体**（去掉占位符后无实质文本）且距其上一条消息 < `MEDIA_ATTACH_WINDOW_S`（120s）
  → 该消息**不单独开 LLM 回合**，只做：写 chat_log（事实）+ 作为上一次发言的附件进入上下文。
- 这是**结构判定**（同一段消息的类型与时间关系），不是语义判定，也不是「要不要回复」的决定——
  与「@消息不消耗插话配额」同族。**不引入任何关键词门控**。
- 反例（必须保持）：用户**只发**一张图（上一条不是自己 120s 内的消息）→ 那它就是一次发言，正常进 LLM。

### P0-② 事实进上下文，解释不预置
- 图/表情包在上下文里给**事实**：`（发了张表情包）` / `（发了张图片）` + 可取回引用（message_id/file_id/url）。
- **不再**把 vision 的情绪解释当成用户说过的话写进历史。

### P0-③ 识图从我调变成她调（减负主任务在识图上的落点）
- 系统不再**无条件**识图；给她一个工具（`look_at_image`）由她决定「看不看、看哪张」。
- 她看过之后的结果才进历史（她的行为，不是系统的预判）。

## 五、边界（不做）
- 不动 `[图片]` → `（发了张图片）` 的中性化（2026-08-16 的结构性修复，防 LLM 回显占位符）。
- 不动「窗口内同一用户每条消息逐条进 LLM」这条契约：P0-① 只对**纯媒体**生效，文字消息一条不少。
- 不做多气泡出站归账（ADR-003 §2026-10-15 已定不做）。
