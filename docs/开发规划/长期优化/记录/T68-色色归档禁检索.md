日期：2026-10-23　执行：Lead（主人拍板 + 授权「按你的判断执行」）

## 1. 定案与来源

主人原话：**「色色 `_原文` 不允许检索」**。

此前这条一直是「**待主人拍板**」（`agent/intimate_reference.py` 末尾注释：「要开放按需检索，需先和主人确认白/黑名单」）。
拍板之后它不是待办，是**约束**：本任务的实质不是「加功能」也不是「删数据」，而是把一条口头约定变成
**不依赖人记住的机器约束**——否则下一个人（或下一次重构）只要重新「觉得开放检索挺合理」，就会把它接上。

## 3. 主要矛盾：同一个目录名被写了两遍，且两处没有互相校验

- `agent/intimate_reference.py:47`：`PACKAGE_DIRNAME = "色色参考"`
- `agent/knowledge.py:59`：`SENSITIVE_DIRECTORY_NAMES = frozenset({"色色参考", "adult", "nsfw"})` ← **另一份字面量**

第 ② 条是唯一拦住「`_原文/` 随全库索引一起被 `search_knowledge` / `read_document` 检索到」的机制。
它凭的是一个**手抄的字符串**。改包名（`色色参考` → 别的名字、或移动目录）时，Python 不会报错、
测试全绿、日志安静——而归档原文会**整目录进索引**，任何群友都能用 `search_knowledge` 搜到蒸馏前的原文，
包括主人刻意排除的那两处（CG 系统说明 / 睡奸与醉奸）。

这正是教训 #34 的形态：**代码里已经写明的语义，不要在另一处重新猜一遍**。
⇒ 修法是把包名做成**单源**：`knowledge.SENSITIVE_DIRECTORY_NAMES` 从 `intimate_reference.PACKAGE_DIRNAME` 取，
不再手抄。

## 5. 闸门（原来的那条是「拦名字」的，现在是「拦能力」的）

旧闸门只有一句：`assert not hasattr(IR, 'search_archive')`。它拦的是**一个名字**——换个名字（`load_archive`、
`search_raw`、或直接在 handler 里 `glob("_原文/*.md")`）就绕过去了。它测的不是「归档不可检索」，是「这个词不存在」。

新的五条：

1. `test_archive_stays_out_of_the_payload` —— 常驻注入里不许出现归档指纹（6 条指纹，不是两个硬编码词）。
2. `test_archive_retrieval_is_never_wired` —— **公开面白名单**：`intimate_reference` 的模块级函数/类必须恰好是
   `{Reference, package_dir, discover_slot_files, load, format_block}`，多一个就红（新增读归档入口 → 先重新拍板）。
   这一条替代旧 `hasattr`：拦的是「长了新入口」，不是「出现某个词」。
3. `test_every_knowledge_read_surface_skips_the_archive` —— 上表七个读面用**真实数据**全跑一遍，指纹一处不许出现。
4. `test_sensitive_dirname_is_single_sourced` —— 包名必须在敏感集合里，且 `knowledge.py` 里不许再出现 `"色色参考"` 字面量。
5. `test_archive_probe_would_catch_a_leak` —— **阳性对照**：把带哨兵的假归档塞进槽位/归档目录，
   `IR.load()` 必须命中槽位哨兵、必须**不**命中归档哨兵。没有这条，上面四条「零泄漏」可能是永久假绿（教训 #37）。

### 7.1 跑全量时踩到的三个环境事实（都不是代码问题，但都会造假红）

本轮全量是**分 4 组**跑的（801 / 806 / 806 / 797，总 808s）。不是图快，是三个坑逼出来的——记下来省下次的时间：

1. **`pytest` 直接跑会在插件加载阶段就崩**：`hydra-core 1.0.7` 与 `omegaconf 2.3.1` 不兼容，
   `from omegaconf._utils import get_ref_type` → `ImportError`，**一个测试都没跑就退出**。
   ⇒ 必须 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`。
2. **禁用自动加载会连带禁掉 `pytest-asyncio`**，于是 async 测试报「async def functions are not natively supported」
   —— 实测前 4% 处 **6 个假红**。⇒ 必须显式 `-p asyncio`。补上后同一区段全绿。
3. **测试环境缺 `USERPROFILE`/`HOME`** ⇒ `Path.home()` 抛 `RuntimeError: Could not determine home directory`
   （`test_sync_codex_mcp_block.py` **26 个假红**）。补上 user/system 变量即可。
   但**不能顺手补 `PATH`**：一旦显式给 PATH，`CreateProcess` 就只用它、不再走 App Paths，
   于是 `test_release_sanitizer.py::test_scaffold_notes_survive_gitignore` 找不到 `git.exe`（**1 个假红**）。
   ⇒ 正确做法是**补 user/system 变量、不设 PATH**。

这三条都属于教训 #37 形态「判据测的是环境不是行为」：**同一份代码在不同 env 下会给出完全不同的红绿**。
写在这里是因为它们下次还会发生（每一次新会话的 `process.env` 都是空的）。

## 8. 边界（有意不做）

- **不删 `_原文/`**：它是蒸馏溯源归档，`tests/test_seductive_slots.py` 有闸门保证「≥5 篇且保留」。
  「不允许检索」≠「销毁原文」——主人要的是不可被检索，不是不可追溯。
- **不加任何「受限只读」工具**（例如「仅 seductive 场景可见的 archive 查询」）。
  这是最容易在下一轮被好心提回来的方案：它把「禁检索」降级成「有条件的检索」，而条件成立与否取决于
  挂载状态、授权状态、模型自觉——每一条都会在某次重构里失守一次。定案是**不许**，不是**看着办**。
- **不动 `蒸馏说明.md`**（数据文件，敏感性高于必要）：理由写在代码注释与本记录，不写进被检索面附近的文件。
- 生产**需重启**才生效（本改动只改了常量来源与注释；重启前旧进程行为与新版等价）。
