## 三、⚠ 一个必须写明的口径陷阱：多气泡**无法与修复前对比**

第一版统计得出「修复前多气泡 **0.0%** → 修复后 44.8%」，**那是编造历史**：

- `bubble_count` 是 **T22（2026-10-14）才加的列**，实测 `IS NULL` **3674 行**、非 NULL **315 行**；
- 非 NULL 的最小时间戳 = `2026-10-14 09:54:35`——**正好是切点之后**；
- 也就是说：修复前那 3674 行**根本不知道发了几条**，把它们算成「0% 多气泡」等于声称「以前从不拆条」——而真相是**以前没记**。

**这正是 T22 记录里自己警告过的那件事**（「填 0 或 1 都是编造历史，会让改动前后密度对比看起来有假基线」）。
所以本节只给**修复后的绝对值**，不给 delta：

| 周期 | n | 均长 | 超100% | 喵% | 多气泡% |
|---|---|---|---|---|---|
| W1 10-14 | 32 | 39.9 | 0.0 | 3.1 | 37.5 |
| W2 10-15~17 | 202 | 92.8 | 24.3 | 19.8 | 45.5 |
| W3 10-18~20 | 30 | 71.0 | 13.3 | 10.0 | 36.7 |
| W4 10-21~23 | 51 | 82.4 | 29.4 | 43.1 | 51.0 |

**多气泡稳定在 37–51%**，且与长度正相关（`<40` → 1.13 条 / `40-80` → 1.48 / `80-140` → 1.83 / `≥140` → **2.65** 条）

## 七、方法论沉淀（本轮踩到的）

1. **「待取证」有时是「取证材料找错了地方」**：T8 挂在「等 7 天」上很久，而日志只留当日（T55-F 后不跨机同步）；
   真正的数据源是**持久表** `reply_metrics`。**换数据源比等时间更有效。**
2. **新增列不能与历史对比**：`bubble_count` 的 NULL 分布一眼就能看出「修复前不知道」，但第一版脚本按 0 算了。
   这与 T22 自己写的警告是同一件事——**警告写在记录里，脚本里照样踩**。⇒ 判据要写成代码（`where bubble_count is not null`），不能靠记得。
3. **总量指标会骗人，拆到会话层才看得见机制**：W4 喵 43.1% 看起来像「回升」，拆开是**一个会话的 77.8%**。
   与 T19「数字反常时先怀疑口径」、T23「主要矛盾是基线不是动量」同族：**先问「这个数字是谁贡献的」。**
