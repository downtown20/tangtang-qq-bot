**守护什么**：糖糖的冷热场学习（`COLD_FIELD_PENALTY`/`WARM_REPLY_BONUS`）、per-user 主动私聊冷却、24h 冷场结算、优雅退出持久化。

**后果**：

**根因**：2026-08-16 按教训 #15 修的是「没落盘」；这次是「**落盘失败不可见**」——**同一错误的第二形态，更隐蔽（代码看起来是对的）**。

## 二、修法（最小改动，收敛 7 处为 1 个 helper）

新增 `AutonomyMixin._persist_self_state(what: str) -> bool`（`agent/handler_autonomy.py:1535`）：

```python
def _persist_self_state(self, what: str) -> bool:
    """落盘自我状态；失败必须留下可观测事实（2026-10-14 台账 T9）。"""
    try:
        self.self_state.save()
        return True
    except Exception as exc:
        logger.error(
            "💾 自我状态落盘失败（%s）：%s: %s——本次学习/冷却不会被记住，重启后可能复发",
            what, type(exc).__name__, exc,
        )
        try:
            self.metrics.incr("self_state_save_failed")
        except Exception:
            logger.debug("self_state_save_failed 指标记录失败", exc_info=True)
        return False
```

设计取舍：
- **fail-open**（不重抛）：主动私聊/结算主流程不应被持久化失败阻断，否则一次磁盘抖动就让糖糖停止学习；
- **但必须可观测**：`logger.error`（带 `what` 参数定位是哪条路径丢的）+ `metrics.incr` 计数；
- 指标自身失败只降级到 debug，不反向搞崩 persist。

替换的 7 处（`what` 各不相同，便于日志定位）：

| 文件:行 | 所在方法 | what |
|---|---|---|
 | handler_autonomy.py:1584 | `_adjust_willingness` | 主动私聊意愿分调整 |
 | handler_autonomy.py:1593 | `_mark_seek_sent` | 主动私聊状态更新 |
 | handler_autonomy.py:1599 | `_mark_seek_gave_up` | 主动私聊状态更新 |
 | handler_autonomy.py:1694 | `_settle_stale_seeks` | 主动私聊24h冷场结算 |
 | handler_autonomy.py:1720 | `_settle_seek_with_reply` | 主动私聊状态更新 |
 | handler.py（stop_services）| 优雅退出 | 优雅退出保存 |
 | handler.py（_do_scheduled_restart）| 凌晨6点重启 | 定时重启前保存 |

顺带修掉的两处隐患（原外层裸 except 掩盖的）：
- `_do_scheduled_restart` 里的 `_save_extraction_state()` 与 `catch_up.record_offline()` 此前被同一个裸 except 吞掉；现已拆开，`record_offline` 单独有 `logger.warning`。

## 四、踩坑（记入环境事实）

**变异探针第一版打偏了**：`t.find('logger.error(')` 找到的是文件里第一处（line 191），
不是 helper 内那一处（1557）→ M1 变异实际没改到目标代码，测试自然仍绿。
我一度误判为「测试失效」，实际是**探针定位错**。
修法：先 `t.find('def _persist_self_state')` 定位 helper，再 `t.find(old, hidx)` 在其后搜索。
教训：变异阳性对照报「未变红」时，**先验证变异真的作用到了目标代码**，再怀疑测试。
