# 📡 台式机 ↔ 笔记本 文件同步指南

> 台式机改文件 → 自动同步到笔记本 → 笔记本上糖糖读到最新数据
> 全程自动，不需要 U盘拷贝，不需要手动传文件。

---

## 一、装 Syncthing

**两台电脑都装**，打开终端（Win+R → `cmd`），粘贴：

```bash
winget install Syncthing.Syncthing
```

装完后启动：

```bash
syncthing --no-browser
```

浏览器会自动打开管理页面。没打开的话手动访问 `http://127.0.0.1:8384`

---

## 二、配对两台电脑

### 1. 台式机获取 ID

台式机浏览器 `http://127.0.0.1:8384` → 右上角「操作」→ **显示 ID** → 复制那串代码

### 2. 笔记本添加台式机

笔记本 `http://127.0.0.1:8384` → 右下角「添加远程设备」→ 粘贴台式机的 ID → 保存

### 3. 台式机确认

台式机页面顶部弹出提示 → **添加设备** → 保存

---

## 三、创建同步文件夹

**在台式机上**（只在一台创建，另一台接收）：

1. Syncthing 页面 → **添加文件夹**
2. 标签填 `糖糖`
3. 路径选项目文件夹（如 `D:\qq-小糖糖`）
4. **共享** → 勾选笔记本 → 保存

笔记本页面弹出「共享了糖糖文件夹」→ **添加** → 选笔记本上的保存路径 → 保存

---

## 四、什么该同步，什么不该同步

> ⚠️ **Syncthing 是双向同步**——两台电脑改了同一个文件都会互相同步。

| 文件 | 是否同步 | 说明 |
|------|---------|------|
| 代码、歌词、角色卡、表情包、知识库 | ✅ 同步 | 改完重启糖糖 / `/人格 重载` 生效 |
| `memory.db`（记忆数据库） | ❌ **不同步** | WAL 模式数据库，同步会损坏/丢数据（历史上已产生 10 个冲突文件） |
| 运行状态文件（.tangtang_self / .mood_state 等） | ❌ 不同步 | 每台机器各自生成 |
| `config.yaml`、`.env` | ✅ 同步 | 同一账号换机场景两边配置一致；**若两台同时跑不同 QQ** 才需要排除 |
| `memory_sync/`（记忆快照） | ✅ 同步 | 记忆同步的中转站——见下节 |

**为什么 memory.db 不能同步**：糖糖运行中，最新数据在 `memory.db-wal` 文件里，主文件是不完整的。Syncthing 同步过去的是缺 WAL 的旧数据，另一台打开会丢记忆甚至报损坏。

## 五、记忆怎么跨机器同步（记忆快照方案）

`memory.db` 不走 Syncthing，走**快照方案**——项目已自带 `.stignore` 忽略数据库本体，换机流程：

```
台式机糖糖退出（自动打包快照）
        ↓
memory_sync/memory-台式机.db   ← Syncthing 同步这个目录
        ↓
笔记本启动糖糖前 → 菜单 3「解包记忆」→ 启动
```

### 操作方式

| 操作 | 怎么做 |
|------|--------|
| 查看状态 | 双击 `安装糖糖.bat` → 菜单 6，或 `python tools/同步记忆.py 检查` |
| 打包（跑完糖糖后） | **自动**——糖糖任何方式退出时控制台自动打包（数据没变自动跳过）。也可手动：菜单 2 |
| 解包（启动糖糖前） | 菜单 3（**糖糖必须已停止**；自动选择最新的快照，也可指定机器名） |

### 记忆同步纪律

- 口诀：**跑完的那台「打包」，要跑的那台「解包」**
- 忘了打包就切机 = 丢记忆（解包时快照更新会直接覆盖，不警告）——所以糖糖退出会自动打包，杜绝这个风险
- 换机前等 Syncthing 把 `memory_sync/` 同步过去（`检查` 能看到快照时间）

## 六、新电脑首次运行（必做）

> 📋 按顺序操作，每步完成后打勾确认。

### ☐ 1. 装 Python 3.10

下载：https://www.python.org/downloads/release/python-31011/
→ 底部 **Windows installer (64-bit)**
→ **必须勾选** ✅ Add Python to PATH
→ 安装路径保持默认

### ☐ 2. 处理多 Python 冲突

多版本共存时 `python` 命令可能指向错误版本。验证：

```bash
python --version          # 应该显示 3.10.x
python -c "print('hello')" # 应该有输出
```

**如果没有输出**（最常见的坑）：说明 PATH 里的 python 不是 3.10。使用完整路径代替 `python`：

```bash
C:\Users\%USERNAME%\AppData\Local\Programs\Python\Python310\python.exe --version
```

项目自带的 `启动控制台.bat` 和 `安装糖糖.bat` 已自动处理这个问题。

### ☐ 3. 装 FFmpeg

```bash
winget install ffmpeg
```

装完**关掉终端重开**，验证：`ffmpeg -version`

### ☐ 4. 安装依赖（统一向导）

双击 `安装糖糖.bat` → 菜单 **1 安装依赖** → 勾选功能（聊天+记忆必选；语音=发语音+听懂语音消息；识图/唱歌/读文档/控制台/运维工具按需）→ 自动装对应依赖（含 torch CPU 版）。

语音识别模型 `asr_models/` 缺失时，首次语音输入会自动下载约 233MB；也可从台式机拷贝该目录。

只装核心也可直接：`pip install -r requirements.txt`

> 旧版 `一键安装.bat` 已退役（装不全依赖）。唱歌（RVC）相关的 fairseq 等重依赖仅在选择唱歌功能时需要。

**⚠ 语音依赖的 MSVC 前置（2026-09-05 起清单已声明）**：GPT-SoVITS 分词加速包 `jieba-fast` 在 Windows 上常无预编译 wheel，pip 会尝试源码编译——需先装 **VS2022 Build Tools**（勾选「使用 C++ 的桌面开发」含 MSVC x64 与 Windows SDK）。安装器会检测 `cl.exe` 并提示。没装 MSVC 也能跑语音：`start_api_patched.py` 会自动回退纯 Python `jieba`（较慢但可用）。装完 MSVC 后要**重开终端**再装依赖，否则 PATH 里仍找不到 cl.exe。

### ☐ 4.1 体检验证

两种方式任选：
- 双击 `安装糖糖.bat` → 菜单 **7 体检**（跑完自动等你按键再退出）
- 命令行 `python tools/体检.py`（双击 tools/体检.py 也可以——跑完停在「按任意键退出」）

对照台式机输出，确认新机的 ❌/⚠ 行与本次所选功能一致；若本机不启用语音或本地识图，对应行可忽略。

### ☐ 5. 解包记忆（可选）

如果台式机的记忆快照已同步过来（`memory_sync/` 里有文件）：

双击 `安装糖糖.bat` → 菜单 **3 解包记忆** → 应用台式机的最新记忆。

### ☐ 6. 装 SnowLuma 并登录

运行 `SnowLuma/SnowLuma-v*/launcher.bat`，弹出的 QQ 窗口扫码登录。

> ⚠️ 同一个 QQ 号**不能两台电脑同时在线**——笔记本登录会把台式机的糖糖顶下线，反之亦然。切换机器前先停止另一台的糖糖。

### ☐ 7. 配置 SnowLuma OneBot

```bash
python tools/配置SnowLuma.py
```

### ☐ 8. 启动

双击 `启动控制台.bat` → 启动 SnowLuma → 扫码 → 启动糖糖。

## 八、踩过的坑

### 控制台 emoji 乱码/崩溃

**现象**：日志刷屏 `UnicodeEncodeError: 'gbk' codec can't encode character`

**原因**：Windows 中文版控制台默认 GBK 编码，糖糖日志里的 emoji（📋🎤🧠 等）无法写入。

**修复**：已在 `main.py` 顶部强制 UTF-8 输出。如果还出现，在启动前设置环境变量：
```bash
set PYTHONIOENCODING=utf-8 && python main.py
```

### Python 路径不一致

**原因**：代码里硬编码了 `C:\Users\Administrator\...\Python310\python.exe`，但新电脑用户名不同（如 `李成展`）。

**修复**：一键安装会自动检测并替换。如果手动迁移，需要全局搜索替换（涉及 `糖糖控制台_qt.py`、`tools/diff_sing.py` 等）。

### QQ 不能同时在两台电脑登录

同一个 QQ 号不能同时在线。如果在笔记本开发测试，台式机的 QQ 会被踢下线。建议：
- 切换机器前先停止另一台的糖糖
- 开发测试用另一个 QQ 号（需要改 config.yaml 的 bot.qq_id）

### Syncthing 文件夹路径有中文

**现象**：路径包含中文时可能无法索引。

**修复**：用英文路径（如 `D:\qq-tangtang`），避免中文文件夹名。

### SnowLuma 需要单独安装登录

Syncthing 只同步项目文件，不同步 SnowLuma 的登录状态。每台电脑都要单独运行 SnowLuma 并扫码登录。

### 多个 Python 版本冲突

**现象**：`python --version` 输出不是 3.10，或者 `python -c "print('hello')"` 没有任何输出。

**原因**：装了多个 Python（如 msys64 自带的、Windows Store 版、3.14 等），PATH 里的 `python` 指向了错的那个。

**解决**：使用完整路径 `C:\Users\%USERNAME%\AppData\Local\Programs\Python\Python310\python.exe`。项目的 .bat 文件已自动处理。

### pip 命令无反应

**现象**：`pip install xxx` 没有任何输出，直接回到提示符。

**原因**：和上面一样——PATH 里的 pip 不是 Python 3.10 的。

**解决**：用 `C:\Users\%USERNAME%\AppData\Local\Programs\Python\Python310\python.exe -m pip install xxx`。

### memory.db 的 sync-conflict 文件（历史遗留）

项目里曾有 10 个 `memory.sync-conflict-*.db` 冲突文件——这是旧版"直接同步数据库"时代留下的。现在的 `.stignore` 已排除 `memory.db*`，不会再产生。旧冲突文件可手动删除（数据以当前 memory.db 为准）。

## 九、推荐的 Syncthing 设置

| 设置 | 推荐值 | 原因 |
|------|--------|------|
| 版本控制 | 简易版本控制 | 误删文件可以恢复 |
| 扫描间隔 | 10 秒 | 代码改动快速同步 |
| 开机自启 | 开启 | 不需要每次手动启动 Syncthing |

## 十、日常使用

| 场景 | 操作 |
|------|------|
| 台式机改了代码 | 自动同步到笔记本 → 笔记本重启糖糖 |
| 笔记本单独加了翻唱 | 自动同步回台式机 |
| 跑完糖糖准备换机 | 什么都不用做——退出时已自动打包，等快照同步过去即可 |
| 启动糖糖前（新机器） | 菜单 3「解包记忆」应用快照 |
| 想看同步状态 | 浏览器打开 `http://127.0.0.1:8384` |
| 想看记忆快照状态 | `python tools/同步记忆.py 检查` |
