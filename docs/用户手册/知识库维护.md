# 知识库维护说明

> 给糖糖的维护者/AI 接手者：knowledge/ 目录是什么、怎么写、怎么被检索、有什么纪律。
> 机制以 agent/knowledge.py + agent/knowledge_index.py 为准（2026-09-05 核对）。

## 一、知识库是什么（不是什么）

**是什么**：糖糖可以**主动查阅**的背景知识资料库——游戏设定、技术笔记、风格参考等长期有效的事实性内容。
糖糖通过 `search_knowledge` 等 LLM 工具检索它，需要时查、不需要时不进上下文。

**不是什么**：
- ❌ 不是聊天记录/记忆库——糖糖从聊天中学会的东西进 `memories`（数据库），**永不写入这里**。
  （旧机制的 `learned_*.md` 是历史残留，新代码已不写；发布时也排除这类个人内容。）
- ❌ 不是能力清单/说明书——歌单、技能说明等随工具按需注入，不靠知识库常驻。

## 二、放哪、支持什么格式

- 位置：项目根 `knowledge/`，**任意子文件夹都递归加载**（可用子目录分类）。
- 格式：`.md` 和 `.txt` 都支持（早期只认 .md、`千恋万花_丛林.txt` 被漏加载过的教训——现已修复）。
- 索引：`knowledge/.knowledge_index.sqlite3`（持久化索引，启动时自动构建/同步）。
  新增/修改条目后**重启糖糖**（或下次启动）即生效；`.knowledge_index.sqlite3` 是生成物，不用手工维护。

## 三、怎么写一条好的知识条目

参考现有好条目：`knowledge/minecraft.md`、`knowledge/snowluma.md`、`knowledge/记忆系统技术文档.md`。

```markdown
# 标题：主题一句话

## 是什么
两三句说清对象。

## 要点（按场景写小节）
- 事实性描述，像给人看的速查笔记
- 糖糖检索时按语义匹配取块——**自然语言写清即可命中**，
  不需要堆砌关键词（检索是 关键词 FTS + BGE 语义 + RRF 融合 + Reranker 重排）
```

纪律：
1. **只放长期有效的事实**；临时/一次性内容、私聊内容、个人隐私绝不入知识库
2. **文件名全库唯一**——`a/guide.md` 与 `b/guide.md` 同名会共享检索证据身份，互相干扰
3. 一个主题一个文件，别写超大杂烩（内容会被切块检索）
4. 敏感资料不放默认 knowledge/（代码里对"普通知识工具"有安全边界；敏感内容需显式授权场景）
5. `.bak`/临时文件会被排除，但别往里面丢垃圾

## 四、维护节奏建议

- 糖糖长期使用后：定期看 knowledge/ 有没有过时条目（例如版本类内容标注日期）
- 发布/换机：整个 knowledge/ 是纯文本，直接复制即可；**先剔除 `learned_*` 个人内容**
- 想确认某条是否被加载：启动日志看"📚 知识库为空…"反转判断——为空说明路径不对

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 新增 .md 后糖糖查不到 | 重启（索引启动时同步）；确认扩展名 .md/.txt |
| 写了条目但总被无关引用 | 文件太杂——拆主题；或语义离目标太远，改写更直白 |
| 想让某些内容**永不**被查到 | 移出 knowledge/（如 backups/），不要只改名 |
| 知识库为空日志 | knowledge/ 下没有 .md/.txt——检查路径与格式 |
