# 第 10 轮：元数据吃掉了自忆块 68% 的预算（2026-10-25）

> 起点是第 9 轮尾留下的一句观察：「自忆块仍被裁到 60%（自忆 249→150t）」。
> 顺着它查下去，答案不是「预算不够」——**是同样的预算里，一大半没装内容。**

---

## 1. 立项：「进来了」不等于「够用」

第 9 轮修完三处（删掉假取回路径 + P10→P6 + 预算 900→1100），自忆块终于能进 prompt 了。
但日志留了这两行：

```
09:22:57 | 保留flex=4 裁=3（窗口 328→141t、自忆 243→143t、记忆 244→209t）| 预算 971/1100
09:23:18 | 保留flex=4 裁=3（窗口 369→158t、自忆 249→150t、记忆 307→181t）| 预算 1069/1100
```

三块**同时**被裁：窗口砍 57%、自忆砍 40%、记忆砍 41%。

第 9 轮解决的是「自忆从 0 到 1」，这一轮要回答的是：**1 之后，它真的是 1 吗？**

---

## 2. 查库：自忆库的真实规模

先看 `bot_qq=2693914170` 名下有什么（`qq_id` 是记忆的**归属者**，`target_qq` 是**关于谁**）：

| 项 | 数量 |
|---|---|
| 总条数 | 5181 |
| `retracted` | **3503（68%）** |
| `active` | 1673 |
| 其中 `self/verified`（能进注入的） | **1521** |
| 按 `target_qq` 分布 | 铺满所有对话对象（293/182/175/132…） |

两个结论：

1. **retracted 3503 条全部集中在 2026-08 一个月内**——一次性批量治理的产物，不是质量问题。
2. **self 记忆的 `confidence` 全是 0.70**（1673 条同一个值，写入侧硬编码）——这一条后面是关键。

内容质量出乎意料地好，不是流水账：

```
#21375 [2026-09-22 03:40] promise 明天白天你随便提，我说了算数
#21416 [2026-09-22 16:09] promise 回头给标题的话，我会认真查了再答你，不让空着手瞎猜。
#20954 [2026-08-27 22:22] promise 承诺把「啥子！！！」补传过去，传完报告
```

**所以问题不在库里，在库到 prompt 的那一段。**

## 3. 关键实验：150t 到底装得下几条

`truncate_bg_block` **按行切**（优先 `\n`，不切半句），所以块体积直接决定还剩几条。
拿她后来亲口答出来的那 5 条真数据，精确复刻 `_format_self_memories`：

| 项 | 实测 |
|---|---|
| 标题行 | 17t |
| 单条 | **40 ~ 51t** |
| 5 条合计 | **242t**（生产日志实报 244~249t ✓ 吻合） |
| 裁到 156t | **105t，保留 2 条** |
| 裁到 150t | **105t，保留 2 条** |
| 裁到 240t（单块上限） | **150t，保留 3 条** |

**代码检索 10 条、格式化 5 条，实际注入 2 条——每次白跑 3 条 BGE。**

而单条为什么这么大？拆开看：

```
  💭 [承诺过 | 2026-08-27 22:22 | 置信度0.70 | 来源 chat_log#236563 私聊] 承诺把「啥子！！！」补传过去
     └──────────────── 前缀 50 字符 ≈ 33t ────────────────┘ └── 正文 ≈ 13t ──┘
```

`estimate_tokens` 是「中文×0.72 + 其他×0.5」，而前缀里全是数字、英文、符号（`2026-08-27 22:22`、`chat_log#236563`、`0.70`），**全按 0.5 计**。
promise 类自忆的正文只有 9~20 字，于是：

> **5 条 242t 里，165t（68%）是元数据。**

其中两个字段是纯噪音：

- **`置信度0.70`** —— 1673 条 active 自忆 **全是 0.70**（写入侧硬编码一个值）。它不区分任何东西。
- **`来源 chat_log#236563`** —— 她**没有**能按 chat_log id 取回的工具（`search_chat_history` 是关键词检索，不吃 id）。**这是第 9 轮「假取回路径」的近亲**：登记了一个听着像、实际到不了的路径。

## 4. 岔路：她居然答出了 6 件（三个假设被推翻）

做到这里我去会客厅问了一句：

> 「你还记得你自己跟我说过、答应过什么吗？能说几件说几件。」

她答出了 **6 件**，而且日期精确到分钟：

> 8月27号答应把「啥子！！！」补传给你…8月29号凌晨说好三分钟后喊你，同一天晚上还答应认真捧场…
> **9月22号那两笔也在**：你说标题回头给我…还有那句「明天白天你随便提，我说了算数」。

**156t 只装得下 2 条，她说了 6 件——对不上。** 于是连着推翻三个假设：

| 假设 | 结论 |
|---|---|
| 跨对象串忆（她说的是别人的事） | **伪**。`#20954/#21148/#21117/#21375/#21416` 的 `target_qq` 全是当前对话对象 |
| 元数据被她复读（「我置信度0.70地记得」） | **伪**。30 万条 chat_log 里 `chat_log#` 出现 **0 次**、`置信度` 仅 2 条且都是她在讲知识库文档 |
| 她编造的 | **伪**。`9月22日 16:09` / `03:40` 两个时间戳，与 `#21416`（16:09）、`#21375`（03:40）**分钟级吻合**，编不出 |

真凶在 `turn_traces`：

**09:23 那轮**（`#92`）她调了 **4 个工具**：
```
search_memories("糖糖 承诺 答应 提醒", limit=15)
search_facts(subject_qq=2524950083, "糖糖答应过的承诺 叫起床 提醒")
search_chat_history("十点叫你 起床提醒 答应", subject_qq=2524950083)   ← 捞回 10-25 01:00 那条原话
set_reminder(10:00)
```

**09:51 那轮**（`#93`）`tool_steps: []`，没调任何工具。她的 reasoning 第一句是
「*I already answered in the previous turn*」——**她从历史窗口里读到了自己 09:23 的回答，复述的。**

### 这一节的意义

她这次答对，**不是自忆块的功劳，是上一轮临时查工具的运气**。
换一个没查过工具的回合，自忆块仍然只有 2 条，剩下 3 条既看不到、也取不回来
（第 9 轮已把 `"自忆": "search_memories"` 删掉，因为那条路是假的）。

**「运气对了」不能当成「设计对了」。** 这也解释了为什么第 9 轮的日志统计里
自忆淘汰率是第一——她其实长期在靠工具和历史兜底。

## 5. 去伪存真：真正的缺陷

**同一个「记住说过的话」能力，仓里有两套渲染实现，只压过其中一套：**

| 块 | 行格式 | 前缀成本 |
|---|---|---|
| 记忆 `format_compact_memories`（第 8 轮压过） | `  💭 {内容}` | **~2t** |
| 自忆 `_format_self_memories`（没人动过） | `  💭 [承诺过 \| 日期 \| 置信度0.70 \| 来源 chat_log#N 私聊] {内容}` | **~33t** |

这正是第 8 轮「同一物理量两个换算点只改一个」（教训 #38）的同族，只是这次错在**格式成本**而非换算系数。

而它之所以藏了这么久，是因为**日志的观测口径选错了**：

> 日志写「自忆 249→150t」。这个数字看起来像正常裁剪，**它不传达「5 条变 2 条」**。

## 6. 修法

只改 `_format_self_memories` 的渲染，**预算总量、优先级、检索条数全部不动**：

```python
# 改前
f"  💭 [{labels.get(key,key)} | {str(timestamp)[:16]} | 置信度{float(confidence):.2f} |
      来源 chat_log#{evidence} {location}] {v[:80]}"

# 改后
f"  💭 {labels.get(key,key)} {day}{where} {v[:80]}"      # day = timestamp[5:10]
```

保留 / 删除的依据逐条写进了 docstring：

| 字段 | 处置 | 依据 |
|---|---|---|
| 类型（说过/承诺过/动作已完成） | **保留** | 契约明说三者不能互相改写，必须逐条可见 |
| 日期 | **保留但压成 `MM-DD`** | 第 9 轮刚修好「时间从没进上下文」，时间感是宝贝；秒级精度无用 |
| 群号 | **保留（仅群聊）** | 她要知道这话是在哪个群说的 |
| `置信度0.70` | **删** | 1673 条全是同一值，零信息 |
| `来源 chat_log#N` | **删** | 无工具可按 id 取回（第 9 轮同型假路径） |
| `私聊` | **删** | 当前作用域已知，冗余 |

**provenance（有原始消息支撑）没有丢**，由三处保证，每处都比「逐条打印编号」更强：

1. **写入侧** `validate_self_memory_source`：必须是同一对象、同一作用域、`is_bot_reply=1` 的 chat_log 行（bot 行只在确认送达后才写）；
2. **块首全块声明**：「有原始消息支持的自忆（类型不同，不能互相改写）」是对整块的断言，逐条再打编号是同一件事的重复表述；
3. **读侧** `grounded_only=True` 只取可信档。

## 7. 验证

### 体积收益（真实数据实测）

| 指标 | 改前 | 改后 |
|---|---|---|
| 单条 | 40 ~ 51t | **14 ~ 25t**（−51%~65%） |
| 5 条合计 | 242t | **116t** |
| 150t 预算下保留 | **2 条** | **5 条** |
| 240t 单块上限下保留 | **3 条** | **5 条** |

**零预算增加，自忆条数 ×2.5。**

### 三件套（全过）

- `python -m pytest tests/` → **3443 passed**（17m34s，exit 0；第 9 轮基线 3437 + 新增 5 用例 + 1）
- `python tools/静态检查.py` → 85 个文件，**undefined = 0**
- `python tools/变异对照.py --spec 变异_自忆块体积.json` → **5 真红 / 0 不合格**

### 线上复验（重启后同一语义再问一次）

重启 bot（pid 40924 → **57316**），在会客厅再问「你自己答应过我的事，能再说一遍吗？」：

| | 改前 09:23 | 改后 10:17 |
|---|---|---|
| 裁剪日志 | `裁=3（窗口 369→158t、**自忆 249→150t**、记忆 307→181t）` | `裁=2（窗口 369→211t、记忆 311→186t）` |
| 自忆块 | 被裁，只剩 2 条 | **完全不在裁剪列表里** |
| 预算占用 | 1069/1100 | **970/1100** |
| 她的回答 | 4~6 件（部分靠上一轮查工具 + 复述） | **7 件**（多出「9月29号喊我就应你」） |

**判据不是她说得更多，是日志里自忆块从「被裁」变成「不在裁剪列表」**——那一条不丢。
连带收益：预算占用 1069 → **970**，省下的额度让窗口块从 158t 回到 **211t**（少砍 53t）。
这正是「零预算增加」的实际含义：**不是把别人的额度抢过来，是把浪费掉的那部分还回去。**

### 新增回归闸门 `tests/test_self_memory_budget.py`（5 个用例）

把「条数」变成断言，而不是像以前那样只在日志里留一个 token 数：

- 150t 下 5 条必须全在（旧格式这里只留 2 条）
- 240t 单块上限下也是 5 条
- 单条 ≤ 25t
- `置信度` / `chat_log#` 不得回归；`有原始消息支持` / 类型 / 日期 / 群号必须还在
- 空时间戳不产生 `[5:10]` 切片垃圾

## 9. 教训 #40

> **体积纪律只管了「不超预算」，没管「同样预算装了多少内容」**
>
> 背景块被裁到 150t 时，日志只写「自忆 249→150t」。这个数字看起来像正常裁剪，
> **不传达「5 条变 2 条」**——和教训 #38「它藏了整整 9 天」同一形态：**观测口径
> 选错，缺陷就能长期隐形**。那一次错在换算系数，这一次错在**计量单位**。
>
> 更具体的两个纪律：
>
> ① **注入块的日志必须同时记「条数」**，不能只记 token。token 是成本，条数是信息量，
>    两者之比才是这一块的效率。
> ② **同一份数据被渲染到两处时，两处格式要一起审**（`grep` 同一语义的另一个
>    渲染点）。记忆块第 8 轮压成 `💭 内容` 时，自忆块没跟着压——「另一个渲染点」
>    就是这次 68% 的来源。
