## 三、两个新坑（都写进 CLAUDE.md #45）

### 3.1 测量工具会污染被测系统（观察者效应）

J4 的 5 条虚构探针走会客厅（真实生产路径）→ 写真实 `chat_log` → **触发了一次记忆提取**
→ 她「表示对陶艺没印象」的回复被存成一条自忆（#25938）。

- 已用 `set_memory_status(25938, 'retracted', actor='诊断工具J4', reason=...)` 回滚（带流水）；
- **5 个虚构词（陶艺/绿萝/松果/清河/蓝湾）永久作废**——它们已在 chat_log 里；
- 工具改成：跑之前查库，脏了 **exit 2 拒绝量**；`--probe 新词=问题` 造新词；
- 测试也从「生产库必须永远干净」改成「脏了必须拒绝」——前者会被工具自己弄红。

### 3.2 只报绝对精度 = 没测

J1 的 0.956 看着很好。但那三个对象名下 verified 记忆里 promise 占比分别是
**50% / 29% / 32%**——随机取 5 条也有 **0.37** 的期望精度。

不报随机基线，读者会把「池子里一半是承诺」误读成「检索很准」。
报出来之后：J1 = 2.59×（真的有信息量），J2 = 1.79×（几乎等于随机）。

**这是教训 #37 的延伸**：不只闸门要能红，**精度要能定锚**。

## 四、J2 = 0.289 意味着什么（谨慎解读）

三种可能机制（**都未取证**）：

1. `recall()` Phase 2 的时间衰减 `exp(-0.008×(age-30))`，30 天后开始压；
2. 新记忆把 top5 位置占满（池子里有 20~49 条老承诺，每问只取 5 条）；
3. 承诺 value 短，与泛问句的 BGE 距离远。

⚠ **但这条口径对老记忆天然不利**：用「你还记得你答应过我什么」这种**自由回忆式泛问**，
不携带那条具体承诺的线索。人类在同样条件下也会崩。

所以 0.289 同时反映「系统」和「测法」。**下一轮第一件事不是改代码，是补线索化口径**：
用每条老承诺自己的关键词作问句，测「那一条能不能被召回」。两个数字放在一起，
才能分清「泛问检索弱」还是「记忆真被压没了」。

## 六、顺带发现：第 14 轮的「同一件事只一条」只管得住同一批

清点 `open_loops` 时发现 13:59 的一次提取又产出了三条：

| id | topic | 问题 |
|---|---|---|
| #5 | 明早八点要起来抢号（预约检查/门诊） | 与 #4「明天要去医院复查」是**同一件事的不同侧面** |
| #6 | 下周要交一份报告，完全没开始写 | 与 #3「…还没开始写」**只差「还/完全」两个字**——归一化后不相等 |
| #7 | 让糖糖提醒自己复查 | 是「安排」不是「没结的事」——提取偏宽 |

**根因**：第 14 轮加的「同一件事只输出一条」是 prompt 约束，只能在**同一批消息内**生效；
#3/#6 分属两个提取批次（13:19 / 13:59），跨批去重仍靠「归一化 topic 完全相等」——
差两个字就不相等。

三条已用 `store.resolve_open_loop(outcome='dropped')` 收尾（带 resolution 说明），
保留 #3/#4 作注入样本。

**这条记入待办，不在本轮修**（本轮只造尺子）：
跨批重复需要**写入侧去重键升级**（比如同 `qq_id` + 同 `expected_at` + 高相似度 → 更新而非新建），
但计划 §2.3 明确说过「不要在 store 里加模糊匹配」——所以要么改提取 prompt 让 value 规范化
（不可靠），要么另设计一个可解释的合并口径。下一轮之后再议。
