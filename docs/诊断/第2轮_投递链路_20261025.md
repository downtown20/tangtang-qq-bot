# 第 2 轮｜她有一半说明书从来没送到 —— 预算尺子坏了

> 2026-10-25 05:40–06:00。工作流见
> [自主发现修复闭环_毛选视角](../工作方式/自主发现修复闭环_毛选视角_20261025.md)。
>
> 第 1 轮末尾留下的尾巴：`estimate_tokens` 把真实 token 高估约 80%，
> 实测 system prompt 渲染后只剩 1580 字符（原 3005），「## 关系」「风格锚」
> 「FOLLOW_UP_PROTOCOL」整段被砍。本轮就查这一条。

---

## 第 0 步 立项

预测：确认高估倍数 ≥1.8 倍；修完后 system prompt 能从 1580 字符恢复到 3000 字符左右；
连带影响 ≥1 处依赖绝对预算的模块需要重新折算。

---

## 第 1 步 调查（不估算，直接问 API）

**方法**：把她真实的 system prompt 原样发给同一个模型（`deepseek-v4.1-flash`，
`buddybackend.cloud`），读返回的 `usage.prompt_tokens`。这是唯一可靠的尺子。

| 量 | 值 |
|---|---|
| system prompt 字符数 | 3000（中文 2340 / 其他 660） |
| `estimate_tokens` 旧公式估算 | **4542** |
| **API 实测 `prompt_tokens`** | **1926**（含 user「在吗」约 4） |
| **高估倍数** | **2.36×** |

再测四个样本标定系数：

| 样本 | 中文 | 其他 | 真实 tokens | 真实/字符 |
|---|---|---|---|---|
| 纯中文 | 192 | 16 | 133 | 0.64 |
| 纯英文 | 0 | 405 | 127 | 0.31 |
| 中英混合+标点 | 27 | 54 | 75 | 0.93 |
| 纯代码 | 0 | 105 | 69 | 0.66 |

结论：旧公式 `中文×1.8 + 其他×0.5` 的中文系数错得最厉害（1.8 vs 实测 0.64）。

---

## 第 2 步 建真值

这不是「答得好不好」的问题，是**算术问题**：预算 3000「估算 tokens」
实际只装得下约 1271 真实 tokens。所以：

- 她的 system prompt 3005 字符（真实约 1922 tokens）**必然超** 1271 → 必被截断；
- `_truncate_text` 从头保留、砍尾部 → 「## 关系」「说话示范」「FOLLOW_UP_PROTOCOL」
  这些排在后面的段**整段消失**；
- 而 `## 必须遵守`（契约）和「## 此刻」靠豁免活下来——所以现象是
  「她守规矩、知道时间，但没有性格细节、不知道关系档位」。

---

## 第 3 步 归因（二分）

**是「投递链路」缺陷，不是「她不会用」。** 内容写对了、也在 prompt 里，
但被预算尺子误判超限、砍掉了。属于第 1 轮总结的第 7 条纪律：
「区分『她不知道』和『她没看到』」。

更深一层的性质：**尺子自己就是被测对象，却从来没有被真实数据校准过**。
全系统十几处预算判断都挂在 `estimate_tokens` 上，而它只被「看起来差不多」验证过。

---

## 第 4 步 修复

### 主修：`agent/context_builder.py` `estimate_tokens`

中文系数 **1.8 → 0.72**（比实测 0.64 略保守，宁高勿低）；其他字符保留 0.5
（对纯英文仍高估 1.6 倍，是安全方向——低估会让预算守不住，比高估危险）。

真实 prompt 复算：`0.72×2340 + 0.5×660 = 2015` vs 真实 1926 → **+4.6%**，
落在「略保守」的目标区间。

### 必须同步：`_truncate_text` 的字符换算系数

`char_limit = token_budget / 1.8` 里的 1.8 **是同一把旧尺子**的来源。
只改 `estimate_tokens` 不改它，就会「判断用新尺、换算用旧尺」——
判超预算了，却只留 `预算/1.8` 个字符，截完还是不达标。改成 `/ 0.72`。

### 连带重算：所有依赖绝对预算常量的地方

换尺子会让所有预算的**真实容量**×2.36。有的变大是好事（system prompt 装得下），
有的是破坏（背景块变多 = 2026-08-17 特意压下去的「材料综述/演讲腔」土壤）。
逐个按「保持原真实容量」折算：

| 常量 | 旧值 | 新值 | 依据 |
|---|---|---|---|
| `BACKGROUND_BUDGET_TOKENS` | 1200 | **480** | 原注释就写着「≈660 汉字」——目标是 660 汉字不是 1200 token，660×0.72≈475 |
| `MAX_BACKGROUND_BLOCK_TOKENS` | 600 | **240** | 同比例，保持单块真实容量 |
| `EVIDENCE_RESERVE_TOKENS` | 400 | **160** | 原来是背景预算的 33%（400/1200）；不折算的话它会变成 480 的 83%，证据块几乎吃掉全部预算，行为大变 |
| `BUDGET_CORE + RELEVANT + SUPPLEMENTARY` | 3000 | **3000（不动）** | 这正是修复目标：让真实 1922 tokens 的 prompt 装得下 |

### 连带改测试（三处「前提」失效，判据没变）

换尺子后，三条测试的**前提**（「预算不够，所以有块被淘汰」）不成立了——
它们原本写死了旧尺子下的预算数字：

| 测试 | 处理 |
|---|---|
| `test_dialog_quality::test_priority_selection_not_append_order` | 预算 600 → 400（重算到「够两块不够三块」区间），注释写明判据没变是尺子变了 |
| `test_background_gap_notice::test_relationship_archive_survives_a_saturated_round` | 改成用 `protocols._bg_est` **现场算**「刚好装下协议+关系档案」，以后再换尺子不用再改 |
| `test_self_location_context::TestPromptBudgetKeepsWholeManual` | 整组重写：从「时间块在截断后存活」升级为「**真实 prompt 不该被截断，尾部各段全在**」+ 强制截断路径用人工构造的长 base（不再依赖真实 prompt 恰好超预算） |

最后一条是本轮的副产品：**原测试把「真实 prompt 恰好超预算」当成前提**，
这个前提在 prompt 一瘦身之后就会静默失效（闸门变成测空气）。改成人工构造，
闸门才活得久。

## 第 7 步 沉淀

### 教训候选（值得进 CLAUDE.md 教训表）

**「尺子自己也要被校准」**：本项目十几次预算判断全挂在 `estimate_tokens` 上，
而它从上线起就把中文 token 高估 2.36 倍——于是「预算够不够」这件事一直是错的，
只是错得刚好没人发现（内容被砍了，表现是「她有点单薄」，不像 bug）。

判据：**任何「估算/阈值/评分」函数，必须有至少一条拿真实数据校过的回归测试**
（本轮新增 `test_estimate_tokens_matches_measured_usage`，拿 API 实测 133 做基准）。

### 新发现的尾巴（下一轮候选）

其他字符系数 0.5 对纯英文仍高估 1.6 倍；符号/换行密集的文本（代码、JSON schema）
反而被**低估**（0.64 倍）。工具 schema 估算 5614t 里真实可能在 3900 左右——
「按需工具」的阈值判断仍偏保守。不影响正确性，影响 tool 预算判断的准确度。

### 仍然没做的：她这一轮看到了什么

`turn_traces` 只记 `reasoning_text` 和 `tool_steps`，`prompt_chars` 恒为 0
（`_persist_turn_trace` 根本没传这个参数）。**「她看到了什么」依然没有留档**——
第 1 轮就指出这是盲区，现在仍然只能靠本地复刻 + 日志推断。建议下一轮优先补上
（存摘要不存全文）。
