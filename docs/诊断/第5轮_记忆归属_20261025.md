根因是**判据口径不一致**而非单点 bug。

## 第 2 步 建真值

这不是「某条记忆错了」的问题，是**两个独立维度被混成一个**：

- **出处维度**：这句话在 `chat_log` 里被逐字说过吗？→ 语义回挂验证的是这个
- **归属维度**：这条记忆是不是关于 ta 本人的、可信的事实？→ 回挂**不验证**这个

小说情节、玩笑、转述、引用、假设，在出处维度上全部成立。

---

## 第 3 步 归因（口径不一致，不是单点 bug）

同一件事，代码里有两套判据：

| 路径 | verified 要求 |
|---|---|
| 新提取 `insert_memory` | 有 quote **且** `claim_type == "stated"` **且** `confidence >= 0.75` |
| 重验证 `update_memory_evidence` | 有 quote **且** allow flag **且** reviewer/reason —— **没有置信度门槛** |

**重验证这条路从来不看置信度。** 提取它的 LLM 当时写下的 `confidence=0.5`
（「我不确定这是不是真事实」）在升级时被完全忽略了。

这正是本项目反复踩的那条：**同一件事两套判据**（教训 #4 变体：
config 与控制台不同步；教训 #37 变体：判据与目标不同源）。

---

## 第 4 步 修复

`agent/store.py`：

```python
LEGACY_PROMOTION_MIN_CONFIDENCE = 0.7   # 模块级具名常量，不是散落的魔数
```

在 `update_memory_evidence` 的 `is_legacy` 分支内加一道门：

```python
if float(confidence or 0) < LEGACY_PROMOTION_MIN_CONFIDENCE:
    return False
```

**为什么是 0.7 而不是与 `insert_memory` 一样的 0.75**：

- 重验证额外拿到了原文证据，证据强度高于纯新提取，可以略宽；
- 0.7 是常规提取的**默认置信度**（库里 verified 中 conf=0.7 有 4,959 条），
  卡 0.75 会把大量正常记忆一并挡在门外；
- 挡掉的目标是「LLM 自己都说不确定」的那批（0.5 / 0.55 / 0.6），
  它们恰好就是小说情节和玩笑的聚集区。

**这道门只在 legacy 分支内**：已经 verified 的记忆补一条引用不属于「升级」，
不该被置信度挡住（有专门的反向变异钉住这件事）。

### 一条方法论

**「有出处」和「是真的」是两个正交维度。** 任何「我不确定，但我能证明它被说过」
的情形都会滑向这个坑——代码评审里叫「证据充分性 vs 证据相关性」。
判据要成对写：**出处校验**负责「有没有说过」，**置信/类型校验**负责「算不算事实」，
只做前者等于把后者静默放行。

### 还没做的

`claim_type` 目前在 `insert_memory` 里只作为**入参**使用，**没有存进 `memories` 行**。
所以回挂时无法复核「这条记忆当初是 stated 还是 inferred」——只能退而用
`confidence` 做代理。要更精确，得给 `memories` 加 `claim_type` 列并回填，
那是独立一轮的工作量，不塞进本轮。

## 附：本轮碰到的一个副产品（README 徽章过期）

全量测试第一次跑挂了 1 条：

```
FAILED tests/test_release_readme_contract.py::test_claimed_numbers_match_reality
AssertionError: README 还写着 2900+，实际已有 3407 —— 数字太旧了
```

这是**契约测试在正常工作**——「文档当代码测」（教训 #35）的机制拦住了数字腐烂。
修法是把徽章从 `tests-2900%2B` 提到 `tests-3400%2B`（下限声明，比实际 3407 低一点，
避免形成「更新 README 就改变总数」的反馈环）。

两个细节值得记：

1. 我一开始改的是**根 `README.md`**，测试还是红——因为契约测试读的是
   `docs/发布/README.md`（开发态源码在 `docs/发布/`，发布时才搬到根）。
   **两份 README 是重复内容**，正是《反对党八股》说的「无的放矢，不看对象」；
   短期不动（发布流程依赖这个布局），但改数字必须改对那一份。
2. 这个失败**不是本轮改动引起的**，是测试数涨到 3400 之后必然发生的——
   它只是在第 5 轮被跑出来。属于「发现了一个早就存在的问题」。
