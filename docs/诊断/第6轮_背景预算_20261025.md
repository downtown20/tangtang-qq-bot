## 第 1 步 对话取证

我问：「问你个事——你还记得我是什么身份吗？上学还是在工作？」

她答（正确）：

> 「大二的，在郴州苏仙区上白水那块，住校外没住宿舍——你之前还嫌外卖难吃来着。」

答对了。但**同一轮的 digest 暴露了另一件事**：

```json
"user_bg_labels": ["关系档案", "协议", "窗口", "缺口"]
```

**没有「记忆」块。** 而她的 reasoning 原话是：

> 「The background says **memory is empty**, need to search.」

——她不是勤快才去查 `search_facts`，是**没人给她**。

## 第 2 步 建真值（日志全量统计，不抽样）

`日志/tangtang.log` 里 35 条「背景块淘汰/裁剪」记录：

| 指标 | 数值 |
|---|---|
| 有块被淘汰的回合 | **35 / 35（100%）** |
| **「记忆」块被淘汰** | **27 条（77%）** |
| 预算打满（用量 ≥ 上限-5） | **33 条（94%）** |

典型两行（分别来自旧尺子和新尺子，说明**与第 2 轮的尺子改动无关，是结构性问题**）：

```
🧺 保留flex=2 淘汰=2（记忆(P7,435t)、自忆(P10,430t)） 裁=2（关系档案 662→480t、窗口 864→240t）| 预算 1246/1200 ⚠保护块已超顶
🧺 保留flex=2 淘汰=2（记忆(P7,215t)、自忆(P10,241t)） 裁=1（窗口 205→49t）| 预算 479/480
```

## 第 3 步 归因

不是「记忆系统坏了」——**记忆全在库里**（17,283 条 active，9,735 条可注入）。
是**投递环节**：背景块预算只有 480「估算 tokens」，而一轮的块价是：

| 块 | 估算价 |
|---|---|
| 关系档案 | ~240（单块上限封顶） |
| 窗口 | ~53（原始可到 240+） |
| 协议（保护块） | ~30 |
| 缺口（告知哪些块没进来） | ~70 |
| **记忆** | **~215** |
| 自忆 | ~240 |

合计 ~848 > 480。**记忆结构性装不下**，而它的优先级（P7）排在窗口（P5）之后，
所以先被淘汰。

性质与第 2 轮同族：**「信息在不在库里」和「信息有没有送到她手上」是两件事**。
第 2 轮坑在 system prompt 截断，这轮坑在背景块预算。

---

## 第 4 步 修复（两档，第二档是被实测逼出来的）

`agent/protocols.py`：`BACKGROUND_BUDGET_TOKENS` **480 → 720 → 900**。

**为什么走了两档**（这是本轮最有价值的过程记录）：

第一次只调到 720，理由是「保持简洁，够装下记忆就行」。重启后实测：

```
🪺 保留flex=3 淘汰=1（自忆(P10,239t)） 裁=1（记忆 156→35t）| 预算 683/720
```

**记忆块进来了，但被裁到 35t。** 她确实看到「记忆」这个块，可里面只剩几条残缺的字。
她自己的复验原话：「缺的是自忆和**一部分记忆**，没给我，得我自己去捞。」

——**「有块没内容」等于没给**。所以第二档调到 900，把完整的需求量（~848）留出余量。

**为什么 900 不算「放开材料堆」**：它约等于 833 真实 tokens，是 system prompt
（≈2100 真实 tokens）的三分之一。2026-08-17 反对的是「一次塞十几个块导致
材料综述/演讲腔」；这里是「4 个有用的块装得下」，不是同一件事。
**自忆仍然是最低优先级、仍会被淘汰**——预算没控失控。

> 才真红。**这本身就是教训 #37 的一次现场复现：测试构造不真实 = 假绿。**

## 第 6 步 复验（生产实测，三档对照）

```
修复前   保留flex=2 淘汰=2（记忆(P7,215t)、自忆(P10,241t)） 裁=1（窗口 205→49t）| 预算 479/480

```

`prompt_digest.user_bg_labels`：

- 修复前：`["关系档案", "协议", "窗口", "缺口"]`
- **900 档：`["关系档案", "协议", "窗口", "缺口", "自忆", "记忆"]`** —— 六块全在

**行为复验**（问「这会儿你手上有什么」）：

> 「手上这些：你最近三句话，一份关系档案……**还有几条我自己应下过的话**，比如喊我就应你。
> 缺的还是窗口，只给了片段……**另外翻到一条挺有意思的：你之前气到哄不好的那种，
> 还说过「你很失败」。这账我可记着呢。**」

她开始**主动**提记忆里的内容了——不再是「你问了我才去查」。

### 一个方法论：两轮之间是互相验证的

第 3 轮补 `prompt_digest` 时说的是「让下次排查不用复刻 prompt」。但真正的收益
比那更大：**它让第 2 轮的修复第一次被真正验证了**——第 2 轮我改完尺子只验证了
「system prompt 变完整」，背景块那条链路根本没有观测手段。这轮一查日志，
才发现记忆块 77% 被淘汰。

### 新发现的缺陷（下一轮候选）

**同一主体有两份互斥的记忆同时 active**：

| 记忆 | 内容 | 信任等级 | 时间 |
|---|---|---|---|
| `mem#17589` | 「成展是大学大二学生（**不是高中生**）」 | **corrected** conf=1.0 | 08-17 |
| `mem#18121` | 「今年7月刚靠指标生名额考上一中，**是高一新生**」 | verified conf=0.95 | **08-18** |

纠正之后**第二天**，提取器又把旧错误提取成一条新的 verified 记忆。
`correct_memory` 只撤「当时存在的」行，撤不了「以后才被提取的」。

这轮她答对了（检索命中 corrected 那条），但那是运气——两条都在 `search_facts`
的候选池里。**注入/material 里没有仲裁机制**。下一轮处理。
