# 多模态 canary 清单（2026-09-03 · H6）

目的：每个功能域只做一次真实触发，取得 **成功 / 失败 / 未触发** 三态证据；端口可用、模型加载或单独的日志片段均不能代替端到端事实。

## 执行约束与统一取证

1. 本清单不要求重启 bot。先从当前 `tangtang.log` 的同一 boot 中取得本次触发的 `boot`、`cid`；记录触发起止时间、会话范围和观察到的 QQ 现象。
2. 每个步骤只触发一次。若失败或证据不足，停止重复触发，保存首个失败/缺失证据交主负责人裁决。
3. 日志摘取默认脱敏：`./python310/python.exe tools/extract_canary_evidence.py --log tangtang.log --boot '<boot>' --cid '<cid>' --output 'docs/运行验收/evidence/H6_<域>.txt'`。脚本会在输出中伪匿名化 boot/cid/QQ 类 ID、绝对路径，以及 ASR/识图的自由文本；过滤在脱敏前按真实 boot/cid 完成。
4. DB 取证仅允许只读连接：`sqlite3.connect('file:memory.db?mode=ro', uri=True)` 后执行 `PRAGMA query_only=ON`。报告只记录行数、状态和哈希化 ID；不要把 QQ、完整 `receipt_json`、原始消息或语音转写贴入协作文档。
5. 下列 SQL 的 `<开始>`、`<结束>`、`<scope>`、`<群号>` 由执行人以本次 canary 真实值替换。时间窗只覆盖本次操作前后约两分钟。

## 1. 知识库检索

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 在可观察会话发送：`请先调用本地知识库 search_knowledge，再回答：Black Souls II 的“超越结局”需要收集多少个古神遗物？请给出本地资料来源，不要凭常识猜。` |
| 预期行为 | LLM 调用 `search_knowledge`；答案为 13，并能指向 `knowledge/blacksouls.md` 的来源证据。该问题要求本地材料，不能以模型常识或“没查到”冒充成功。 |
| 日志 + DB 取证点 | 同一 cid 中应有 `📚 Knowledge Tool | tool=search_knowledge outcome=success` 与 `📚 Knowledge Retrieval | hits=… sources=… paths=blacksouls.md:… latency_ms=…`。知识检索不产生独立业务 receipt，DB 取证应为 **不适用**；只读确认可记录 `chat_log` 在时间窗内对应入站/回复行数，不把消息正文导出。`SELECT timestamp,is_bot_reply,event_key,length(raw_message),length(segments) FROM chat_log WHERE timestamp BETWEEN '<开始>' AND '<结束>' ORDER BY id;` |
| 通过 / 不通过 / 未触发 | **通过**：两条日志均在同 cid，`hits>0`、`paths` 含 `blacksouls.md`，且实际回复给出“13 个古神遗物”。**不通过**：`outcome=empty/error/invalid`、来源不匹配、答案与资料矛盾，或用户回复没有知识工具成功记录。**未触发/证据不足**：无该工具调用或无同 cid 结果，不能拿旧样本凑数。 |

**算法路径的严格说明**：现有运行日志只记录命中数、来源和耗时；`KnowledgeEvidence.match_type` / `rerank_score` 被交给工具结果但未写入该日志。因此本 canary 能证明端到端命中与来源，不能仅凭现有日志单独证明本次真的走了 hybrid + RRF + rerank。若主负责人要求该子条件作为硬门槛，应记录为“算法路径证据不足”，不能伪称通过；这需要后续批次提供脱敏的结构化 retrieval trace，H6 不修改业务日志。

## 2. 识图

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 在测试会话发送一张内容清楚、无个人信息的图片（例如单色物体或公开测试图），同一条或紧随其后 @糖糖：`这张图的主体和主色是什么？` |
| 预期行为 | 图片经按需 VL 识图，回复的主体和主色与图片一致；不要只验证图片被网关收到。 |
| 日志 + DB 取证点 | 同一 cid 应有 `糖糖.Handler` 的 `🖼 按需识图:`；若失败应保留 `糖糖.Vision` 的“识图失败”日志。只读 DB 同时证明该入站原文和 typed segment 均已保存（不导出正文）：`SELECT id,timestamp,event_key,json_valid(segments) AS segments_json,length(segments) AS segment_bytes FROM chat_log WHERE timestamp BETWEEN '<开始>' AND '<结束>' AND raw_message LIKE '%[CQ:image%' ORDER BY id;` 预期 `segments_json=1` 且 `segment_bytes>0`。 |
| 通过 / 不通过 / 未触发 | **通过**：日志成功、DB 有对应有效 typed segment，且人工核对回复内容正确。**不通过**：出现“识图失败”、DB 段为空/无效、或回复明显与图不符。**未触发/证据不足**：没有 `🖼 按需识图:`（仅上传图、贴图偷图、端口正常都不算）。 |

## 3. 角色切换（米雪儿 → 糖糖）

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 在拥有角色命令权限的会话发送 `/角色 米雪儿`，收到命令回执后发一句普通中文短句；再发送 `/角色 糖糖` 恢复。不要以重启或修改配置辅助切换。 |
| 预期行为 | 米雪儿阶段使用其角色卡、`michele` 音色和 `michele` 贴图库；恢复阶段回到默认角色卡、`v4`/中文丛雨音色和 `default` 图库。普通短句用于确认切换后仍能正常对话。 |
| 日志 + DB 取证点 | 每次切换均需要三处事实：`📋 角色卡已加载: role_card_michele.md`（或 `📋 角色卡已恢复默认（糖糖）`）、`🎙️ GPT-SoVITS 模型已切换: michele`（或 `v4`）、`🎨 表情包切换: michele`（或 `default`）。角色状态是进程内状态，**没有**持久化角色表；DB 只用于证明命令/命令回执发生：`SELECT timestamp,is_bot_reply,event_key,length(raw_message) FROM chat_log WHERE timestamp BETWEEN '<开始>' AND '<结束>' ORDER BY id;`，不能用 DB 行替代三处运行事实。 |
| 通过 / 不通过 / 未触发 | **通过**：米雪儿和恢复默认各具备三处日志，且两次命令回执与中间普通对话可见。**不通过**：任一步失败、只有音色切换而缺角色卡/图库切换，或恢复不完整。**未触发/证据不足**：只有启动期模型加载（cid 为 `-`）或旧日志，不算角色切换。 |

## 4. 语音输出与语音输入

### 4a. 语音输出

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 在可听取的测试会话发送：`请只用语音说“这是 H6 语音输出校验”。` 收到后播放一次。 |
| 预期行为 | 收到一条可播放、内容可辨的语音；不应额外自动补发重复文本。若系统明确文字兜底，则这次不计语音成功。 |
| 日志 + DB 取证点 | 同 cid 的顺序应包含 `🎤 语音触发:`（如有）、`🎙️ 语音发送:`、`🎤 语音已发送` 或 `🎙️ 语音已发送`；失败证据为 `语音生成失败`、`语音发送失败` 或“未确认”。只读 DB 查询：`SELECT action_id,source_id,kind,channel,action_status,ordinal,created_at,json_extract(receipt_json,'$.status') AS receipt_status FROM action_receipt_mailbox WHERE created_at BETWEEN '<开始>' AND '<结束>' AND kind='voice' AND scope_id='<scope>' ORDER BY created_at,ordinal;`。如为 confirmed，可额外核对 `confirmed_action_facts` 同一 `domain_action_id`。 |
| 通过 / 不通过 / 未触发 | **通过**：人工可听、完整发送日志同 cid，且同时间窗有且仅有本次 `voice` receipt 为 `confirmed`。**不通过**：失败/uncertain、没有可播放音频、重复送达，或 DB/日志身份不一致。**未触发/证据不足**：只看到模型就绪、TTS 文件生成或端口监听，没有送达事实。 |

### 4b. 语音输入

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 发送一段清晰、无敏感信息的 QQ 语音：`这是 H6 语音输入校验，我问二加三等于几？` |
| 预期行为 | ASR 转写与原话一致到足以得出 5，糖糖据此自然回答；不要把后续 LLM 纯猜对“5”当成 ASR 成功。 |
| 日志 + DB 取证点 | 同 cid 应有 `糖糖.ASR | 🎤 ASR →`；失败为 `❌ 语音识别失败`、`SILK 解码失败` 或 `ffmpeg 转码失败`。只读 DB：`SELECT id,timestamp,event_key,json_valid(segments) AS segments_json,length(segments) AS segment_bytes,length(raw_message) AS raw_bytes,length(message) AS transcript_bytes FROM chat_log WHERE timestamp BETWEEN '<开始>' AND '<结束>' AND raw_message LIKE '%[CQ:record%' ORDER BY id;`；预期 `segments_json=1`、`segment_bytes>0` 与 `transcript_bytes>0`。 |
| 通过 / 不通过 / 未触发 | **通过**：ASR 成功日志、DB typed record segment 与非空转写均存在，人工比对转写/回答可确认问题被听懂。**不通过**：任一解码/转写失败、转写错误导致答非所问，或 typed segment 缺失。**未触发/证据不足**：只有文字回复或音频上传，不见 ASR 成功行。 |

## 5. 唱歌（H2 新路径）

| 要素 | 一次性 canary |
| --- | --- |
| 触发步骤 | 在测试会话点一首**当前曲库中已确认有音频文件**的歌：`请唱《<曲库现有歌名>》的默认段落。` 收到后播放实际音频；不要为失败反复点歌。 |
| 预期行为 | LLM 的 `[SING:…]` marker 在 ReplyPipeline 清洗前已冻结，按 H2 新 `ActionPlan` 链路送达一段可播放的真实歌曲音频。回复文本中没有裸 marker 是正常现象。 |
| 日志 + DB 取证点 | 同 cid 应有 `🎤 Tool唱歌已确认:`；失败/不确定为 `🎤 Tool唱歌音频未确认:` 或 `❌ 唱歌失败`。只读 DB：`SELECT action_id,source_id,kind,channel,action_status,ordinal,created_at,json_extract(receipt_json,'$.status') AS receipt_status,json_extract(receipt_json,'$.actual.delivery_kind') AS delivery_kind,json_extract(receipt_json,'$.actual.fallback_used') AS fallback_used FROM action_receipt_mailbox WHERE created_at BETWEEN '<开始>' AND '<结束>' AND kind='sing' AND scope_id='<scope>' ORDER BY created_at,ordinal;`。可再查 `confirmed_action_facts` 的同一 `domain_action_id`。 |
| 通过 / 不通过 / 未触发 | **通过**：音频实际到达且可播放、`sing` receipt 为 `confirmed`、`delivery_kind='sing_audio'`、`fallback_used=0`，并有同 cid 成功日志。**不通过**：failed/uncertain、无 DB receipt、`sing_voice_fallback`（仅 TTS 兜底而非歌曲音频）、或重复送达。**未触发/证据不足**：只有 LLM 文本、裸 marker 或曲库列表，没有音频和 receipt。 |

## 交付给主负责人的最小证据包

每域交付一份脱敏日志摘录、一次人工可见结果、以及相应 SQL 的**行数/状态摘要**。对失败和未触发同样交付首个证据。主负责人再独立复跑 SQL 与观察器；本清单不将任何一次 canary 外推为长期稳定性结论。
