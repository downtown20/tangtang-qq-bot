# 记忆长尾公平调度验收（2026-08-28）

## 结论

生产观察发现的 `1112` 条零消化积压，根因不是 worker 或 LLM 故障，而是旧调度只准入单用户 `>=10` 条消息：全部债务分散在 311 人、每人 1–9 条，因此永久停在持久队列之外。

本批采用统一老化策略：`>=10` 条立即准入；3–9 条等待 7 天；1–2 条等待 21 天。任务仍受全局开放数 8、每轮准入数 8 和单 worker 约束，避免路人单句即时消耗 LLM。

## 生产证据

- backlog：1112 条 / 311 人；最早 `2026-06-26 23:08:37`。
- 分布：1 条 78 人、2 条 60 人、3 条 36 人、4 条 32 人、5 条 36 人、6 条 19 人、7 条 24 人、8 条 18 人、9 条 8 人。
- extraction jobs：4023 个均为 `done`；open/dead/error 均为 0。
- 观察窗内自治心跳存在，无 worker 异常、无 LLM 调用；旧 `messages>=10` 过滤足以完整解释零消化。
- 新策略在当前库可立即准入 182 人 / 699 条，其余为尚未到期尾部。

## 实现与观测

- `agent/extraction_policy.py` 是数量/老化阈值的单一事实源。
- stale admission 按 owner 优先、其余 oldest-first，有界进入持久任务。
- Store 和只读生产快照分别报告 `eligible_*` 与 `deferred_*`，不暴露用户标识。
- 观察器只把“已到期债务不下降”判为故障；等待期尾部无真实工作量时为 `INSUFFICIENT`，不假报 worker 停止。
- 健康检查首次采样预热；连续样本证明到期债务零消化时告警，大规模 `>30` 债务仍立即告警。

## 开源对照与取舍

- Nekro Agent 采用数量阈值、时间老化、heap 版本和 semaphore；本项目保留其有界/老化思想，但补后台 tick，避免低流量 workspace 必须等新消息才重新计算。
- [OpenClaw memory architecture](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory-architecture.md) 与 [dreaming](https://github.com/openclaw/openclaw/blob/main/docs/concepts/dreaming.md) 使用轻重双 lane、周期 flush 和有界 consolidation；本批只借鉴 quiet/age flush，不引入第二决策脑。
- [Mem0 AsyncMemory](https://github.com/mem0ai/mem0/blob/main/docs/open-source/features/async-memory.mdx) 提供异步调用、限并发和重试范式，不提供消息级公平队列，不能替代当前持久调度器。
- [Letta queue runtime](https://github.com/letta-ai/letta-code/blob/main/src/queue/queue-runtime.ts) 的稳定 item ID、scope 合并、阻塞/丢弃回调可用于后续动作队列观测；本批不扩大到动作层。

## 上线与回滚

- 代码需重启 bot 才生效；当前 2h 基线观察结束前不重启。
- 上线后核验 eligible backlog、oldest、open/dead、LLM 后台耗时和前台等待；先跑 2h，再决定 12h soak。
- 回滚只需恢复旧准入条件；无 schema/data migration，已完成任务与游标保持有效。
