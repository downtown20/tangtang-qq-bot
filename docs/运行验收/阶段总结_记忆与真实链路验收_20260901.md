## 四、本阶段发现并修复的问题

1. **私聊批处理异常**：纯文字私聊在自我记忆收尾引用未初始化的 `_self_memory_action_id`，触发 `UnboundLocalError`。源码已设置明确默认值并增加回归。
2. **贴图观察器假红**：生产链路已经迁移为 `Sticker ActionPlan`，观察器仍只识别旧 `Sticker Tool` 文案。解析器已兼容两种合同，现有日志回放为 8/8 confirmed。
3. **窗口回复默认偏置**：15 个窗口样本全部回复，但多数是明确请求，不能直接判为刷屏；唯一明显的收尾语暴露协议提示不足。现已明确“没事/好的/嗯”等情境不应为维持窗口而凑回复，决定权仍归 LLM。
4. **容量验收工具自身过慢**：原工具用数千次独立 SQLite 提交装载夹具，混淆测试器开销与系统能力。现在用真实写入预检锁定契约，再单事务装载容量夹具，状态机保留有界真实样本，并支持 `--output` 产出正式 JSON。

## 五、剩余优化点与优先级

### P0：下一次继续首先闭环

1. 用户手动重启糖糖和观察器，加载私聊初始化、贴图解析和窗口协议修复。
2. 同一新 boot 做三个短 canary：普通私聊不再抛异常；贴图被观察器判 confirmed；窗口收尾语出现合理 `skip_response`。
3. 将 legacy 候选的“批准 / 拒绝 / 延后”都写入结构化审计，记录证据、复核人、理由和时间；拒绝项不再反复进入待审队列。
4. 用一次统一全量门禁覆盖本阶段最后的小改动，形成新的完整测试基线。

### P1：质量提升

1. **低频记忆时效**：当前 deferred backlog 不是 worker 卡死，而是最长 21 天准入策略。用真实 LLM 成本、提取收益和老化曲线评估低成本批处理或缩短阈值。
2. **窗口自然度**：积累真正包含无关消息、群友互聊和收尾语的样本，再看 reply/skip/fade；不要用一组全是明确请求的验收消息调参数。
3. **自治与驱动力**：验证带证据的 promise→completion 结算能否解除长期接近 1.0 的驱动力饱和，避免自治噪声和错误状态注入。
4. **知识评估集**：当前索引内核已经完成，不再重复建设。下一步扩展多来源、长文、冲突版本和空召回黄金集，用结果决定是否需要版本 diff/回滚或轻量实体关系。

### P2：长期增强

1. 为低频唱歌、生日、定时图片、自然自治建立按需验收，不为凑覆盖率强行触发。
2. 持续观察 SQLite 写锁、后台队列和模型冷启动尾延迟；只有真实指标越线才调整并发或数据库参数。
3. 定期整理 ROADMAP，把已完成能力从“待办”移除，防止后续 agent 重复设计已经落地的系统。

## 六、经验与架构判断

- **代码完成、部署加载、真实验收是三件事。** 单元测试通过不代表当前 bot 已加载；跨 boot 报告也不能认证单实例稳定。
- **记忆强不等于记得多。** 先确保对象、作用域、原文、时间和动作状态可靠，再扩大召回率；不确定的 legacy 留作线索比错误事实进入上下文更安全。
- **有 evidence ID 不等于证据支持结论。** 玩笑、口语、省略和感叹句必须经过语义复核，不能因存在聊天行就升级可信等级。
- **监控是运行契约的消费者。** Tool→ActionPlan 等日志合同迁移必须同步更新观察器和回归，否则会制造假红，反过来误导修复方向。
- **性能测试要隔离夹具成本。** 容量、稳态延迟、冷启动、并发写锁和 LLM 服务率应分开测，不能让测试器的建连方式替系统背锅。
- **LLM 是行为决策者，系统提供事实、工具和边界。** 窗口是否回复仍由 LLM 决定；系统只把“收尾、互聊、无关消息”等情境讲清楚并记录结果。
- **开源项目用于校准设计，不用于堆依赖。** WeKnora、Mem0、Letta 的价值已经转化为持久索引、证据协议、分层记忆和异步整理思路；当前没有整体接入它们的必要。
