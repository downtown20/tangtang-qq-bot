## 二、云训练 RVC 模型的教训

### 2.1 为什么失败了

**核心问题**：用了 CosyVoice TTS 朗读作为训练数据去训练 RVC 唱歌模型。

- TTS 朗读 = 说话的音色分布（音高、节奏、情感范围窄）
- RVC 唱歌 = 需要歌唱的音色分布（音高跨度大、有旋律、有拖音）
- **TTS 样本无法覆盖唱歌时的音色空间，训练出来的模型唱歌跑调严重**

### 2.2 训练日志

- 平台：AutoDL 云 GPU（RTX 3090, 30GB 磁盘）
- 数据：50 条 CosyVoice TTS 朗读（~58MB 压缩包）
- 配置：RVC v2, 40kHz, batch_size=5, 200 epochs（没跑到）
- 崩溃点：大约第 34-37 步 segfault（numba + librosa 不兼容）
- 磁盘满了：每个 checkpoint 417MB，30GB 很快不够

### 2.3 关键发现

1. **唱歌训练必须用真实的歌唱数据**，不能是 TTS 朗读
2. **云 GPU 磁盘太小**（30GB），RVC 训练 checkpoint 很大
3. **numba/librosa 兼容性问题**是已知坑
4. **checkpoint 格式不同**：fairseq 训练格式 vs RVC 推理格式（见第三节）

### 2.4 如果下次要训练

必要的数据准备：
- **真实人声翻唱**（不能是 TTS），至少 10-30 分钟
- 需要覆盖音域范围（高音、低音都要有）
- 质量 > 数量：3-5 首完整歌曲比 50 句朗读好得多
- 云磁盘至少 100GB
- Python 3.10 环境，预先装好 numba==0.56.4 + librosa==0.9.2

## 三、RVC Checkpoint 格式转换

### 3.1 两种格式

**Fairseq 训练格式**（云训练的 G_990.pth）：
```python
{
    "model": OrderedDict(...),     # 模型权重
    "iteration": 990,
    "optimizer": {...},            # 优化器状态
    "learning_rate": 0.00015
}
```

**RVC 推理格式**（infer_cli.py 需要）：
```python
{
    "weight": OrderedDict(...),    # 模型权重（同 model）
    "config": [768, 12800, 192, 192, 768, 2, 6, 3, 0, "1",
               [3,7,11], [[1,3,5]×3], [10,10,2,2], 512,
               [16,16,4,4], n_spk, 256, 40000],
    "f0": 0,                      # 0=使用输入音频的 f0
    "version": "v2"
}
```

### 3.2 如何反向推断 config

从权重 tensor 的 shape 反推架构参数：
- `emb_g.weight.shape[0]` → n_spk（说话人数量）
- `enc_q.pre.0.weight.shape` → spec_channels=768（v2=768维HuBERT）
- upsample 层的数量和 ratio 推断采样率

工具脚本：`convert_checkpoint.py`（已保留）

## 四、Python 版本隔离

### 4.1 两套 Python 环境

| 组件 | Python | 原因 |
|------|--------|------|
| CosyVoice2 | 3.14（主项目） | 需要 hyperpyyaml, modelscope 等 |
| RVC | 3.10 | RVC WebUI 依赖旧版 torch/numba/librosa |
| Demucs | 3.10 | 与 RVC 同环境 |

**绝对不能混用**：在不同 Python 版本下 import 会导致依赖地狱。

### 4.2 跨版本调用模式

```python
# 从 Python 3.14 调用 Python 3.10 的 RVC
subprocess.run([
    r"C:\Users\Administrator\AppData\Local\Programs\Python\Python310\python.exe",
    "tools/infer_cli.py",
    "--input_path", input_wav,
    "--opt_path", output_wav,
    "--model_name", "hutao",
    "--index_path", index_path,
    "--f0method", "pm",   # "pm" 比 "rmvpe" 省内存
], cwd=RVC_DIR, env={
    **os.environ,
    "OPENBLAS_NUM_THREADS": "1",
    "OMP_NUM_THREADS": "1",
})
```

## 五、RVC 内存问题

### 5.1 症状
```
OpenBLAS: malloc failed in gemm_driver
```
在 CosyVoice → RVC 连跑时出现，因为 CosyVoice 已占用大量内存。

### 5.2 解决方案

1. `OPENBLAS_NUM_THREADS=1` — 限制 OpenBLAS 线程
2. `OMP_NUM_THREADS=1` — 限制 OpenMP 线程
3. `--f0method pm` — 用 "pm"（parselmouth）替代 "rmvpe"（深度学习），省 ~2GB
4. 两个步骤间加 `gc.collect()` + `time.sleep(2)`
5. 不要在同一个进程里跑 CosyVoice 和 RVC — 用 subprocess 隔离

## 七、CosyVoice 音色注册流程

```
1. CosyVoice TTS 生成参考朗读（用任意已有音色，如 xiaogong）
2. RVC 把参考朗读转成目标音色
3. CosyVoice register_speaker() 注册新音色
4. 配置 config.yaml → voice.cosy_speaker = "新音色名"
5. 清理临时文件 → 重启糖糖
```

关键点：
- 参考音频 3-10 秒即可
- 参考文本必须与音频内容一致
- 注册后即时生效，无需重启（但切换配置需要重启糖糖）

## 八、唱歌系统（RVC 唱歌）

### 8.1 歌曲制作流程

```
原始翻唱 (songs/covers/)
  → Demucs 人声分离 (songs/covers/htdemucs/)
  → RVC 音色转换 (songs/audio/)
  → 点歌时播放
```

### 8.2 batch_convert.py 注意点

- 路径必须用 `os.path.abspath()` 否则 `load_audio` 找不到文件
- f0method: `rmvpe` 质量更好但吃内存，`pm` 稳定
- 输出格式：`.wav`（WAV PCM），大约 15-27MB 每首
- 共 18 首歌已转换完成

### 8.3 点歌优先级

预制音频 (songs/audio/) > TTS 朗读

## 九、下次做语音的方向

### 如果想改进唱歌质量：

1. **用真人翻唱训练 RVC** — 找 3-5 首胡桃声线相近的真人翻唱作为训练数据
2. **换更好的 SVC 方案** — RVC 之外还有 So-VITS-SVC、DDSP-SVC 等
3. **直接找更好的预制模型** — 胡桃是原神热门角色，网上可能有高质量开源模型

### 如果想改进说话质量：

1. **换更好的 TTS** — CosyVoice2 效果已经不错，可以考虑 CosyVoice3 或 GPT-SoVITS
2. **优化参考音频** — 用更好的参考音频重新注册，影响 TTS 质量
3. **情绪控制** — 目前 edge-tts 有情绪调速，CosyVoice 可能需要额外的 prompt engineering

### 如果想统一说话和唱歌：

- **GPT-SoVITS** — 端到端方案，说话和唱歌都能做，但需要 1 小时以上的训练数据
- 目前两个独立系统各司其职是合理的折中

## 十、踩坑清单

| 坑 | 症状 | 解决 |
|----|------|------|
| TTS 训练 RVC | 唱歌声音完全不像 | 必须用真实唱歌数据训练 |
| checkpoint 格式不匹配 | `KeyError: 'config'` | convert_checkpoint.py |
| Python 版本混用 | import 报错 | 两个 Python 分别调用 |
| OpenBLAS 内存溢出 | malloc failed in gemm | 限制线程 + f0method=pm |
| 相对路径 | load_audio 找不到文件 | os.path.abspath() |
| 云磁盘满 | 训练中断 | 100GB+ 磁盘，定期清理旧 checkpoint |
| numba/librosa 不兼容 | segfault | 固定版本组合 |
| CosyVoice Whisper 依赖 | ModuleNotFoundError: whisper | pip install openai-whisper |
