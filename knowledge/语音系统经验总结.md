> 用途：下次动语音 / 唱歌相关代码或素材前，先读这篇。
>
> **2026-10-15 重写**：原版（2026-06-30 记）写的是 CosyVoice2 + RVC 那一套，而那两个引擎
> 连同各自目录已于当日整体删除。本篇只写**现在真实存在的东西**；被删的链路收在第二节，
> 因为其中的教训仍然成立。

## 一、现在的语音栈（2026-10-15 定版）

| 功能 | 技术 | 说明 |
|------|------|------|
| 说话（TTS） | **GPT-SoVITS——唯一的 provider** | 本地 API `http://127.0.0.1:9880`；`config.yaml` → `voice.provider: gpt-sovits` |
| 唱歌 | **播放录音成品（不做实时合成）** | `songs/audio/歌名.wav`（糖糖声线）+ `songs/covers/separated/歌名_FINAL.*`（原声） |
| 听懂别人发的语音 | sherpa-onnx / whisper（`agent/asr.py`，模型在 `asr_models/`） | 与唱歌无关 |

**三条要点**：

- 唱歌**不需要任何模型**：`sing` 工具 → `agent/songs.py` → 直接放文件。
- 所以**不需要 RVC / HuBERT / FAISS 索引 / demucs / UVR5 / DiffSinger**——任何文档还在讲
  这些工具的用法，都是漏改的过期内容。
- `tools/` 下的翻唱/分离脚本（`separate_vocals.py`/`.bat`、`rvc_sing.py`、`rvc_convert.py`、
  `train_rvc.py`、`prepare_rvc_dataset.py`、`register_hutao_speaker.py`、`diff_sing.py`、
  `歌唱组件.py`、`download_covers.py`、`batch_render_all.py`）已于 2026-10-15 一并删除——
  别再照旧文档去调它们。
- 说话链与唱歌链**没有交集**：除了"都是音频"之外互不依赖。改一条不要顺手改另一条。

### 1.1 说话：参考音与情绪

- 参考音目录：`gpt-sovits/speakers/<名字>/ref.wav`。实测存在的目录：
  `normal / gentle / happy / excited / coquettish / tsundere / sad / surprised / angry / disgust`
  （米雪儿中文情绪参考音）、`murasame`（丛雨日语）、`xueli / xueli_gentle / xueli_happy / xueli_tsundere`。
- **情绪传递机制**：参考音频的情感直接传到输出——嘶吼的参考 → 嘶吼的输出，不用调参数。
  选对参考音频就完成了一半。
- 糖糖现用音色参考音是**丛雨（murasame）**；原始素材在 `音频/丛雨/`（400 个 `mur001_*.wav`）。
  ⚠️ 这 400 个文件**不是 RVC 产物**，是选参考音用的原始语料，清理时保留。
- `/角色` 会原子联动"模型 profile + 参考音 + 角色卡 + 贴图库"；语音服务没起来时
  `switch_model` 失败，**人格卡与贴图都不会切**（`agent/handler_commands.py` `_cmd_role`）。

### 1.2 唱歌：只有播放，没有制作

- 曲库就是 `songs/` 目录：`歌名.txt`（歌词）+ `audio/歌名.wav`（糖糖声线）+
  `covers/separated/歌名_FINAL.*`（原声）。
- 可复现口径：`SongLibrary("./songs")` → **45 条曲目，其中 41 首有音频**。
- 加歌 = 放音频 + 放同名歌词 txt + `/歌单 重载`（歌词格式：第一行歌手，空一行，
  再按 `[主歌1]`/`[副歌]`/`[主歌2]`/`[尾声]` 分段）。
- 控制台里**没有曲库页、没有歌唱工作室**：制作侧整页已于 2026-10-15 移除。

## 二、历史：被删除的链路（教训仍有效）

### 2.1 CosyVoice2 / CosyVoice3 说话

- 形态：CosyVoice2 自建服务 + `register_speaker()` 注册音色（胡桃 hutao），
  `config.yaml` 的 `voice.cosy_speaker` 指过去；后来作为 `cosyvoice` provider 与
  GPT-SoVITS 并存，属于降级/备用路径。
- 为什么删：与 GPT-SoVITS 功能重叠，两套并存是维护负担；主人拍板说话侧只留 GPT-SoVITS
  （决策见 `docs/发布/GitHub发布计划_20260905.md` 的对比表）。
- **留存的通用教训**：音色注册类流程必须能复现——参考音频、参考文本、注册参数三者缺一，
  换机之后就复原不出来。

### 2.2 RVC 自训练唱歌（三次尝试全部失败）

- **主要矛盾：训练数据与目标场景不一致。** 用 TTS 朗读当训练数据去训唱歌模型——TTS 朗读是
  "说话"的音色分布（音高、节奏、情感范围都窄），而唱歌需要音高跨度大、有旋律、有拖音的分布。
  训出来的模型唱歌跑调严重。
- 其它硬门槛：48k 预训练底模是 RVC **v1 架构**，而 WebUI 的 config 是 **v2 架构**，加载直接失败
  （原风险表只想到显存和下载速度，**漏判了架构兼容性**）；云 GPU 30GB 磁盘装不下 checkpoint
  （每个 417MB）；numba / librosa 版本不兼容导致 segfault。
- 结论（当时如此，现在也是）：**唱歌不做合成**。糖糖唱歌 = 播录音成品。
- **留存的通用教训**：① 数据分布必须与目标场景一致，"够多"不能替代"够像"；
  ② 引入任何预训练模型前，先验证底模与运行时的**架构兼容性**。

### 2.3 人声分离（demucs / UVR5）

- 当时用途：把原曲分离出人声，或给 RVC 做音色转换的输入，或直接当"原声"版本。
- 现在**不需要了**：原声版本是成品文件（`covers/separated/*_FINAL.*`），不再现做分离。
  `venv_demucs/` 与 `uvr5_models/` 已于 2026-10-15 删除。
- **留存的通用教训**：分离 / 转码这类离线重工具链要单独建 venv——当时的 GPU 驱动与老版
  PyTorch 会互相破坏。以后引入任何离线音频工具都照这条办，别塞进主环境。

### 2.4 逐段歌声合成（DiffSinger）

- 当时形态：MiniEngine + 莲华 ONNX 声库，配合 `[SING:段落]` 播放段落级音频；端口 9266。
- 段落音频**从来没有真正生成出来**（`songs/audio/歌名/` 下没有段落文件），实际降级路径是
  TTS 朗读歌词——而朗读不是唱。
- 现在：DiffSinger 与 MiniEngine 已删除，`[SING:段落]` 仍然存在，但只有"整首播放"这一条路。

## 三、踩坑清单（仍然成立的部分）

| 坑 | 症状 | 处理 |
|----|------|------|
| 用 TTS 数据训唱歌模型 | 唱歌声音完全不像 | 唱歌数据必须是真唱；本项目已不做合成 |
| 底模与运行时架构不匹配 | 加载直接失败，无报错线索 | 引入预训练模型前先核对架构版本 |
| Python 版本混用 | import 报错 / 依赖地狱 | 每条重依赖链单独一个 venv（主环境是 3.10） |
| 中文路径 + C++ 窄字符 `fopen` | 索引 / 模型**静默**加载失败，只是效果变差 | 传相对路径，或落在纯 ASCII 路径下 |
| 并发加载模型 | 权重不完整、推理全废 | 所有模型加载串行（`agent/model_lock.py`） |
| 语音缓存无限膨胀 | 磁盘一直涨 | 缓存按 500 文件 / 200MB 上限按 mtime 清理 |
| GPT-SoVITS 截断输出 | 用户听到"叽"一声，HTTP 200 无报错 | 时长 < 字数×0.06s 判定截断 → 自动重试最多 3 次 → 再失败降级 edge-tts |

## 四、常用命令

```bash
# 曲库现状（可复现口径：45 条 / 41 首有音频）
python -c "from agent.songs import SongLibrary; l=SongLibrary('./songs'); print(len(l.songs), len(l.list_songs_with_audio()))"

# 曲库热重载（聊天里也等价于 /歌单 重载）
python -c "from agent.songs import SongLibrary; SongLibrary('./songs').reload()"
```

> 说话链路的就位检查走 `tools/体检.py`；这里不重复已删引擎的命令。
