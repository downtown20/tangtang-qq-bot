# ── torch：**必须装加速版，且按机器选**（2026-10-14 T51/T52 定案；T54-A 自动化）──
#   [!] 这一节是「判决书」，不是手工步骤——**安装器已按本机设备自动选档**：
#         python tools/安装糖糖.py 安装                        # auto：探测本机设备选档
#         python tools/安装糖糖.py 安装 --torch-variant cpu    # 人工覆盖（探测判错/离线时）
#       判定规则（可判定，不是口号；实现 tools/安装糖糖.py:detect_torch_variant）：
#         ① nvidia-smi 能列出显卡 且 算力 ≥ sm_70            → cuda 档（cu130）
#         ② 否则 WMI 显示适配器里有 Intel Arc / Iris Xe      → xpu 档
#         ③ 否则（含 AMD 核显/独显——PyTorch 在 Windows 上无官方 ROCm）→ cpu 档
#       判据①**不依赖 torch**：新机器上 torch 还没装，agent/devices.py 的检测必然报
#       CPU，只有 nvidia-smi / WMI 判得出「这台机器有卡」——这正是原先漏掉的那一环。
#
#   本项目跑在两台机器上，它们的 torch 版本**不一样**，这是刻意的：
#
#   ① 台式机 <台式机>（NVIDIA RTX 5070 / sm_120）→ CUDA 版
#        pip install "torch==2.13.0+cu130" --index-url https://download.pytorch.org/whl/cu130 --no-deps
#      实测：arch 含 sm_75..sm_120、CUDA 可用、reranker 在 GPU 上 177ms 给出正确排序。
#
#   ② 笔记本 <笔记本>（Intel Arc 130T 核显，**没有 NVIDIA 卡**）→ XPU 版
#        pip install "torch==2.9.1+xpu" "torchaudio==2.9.1+xpu" --index-url https://download.pytorch.org/whl/xpu --no-deps
#      cp310-win 上 XPU 轮子最高只到 2.9.1（Intel 对 Arrow Lake-H 的 Windows 支持
#      目前仍标 beta）。装完后 python -c "import torch;print(torch.xpu.is_available())"
#      为 True 时，agent/devices.py 会自动把它排到 CPU 前面 —— GPT-SoVITS 的设备
#      补丁（gpt-sovits/start_api_patched.py）、重排、降噪一起生效。
#      **没装 XPU 也不会坏**：设备阶梯自动退到 CPU，只是慢（见最下面的实测）。
#
#   ⚠ 为什么两台机器不能共用一份 torch：
#     CPU 版没有 sm_120 内核 → 台式机的 5070 等于废卡；
#     CUDA 版在笔记本上没有 NVIDIA 卡 → 白占约 1.8 GB，设备判定只会退到 CPU。
#
#   ⚠ 为什么两台都不能用 .dev（nightly）版：
#     agent/reranker.py 的守卫只放行**稳定版**（版本号含 .dev 直接跳过加载、退化为
#     纯余弦排序）。那是 2026-08-15 模型加载事故留下的防线，不要绕过它。
#
#   ⚠ --no-deps 是故意的：torch 会顺手把 numpy 顶到 2.x，而本项目把 numpy 钉在
#     <1.24（numba 0.56 需要，见上方 numpy 那条）；torch 自身的依赖装它时已在位。
#
#   ⚠ torchaudio 在 cp310-win_amd64 上**没有 2.13 对应轮子**（cu130/cu128/cu126
#     三条线的最高都是 2.11.0）。台式机实测 torch 2.13.0 + torchaudio
#     2.11.0.dev20260727+cu130 导入与 resample 均正常，故保留不动。
#     笔记本那条线是**匹配的** 2.9.1+xpu 对 —— 不要为了「统一」去动两台的 torchaudio。
#
#   ⚠ 无加速卡时的真实代价（2026-10-14 同一台机器实测，GPT-SoVITS 合成同一批文本）：
#         GPU  2 / 18 / 50 / 100 字 = 1.2 / 1.5 / 2.7 / 5.4 秒
#         CPU  2 / 18 / 50 / 100 字 = 42.8 / 40.2 / 80.9 / 198.2 秒
#     voice.py 的超时预算按设备自适应（agent/voice.py 的 tts_timeout），所以 CPU 上
#     不会「超时失败」，只是**要等**。想快就装上面 ② 的 XPU 版。
