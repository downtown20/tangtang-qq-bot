# 糖糖回归测试套件 🧪

主动测试体系——替代"慢观察期"，验证糖糖行为是否正确、对话是否有质量（2026-08-11）。

## 一、为什么需要它

- 固定脚本场景（女仆装/猫娘图/叫名字/窗口/记忆/隐私）→ 验证**触发逻辑**没回归
- 真实对话（GPT 扮演用户聊天）→ 验证**对话质量**（共情/分寸感/人设/机械感）——固定脚本发现不了这些

## 二、架构

```
tools/测试套件/
├── 测试指挥.py        # 🕹️ 聊天式测试 Agent——自然语言指挥（推荐入口）
├── 套件.py            # 底层：场景运行 / 真实对话 / GPT 审查 / 报告 / 净化
├── 场景库/            # 脚本场景（触发逻辑回归）
│   ├── 基础行为.py     # 误触发×2 / 叫名字 / 窗口对话 / 互聊不每条回
│   ├── 记忆与隐私.py   # 私聊记忆 / 交叉上下文收紧
│   └── 命令与工具.py   # /状态 / @回复
├── 剧本库.json        # 10 个真实对话剧本（GPT 扮演用户的场景设定）
├── 报告/              # 每次运行生成 md 报告
└── README.md
```

## 🕹️ 推荐入口：测试指挥（聊天式 Agent）

```bash
python tools/测试套件/测试指挥.py
```

对话式控制（GPT 理解意图并执行）：

```
> 测一下隐私场景        → 跑 记忆与隐私 场景组
> 跑全部回归            → 全部脚本场景
> 跑个加班的对话        → 真实对话「加班到只剩外卖盒」
> 换个话题聊暗恋        → 切到「那个人是不是也有点喜欢我」
> 有哪些剧本            → 剧本列表
> 看报告                → 最近一次测试报告
> 退出                  → 结束
```

## 四、用法

### 脚本回归（触发逻辑）

```bash
# 全部场景（含 GPT 质量审查）
python tools/测试套件/套件.py --group 1092609076 --all --gpt审查

# 指定场景组（如重跑失败项）
python tools/测试套件/套件.py --group 1092609076 --组 基础行为
```

### 真实对话（对话质量）

```bash
# 列出剧本
python tools/测试套件/套件.py --剧本列表

# 跑一个剧本（GPT 扮演"浪浪"和糖糖自然聊天 8 轮 + 审查）
python tools/测试套件/套件.py --真实对话 "加班到只剩外卖盒" --轮数 8

# 指定剧本名（--真实对话 参数支持部分匹配之外的精确名）
python tools/测试套件/套件.py --真实对话 "凌晨两点的情绪缺口"
```

**建议**：每次改动代码后跑 `--all --gpt审查`；想查对话质量时挑 1-2 个剧本跑真实对话。

## 六、GPT 在测试里的角色

1. **扮演用户**（真实对话）：codex 按剧本 + 对话历史生成"浪浪"的下一句——糖糖的回复影响下一句，像真人聊天
2. **质量审查**（--gpt审查 / 对话结束）：codex 按剧本观察点评估糖糖表现——人设/异常/分寸感

技术要点（踩坑记录）：
- codex 调用用 `codex.cmd`（Windows npm 包装）+ `--json`（JSONL 事件流，提取 `agent_message` 的 text）
- **prompt 必须经 stdin 传入**——Windows 命令行参数会破坏含换行的中文（codex 会"收不到对话记录"）
- 扮演 quality：medium effort + "直接输出消息本身"措辞 + 元确认（"收到/你希望我"）时重试一次

## 七、自动化净化（套件内置）

每次真实对话/回归前自动执行（测试指挥已接入；命令行可用 `--不重置亲密` 跳过）：
1. **测试号亲密清零**——密集测试互动会快速堆高亲密（每日奖励+互动×N），亲密≥50 触发"信任"→ 隐私脱敏失效
2. **清私聊窗口历史**（`状态/.conversation_state.json`）——过往泄露的问答被注入私聊上下文，LLM 凭上下文复述

> 2026-08-11 实测教训：连续跑两个剧本时，糖糖会把新剧本开场当成旧话题延续（**剧本串戏**）；
> 重复跑同一剧本时，窗口记忆让"新用户"变"老熟人"（"这句话你今晚说了第三遍了"）——两者都源于窗口历史不隔离，
> 净化前置到每次测试前解决。

## 八、已知局限

1. **回复内容数据通道**：日志（handler 完整输出，repr 转义单行）——SnowLuma history API 不可靠：
   测试号收消息断导致 3010 历史冻结；糖糖侧 3000 的 reportSelfMessage 对 history 无效
2. **批跑串扰**：连续跑多个剧本时，糖糖的长期记忆（memory.db）会跨剧本引用上一剧本话题
   （如跑完体检剧本，后续剧本糖糖还提"明早拍单子"）——净化只清窗口历史+亲密，不清长期记忆。
   真实场景中记住用户过往是正常行为，审查 prompt 已注明"自然相关不算跑题"
3. **真实群干扰**：真实群活跃时（群友刷屏）糖糖 LLM 被占用 → 测试消息排队/跳过 → 偶发"无回复"（重跑该场景确认即可）
4. **单测试号**：只能模拟单角色（浪浪）——群聊多角色互动受限
5. **扮演稳定性**：GPT 扮演浪浪偶发元确认/角色错乱（"从现在起我是浪浪"）——已加重试拦截，极端仿写型污染（照抄糖糖原话）可能漏网
